CRITICAL ISSUES (Block Testing & Deployment)
-----------

1. EXTERNAL CONTROL SIGNALS NOT IMPLEMENTED (ALL EQUIPMENT)
   Location: battery.rs:1014, pv.rs, ev.rs, generator.rs
   Impact: HARES cannot accept any external control commands
   Severity: CRITICAL
   Evidence: update_control() is a stub (returns current mode unchanged)
   Test Impact: Any test using ControlSignal will silently fail
   Estimated Fix: 2-3 days (1 day per equipment type)

   Affected Controls:
   - Battery: SOC targets, power setpoints, import/export limits
   - PV: Curtailment, reactive power, inverter priority
   - EV: Power limits, SOC targets
   - Generator: Power setpoints, self-consumption mode

2. BATTERY DEGRADATION q_li1 FORMULA MISMATCH
   Location: battery.rs:473-480
   Impact: Battery aging trajectory differs from OCHRE Smith 2017 model
   Severity: HIGH
   Evidence: HARES uses b1_eff / sqrt(day_age), OCHRE uses state-dependent 0.5*b1²/q1
   Verification: Need 5-year simulation comparison
   Estimated Fix: 1-2 days (requires literature review & validation)

HIGH PRIORITY ISSUES (Correctness Gaps)

4. GENERATOR RAMP RATE UNITS INCOMPATIBILITY

================================================================================
ARCHITECTURAL IMPROVEMENTS (HARES > OCHRE)
================================================================================

HARES Advantages:
1. Smith 2017 degradation with explicit rainflow cycle counting
   - More accurate aging than OCHRE's ad-hoc model
   - Proper cycle detection via ASTM E1049-85

2. Explicit lumped cell thermal model with temperature derating
   - Better physics; OCHRE only has basic one-node RC
   - Cell heater logic clearly implemented

3. Ohmic power clamping at matched impedance limit
   - More physically sound power limitation
   - OCHRE has no explicit clamping

4. PV: Wind-corrected NOCT cell temperature model
   - Matches PVWatts v8; OCHRE doesn't expose wind correction

5. PV: SAM lookup table caching
   - Performance improvement; OCHRE runs SAM every step

6. EV: Explicit battery thermal model
   - OCHRE doesn't have temperature-dependent EV charging

7. EV: DriverArchetype enum instead of CSV
   - Cleaner, type-safe; no loss of functionality

8. Generator: Fixes OCHRE quadratic efficiency bug (min → max)
   - Correctness improvement over OCHRE

9. Port-based architecture vs schedule injection
   - Cleaner data flow; more extensible than OCHRE's dict-based approach
