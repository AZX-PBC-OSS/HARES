## Background/Context

`build_config` always emits `initialization_duration: None`, ignoring any `initialization_duration` kwarg. Both compat layer and gym env forward this parameter but it's never read. Result: warm-up never runs, giving incorrect initial thermal state.

## Work to Do

- [ ] In `build_config`, extract `initialization_duration` from `kwargs` using `extract_seconds` (same pattern as `duration`)
- [ ] Convert to `std::time::Duration` (not `chrono::Duration`) — `DwellingConfig.initialization_duration` is `Option<std::time::Duration>`
- [ ] Reject negative values with `PyValueError`; treat zero as `None` (no warm-up)
- [ ] Support both seconds (int/float) and timedelta formats
- [ ] Add Python test: `Dwelling(initialization_time=timedelta(days=7))` produces a dwelling whose thermal state differs from one without warm-up (not just checking the config field is non-None)

## Files to Touch
