# FIX-004: HVAC number_of_speeds not derived from HPXML

> **REVISED** (Codex review 2026-03-19): Adding `number_of_speeds` alone is insufficient — stage capacities, EIR, and curve selection must also be wired. Corrected SEER thresholds to match OCHRE exactly. Noted overlap with FIX-015.

> **Architecture note:** HARES Rust core must use clean, typed, SI-unit config keys only. Any OCHRE key/unit translation happens in the Python adapter layer (`python/ochre_next/compat/`). Do not add dual-key lookups or OCHRE naming conventions to Rust code.

**Severity:** CRITICAL
**Crate:** `hares-io`
**File:** `crates/hares-io/src/hpxml/equipment.rs`

---

## Bug

HPXML parsing extracts `CompressorType` and maps it to `speed_control_mode` (lines 227-235), but doesn't compute the integer `number_of_speeds` (1/2/4) that HVAC equipment models need. The `number_of_speeds` key is never inserted into the equipment config. More critically, even if `number_of_speeds` were set, the per-speed capacity ratios, COP values, and performance curve selection are not wired — so the equipment would still run as single-speed.

```rust
// equipment.rs:227-235
if let Some(compressor_type) = child_text(heat_pump, "CompressorType") {
    let mode = match compressor_type.to_ascii_lowercase().as_str() {
        "single stage" => "single_speed",
        "two stage" => "two_speed",
        "variable speed" => "variable_speed",
        _ => "single_speed",
    };
    params.insert("speed_control_mode".to_string(), Value::String(mode.to_string()));
}
// NOTE: number_of_speeds is NOT derived or inserted
```

A grep for `number_of_speeds` across all crates returns zero results. All multi-speed equipment runs as single-speed because the per-speed capacity ratios and COPs are never populated (see also FIX-015).

## OCHRE Reference

OCHRE `Dwelling.py` maps compressor type to `number_of_speeds`:
- `single_stage` -> 1
- `two_stage` -> 2
- `variable_speed` -> 4

OCHRE has SEER-based fallback logic when CompressorType is absent (exact thresholds):
- SEER <= 15 -> 1 speed
- SEER <= 21 -> 2 speeds
- SEER > 21 -> 4 speeds

OCHRE then uses `number_of_speeds` to key into `HVAC Multispeed Parameters.csv` to look up capacity ratios and COP multipliers for each speed stage.

## Fix

All `number_of_speeds` derivation from CompressorType + SEER belongs in `hares-io` HPXML parsing — the boundary between external formats and HARES internals. The Rust equipment model simply reads `number_of_speeds: u8` from its typed config struct. No OCHRE-style string matching (e.g., `"single stage"` → speeds) in equipment code.

This requires end-to-end multispeed parameterization, not just setting `number_of_speeds`:

1. **Derive `number_of_speeds` in `hares-io` HPXML parsing** from CompressorType + SEER using OCHRE's exact thresholds:

```rust
// In hares-io/src/hpxml/equipment.rs
let n_speeds: u8 = match mode {
    "single_speed" => 1,
    "two_speed" => 2,
    "variable_speed" => 4,
    _ => 1,
};
params.insert("number_of_speeds".to_string(), json!(n_speeds));
```

2. **SEER-based fallback in `hares-io`** when CompressorType is absent (matching OCHRE exactly):

```rust
// In hares-io/src/hpxml/equipment.rs
if !params.contains_key("number_of_speeds") {
    let seer = params.get("efficiency_seer").and_then(|v| v.as_f64()).unwrap_or(0.0);
    let n_speeds: u8 = if seer > 21.0 { 4 } else if seer > 15.0 { 2 } else { 1 };
    params.insert("number_of_speeds".to_string(), json!(n_speeds));
}
```

3. **Load multispeed parameters in `hares-io`**: Use `number_of_speeds` to look up capacity ratios and COP per speed from `defaults/HVAC Multispeed Parameters.csv`. Insert per-speed capacity ratios and EIR values into the equipment config.

4. **Wire stage capacities/EIR into equipment config** so that the HVAC equipment model can actually use multispeed operation at runtime. The equipment model receives clean typed arrays (`capacity_ratios: Vec<f64>`, `speed_cops: Vec<f64>`) — no CSV paths or OCHRE column names.

Apply the same logic to `CoolingSystem` entries (lines 132-163) which also have CompressorType.

**Note:** This ticket overlaps significantly with FIX-015 (multispeed curve wiring). They should be implemented together or sequenced FIX-004 first, then FIX-015.
