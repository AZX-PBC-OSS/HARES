## Background/Context

Five equipment canonical names produced by HPXML resolvers have no corresponding
registry entry — construction silently succeeds with the equipment absent. The
`registry.create()` failure path then logs a warning and `continue`s, meaning
the simulation runs with missing equipment and no user-visible error.

Confirmed mismatches (from AR-005):

| Resolver emits | Registry has | Severity |
|----------------|--------------|----------|
| `"Gas Tankless Water Heater"` | `"Tankless Water Heater"` only | HIGH |
| `"Generic Heater"` | not registered | HIGH |
| `"Generic Cooler"` | not registered | HIGH |
| `"Water Heating"` | not registered | MEDIUM |

Note: `"Electric Vehicle"` is already registered — AR-005 F-001 was previously
fixed. The remaining four are addressed here.

Fixes: AR-005 F-002, AR-005 F-003, AR-005 F-004, AR-005 F-008, AR-005 F-009,
CC-005.

## Work to Do

### Registry name fixes

- [ ] In `crates/hares-equipment/src/water_heater/tankless.rs`
  `register_with_registry()`: add alias
  `registry.register("Gas Tankless Water Heater", ...)` pointing to the same
  `TanklessWH::new` factory. The fuel type is determined at `init()` time from
  the config `fuel_type` key, so the same constructor handles both.
- [ ] Do NOT register `"Generic Heater"` or `"Generic Cooler"` as aliases.
  For strong type safety, the resolver must produce a real equipment name or
  fail loudly. No generic fallback aliases.
- [ ] Audit `resolve_hvac.rs:588` (`"Generic Heater"`) and `resolve_hvac.rs:596`
  (`"Generic Cooler"`) match arms. Replace the `_ => "Generic Heater"` and
  `_ => "Generic Cooler"` fallbacks with `Err` returns from the resolver
  function. The caller must propagate the error rather than silently producing
  an unregistered name. Document which HPXML system type strings trigger this
  arm so the error message names them.
- [ ] Audit `resolve_water_heater.rs:341` (`"Water Heating"` fallback). Replace
  with `Err` return from `canonical_water_heater_name` (change its signature
  to `Result<String, HpxmlError>`). The caller propagates the error. Document
  which WH type + fuel combinations hit this arm.
- [ ] Add `EquipmentRegistry::known_names(&self) -> Vec<&str>` method returning
  all registered canonical names, sorted. Used in tests and diagnostics.

### Registration failure → hard error

- [ ] In `crates/hares-core/src/dwelling/mod.rs`: find all `registry.create()`
  call sites. Change the `Err(e) => { warn!(...); continue; }` pattern to
  `Err(e) => return Err(e)` for equipment in the categories:
  `EndUse::HVAC_HEATING`, `EndUse::HVAC_COOLING`, `EndUse::WATER_HEATING`,
  `EndUse::EV`, `EndUse::BATTERY`, `EndUse::PV`.
  Scheduled loads and event loads that fail can remain as warnings (they are
  user-defined optional additions) — but log at `error!` level not `warn!`.
- [ ] Similarly, equipment `init()` failures (`eq.init(config, env)` returning
  `Err`) must propagate as `Err` for the same critical categories. The
  `continue` pattern is not acceptable for core HVAC/WH/DER equipment.
- [ ] Add `EquipmentRegistry::assert_no_silent_overwrites` guard: the `register()`
  method currently silently overwrites existing entries. Change to:
  `#[cfg(debug_assertions)] assert!(!self.factories.contains_key(...),
  "duplicate registration for {name}")`. This catches programming errors in
  tests without a runtime cost in release builds.

### Tests

- [ ] Add test `all_canonical_resolver_names_are_registered`:
  enumerate every string that `canonical_water_heater_name`,
  `canonical_hvac_name` (heating and cooling sides), and `resolve_der.rs`
  emit as `ochre_class` and assert each is present in
  `EquipmentRegistry::new().known_names()`. This is the AR-005 T-001 test.
- [ ] Add test: constructing a dwelling with an unregistered equipment name in

- [ ] Add test: `"Gas Tankless Water Heater"` creates a `TanklessWH` successfully
  and `init()` sets `fuel_type = FuelType::Gas`.
