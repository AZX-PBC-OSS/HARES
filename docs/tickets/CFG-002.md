## Background/Context

`inject_kw_schedule` writes up to 525,600 individual `schedule_kw_N` JSON keys per equipment into EquipmentSpec.parameters. Replace with compact config keys that equipment uses to construct the right ScheduleSource variant. No legacy keys — compact-only from the start.

## Work to Do

- [ ] Change `inject_schedule_into_specs` signature: `schedule: &mut ScheduleTimeSeries` (was `&`)
- [ ] **CSV-sourced path**: compute max_kw, add pre-scaled kW column to ScheduleTimeSeries, inject `power_schedule_source: "column"` + `power_schedule_col: <col_idx>`
- [ ] **Default-profile path**: inject `power_schedule_source: "daily_profile"` + `power_profile_max_kw` + `power_profile_weekday` (FloatArray) + `power_profile_weekend` (FloatArray) + `power_profile_month` (FloatArray)
- [ ] **Constant/zero path**: inject `power_schedule_source: "constant"` + `power_constant_kw: f64`
- [ ] **Event schedules**: inject `event_window_schedule_col` for CSV, `event_window_source: "constant"` for flat
- [ ] Delete `inject_kw_schedule`, `inject_zero_schedule`, `inject_event_window` — these are the old N-key emitters
- [ ] Delete `parse_indexed_series` — no consumer will need it
- [ ] Update all callers of `inject_schedule_into_specs` to pass `&mut ScheduleTimeSeries` — this includes `dwelling.rs` which currently passes immutable schedule ref from EnvironmentManager. Add mutable accessor or restructure to allow mutation before equipment init.
- [ ] Tests: compact keys for CSV, profile, and constant paths. No legacy key tests.
