## Status: INVALID — Closed by review

**The described bug does not exist.** HARES's `0.75 * t_upper + 0.25 * t_lower` composite sensor is **identical** to OCHRE's HPWH compressor control path (WaterHeater.py:593: `t_control = (3/4) * t_upper + (1/4) * t_lower`).

The "separate threshold checks" the ticket references (`t_upper < setpoint - deadband`, `t_lower < setpoint - deadband`) appear only in `ElectricResistanceWaterHeater.run_thermostat_control` (lines 405-422), which governs Upper/Lower resistance element control — **not** HPWH compressor control. The ticket incorrectly applied ERWH logic to the HPWH path.

**Do not implement this ticket.** Applying the proposed change would introduce a regression by diverging from OCHRE's correct HPWH behavior.

## Real divergence to track separately

OCHRE's HPWH thermostat (lines 595-599) includes hard-coded backup resistance escalation thresholds (-13°C and -15°C below setpoint) that are absent from HARES. HARES uses a single configurable `backup_enable_offset_c` (default 8°C). This is a real behavioral divergence that warrants its own ticket if alignment is desired.
