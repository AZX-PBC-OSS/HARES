## Background/Context

Six test quality issues that cause flakiness, false passes, or maintenance burden:

1. **T6-1:** Hardcoded temp-file paths (`"hares_smoke_beopt_1h.csv"`, etc.) in `temp_dir()` cause data races under parallel `cargo test`.
2. **T6-3:** Stale-temp regression test uses `<=` — passes whether defect is present or absent.
3. **T6-4:** Magic number `2.0` for `Disconnected` connection state, `0.301` for SOC tolerance.
4. **T6-5:** `thread::sleep(5ms)` in fleet test to force parallelism detection.
5. **T6-6:** Urgency ordering assertion uses `>=` instead of `>`.

## Work to Do

- [ ] Replace all static temp-dir filenames with unique paths using nanosecond suffix (adopt pattern from `orchestration_parity.rs::unique_temp_path`)
- [ ] Fix `orchestration_parity.rs:471`: change `<=` to a directional assertion that detects whether the defect is present vs fixed
- [ ] Replace magic `2.0` in `ev/tests.rs:113` with a named constant (e.g., `CONNECTION_STATE_DISCONNECTED`) or compare against the enum's telemetry encoding method
- [ ] Replace `0.301` tolerance with `soc_target + TOLERANCE` using a named `const TOLERANCE: f64`
- [ ] Replace `thread::sleep(5ms)` in `fleet.rs:538` with a `std::sync::Barrier` or channel-based synchronization
- [ ] Change `>=` to `>` in `departure.rs:183` urgency ordering assertion
