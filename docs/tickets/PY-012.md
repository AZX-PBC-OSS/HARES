## Background/Context

The Rust `EnvironmentManager` already supports `set_solar_override(Vec<Vec<SurfaceIrradiance>>)` to replace the internal Perez tilted irradiance model with externally computed plane-of-array (POA) data. This is used in tests (pvlib CSV overrides) but has no Python binding.

Users need to:
1. Compute POA using pvlib or PySAM in Python
2. Pass it to the simulation as numpy arrays, polars DataFrames, or Parquet file paths
3. Override envelope + PV solar calculations with their external data

The Rust types involved:
- `SurfaceIrradiance { surface_id: u32, direct_w_m2: f64, diffuse_w_m2: f64, reflected_w_m2: f64, angle_of_incidence_rad: f64 }`
- Override data is `Vec<Vec<SurfaceIrradiance>>` — outer vec is per-timestep, inner vec is per-surface

## Work to Do

- [ ] Add `set_solar_override()` method to `PyDwelling`:
  - **From Parquet file:**
    `set_solar_override(path: str)` — load a Parquet file with columns matching the existing CSV format: `step, s0_direct, s0_diffuse, s0_reflected, s0_aoi, s1_direct, ...` (surface-indexed columns). Parse in Rust using the same logic as `load_solar_override` in test fixtures.
  - **From polars DataFrame:**
    `set_solar_override(df: polars.DataFrame)` — accept a DataFrame with the same column layout. Convert via Arrow IPC bridge (from PY-001) or extract columns directly.
  - **From numpy arrays:**
    `set_solar_override(data: dict[int, dict[str, numpy.ndarray]])` — dict mapping `surface_id` → `{"direct": array, "diffuse": array, "reflected": array, "aoi": array}`. Each array has length == n_timesteps.
  - **From structured list (low-level):**
    `set_solar_override(data: list[list[dict]])` — list of timesteps, each containing a list of `{"surface_id": int, "direct_w_m2": float, "diffuse_w_m2": float, "reflected_w_m2": float, "angle_of_incidence_rad": float}` dicts
  - Use `#[pyo3(signature)]` with union-typed argument or separate method names if PyO3 doesn't support dispatch
  - Internally: convert to `Vec<Vec<SurfaceIrradiance>>`, call `dwelling.environment.set_solar_override(data)`
- [ ] Add `clear_solar_override()` method to `PyDwelling`:
  - Calls `dwelling.environment.clear_solar_override()`
- [ ] Add `has_solar_override() -> bool` property to `PyDwelling`:
  - Returns whether a solar override is currently active
- [ ] Add `surface_ids()` method to `PyDwelling`:
  - Returns `list[int]` of surface IDs used by the envelope + PV models
  - Users need this to know which surfaces to compute POA for
- [ ] Update `_hares.pyi` with stubs
- [ ] Write `tests/python/test_py_solar_override.py`:
  - Load a test EPW fixture, construct a dwelling
  - Call `surface_ids()` → verify non-empty list of ints
  - Create synthetic POA data as numpy arrays (all zeros) → `set_solar_override()` → `step()` → verify PV output is ~0
  - Create synthetic POA data as polars DataFrame → same verification
  - Load existing pvlib CSV fixture as polars DataFrame → `set_solar_override()` → run 10 steps → verify PV produces power > 0
  - Call `clear_solar_override()` → step → verify internal Perez model resumes (output changes)
  - Verify dimension mismatch raises ValueError (wrong number of timesteps or surfaces)
  - Verify Parquet file path works: write polars DataFrame to temp Parquet → pass path → verify same results
