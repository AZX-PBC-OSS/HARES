## Background/Context

HARES adds forced ventilation linearly on top of infiltration but does not account for HRV/ERV heat recovery. OCHRE (Envelope.py:73-74) also uses linear addition but applies recovery efficiency: `sensible_flow = total_nat_flow + forced_vent_flow * (1.0 - sens_recovery_eff)`. HARES is missing the `sens_recovery_eff` / `lat_recovery_eff` parameters entirely, meaning HRV/ERV systems provide zero heat recovery benefit.

**Note:** The original audit incorrectly claimed OCHRE uses quadrature combination. Codex review confirmed OCHRE uses linear addition with recovery adjustment. The fix scope is corrected accordingly.

## Work to Do

- [ ] Add `sensible_recovery_efficiency: f64` and `latent_recovery_efficiency: f64` fields to `VentilationConfig` (default 0.0)
- [ ] Add `balanced: bool` field to `VentilationConfig` — derived from HPXML fan type: `balanced = fan_type in ["energy recovery ventilator", "heat recovery ventilator", "balanced"]` (as OCHRE does at hpxml.py:556)
- [ ] Parse `SensibleRecoveryEfficiency` and `TotalRecoveryEfficiency` from HPXML ventilation systems. **`LatentRecoveryEfficiency` does not exist in the HPXML schema** — derive latent recovery as `total_recovery_efficiency - sensible_recovery_efficiency` (matching OCHRE hpxml.py:560)
- [ ] Apply recovery efficiencies only for balanced ventilation: `forced_sensible = forced_flow * (1.0 - sens_recovery_eff)`, `forced_latent = forced_flow * (1.0 - lat_recovery_eff)` (matching OCHRE Envelope.py:73-74)
- [ ] Document decision on unbalanced ventilation: OCHRE uses quadrature combination for unbalanced fans (Envelope.py:72) — decide whether HARES matches or diverges, and document the choice
- [ ] Add test for sensible recovery AND latent recovery paths
- [ ] Verify HARES linear ventilation+infiltration addition is correct (it matches OCHRE)
