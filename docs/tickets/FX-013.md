## Background/Context

`initialize_steady_state` currently sets all RC nodes to `indoor_temp_c` (a deliberate revert — see comment at thermal_solver.rs:751-755). A previous implementation tried the matrix solve but caused a 38°C discontinuity because the HVAC heat injection was omitted from `u_initial`. OCHRE avoids this by treating the indoor zone as a fixed boundary condition (removing T_LIV from state, adding it to inputs) before solving.

## Work to Do

- [ ] Use discrete-domain steady-state solve: `x_ss = (I − A_d)⁻¹ · B_d · u_initial` (A_c/B_c are not stored after construction; only A_d/B_d are available in `StateSpaceModel`)
- [ ] **Critical**: `u_initial` must include HVAC heat injection consistent with maintaining `indoor_temp_c`. Either:
  - (a) Treat the indoor zone as a fixed boundary condition: remove T_zone from state, add it to inputs (OCHRE's approach — Envelope.py:1013-1033), or
  - (b) Solve for the required zone heat injection first, then include it in `u_initial`
  - Without this, the solve will produce unconditioned equilibrium at outdoor temp (the exact 38°C discontinuity the code comment warns about)
- [ ] Set `zone_sensible_input_indices` entries correctly in `u_initial` — not just `indoor_temp_input_indices`
- [ ] Fall back to indoor-temp initialization only if `(I − A_d)` is singular
- [ ] Add test: steady state of a simple model matches expected temperature gradient; verify first-step discontinuity is < 1°C
