## Background/Context

Four hot-loop performance issues in the thermal solver:

1. **T2-3:** `format_domain_update()` allocates and sorts `zone_temperatures_c` and `latent_pairs` Vecs every step. Zone ordering is fixed after init — no sort needed per step.

2. **T2-7:** `lwr_by_zone_buf` is unconditionally `.clone()`d into `EnvelopeComponentGains` every step. If callers only read by reference, the clone is unnecessary.

3. **T2-9:** 8 separate `.iter().find()` calls over `infiltration_buf` per step to extract different fields from the same entry. Should extract once.

4. **T2-10:** `GlazingCurve::from_u_shgc()` is called per surface per step with constant U-factor and SHGC values. Should be precomputed at init.

## Progress

**Session 2026-03-27:**

- [x] **(T2-7)** `lwr_by_zone_buf`: Changed from `.clone()` to `std::mem::swap` pattern. Zero-copy handoff to `EnvelopeComponentGains`. Capacity is preserved after the swap via `reserve`.
- [x] **(T2-9 partial)** `infiltration_by_zone_buf` pre-allocated as a scratch field on `ThermalSolver`. Each step: `clear()` + `extend()` + `sort_by_key()` reuses existing capacity. Swapped into `component_gains` using the same swap pattern as `lwr_by_zone_buf`. Capacity preserved.

- [x] **(T2-3)** `format_domain_update()` zone_temps prealloc: zone IDs pre-populated at init in sorted order, `f64` values updated via indexed assignment per step. No per-step sort. The `DomainUpdate` clone is unavoidable since it must be returned as owned — one small Vec clone per step is acceptable.
- [x] **(T2-9)** Infiltration lookups consolidated via `infiltration_by_zone_buf` prealloc + single `indoor_inf` binding.

**Note:** GlazingCurve precomputation (T2-10) has been split into RV-007b.

## Work to Do

- [x] `lwr_by_zone_buf`: Use `std::mem::swap` instead of clone to hand off to `EnvelopeComponentGains`. Reserve capacity after swap.
- [x] `infiltration_by_zone_buf`: Pre-allocate as scratch field. Use `clear()` + `extend()` + swap pattern to avoid per-step allocation.
- [x] `format_domain_update()`: `zone_temps_buf` and `latent_pairs_buf` pre-allocated as fields. Zone IDs populated at init in sorted order. Per-step: indexed `f64` update only, no sort. `DomainUpdate` returned via clone (unavoidable — owned return, small Vec).
- [x] Infiltration lookups: consolidated via single `indoor_inf` binding after `infiltration_by_zone_buf` swap.

**Note:** GlazingCurve precomputation (T2-10) has been split into RV-007b because window surface properties (shading, dynamic glazing) may change mid-simulation — precomputing assumes immutability which needs separate verification.
