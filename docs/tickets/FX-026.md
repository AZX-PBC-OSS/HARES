## Background/Context

`_map_ochre_payload` maps `"Setpoint Temperature (C)"` to `heating_setpoint_c` only. Cooling setpoint is ignored. Also, OCHRE actually uses `"Setpoint"` key (not `"Setpoint Temperature (C)"`), so real OCHRE control calls are silently dropped.

## Work to Do

- [ ] **Change function signature**: `_map_ochre_payload(equipment_name: str, payload: Mapping[str, Any])` — the function needs the equipment name to route heating vs cooling. Update call site at dwelling.py:87
- [ ] Map OCHRE's canonical key `"Setpoint"` — remove the old `"Setpoint Temperature (C)"` key entirely. The compat layer's job is to translate OCHRE keys correctly, not accumulate aliases
- [ ] Route based on equipment name: `"HVAC Heating"` → `heat_c`, `"HVAC Cooling"` → `cool_c`
- [ ] Correct the `"ER Capacity"` key — OCHRE uses `"Capacity"` (generic, in watts), not `"ER Capacity"`. Verify HARES's `ControlSignal` enum has a variant for it; if not, defer with a comment
- [ ] Note: `"Duty Cycle"` is already partially handled (lines 131-136). Gap is ASHP multi-key case (`"HP Duty Cycle"` + `"ER Duty Cycle"`)
- [ ] Add `"Deadband"` mapping — route to `heat_c=None, cool_c=None, deadband_c=value` based on equipment name prefix
- [ ] Log WARNING for unknown keys — unknown keys are likely a misconfiguration
- [ ] Fix existing test at `test_compat_dwelling.py:137` — update to use OCHRE's canonical `"Setpoint"` key
- [ ] Add test: payload sent to `"HVAC Cooling"` with `{"Setpoint": 26.0}` results in `ThermalSetpoint` with `cool_c=26.0, heat_c=None`
