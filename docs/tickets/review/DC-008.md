## Background/Context

HARES `min_on_time_s` and `min_off_time_s` default to `0.0` (no lockout). The inline comments in
`hvac_core.rs` claim "OCHRE defaults: 120 s / 180 s". This ticket verifies those claims and
assesses whether the HARES defaults are a behavioral defect.

---

## Findings

### 1. HARES defaults

**`HvacEquipment::new()` — struct initializer** (`hvac_core.rs:250-251`):
```
min_on_time_s:  0.0
min_off_time_s: 0.0
```

**`HvacEquipment::init()` — config parse** (`hvac_core.rs:406-407`):
```rust
self.min_on_time_s  = extract_numeric(config, "min_on_time_s").unwrap_or(0.0);
self.min_off_time_s = extract_numeric(config, "min_off_time_s").unwrap_or(0.0);
```

Both paths default to `0.0`. `IdealHvac` mirrors this (`ideal_hvac.rs:110-111`).

The `DEFAULT_MIN_CYCLE_TIME_S = 60.0` constant (`hvac_core.rs:36`) is the **thermostat
bang-bang guard** (`min_cycle_time_s`), not a compressor short-cycle lockout. It governs how
long the thermostat must remain in the current mode before it can toggle again. It is entirely
separate from `min_on_time_s`/`min_off_time_s`.

**No HPXML path sets these fields.** A search of `crates/hares-io/src/hpxml/` finds zero
references to `min_on_time_s` or `min_off_time_s`. They can only be set via raw
`EquipmentConfig` key injection (tests, Python API).

---

### 2. OCHRE defaults

**`Equipment.__init__()` base class** (`Equipment.py:96-99`):
```python
on_time  = kwargs.get(self.end_use + " Minimum On Time",  0)   # minutes
off_time = kwargs.get(self.end_use + " Minimum Off Time", 0)   # minutes
self.min_time_in_mode = {mode: timedelta(minutes=on_time) for mode in self.modes}
self.min_time_in_mode["Off"] = timedelta(minutes=off_time)
```

**OCHRE HVAC subclass** (`HVAC.py`) does **not** override these kwargs. No HVAC-specific default
for minimum on/off time is set anywhere in `HVAC.py` or in any OCHRE defaults CSV/JSON/YAML.

**OCHRE HVAC default: 0 minutes (0 seconds) for both min-on and min-off.**

The inline comment at `hvac_core.rs:405` — `"OCHRE defaults: 120 s / 180 s"` — is **factually
incorrect**. OCHRE uses 0 s for both by default. The 120 s / 180 s values appear nowhere in OCHRE
for HVAC. (The only OCHRE equipment with non-zero defaults is HPWH: 10 min on, 0 min off —
`WaterHeater.py:436-439`.)

---

### 3. Two-speed speed-stage timer

Separate from the compressor on/off lockout, OCHRE's two-speed equipment has a per-speed-stage
minimum hold time (`HVAC.py:759-761`):
```python
min_time_in_low  = kwargs.get("Minimum Low Time (minutes)",  5)   # default 5 min = 300 s
min_time_in_high = kwargs.get("Minimum High Time (minutes)", 5)   # default 5 min = 300 s
```

HARES sets `min_time_per_speed_s` from config:
```rust
self.min_time_per_speed_s = extract_numeric(config, "min_time_per_speed_s").unwrap_or(300.0);
```
(`hvac_core.rs:402-403`)

**HARES default: 300 s (5 min) = OCHRE default.** This is correct.

---

### 4. Classification

| Parameter | HARES default | OCHRE default | Verdict |
|---|---|---|---|
| `min_on_time_s` (compressor on lockout) | `0.0 s` | `0 s` | **MATCH — no defect** |
| `min_off_time_s` (compressor off lockout) | `0.0 s` | `0 s` | **MATCH — no defect** |
| `min_time_per_speed_s` (two-speed stage hold) | `300 s` | `300 s` | **MATCH — correct** |

The original hypothesis that OCHRE defaults to 120s/180s is **false**. OCHRE defaults to 0 for
both, same as HARES. There is no behavioral mismatch.

---

### 5. Defect: incorrect inline comment

`hvac_core.rs:405` contains a misleading comment:
```
// "min_on_time_s" / "min_off_time_s" keys. OCHRE defaults: 120 s / 180 s.
```

This is wrong. OCHRE defaults are 0 min / 0 min. The comment must be corrected to avoid future
developers applying incorrect OCHRE-parity values.

---

## Recommended Fix

Remove the incorrect claim from the inline comment at `hvac_core.rs:405`. Correct text:

```rust
// "min_on_time_s" / "min_off_time_s" keys.
// OCHRE Equipment.py base class defaults both to 0 minutes (no lockout).
// Non-zero values must be supplied explicitly via config for short-cycle protection.
self.min_on_time_s  = extract_numeric(config, "min_on_time_s").unwrap_or(0.0);
self.min_off_time_s = extract_numeric(config, "min_off_time_s").unwrap_or(0.0);
```

Similarly, correct the misleading doc-comment on the struct fields `min_on_time_s` /
`min_off_time_s` at `hvac_core.rs:148-153`:

```rust
/// Minimum time [s] compressor must remain On before an Off transition is allowed.
/// Prevents short-cycle wear. 0.0 = disabled (OCHRE default; no lockout unless configured).
pub min_on_time_s: f64,
/// Minimum time [s] compressor must remain Off before an On transition is allowed.
/// Prevents short-cycle wear. 0.0 = disabled (OCHRE default; no lockout unless configured).
pub min_off_time_s: f64,
```
