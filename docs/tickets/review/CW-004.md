## Background/Context

Boilers (gas and electric) serve hydronic heating systems. Config includes efficiency,
capacity, distribution losses, and possibly pump power. PARITY-009 added EIR curves
to HARES boilers — this ticket verifies config wiring is complete.

## Investigation Instructions

1. Read OCHRE `GasBoiler.py` and `ElectricBoiler.py` — all config keys.
2. Read HARES `boiler.rs` — all config keys consumed.
3. Read `resolve_hvac.rs` boiler path — what keys are set?
4. Build comparison table including EIR curve parameters.
5. Note HARES improvements (EIR curves if OCHRE doesn't have them).


## Findings

### OCHRE config keys consumed (GasBoiler / ElectricBoiler)

OCHRE `GasBoiler` and `ElectricBoiler` are thin subclasses of `Heater` → `HVAC`. All
boiler config is injected from `ochre/utils/hpxml.py:parse_hvac()` as a flat dict.
The keys consumed by the HVAC base class are:

| OCHRE key | Meaning |
|---|---|
| `Capacity (W)` | Rated heating capacity |
| `EIR (-)` | Energy Input Ratio = 1 / AFUE (for gas), = 1.0 (for electric) |
| `Rated Auxiliary Power (W)` | Pump/fan power; for Boiler: `ElectricAuxiliaryEnergy kWh/yr ÷ 2080 × 1000` |
| `Conditioned Space Fraction (-)` | Fraction of load served |
| `Number of Speeds (-)` | Always 1 for boilers |
| `Deadband Temperature (C)` | Thermostat deadband |
| `Deadband Offset (C)` | Setpoint overshoot offset |
| `Ducts` | Dict with `DSE (-)` and `Zone`; boilers set `DSE=1` effectively (no duct system) |
| `Basement Airflow Ratio (-)` | Fraction of heat routed to finished basement zone |

`GasBoiler.__init__` additionally consumes, after construction:
- `self.eir_max` (set from `EIR (-)` list)
- `self.condensing` derived as `eir_max < 1/0.9` (i.e., AFUE > 90%)
- `self.outlet_temp` hardcoded from condensing flag (65.56 C condensing, 82.22 C non-condensing)
- `self.efficiency_coeff` hardcoded 6- or 10-element array (not user-configurable in OCHRE)

`ElectricBoiler` adds no additional keys beyond the `Heater` base class.

### Defect 1 — CRITICAL: AFUE from HPXML never reaches GasBoiler (efficiency key mismatch)

**Severity: Critical — silent wrong-energy calculation**

`resolve_hvac.rs:insert_annual_efficiency()` writes `heating_efficiency` (with
`heating_efficiency_units`). For AFUE direct child elements it writes `efficiency_afue`.

`GasBoiler::init` searches `["fuel_efficiency", "afue", "efficiency"]`. Neither
`heating_efficiency` nor `efficiency_afue` appears in that list.

Result: any boiler built from an HPXML file silently falls through to the default
`DEFAULT_GAS_BOILER_AFUE = 0.80`, regardless of what the HPXML specifies. A 95% AFUE
condensing boiler built from HPXML will run at 80% AFUE in simulation, and the condensing
flag (derived from `fuel_efficiency > 0.9`) will be `false`, causing the wrong EIR
polynomial to be used.

Fix: add `"heating_efficiency"` and `"efficiency_afue"` to the key list in
`GasBoiler::init`, and add a unit check: when `heating_efficiency_units` is `"PERCENT"`,
divide by 100 before storing.

### Defect 2 — CRITICAL: ElectricBoiler efficiency from HPXML never applied (key mismatch)

**Severity: Critical — silent wrong-energy calculation**

`ElectricBoiler::init` searches `["efficiency", "boiler_efficiency"]`. HPXML injects
`heating_efficiency` (units typically `"PERCENT"`, value in 0–1 range as AFUE). Neither
key alias matches.

Result: electric boiler always uses `efficiency = 1.0` regardless of HPXML input.

Fix: add `"heating_efficiency"` (with PERCENT-unit division if needed) to the search list.

### Defect 3 — MINOR: `fan_power_w` from `extension/FanPowerWatts` is not consumed by boiler

`resolve_hvac.rs` inserts `fan_power_w` for heating equipment when `FanPowerWatts` is
present in the HPXML extension. `GasBoiler::init` reads
`["pump_kw", "fan_kw", "parasitic_kw"]` and falls back to `auxiliary_power_w`.
`fan_power_w` (watts, not kW) is not in the kW list, but the `auxiliary_power_w` fallback
correctly converts via `/ 1_000.0`. However, `fan_power_w_per_cfm` (if present instead of
`FanPowerWatts`) triggers a per-ton calculation and inserts `fan_power_w_per_cfm`, which
is not readable by the boiler at all. Since boilers don't have airflow the per-CFM path
is semantically wrong for them; a guard in `resolve_hvac.rs` should skip it for boiler
equipment and only use `ElectricAuxiliaryEnergy` (matching OCHRE's explicit boiler branch
in `hpxml.py:889-892`).

### HARES improvements over OCHRE

1. **EIR polynomial coefficients are user-configurable** (`condensing_eir_coeffs` and
   `non_condensing_eir_coeffs`). OCHRE hardcodes them and exposes no override.
2. **`eir_max` override** allows explicit cap without deriving from AFUE.
3. **Hydronic loop physics**: HARES models supply/return water temperatures using
   `flow_rate_kg_s`, `CP_LIQUID_WATER_J_KG_K`, and loop return temperature from the
   fluid domain. OCHRE has no hydronic loop; boiler output goes directly to zone air.
4. **Jacket loss** is computed as `(fuel_input_w + electric_kw * 1e3 - thermal_output_w).max(0.0)`
   and routed as a `ThermalCategory::JacketLoss` gain to the zone. OCHRE does not model this.
5. **`outlet_temp_c` is configurable**. OCHRE hardcodes 65.56/82.22 °C.
6. **Multi-fuel support**: `fuel_type` field allows propane, oil, etc. OCHRE treats all
   gas boilers as natural gas.

## Recommended Tests

### Test 1 — `gas_boiler_afue_from_hpxml_is_applied`

Build a minimal HPXML XML string with a `HeatingSystem` of type `Boiler`, fuel `natural gas`,
`AnnualHeatingEfficiency Units=AFUE Value=0.92`. Parse through `resolve_equipment`, construct
a `GasBoiler` via registry with the resulting `EquipmentConfig`, call `init`. Assert:
- `boiler.eir_max` ≈ 1/0.92 = 1.087 (not 1/0.80)
- `boiler.condensing == true` (0.92 > 0.9)

This test will fail until Defect 1 is fixed, proving the bug.

### Test 2 — `electric_boiler_efficiency_from_hpxml_is_applied`

Same pattern with `ElectricBoiler`, AFUE `Units=PERCENT Value=0.98`. Assert
`boiler.efficiency` ≈ 0.98, not 1.0. This test will fail until Defect 2 is fixed.

### Test 3 — `gas_boiler_condensing_eir_polynomial_boundary`

Unit test directly on `GasBoiler::current_eir` with known PLR/temperature values:
- PLR=1.0, T=20°C, condensing=true → verify output matches hand-calculated polynomial
- PLR=1.0, T=20°C, condensing=false → verify correct non-condensing polynomial branch
- PLR=0.0, any T → result should equal `eir_max` (step logic gates to `eir_max` when `thermal_output_w == 0`)

### Test 4 — `gas_boiler_auxiliary_power_from_electric_auxiliary_energy`

Round-trip test: inject `auxiliary_power_w = 150.0` (from 312 kWh/yr EAE ÷ 2080 × 1000).
Call step with full duty cycle. Assert `electric_kw ≈ 0.150` in telemetry.

### Test 5 — `gas_boiler_jacket_loss_routed_to_zone`

Step a `GasBoiler` with known `fuel_input_w`, `thermal_output_w`, `electric_kw`. Assert
that the `Thermal` port contribution's `sensible_gain_w` equals
`(fuel_input_w + electric_kw * 1e3 - thermal_output_w).max(0.0)`. Include a condensing
case where `eir < 1.0` and assert `jacket_loss_w == 0.0` (clamped by `.max(0.0)`).

### Test 6 — `gas_boiler_fan_power_w_per_cfm_not_applied_to_boiler` (regression guard)

Inject an HPXML extension `FanPowerWattsPerCFM` on a boiler node. Assert that the
resulting `EquipmentConfig` does NOT contain `fan_power_w_per_cfm`, or that the boiler
`pump_kw` is zero (i.e., the per-CFM path is blocked for boiler equipment).
