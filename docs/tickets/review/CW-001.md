## Background/Context

Gas furnaces are one of the most common heating systems in US homes. Every config field
OCHRE extracts from HPXML must have a HARES equivalent or a documented reason for
omission. This ticket traces the full config path for gas furnaces.

## Investigation Instructions

2. **Read OCHRE `GasFurnace.py` `__init__()`:**

## Recommended Tests

1. **Startup degradation zero for gas furnace:** Construct an `EquipmentConfig` representing a
   gas furnace (with only `heating_efficiency` and `heating_capacity_w` set, no `startup_cd`
   key). Call `HvacEquipment::init` and assert `hvac.startup.c_d == 0.0`. This test will
   currently fail because `insert_startup_degradation` unconditionally writes `startup_cd=0.11`.

2. **AFUE round-trip:** Parse a minimal gas furnace HPXML fragment with `<AFUE>0.92</AFUE>`.
   Assert the resulting `EquipmentSpec` has `heating_efficiency == 0.92` and that
   `GasFurnace::init` reads this as `fuel_efficiency == 0.92`. Covers the
   `insert_annual_efficiency` → `first_f64` path.

3. **Fan power from FanPowerWattsPerCFM:** Parse a gas furnace HPXML fragment with
   `<extension><FanPowerWattsPerCFM>0.5</FanPowerWattsPerCFM></extension>` and rated capacity
   20 kBtu/h. Assert the resulting `fan_power_w` in `GasFurnace` equals
   `0.5 * 350 * (20000 / 3517) ≈ 992 W`. This verifies the 350 CFM/ton convention is
   consistently applied.

4. **Fan power from FanPowerWatts:** Parse a gas furnace HPXML fragment with
   `<extension><FanPowerWatts>400</FanPowerWatts></extension>`. Assert `fan_power_w == 400`.
   Verifies the direct-watts fallback path.

5. **ElectricAuxiliaryEnergy round-trip:** Parse a heating system with
   `<ElectricAuxiliaryEnergy>2080</ElectricAuxiliaryEnergy>` (= 1000 W equivalent). Assert
   `auxiliary_power_w == 1000.0` in the spec. Confirms the `kwh/year / 2080 * 1000` formula.

6. **fuel_type key correctness:** Confirm that `GasFurnace::init` reading `config.get_str("fuel_type")`
   on a spec produced by `build_spec(..., FuelType::Gas, ...)` yields `FuelType::Gas`. The
   Debug format produces `"Gas"` which `parse_fuel_type` lowercases to `"gas"` — this currently
   works, but should be pinned as a regression test given AR-002 Finding 4.

## Findings

---

### FINDING 1 — BUG (HIGH): `insert_startup_degradation` called unconditionally for gas furnaces — diverges from OCHRE

**Files:**
- `crates/hares-io/src/hpxml/resolve_hvac.rs:309`
- `vendors/OCHRE/ochre/utils/hpxml.py:914-917`

**Evidence:**

OCHRE `parse_hvac()` line 914-917:
```python
# Add startup capacity degradation factor for AC and heat pumps
if has_heat_pump or not is_heater:
    c_d = utils_equipment.calc_c_d(...)
    out["Startup Capacity Degradation (-)"] = c_d
```

For a `HeatingSystem` entry (gas furnace), `has_heat_pump=False` and `is_heater=True`.
The condition is `False or not True = False`. OCHRE does **not** write `Startup Capacity
Degradation` for gas furnaces. OCHRE `HVAC.__init__` then defaults
`self.c_d = kwargs.get("Startup Capacity Degradation (-)", 0.0)` → `c_d = 0.0`.

HARES `resolve_hvac.rs:309` calls `insert_startup_degradation(&mut params, &name, true)`
for every `HeatingSystem`, including gas furnaces. Inside, the code looks for
`"efficiency_hspf"` but gas furnaces have `"heating_efficiency"` (AFUE units). The
key is absent, so `efficiency_ip` defaults to `8.0`, and `calc_startup_degradation`
returns `0.11` (HSPF >= 7.0 branch). The value `startup_cd = 0.11` is inserted into
the spec.

`hvac_core.rs:354-361` reads `startup_cd` and sets `self.startup.c_d = 0.11`.
`hvac_core.rs:413-416` skips the efficiency-derived fallback because `explicit_cd`
is already non-`None`. The startup capacity ramp is then active for gas furnaces.

**Impact:** Gas furnaces will have a startup capacity degradation ramp applied for
approximately `20 * 0.11 + 0.4 = 2.6 minutes` after each on-cycle. OCHRE applies
no such ramp. This degrades modeled heating output for the first ~2-3 minutes of
every furnace on-cycle, causing systematically lower delivered heat at coarse
timesteps. For 5-minute or longer timesteps this affects every on-cycle.

**Fix:** In `resolve_hvac.rs`, gate `insert_startup_degradation` for heating equipment
the same way OCHRE does: only call it for heat pump heaters (`"ASHP Heater"`,
`"MSHP Heater"`), not for `"Gas Furnace"`, `"Electric Furnace"`, `"Gas Boiler"`,
`"Electric Boiler"`, or `"Electric Baseboard"`. Alternatively insert `startup_cd=0.0`
explicitly for non-heat-pump heaters to override the default.

### FINDING 2 — BUG (MEDIUM): AFUE not found by `insert_startup_degradation` efficiency lookup

**Files:**
- `crates/hares-io/src/hpxml/resolve_hvac.rs:785-796`

**Evidence:**

When HPXML specifies AFUE via `<AnnualHeatingEfficiency><Units>AFUE</Units>...`, the
resolver writes `"heating_efficiency"` (not `"efficiency_hspf"`). The
`insert_startup_degradation` function looks only for `"efficiency_hspf"` and falls back to
`8.0` when that key is absent.

Even if Finding 1 is fixed by excluding furnaces entirely, this lookup is still incorrect
for ASHP heaters when HSPF is supplied through `<AnnualHeatingEfficiency>` rather than the
bare `<HSPF>` tag. The bare `<HSPF>` tag path writes `"efficiency_hspf"` (via
`normalize_efficiency_units`), but the `AnnualHeatingEfficiency` path writes
`"heating_efficiency"` with `"heating_efficiency_units": "HSPF"`. The second path is
silently ignored by `insert_startup_degradation`.

**Fix (after fixing Finding 1):** In `insert_startup_degradation`, fall through to
`heating_efficiency` when `"efficiency_hspf"` is absent and
`"heating_efficiency_units" == "HSPF"`.

### FINDING 3 — VERIFIED OK: `fuel_type` key casing (AR-002 follow-up)

**Files:**
- `crates/hares-io/src/hpxml/equipment.rs:87-88`
- `crates/hares-equipment/src/hvac/furnace.rs:316`

`build_spec` writes `"fuel_type"` via `format!("{fuel_type:?}")` → `"Gas"`.
`furnace.rs:316` reads `config.get_str("fuel_type")` → `parse_fuel_type` →
`normalize_ascii("Gas") == "gas"` → matches `"gas" | "natural_gas"` → `FuelType::Gas`.

The round-trip is correct. The PascalCase-vs-snake_case casing issue identified in AR-002
Finding 1 (water heaters) does **not** affect furnaces. The `fuel_type` wiring for gas
furnaces is correct.
