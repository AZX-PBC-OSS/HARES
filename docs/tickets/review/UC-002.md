## Background/Context

HPXML provides HVAC efficiency in various forms: SEER (seasonal, BTU/Wh), EER
(instantaneous, BTU/Wh), HSPF (seasonal, BTU/Wh), AFUE (dimensionless fraction),
COP (dimensionless). HARES must convert these to EIR (Energy Input Ratio = 1/COP)
or COP for internal use. The conversion from SEER→EIR is not simply `1/SEER` —
it involves unit conversion (BTU/Wh → dimensionless) and seasonal-to-rated adjustments.

## Investigation Instructions

1. **Read `resolve_hvac.rs`:**
   - Find where SEER, SEER2, EER, EER2, HSPF, HSPF2, AFUE, COP are parsed.
   - What formula converts each to the internal efficiency representation?
   - SEER2→SEER factor: is it `/ 0.95`? (OCHRE uses this.)
   - HSPF2→HSPF factor: is it `/ 0.95`?
   - SEER→EIR: is it `1 / (SEER / 3.412)` = `3.412 / SEER`?
   - EER→EIR: is it `1 / (EER / 3.412)` = `3.412 / EER`?
   - HSPF→EIR: is it `3.412 / HSPF`?
   - AFUE→EIR: is it `1 / AFUE`?

2. **Compare with OCHRE `parse_hvac()` in `hpxml.py`:**
   - Find the exact conversion formulas OCHRE uses.
   - Note: OCHRE may store COP directly rather than EIR.

3. **Check FX-003 status:**
   - FX-003 was supposed to fix HSPF/EER/SEER→EIR. Was it completed? Is the fix correct?

4. **Write findings** as conversion table with formulas.


## Findings

### Architecture: two-stage pipeline

Efficiency values are stored raw at parse time and converted to EIR inside each
equipment's `init()`. The resolver (`resolve_hvac.rs`) writes keys such as
`efficiency_seer`, `cooling_efficiency` / `cooling_efficiency_units`, or
`heating_efficiency` / `heating_efficiency_units`. Equipment `init()` then reads
those keys and calls conversion helpers.

---

### Finding 1 — CRITICAL: AC EIR fallback ignores HPXML-resolver keys; single-speed AC always uses default EIR

**File:** `crates/hares-equipment/src/hvac/air_conditioner.rs:423-430`

```rust
let default_eir =
    first_f64(config, &["seer", "SEER"]).map_or(DEFAULT_EIR_FALLBACK, |seer| {
        BTU_PER_HR_PER_W / seer
    });
```

The AC `init()` probes `["seer", "SEER"]`. The HPXML resolver never writes a key
named `seer` — it writes `efficiency_seer` (from the bare `<SEER>` child tag) or
`cooling_efficiency` with `cooling_efficiency_units` = `"SEER"` (from
`<AnnualCoolingEfficiency>`). Neither key is read by the AC init.

Confirmed by grep: **`cooling_efficiency` and `efficiency_seer` are referenced
nowhere in `crates/hares-equipment/src/`.**

Result: for every single-speed cooling system resolved from HPXML, `default_eir`
= `DEFAULT_EIR_FALLBACK` = 0.35 (SEER ≈ 9.7), regardless of the actual rated
efficiency. The multi-speed path is unaffected because `apply_multispeed_cooling_parameters`
writes `cooling_eir_stage_N` keys, which are picked up by `load_stage_values`.

**Fix:** Replace the fallback resolution with:
```rust
let default_eir = first_f64(config, &["efficiency_seer", "seer", "SEER"])
    .or_else(|| {
        let units = config.get_str("cooling_efficiency_units")?;
        if units.eq_ignore_ascii_case("SEER") || units.eq_ignore_ascii_case("EER") {
            config.get_f64("cooling_efficiency")
        } else {
            None
        }
    })
    .map(|val| {
        let units = config.get_str("cooling_efficiency_units")
            .map(|s| s.to_ascii_uppercase())
            .unwrap_or_else(|| "SEER".to_string());
        if matches!(units.as_str(), "EER" | "EER2" | "SEER" | "SEER2") {
            BTU_PER_HR_PER_W / val
        } else {
            DEFAULT_EIR_FALLBACK
        }
    })
    .unwrap_or(DEFAULT_EIR_FALLBACK);
```
Note: `EER`→`EIR` and `SEER`→`EIR` share the same formula (`BTU_PER_HR_PER_W / val`)
because EER is already a steady-state ratio in BTU/Wh, identical to the unit
conversion needed for SEER.

### Finding 2 — MEDIUM: EER2 has no conversion factor; passes through as raw EER

**File:** `crates/hares-io/src/hpxml/resolve_hvac.rs:653-661`

```rust
fn normalize_efficiency_units(units: &str, value: f64) -> (String, f64) {
    match units.trim().to_ascii_uppercase().as_str() {
        "SEER2" => ("SEER".to_string(), value * SEER2_TO_SEER_FACTOR),
        "HSPF2" => ("HSPF".to_string(), value * HSPF2_TO_HSPF_FACTOR),
        "SEER" | "EER" | "EER2" | "HSPF" | "AFUE" | "PERCENT" | "COP" => {
            (units.trim().to_ascii_uppercase(), value)
        }
        ...
    }
}
```

`EER2` is passed through with its value unchanged and its units label kept as
`"EER2"`. Downstream code in `air_conditioner.rs` does not recognise `EER2` as
a unit requiring Btu/h → W conversion, and `heater_config.rs:104` does recognise
it but only in the `heating_efficiency_units` path.

Per DOE/AHRI the EER2 test procedure produces values ~3–5% lower than EER
(analogous to the SEER2/SEER relationship). The AHRI 210/240-2023 standard
defines EER2 at the same test points as SEER2 and the ratio is approximately
`EER2 ≈ EER × 0.95` (same factor used for SEER2). OCHRE does not handle EER2
at all (raises `OCHREException` for unknown units); HARES normalises it but
silently discards the 5% adjustment.

**Fix:** Add `"EER2" => ("EER".to_string(), value * (1.0 / 0.95))` to
`normalize_efficiency_units`, mirroring the SEER2 treatment. The constant
`EER2_TO_EER_FACTOR: f64 = 1.0 / 0.95` should be added alongside the existing
`SEER2_TO_SEER_FACTOR`.

### Finding 3 — MEDIUM: AFUE EIR clamped to 1.0, silently corrupting high-efficiency equipment

**File:** `crates/hares-equipment/src/hvac/heat_pump/heater_config.rs:111-119`

```rust
let eir = if cop > 1e-6 { 1.0 / cop } else { default_eir };
let clamped_eir = eir.clamp(0.0, 1.0);
```

AFUE is a dimensionless fraction (0–1 range, e.g. 0.95). It is not converted by
unit; it is treated directly as COP. `1.0 / 0.95 ≈ 1.053`, which exceeds 1.0 and
is clamped to 1.0, emitting only a warning. This means AFUE > 1.0 (e.g. 95% =
value 95 if stored as a percentage) also silently clamps.

OCHRE stores AFUE directly as `cop = efficiency["Value"]` (no scaling), and does
not clamp. The two code paths agree for `AFUE < 1.0` (stored as 0.95), but the
clamping masks any input where the raw fraction rounds to COP > 1.0 (impossible
physically for a gas furnace, but for condensing furnaces AFUE can approach 0.98).
For condensing furnaces AFUE ≈ 0.98, EIR = 1/0.98 ≈ 1.02 — a valid number for a
combustion appliance where EIR is defined relative to fuel HHV. The clamp to 1.0
introduces an error of ~2%.

Note: AFUE EIR > 1.0 is physically valid for combustion equipment (EIR = 1/AFUE
is not bounded by thermodynamics in the same way as a heat pump). The clamp
should be removed or scoped only to heat pump modes.

### Finding 4 — LOW: HSPF2/SEER2 conversion factor not referenced in OCHRE; factor derivation undocumented

**File:** `crates/hares-io/src/hpxml/resolve_hvac.rs:15-16`

```rust
const SEER2_TO_SEER_FACTOR: f64 = 1.0 / 0.95;
const HSPF2_TO_HSPF_FACTOR: f64 = 1.0 / 0.95;
```

OCHRE (`hpxml.py:855`) only handles `["EER", "SEER", "HSPF"]` and raises an
exception for unknown units including `SEER2`/`HSPF2`. The 1/0.95 factor comes
from DOE rulemaking (10 CFR Part 430, 2023); it is not derived from OCHRE. The
factor is correctly applied — this is an informational note, not a bug.

### Conversion Formula Table

| Input units | Stored-as after normalize | Formula in equipment init | EIR formula |
|---|---|---|---|
| `SEER2` | `SEER` | `efficiency / BTU_PER_HR_PER_W` | `EIR = BTU_PER_HR_PER_W / SEER` |
| `SEER` | `SEER` | same | `EIR = BTU_PER_HR_PER_W / SEER` |
| `EER2` | `EER2` (unchanged — **BUG**) | not converted in AC path | undefined in AC path |
| `EER` | `EER` | `efficiency / BTU_PER_HR_PER_W` | `EIR = BTU_PER_HR_PER_W / EER` |
| `HSPF2` | `HSPF` | `efficiency / BTU_PER_HR_PER_W` | `EIR = BTU_PER_HR_PER_W / HSPF` |
| `HSPF` | `HSPF` | same | `EIR = BTU_PER_HR_PER_W / HSPF` |
| `AFUE` | `AFUE` | identity (COP = value) | `EIR = 1.0 / AFUE`, clamped to 1.0 (**partial bug**) |
| `PERCENT` | `PERCENT` | identity (COP = value) | `EIR = 1.0 / value` |
| `COP` | `COP` | identity (COP = value) | `EIR = 1.0 / COP` |

OCHRE reference (`hpxml.py:850-856`):
- `["Percent", "AFUE"]` → `cop = value` directly
- `["EER", "SEER", "HSPF"]` → `cop = convert(value, "Btu/hour", "W")` = `value / 3.412141633`
- SEER2/HSPF2/EER2: not handled (raises exception)

HARES deviates from OCHRE only for SEER2/HSPF2 (intentional improvement) and EER2
(unintentional omission).

### FX-003 status

The code in `heater_config.rs` handles `HSPF/EER/SEER/COP → EIR` for the heating
path and the unit tests (`hspf_to_eir_conversion`, `eer_to_eir_conversion`,
`seer_to_eir_conversion`, `cop_to_eir_no_conversion`) all pass. FX-003 is complete
for the heating path. The cooling path (AC `init`) was not addressed by FX-003 and
retains the broken key lookup described in Finding 1.

## Review Notes

Efficiency values are NOT converted to EIR at parse time — stored as raw SEER/HSPF/EER. Conversion happens later in equipment init. Ask: where does SEER→EIR conversion happen? EER2 passes through unchanged (no normalization) while SEER2→SEER and HSPF2→HSPF are normalized. Check whether EER2 needs a conversion factor.
