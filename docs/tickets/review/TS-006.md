## Background/Context

Infiltration is a major heating/cooling load. The model must account for wind speed,
stack effect (temperature difference), and interaction with mechanical ventilation
(balanced ventilation doesn't change infiltration; exhaust ventilation increases it).
OCHRE uses the ASHRAE enhanced model. THERMAL-006a added semi-implicit infiltration.

   - `thermal_solver/infiltration.rs` — how is infiltration applied to the thermal solver?

## Findings

### 1. Infiltration model

HARES implements three methods, selectable per zone via `InfiltrationMethod` in
`crates/hares-envelope/src/thermal_solver/config.rs:52-74`:

**AshraeWindStack** — the AIM-2 model (Walker & Wilson 1998), matching OCHRE's
`_infiltration_ashrae`. Stack and wind terms are combined in quadrature:

```text
Q_stack = c_s × |ΔT|^n_i
Q_wind  = c_w × (shelter × v)^(2·n_i)
Q       = √(Q_stack² + Q_wind²)
```

`c_s` and `c_w` are derived from ACH50 blower-door data via
`aim2_coefficients_from_ach50()` in `crates/hares-physics/src/infiltration.rs:450`.
The configurable pressure exponent `n_i` defaults to 0.65, matching OCHRE/ResStock.
Valid range [0.5, 0.7] is clamped.

**Ela** — ELA-based infiltration per ASHRAE 62.2 with a fixed square-root exponent
(not configurable). Formula matches OCHRE Envelope.py:596 exactly:

```text
Q = (ELA_cm² / 1000) × √(stack_coeff × |ΔT| + wind_coeff × v²)
```

Stack and wind coefficients are derived via `calculate_ela_coefficients()` from
Walker-Wilson (1998) stack and wind shape factors with ASHRAE HOF Ch. 16 terrain
correction. Convenience helpers exist for attic (`attic_ela_coefficients`) and
garage (`garage_ela_coefficients`) zones.

**Ach** — constant-ACH fallback (weather-independent). Used when no blower-door
data is available.

This is the Sherman-Grimsrud / AIM-2 model, equivalent to "ASHRAE enhanced" per
EnergyPlus ER §15.4. Not a simpler Sherman-Grimsrud constant-k model.

### 2. Application to the thermal solver — semi-implicit treatment

`apply_infiltration_and_ventilation()` in
`crates/hares-envelope/src/thermal_solver/infiltration.rs:62` returns
`InfiltrationCoupling` structs carrying:

- `h_inf_w_k = m_dot × cp` — the sensible conductance [W/K]
- `t_forcing_c = T_outdoor` — the boundary temperature

The caller adds `-h_inf` to the zone diagonal of the A-matrix (implicit term) and
`h_inf × T_outdoor` to the forcing vector (explicit term). This is identical to the
EnergyPlus predictor-corrector zone air heat balance (Eng. Ref. §13.3):
`C_z dT/dt = ... + m_dot·cp·(T_out − T_z)` where `m_dot·cp` enters the implicit
denominator. The treatment is unconditionally stable regardless of ACH or timestep.

OCHRE does not use semi-implicit treatment for infiltration in its default
(non-`linearize_infiltration`) path — it computes sensible gain as a fully explicit
input `h_inf` in W added to `inputs_init[zone.h_idx]` (Envelope.py:1236). OCHRE
does offer `linearize_infiltration=True` which adds fixed RC resistors at
initialization, but this is a static linearization that uses operating-point
coefficients rather than a dynamic semi-implicit update. HARES's semi-implicit
update is more accurate and unconditionally stable — this is a physics improvement.

### 3. Ventilation / infiltration interaction

HARES matches OCHRE Envelope.py:71-81 exactly for both balanced and unbalanced
cases.

**Balanced ventilation (HRV/ERV):**
```text
sensible_flow = (inf + nat_vent) + forced × (1 − sens_recovery_eff)
latent_flow   = (inf + nat_vent) + forced × (1 − lat_recovery_eff)
```
Infiltration is unchanged; the forced flow contribution is attenuated by recovery
efficiency. Balanced ventilation does not interact with the infiltration rate.

**Unbalanced ventilation (exhaust fan):**
```text
combined_flow = √((inf + nat_vent)² + forced²)
```
The quadrature combination increases the effective combined flow above either
component alone. The infiltration and natural ventilation flows are then scaled by
`nat_flow_ratio = (combined − forced) / (inf + nat_vent)` to maintain proportional
attribution. Exhaust ventilation therefore does increase infiltration's contribution
to the combined sensible load.

**ASHRAE 152 duct leakage interaction** is also implemented. When the HVAC fan is
running and duct leakage flows are non-zero, `duct_leakage_infiltration_m3_s()` is
called (infiltration.rs:117-127) to adjust the conditioned-zone infiltration rate per
ASHRAE 152 §9.3. Pressurisation (supply > return) increases infiltration;
depressurisation decreases it, potentially to zero. Unconditioned zones are not
adjusted (only `indoor_zone_id` receives the duct correction).

**OCHRE h_limit stabilisation is NOT implemented in HARES.** OCHRE computes a
`h_limit = solve_for_input(...)` each timestep (Envelope.py:1217) which caps
infiltration sensible gain at the amount needed to bring the zone to outdoor
temperature. HARES does not implement this cap. In HARES the semi-implicit
treatment provides equivalent stability (the zone temperature is bounded
by T_outdoor in the limit), but the gain cap affects how infiltration is reported
diagnostically in high-ACH or extreme-weather conditions. This is a divergence from
OCHRE, not a physics regression: the semi-implicit approach is more physically
correct. However it should be documented, and the diagnostic output may differ
measurably from OCHRE in edge cases.

**OCHRE component attribution difference.** OCHRE computes component heat gains
`inf_heat`, `nat_vent_heat`, `forced_vent_heat` as fractions of the total
`sensible_gain` weighted by flow (Envelope.py:657-659). HARES computes each
component independently using `scaled_q_inf_m3_s × ρ × cp × ΔT`
(infiltration.rs:216-224). For unbalanced systems the forced ventilation component
uses `forced_sens_eff = 1.0` (no recovery) and the nat_flow_ratio scaling, which
matches the OCHRE approach. However OCHRE uses `1.006 kJ/(kg·K) × 1000 = 1006 W/K`
as cp (Envelope.py:83: `1.006 * delta_t * 1000.0`) and HARES uses
`CP_DRY_AIR_J_KG_K = 1006.0`. These are numerically identical.

### 4. Multi-zone infiltration

Per-zone infiltration is supported. `ThermalSolverConfig.infiltration` is a
`Vec<(ZoneId, InfiltrationMethod)>` (config.rs:364). The per-zone loop in
`apply_infiltration_and_ventilation` (infiltration.rs:77) processes each zone in
`env.zones` independently with its own method.

Natural ventilation (`NaturalVentilationConfig`) and forced mechanical ventilation
are currently restricted to the indoor zone (infiltration.rs:130-160). The
`zone_flow_m3_s` map in `VentilationConfig` allows per-zone forced flows, but the
global `ventilation_flow_m3_s` falls back only on `indoor_zone_id`.

OCHRE also restricts natural ventilation and forced ventilation to the Indoor zone
(Envelope.py:603). Multi-zone infiltration with separate ELA/ASHRAE parameters per
zone (attic, crawlspace, garage) is structurally supported via the zone config map.

The ASHRAE 152 duct leakage correction is only applied to `indoor_zone_id`, matching
OCHRE's approach.

### 5. Reference case: ELA = 200 cm², wind = 5 m/s, ΔT = 20°C

Using OCHRE default ELA coefficients (stack = 0.000145 L/(s·cm⁴·K), wind =
0.000087 L/(s·cm⁴·(m/s)²)):

```
driver = 0.000145 × 20 + 0.000087 × 25 = 0.002900 + 0.002175 = 0.005075
√driver = 0.07124
Q = (200 / 1000) × 0.07124 = 0.01425 m³/s = 14.25 L/s
```

ACH depends on zone volume:
- V = 300 m³ (small home): **0.171 ACH**
- V = 480 m³ (typical US single-family): **0.107 ACH**

These are within the expected range (0.1–0.5 natural ACH for residential), confirming
the ELA formula and unit conversion are correct.

For the ASHRAE AIM-2 method with typical residential coefficients (c_s = 0.015
m³/s/K^0.65, c_w = 0.0008 m³/s/(m/s)^1.3, shelter = 0.5, n_i = 0.65):

```
Q_stack = 0.015 × 20^0.65 = 0.015 × 6.727 = 0.1009 m³/s
Q_wind  = 0.0008 × (0.5 × 5)^1.3 = 0.0008 × (2.5)^1.3 = 0.0008 × 3.324 = 0.00266 m³/s
Q       = √(0.1009² + 0.00266²) ≈ 0.1009 m³/s
```

At V = 480 m³: **0.757 ACH**. This is higher than ELA for the same conditions because
the c_s=0.015 coefficient corresponds to a leakier building. The models are applied to
different building types in practice.

### Issues identified

**MEDIUM — Missing h_limit cap has untested divergence from OCHRE in extreme
conditions.** `infiltration.rs` — OCHRE applies an `h_limit` cap computed by
`solve_for_input()` to prevent infiltration sensible gain from exceeding what is
physically needed to equilibrate the zone to outdoor temperature. HARES omits this
cap. The semi-implicit treatment achieves numerical stability but does not bound
the diagnostic gain in the same way. Under extreme ΔT or very high ACH, reported
infiltration heat gains in HARES may diverge from OCHRE diagnostics. This should
be characterised by a regression test.

**LOW — No test covers the ELA reference case with non-default coefficients.**
The existing `ela_physical_reasonableness_typical_residence` test uses generic
coefficients. A pinned test with ELA=200 cm², wind=5 m/s, ΔT=20°C and explicit
expected flow (0.01425 m³/s) would anchor the formula against future refactors.

**LOW — No test covers the ASHRAE wind-stack reference computation.** The existing
`ashrae_hof_ch16_table5_coefficients` test only checks a loose range (`q > 0 && q < 0.01`).
A tighter pinned assertion against a known published value would be more useful.

**LOW — Natural ventilation (window opening) test coverage is minimal.** The
`natural_ventilation_flow_m3_s` function has no dedicated unit test in
`hares-envelope`. Only indirect coverage through integration tests.

## Recommended Tests

**TEST-1 (correctness regression):** Add a unit test to
`crates/hares-physics/src/infiltration.rs` that pins the ELA reference case:
ELA = 200 cm², stack_coeff = 0.000145, wind_coeff = 0.000087, ΔT = 20°C,
wind = 5 m/s. Assert flow ≈ 0.01425 m³/s within 1e-5 tolerance. Name it
`ela_reference_200cm2_wind5_dt20`.

**TEST-2 (correctness regression):** Add a unit test pinning the ASHRAE HOF
Ch. 16 Table 5 coefficients against a tighter expected value, not just a range.
Use the values from the published table and verify the formula matches to at least
3 significant figures.

**TEST-3 (parity divergence characterisation):** Add an integration test in
`crates/hares-envelope/tests/` that exercises a high-ACH scenario (e.g., ACH=5,
ΔT=40°C) and verifies that the combined semi-implicit infiltration gain does not
exceed `m_dot × cp × |ΔT|` (the theoretical maximum). This characterises the
h_limit gap vs. OCHRE without requiring a full OCHRE parity run.

**TEST-4 (natural ventilation gating):** Add unit tests for
`natural_ventilation_flow_m3_s` covering: (a) all three gate conditions returning
zero (T_zone ≤ T_out; T_zone ≤ T_base; w_out ≥ max_hr), (b) the 20-ACH cap
triggering, and (c) the adjustment factor `adj` clamping to [0, 1].

**TEST-5 (duct leakage interaction):** The existing `duct_leakage_infiltration_m3_s`
tests should be verified to cover the three branches: pressurisation, large
depressurisation (returns 0), and partial depressurisation. Check test coverage in
`crates/hares-physics/src/infiltration.rs` tests against these three branches.
