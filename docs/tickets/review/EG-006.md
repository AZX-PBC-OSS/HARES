## Background/Context

Attic volume determines attic zone thermal mass. The triangular prism formula
`V = 0.5 * floor_area * height` assumes a standard gable roof.

## Investigation Instructions

1. Read HARES `compute_attic_volume()`.
2. Compare with OCHRE attic volume formula.
3. Check: does the formula handle attached garage attic volumes separately?


## Recommended Tests

1. **`compute_attic_volume_simple_gable`** — two equal gable walls, no garage. Assert `volume == 0.5 * floor_area * sqrt(gable_area * tan(tilt))`.
2. **`compute_attic_volume_3gable_path_b`** — three attic walls (no Attic Garage Wall boundary), garage present. Assert volume uses 3-term compound formula: `0.5*(floor_area - protruded)*height + 0.5*protruded*garage_height + (1/6)*garage_width*garage_depth*garage_height`. Must differ from naive `0.5 * floor_area * height`.
3. **`attic_floor_area_includes_garage_ceiling`** — HPXML with `<GarageCeiling>` boundary. Assert parsed attic `floor_area_m2` equals conditioned attic area plus garage ceiling area.
4. **`garage_protruded_area_computed`** — two attached garage walls. Assert `garage_protruded_area = garage_floor_area - garage_area_in_main` is non-zero and used in compound formula.
5. **`volume_none_does_not_silently_fallback`** — parse a building with intentionally missing gable walls. Assert `zone.volume_m3` is `None` and that `EnvironmentManager` emits a warning or returns `Err`, not 200.0.

## Findings

### F1 — CRITICAL: 3-gable compound volume formula is entirely absent

`compute_attic_volume` (building.rs:1927–1943) has a single code path for all `len >= 3` cases: sort all gable areas and take `sorted[1]`, then apply `0.5 * floor_area * attic_height`. OCHRE has two distinct 3-gable branches:

**Path A — "Attic Garage Wall" boundary present:**
Uses `max(area[0], area[1])` from the merged Attic+AtticGarage wall list, `third_gable_area = 0`, applies simple prism. HARES has no concept of the "Attic Garage Wall" boundary type.

**Path B — no Attic Garage Wall, `has_garage`, 3 walls:**
Uses `attic_wall_areas[1]` (unsorted second element) as `attic_gable_area` and computes the compound volume:
```
attic_volume = 0.5 * (attic_floor_area - garage_protruded_area) * attic_height   # prism over square
             + 0.5 * garage_protruded_area * garage_height                        # prism over protrusion
             + (1/6) * garage_width * garage_depth_in_house * garage_height       # pyramid bridging prisms
```
HARES produces only `0.5 * floor_area * attic_height`, which both uses the wrong floor area base and omits the pyramid term. All protruding-garage homes get a wrong attic volume.

### F2 — CRITICAL: `attic_floor_area` excludes garage ceiling area

OCHRE hpxml.py:437:
```python
attic_floor_area = top_floor_area + sum(boundaries.get("Garage Ceiling", {}).get("Area (m^2)", []))
```
HARES `build_zone_map` (building.rs:1370–1392) reads `attic.floor_area_m2` only from the `<FloorArea>` HPXML element or falls back to the Conditioned→Attic Floor boundary. Neither includes garage ceiling boundaries. For any home where the attic extends over the garage, the HARES floor area is understated, making `attic_height` and volume both too small.

### F3 — HIGH: `garage_protruded_area` is never computed

OCHRE hpxml.py:494:
```python
garage_protruded_area = garage_floor_area - garage_area_in_main
```
`garage_area_in_main` is derived from the geometry of garage attached walls. HARES has no equivalent. This quantity is required for the compound formula fix (F1). Without it, Path B cannot be implemented correctly.

### F4 — HIGH: Silent 200 m³ fallback swallows parse failures

`DEFAULT_ZONE_VOLUME_M3 = 200.0` (environment.rs:23) is applied silently at runtime in `initialize_zone_states` (line 748) whenever `zone.volume_m3` is `None`. 200 m³ is an arbitrary constant — a large Ranch attic may exceed 500 m³; a small bungalow under 60 m³. Callers receive no warning that geometry parsing failed. This is the mechanism by which F1 and F2 produce no observable error at startup, making them invisible in logs.

### F5 — MEDIUM: Gable selection index mismatch for Path B

OCHRE uses `attic_wall_areas[1]` — the second element of the **unsorted** list as parsed from HPXML — as `attic_gable_area`. HARES sorts and takes `sorted[1]`. When the three input areas are not already in sorted order (common when the garage gable is not the median by magnitude), HARES selects the wrong gable wall, compounding the volume error from F1 even if the simple prism formula were used.

### F6 — LOW: Docstring for `compute_attic_volume` is incomplete

building.rs:1870–1878 describes only `V = 0.5 × floor_area × height`. There is no mention of the 3-gable compound formula, the "Attic Garage Wall" disambiguation, or the garage-ceiling floor-area augmentation. The comment incorrectly implies HARES matches OCHRE lines 584–631.

## Review Notes

HARES uses simplified `0.5 * floor_area * attic_height` unconditionally. OCHRE's combined formula has three terms (standard prism + protruded garage prism + pyramid transition). `attic_floor_area` in HARES may differ from OCHRE's definition (`top_floor_area + garage_ceiling_areas`).

## Measures of Success
- [x] Attic volume formula compared — HARES is missing the 3-term compound formula (F1)
- [x] Garage-attic interaction verified — garage ceiling excluded from floor area (F2), `garage_protruded_area` not computed (F3)

## Required Fixes

1. Compute `garage_protruded_area` in the HPXML parser using attached-wall geometry (mirrors OCHRE hpxml.py:457–480).
2. Add garage ceiling boundary areas to attic `floor_area_m2` when building the zone map (mirrors OCHRE hpxml.py:437).
3. Implement full 3-gable branching in `compute_attic_volume`:
   - Path A: detect Attic Garage Wall boundaries; use `max(area[0], area[1])`, simple prism.
   - Path B: 3 standard attic walls with garage present; use unsorted `areas[1]`; apply compound 3-term formula.
4. Propagate `None` volume as an explicit warning or `Err` in `EnvironmentManager`; do not silently substitute 200 m³.
5. Update `compute_attic_volume` docstring to reflect both paths and the floor-area augmentation.
