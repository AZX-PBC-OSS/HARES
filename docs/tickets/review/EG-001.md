## Background/Context

OCHRE derives ceiling height from `conditioned_volume / conditioned_floor_area`. If
HARES hardcodes a default (e.g., 2.5m) instead of computing it, all zone volumes and
thermal capacitances are wrong.

## Investigation Instructions

1. **Read `building.rs` lines ~418-420** — how is ceiling height computed?
2. **When is the default used?** Only when volume is missing? Or always?
3. **What is the default?** 2.5m? 8ft → 2.44m?
4. **Compare with OCHRE** — same derivation? Same default?
5. **Check FX-005 status** — this ticket was supposed to parse `ConditionedBuildingVolume`.


## Findings

### Derivation — HARES

`crates/hares-io/src/hpxml/building.rs:418–421`

```rust
let ceiling_height_m = match (conditioned_volume_m3, conditioned_floor_area_m2) {
    (Some(vol), Some(area)) if area > 0.0 => Some(vol / area),
    _ => None,
};
```

`conditioned_volume_m3` is read from `<ConditionedBuildingVolume>` (line 414–416) and `conditioned_floor_area_m2` from `<ConditionedFloorArea>` (line 410–412), both with unit-aware parsing. The result is `Building::ceiling_height_m: Option<f64>`.

### Derivation — OCHRE

`vendors/OCHRE/ochre/utils/hpxml.py:253–260`

```python
conditioned_floor_area = convert(construction["ConditionedFloorArea"], "ft^2", "m^2")
conditioned_volume    = convert(construction["ConditionedBuildingVolume"], "ft^3", "m^3")
ceiling_height = conditioned_volume / conditioned_floor_area
if "AverageCeilingHeight" in construction:
    assert abs(convert(construction["AverageCeilingHeight"], "ft", "m") - ceiling_height) < 0.1
```

OCHRE treats both fields as **required** (direct dict access; `KeyError` if absent). If `AverageCeilingHeight` is present it is used only as a cross-check, not a primary source.

The core formula `volume / floor_area` is identical to OCHRE. The divergences are in fallback handling and validation.

---

### DEF-1 — Silent fallback to 2.5 m constant (Severity: Medium)

When either `ConditionedBuildingVolume` or `ConditionedFloorArea` is absent, `ceiling_height_m` is `None`. Three downstream sites substitute `2.5 m` silently:

- `crates/hares-io/src/hpxml/building.rs:672` — zone volume assignment (Conditioned, Garage, Foundation)
- `crates/hares-core/src/dwelling/solver_builder.rs:751` — infiltration height and building-height calculation
- `crates/hares-core/src/dwelling/solver_builder.rs:951` — natural ventilation stack/wind coefficient

The constant produces incorrect zone volumes, infiltration ACH, and natural ventilation with no warning. OCHRE raises `KeyError` for missing required geometry fields. HARES should do the same: treat absence of `ConditionedBuildingVolume` or `ConditionedFloorArea` as a hard parse error. If a default is retained it must be a named constant and logged as a warning at point of use.

### DEF-2 — `AverageCeilingHeight` field ignored (Severity: Low)

OCHRE cross-checks the derived `ceiling_height` against `AverageCeilingHeight` (±0.1 m tolerance) when present. HARES never reads this field. Inconsistent geometry in an HPXML file will produce no diagnostic.

Fix: after computing `ceiling_height_m`, if `AverageCeilingHeight` is present in the XML, compare and emit a warning or error on mismatch.

### DEF-3 — `building_height_m` uses conditioned zone count instead of floor count (Severity: Low)

`solver_builder.rs:751–758` computes building height as `ceiling_height × number_of_conditioned_zones`. OCHRE uses `ceiling_height × IndoorFloors` (`hpxml.py:530`). Zone count is not equivalent to floor count; a single-zone two-storey dwelling yields half the correct height. This propagates into the AIM-2 infiltration height and the natural ventilation stack-pressure coefficient.

`Building::floors_above_grade` is already parsed from `NumberofConditionedFloorsAboveGrade` (`building.rs:423–431`) and should be used in place of the zone count.

---

### FX-005 Status

`ConditionedBuildingVolume` is being parsed (line 414–416). FX-005 appears resolved at the parsing layer. The remaining issues are in fallback handling (DEF-1) and validation (DEF-2, DEF-3).

## Recommended Tests

- `hares_io::hpxml::building` unit test: HPXML with no `ConditionedBuildingVolume` should return a parse error, not `ceiling_height_m = None`.
- `hares_io::hpxml::building` unit test: HPXML with `AverageCeilingHeight` that disagrees with derived value by >0.1 m should emit a diagnostic.
- Integration test: single-zone two-storey building — verify `building_height_m` equals `ceiling_height × floors_above_grade`, not `ceiling_height × 1`.
