## Background/Context

Electric furnaces are simpler than gas (COP≈1, no combustion efficiency), but config
wiring must still be traced to catch dropped parameters.

## Investigation Instructions

Follow the same procedure as CW-001 but for electric furnace:
1. Read OCHRE `ElectricFurnace.py` — what config keys?
2. Read HARES `furnace.rs` — how does it distinguish gas vs electric?
3. Build comparison table of all config fields.
4. Document missing fields and HARES improvements.


## Findings

### OCHRE ElectricFurnace config keys

`ElectricFurnace` in OCHRE (`HVAC.py:664`) is a bare subclass of `Heater(HVAC)` with no
additional fields. All config comes from the `HVAC.__init__` chain via `hpxml.py:parse_hvac`.
The effective config dictionary produced for an `ElectricFurnace` is:

| OCHRE key | Source | Meaning |
|---|---|---|
| `Capacity (W)` | HPXML `HeatingCapacity` (Btu/h → W) | Rated heating capacity |
| `EIR (-)` | `1 / cop`; cop=1 for ElectricResistance (AFUE not applicable) | Energy Input Ratio; always 1.0 for resistance |
| `Rated Auxiliary Power (W)` | `ElectricAuxiliaryEnergy` kWh/yr ÷ 2080 × 1000, or `FanPowerWatts`, or `FanPowerWattsPerCFM × 350 cfm/ton × capacity_tons` | Blower motor power |
| `Conditioned Space Fraction (-)` | `FractionHeatLoadServed` | Space fraction |
| `Number of Speeds (-)` | Always 1 for furnaces | Single-stage |
| `Weekday Setpoints (C)` / `Weekend Setpoints (C)` | `HVACControl` extension | 24-element thermostat schedule |
| `Ducts` | `get_duct_info()` or `DSE (-)` override | Duct DSE and zone |
| `Deadband Temperature (C)` | Optional; defaults to 1 °C | Thermostat hysteresis |
| `Startup Capacity Degradation (-)` | NOT emitted for heaters (only for AC/HP) | n/a for furnace |

Note: OCHRE does not emit `Startup Capacity Degradation (-)` for `ElectricFurnace` (hpxml.py:914-916: only when `has_heat_pump or not is_heater`). HARES correctly mirrors this.

### HARES ElectricFurnace config consumption

`ElectricFurnace::init` (`furnace.rs:113-139`) reads:

| HARES key | Where consumed | Fallback |
|---|---|---|
| `capacity_w` / `heating_capacity_w` / `heating_capacity_kbtu_h` | `first_f64(config, HEATING_CAPACITY_KEYS)` | 10 000 W |
| `eir` / `heating_eir` / `EIR` | `first_f64(config, &["eir","heating_eir","EIR"])` | 1.0 |
| `fan_power_w` / `fan_only_power_w` / `auxiliary_power_w` | indirectly via `hvac.init()` fan flow, then unused in ElectricFurnace step | not read by ElectricFurnace::init at all |
| duct params | `resolve_duct_dse()` + `parse_zone_id_key()` | DSE=1 |
| thermostat setpoints | `hvac.init()` → HvacEquipment | inherited |

### Gas/electric distinction

HARES uses separate struct types (`ElectricFurnace`, `GasFurnace`) registered under different
names. `canonical_hvac_heating_name()` (`resolve_hvac.rs:568`) maps `(Furnace, Electric)` →
`"Electric Furnace"` and `(Furnace, Gas)` → `"Gas Furnace"`, so the type distinction is
correct and explicit.

`GasFurnace` consumes `fuel_efficiency` / `afue` / `efficiency` for combustion efficiency and
emits separate fuel + fan-electric port contributions. `ElectricFurnace` uses a single `eir`
and emits only an electrical port. The separation is clean.

### Defects found

#### DEFECT 1 — CRITICAL: `ElectricFurnace` fan power is never applied to electrical output
**Severity: High — energy accounting error**

`ElectricFurnace::step` (`furnace.rs:154-156`) computes:
```
electric_kw = (self.rated_capacity_w * self.eir * duty) / 1_000.0 * sf
```
This correctly models resistance heat (EIR=1.0 → electric kW equals heat kW), but it does
not add any blower motor power. OCHRE (`HVAC.py:553-554`) adds `fan_power / 1000` to
`electric_kw` for electric equipment:
```python
elif self.is_electric:
    self.electric_kw = power_kw + self.fan_power / 1000
```
HARES `ElectricFurnace` has no `fan_power_w` field and never reads `auxiliary_power_w` /
`fan_power_w` from config. Any `ElectricAuxiliaryEnergy` provided in HPXML is silently
dropped.

`GasFurnace` correctly reads `fan_power_w` and accumulates a separate electrical
contribution, so only `ElectricFurnace` is affected.

#### DEFECT 2 — HIGH: `FURNACE_FAN_CFM_PER_TON` constant disagrees with `AIRFLOW_HEATING_CFM_PER_TON`
**Severity: Medium — inconsistent internal constant produces wrong fan-power default for GasFurnace**

`furnace.rs:30` defines `FURNACE_FAN_CFM_PER_TON = 400.0`.
`hvac_core.rs:69` defines `AIRFLOW_HEATING_CFM_PER_TON = 350.0` and `hvac_core.rs:97-103`
assigns 350 to both `GasFurnace` and `ElectricFurnace` equipment types.

`GasFurnace::init` (line 313-315) falls back to `self.hvac.fan_power_w(airflow_m3_s)` using
the `HvacEquipment` airflow which is initialised from 350 cfm/ton. But the test at
`furnace.rs:740` asserts `expected_airflow_m3_s = FURNACE_FAN_CFM_PER_TON * CFM_TO_M3_S * 3.0`
using 400 cfm/ton. OCHRE uses 350 cfm/ton for heaters (`HVAC.py:142`: `cfm_per_ton = 350 if self.is_heater else 312`).

This means: when `fan_power_w_per_cfm` is absent and no explicit `fan_power_w` is given,
`GasFurnace` derives its default fan airflow via `HvacEquipment` at 350 cfm/ton, but the test
constant `FURNACE_FAN_CFM_PER_TON = 400` is stale and the test assertion at line 740 is wrong.
The constant is also exported as `pub(super)` and used nowhere outside `furnace.rs`, making it
dead code serving only to produce a wrong test value.

#### DEFECT 3 — HIGH: `heating_efficiency` / `heating_efficiency_units` from HPXML resolver is silently dropped for both furnaces
**Severity: High — AFUE from HPXML is never applied to GasFurnace; EIR from HPXML is never applied to ElectricFurnace**

`resolve_hvac.rs:278` calls `insert_annual_efficiency(&mut params, heating, true)` which writes
`heating_efficiency` and `heating_efficiency_units` (e.g. `"AFUE"`) into the param map for
every heating system.

`GasFurnace::init` (`furnace.rs:300-307`) reads `fuel_efficiency` / `afue` / `efficiency` —
none of which match the key `heating_efficiency` that `insert_annual_efficiency` produces.
Result: AFUE from HPXML is dropped; the hardcoded default of 0.80 (`DEFAULT_GAS_AFUE`) is
always used regardless of what the HPXML file specifies.

`ElectricFurnace::init` (`furnace.rs:119`) reads `eir` / `heating_eir` / `EIR` — none of which
match `heating_efficiency`. For electric furnaces EIR is always 1.0 so the practical impact is
smaller, but a `COP`-typed efficiency from HPXML would still be ignored.

Correct fix: both furnace `init` functions should read `heating_efficiency` and, when
`heating_efficiency_units == "AFUE"`, set `fuel_efficiency` to that value. For `ElectricFurnace`
the `COP` branch would compute `eir = 1 / cop`.

#### DEFECT 4 — MEDIUM: `FractionHeatLoadServed` → `space_fraction` for `ElectricFurnace`
**Severity: Low — code gap, but currently correct by accident for most buildings**

`resolve_hvac.rs:281-285` writes `fraction_load_served` into params. OCHRE passes this as
`Conditioned Space Fraction (-)`. `HvacEquipment::init` picks it up via `space_fraction`
extraction. No defect in isolation, but it is not tested for `ElectricFurnace` specifically.

### Comparison table

| Config field | OCHRE key | HARES key(s) consumed | Status |
|---|---|---|---|
| Rated capacity | `Capacity (W)` | `capacity_w`, `heating_capacity_w`, `heating_capacity_kbtu_h` | Correct |
| Resistance EIR | `EIR (-)`=1 | `eir`, `heating_eir`, `EIR` | Correct (default=1.0) |
| Gas AFUE | `EIR (-)=1/AFUE` via `EIR (-)` | `fuel_efficiency`, `afue`, `efficiency` (not `heating_efficiency`) | DEFECT 3 |
| Fan/blower power | `Rated Auxiliary Power (W)` | GasFurnace: `fan_power_w`/`auxiliary_power_w` — ElectricFurnace: nothing | DEFECT 1 |
| Fan W/CFM | `FanPowerWattsPerCFM` (extension) | `fan_power_w_per_cfm` → `hvac_core` for GasFurnace; dropped for ElectricFurnace | DEFECT 1 |
| Space fraction | `Conditioned Space Fraction (-)` | `fraction_load_served` → `space_fraction` in `hvac_core` | Correct |
| Thermostat setpoints | `Weekday/Weekend Setpoints (C)` | `heating_weekday_setpoints_c` etc. | Correct |
| Duct DSE / zone | `Ducts` dict | `duct_*` params via `compute_duct_dse_params` | Correct |
| Deadband | `Deadband Temperature (C)` | `deadband` / `hysteresis_c` in `hvac_core` | Correct |
| Startup degradation | not emitted for furnaces | not applied | Correct |
| Airflow cfm/ton default | 350 (heater) | 350 via `AIRFLOW_HEATING_CFM_PER_TON` in hvac_core, but `FURNACE_FAN_CFM_PER_TON=400` in furnace.rs | DEFECT 2 (stale constant + wrong test) |

## Recommended Tests

### Test 1 — `electric_furnace_fan_power_adds_to_electrical_draw`
In `furnace.rs` unit tests. Configure `ElectricFurnace` with `capacity_w=8000`,
`auxiliary_power_w=400`, indoor temp below setpoint. After one step, assert
`ports.electrical.net_active_kw() ≈ (8000 * 1.0 + 400) / 1000 = 8.4 kW`.
Currently this test would fail because fan power is not implemented.

### Test 2 — `gas_furnace_reads_heating_efficiency_from_hpxml_params`
In `furnace.rs` unit tests. Set `cfg.raw_config["heating_efficiency"] = 0.95` and
`cfg.raw_config["heating_efficiency_units"] = "AFUE"`. Assert after `init` that
`eq.fuel_efficiency ≈ 0.95` (not the default 0.80).
Currently this test would fail — the key is silently dropped.

### Test 3 — `gas_furnace_default_airflow_uses_350_cfm_per_ton`
Fix or replace the existing test `gas_furnace_init_without_fan_power_uses_default_w_per_cfm`
(`furnace.rs:727`). The test's `expected_airflow_m3_s` currently uses `FURNACE_FAN_CFM_PER_TON`
(400). The assertion should use 350 cfm/ton (OCHRE reference value and `AIRFLOW_HEATING_CFM_PER_TON`).
The stale constant `FURNACE_FAN_CFM_PER_TON = 400` should be removed.

### Test 4 — `hpxml_electric_furnace_auxiliary_energy_maps_to_fan_power`
In `hares-io` HPXML parity tests. Build a minimal HPXML `<HeatingSystem>` with
`<HeatingSystemType><Furnace/></HeatingSystemType>`, `<HeatingSystemFuel>electricity</HeatingSystemFuel>`,
and `<ElectricAuxiliaryEnergy>208</ElectricAuxiliaryEnergy>` (208 kWh/yr → 100 W).
Assert the resolved spec contains a fan-power key that the `ElectricFurnace` will consume,
and that a simulated step produces `electric_kw > capacity_w/1000` (fan overhead present).
