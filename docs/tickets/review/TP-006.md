## Background/Context

EV outputs: SOC, charging power, connection state, departure/arrival events.

## Investigation Instructions

1. Read OCHRE EV output columns.
2. Read HARES EV telemetry (including `telemetry.rs`).
3. Build comparison table.
4. Document HARES-only fields (V2G/V2H, driver actor decisions).


## Findings

### F1 — MEDIUM — V2G discharge has no dedicated telemetry field

**Location:** `ev/telemetry.rs:26-101`, `ev/mod.rs:611-648`, `telemetry_keys.rs:76-83`

When V2G is active, `active_power_kw` and `electric_kw` are set to a negative value (grid-export power). There is no separate `v2g_active` flag or `v2g_power_kw` field. This is asymmetric with V2L, which has both `V2L_ACTIVE` and `V2L_POWER_KW`. Consumers distinguishing charging from V2G export must infer from the sign of `active_power_kw`, which is ambiguous when `power_setpoint_kw` is zero during a hold. No `V2G_POWER_KW` or `V2G_ACTIVE` key exists in `telemetry_keys.rs`.

**Fix:** Add `v2g_active: f64` and `v2g_power_kw: f64` fields to `default_telemetry`, `telemetry_fields`, and `write_telemetry`, following the V2L pattern exactly. Add corresponding keys to `telemetry_keys.rs`. Increment `with_capacity` from 14 to 16.

---

### F2 — MEDIUM — `ACTIVE_POWER_KW` and `ELECTRIC_KW` are always identical

**Location:** `ev/mod.rs:614-616`, `ev/telemetry.rs:28-43`

Both fields are written from `self.active_power_kw` in `write_telemetry` with no divergence path. This wastes telemetry storage, and the two descriptions overlap completely. Any future bug that writes them differently would cause silent inconsistency.

OCHRE's cross-equipment concept maps to `ELECTRIC_KW` ("Electric Power (kW)"). `ACTIVE_POWER_KW` is EV-specific naming. One should be removed from the EV telemetry declaration and write path.

**Fix:** Remove `ACTIVE_POWER_KW` from the EV `default_telemetry`, `telemetry_fields`, and `write_telemetry`. Decrement `with_capacity` from 14 to 13. Any consumer currently reading `active_power_kw` from an EV telemetry map must switch to `electric_kw`.

---

### F3 — LOW — No `unmet_load` field for departure-before-full-charge events

**Location:** `ev/telemetry.rs`, `vendors/OCHRE/ochre/Equipment/EV.py:339`

OCHRE emits `EV Unmet Load (kWh)` to track energy not delivered because the vehicle departed before reaching target SOC. HARES has no equivalent. For deadline-aware charging actors, this quantity is computable from `SOC` and `CAPACITY_KWH` at departure time but is not surfaced in telemetry. This makes charging adequacy audits impossible from the telemetry stream alone.

The gap is acceptable for the current actor model since departure is an explicit actor signal. Acceptable to defer until actor departure events are implemented.

---

### F4 — LOW — `HEATER_ACTIVE` boolean not emitted; inconsistent with `V2L_ACTIVE` pattern

**Location:** `ev/telemetry.rs:59-67`, `ev/mod.rs:628-635`

Heater-active state is encoded indirectly: `HEATER_POWER_W` is zero when inactive. `V2L_ACTIVE` uses an explicit 0/1 flag alongside `V2L_POWER_KW`. The inconsistency is minor but means consumers must handle `HEATER_POWER_W == 0` as a sentinel rather than a distinct inactive signal.

**Fix:** Add `HEATER_ACTIVE` key to `telemetry_keys.rs`, `default_telemetry`, `telemetry_fields`, and `write_telemetry`. Increment `with_capacity` accordingly.

---

### F5 — LOW — `fuel_economy_kwh_per_mi` uses imperial unit contrary to SI-units project policy

**Location:** `ev/telemetry.rs:95-99`, `telemetry_keys.rs:83`

Project memory (`feedback_si_units.md`) requires SI units internally. `kWh/mi` mixes SI energy with an imperial distance unit. The SI equivalent is `kWh/km`. OCHRE uses miles as its reference, but HARES explicitly does not inherit OCHRE conventions.

**Fix:** Rename the key and field to `fuel_economy_kwh_per_km`, update `DEFAULT_FUEL_ECONOMY_KWH_PER_MI` in `config.rs` to the km-equivalent value, and update all config keys, tests, and Python bindings that reference this field. The conversion factor is 1 mile = 1.60934 km.

---

### F6 — INFO — OCHRE connection state is a string; HARES encodes as float with documented enum map

**Location:** `ev/telemetry.rs:43-48`, `ev/mod.rs:617-624`

OCHRE's `connection_state` is implicit in the event model (in_event boolean). HARES encodes connection state as a float code (0=HomePluggedIn, 1=AwayPluggedIn, 2=Disconnected). The `TelemetryField` description documents the mapping inline. This is adequate. No action required.

---

### F7 — INFO — `Telemetry::with_capacity(14)` matches the 14-field declaration exactly

**Location:** `ev/telemetry.rs:8`

Capacity hint matches `telemetry_fields()` length. No reallocation will occur. No issue.

---

### F8 — INFO — OCHRE verbosity-gated outputs vs HARES unconditional emit

OCHRE gates `EV SOC (-)` at verbosity >= 3, `EV Parked` at verbosity >= 4. HARES emits all fields unconditionally. This is an intentional improvement. No action required.
