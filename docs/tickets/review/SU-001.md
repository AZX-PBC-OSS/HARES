## Background/Context

The coil bypass factor and SHR computation determine how much cooling is sensible vs latent.
No existing ticket audits the actual coil physics model — only the SHR default value (CW-005)
and the ideal capacity formula (IC-002).

## Investigation Instructions

1. Read `coil_physics.rs` end-to-end — how is Ao factor computed? Bypass factor?
2. How does SHR vary with operating conditions (wet-bulb, airflow)?
3. Compare with OCHRE's coil model
4. Compare with EnergyPlus coil model

## Recommended Tests

1. `calculate_shr` at AHRI rated conditions (26.67 °C DB / W=0.0107 / P=101.3 kPa / nominal capacity / nominal flow / rated Ao) → expected SHR ≈ 0.75.
2. `calculate_shr` with `w_in <= SHR_MIN_HUMIDITY_RATIO` → early-return `shr = 1.0`.
3. `coil_bypass_factor` at AHRI rated conditions → assert `0.01 < BF < 0.3`.
4. Round-trip: `Ao = coil_ao_factor(db, w, p, q, flow, shr)`, then `shr_rt = calculate_shr(db, w, p, q, flow, Ao).shr` → assert `|shr_rt - shr| < 0.001`.
5. Dry-coil path (`shr == 1.0` branch of `coil_bypass_factor`) → assert BF is enthalpy-based and `>= 0.01`.
6. After fixing F-1: re-run HVAC parity tests (`cargo test --package hares-equipment -- hvac_parity`) and confirm results are within tolerance.

## Findings

### F-1 — HIGH: Fan shaft heat correction applied to wet-bulb only; dry-bulb passed to `calculate_shr` is uncorrected

**File:** `crates/hares-equipment/src/hvac/air_conditioner.rs:781–877`

In `calculate_performance`, the fan shaft heat ΔT is added directly to `zone.wet_bulb_c` for the biquadratic input, but `calculate_shr` receives the **uncorrected** zone dry-bulb (`zone.temperature_c`).

OCHRE (`HVAC.py:474–488`) adds ΔT to the **dry-bulb** (`coil_input_db`), then recomputes `coil_input_wb` via a full psychrometric wet-bulb inversion from the new DB + original W. It then passes the corrected dry-bulb to `calculate_shr`.

Two errors compound:

1. `calculate_shr` receives a dry-bulb that is too low, biasing the enthalpy balance and ADP, producing a slightly elevated SHR.
2. Adding ΔT directly to the wet-bulb (without psychrometric recalculation) is physically incorrect. The correct procedure is: `DB_corrected = DB + ΔT`, then `WB_corrected = wet_bulb(DB_corrected, W_in, P)`. Adding ΔT to WB is wrong because the DB–WB depression depends non-linearly on W.

**Fix:**
```rust
let coil_entering_db_c = zone.temperature_c + fan_shaft_heat_correction_c;
let coil_entering_wb_c = if fan_shaft_heat_correction_c.abs() > f64::EPSILON {
    humidity_ratio_from_twb  // or equivalent wet-bulb solver
    // derive WB from coil_entering_db_c, zone.humidity_ratio, pressure
    hares_physics::psychrometrics::wet_bulb_from_db_and_w(
        coil_entering_db_c, zone.humidity_ratio, env.weather.pressure_kpa * 1000.0)
} else {
    zone.wet_bulb_c
};
// ... then pass coil_entering_db_c to calculate_shr
```

### F-2 — MEDIUM: Dry-air vs. moist-air density in mass flow rate — intentional ASHRAE improvement; ~1% SHR offset vs. OCHRE

**File:** `crates/hares-equipment/src/hvac/coil_physics.rs:424–441`

OCHRE uses `GetMoistAirDensity` → `(1+W)/v_da` [kg_moist/m³] multiplied by volumetric flow, yielding kg_moist/s. HARES uses `moist_air_density_kg_m3` → `p/(R_da·T·(1+1.608W))` [kg_da/m³] yielding kg_da/s, which is the correct basis for enthalpy per ASHRAE HOF Ch.1 §1.8.

Since Ao is computed using the same function at init time, the implementation is internally self-consistent. The resulting SHR is physically more correct than OCHRE's, but will differ by ~1% at typical humidity ratios (W ≈ 0.010 kg/kg). This is an intentional improvement, but must be confirmed in parity tests.

**Action:** Verify `cargo test --package hares-equipment -- hvac_parity` passes within defined tolerances. Document this known deviation from OCHRE in `coil_physics.rs`.

### F-3 — MEDIUM: Extra `f1.abs() < small` guard in `iterate` mode-3 diverges from OCHRE/EnergyPlus reference

**File:** `crates/hares-equipment/src/hvac/coil_physics.rs:482–486`

HARES:
```rust
if c.abs() < small
    || f1.abs() < small               // not in OCHRE JIT
    || ((a + (b + c * x1) * x1 - f1) / f1).abs() > small
```

OCHRE JIT (`psychrolib_jit.py:262–266`):
```python
if abs(c) < small:
    mode = 2
elif abs((a + (b + c * x1) * x1 - f1) / f1) > small:
    mode = 2
```

When `f1 ≈ 0`, the third condition `(.../ f1).abs() > small` already produces a large value and triggers mode=2 fallback. The extra `f1.abs() < small` clause therefore fires first for the same condition but also incorrectly inhibits the quadratic step in cases where `f1` is near zero but `f0` is not at convergence yet. Effect is degraded convergence speed, not a correctness failure.

**Fix:** Remove the `|| f1.abs() < small` clause.

### F-4 — MEDIUM: Extra `denom.abs() < small` guard in `iterate` mode-2 diverges from OCHRE/EnergyPlus reference

**File:** `crates/hares-equipment/src/hvac/coil_physics.rs:518–521`

HARES adds `if denom.abs() < small { mode = 1; }` before the secant slope calculation. OCHRE JIT does not have this guard. The guard protects against division-by-zero when `x1 == x0` (a degenerate case) and is conservative-safe. However, it is a deviation from the reference implementation.

**Action:** Keep the guard; add a comment noting the deviation from the OCHRE/EP reference.

### F-6 — LOW: Single `rated_shr` used for all speed stages in Ao computation

**File:** `crates/hares-equipment/src/hvac/latent_degradation.rs:23–60`

`compute_coil_ao_by_stage` uses a single `rated_shr` scalar for every stage. OCHRE passes a per-stage SHR list. For multi-speed equipment, low-speed and high-speed Ao factors should differ because the coil operates at different wet-coil conditions at each speed. Using a single SHR for all stages introduces a systematic Ao error that grows with the speed ratio.

**Fix:** Accept `&[f64]` for per-stage SHR in `compute_coil_ao_by_stage`, falling back to the scalar for single-speed equipment. Update config loading to parse `rated_shr_stage` analogously to `cooling_capacity_w_stage`.

### F-7 — LOW (informational): `SHR=1` path `W_ADP` formula vs. OCHRE `GetHumRatioFromTWetBulb(T,T,P)` — no action required

**File:** `crates/hares-equipment/src/hvac/coil_physics.rs:326–331`

OCHRE uses `GetHumRatioFromTWetBulb(T_ADP, T_ADP, P)` to compute `W_ADP`. HARES uses `humidity_ratio_from_rel_hum(t_adp, 1.0, p_pa)`. When T_WB = T_DB (saturation), both produce the same saturation humidity ratio to within 0.01%. HARES matches the OCHRE JIT path (`psychrolib_jit.py:335`) and EnergyPlus `DXCoils.cc`. No action required.
