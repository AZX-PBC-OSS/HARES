## Background/Context

ASHP (air-source heat pump) heaters are complex: biquadratic capacity/EIR curves as
functions of outdoor/indoor temp, defrost model, backup electric resistance, lockout
temperatures, multi-speed operation. This is one of the most config-heavy equipment
types.

## Investigation Instructions

1. **Read OCHRE `ASHPHeater.py`** — list every config key:
   - Rated capacity, HSPF, COP at rated conditions
   - Biquadratic coefficients (capacity_f_T, eir_f_T, capacity_f_ff, eir_f_ff)
   - Defrost parameters (defrost_temp, defrost_factor)
   - Backup: type, capacity, efficiency, switchover temp, lockout temp
   - Fan power, crankcase heater
   - Speed control: number of speeds, per-speed capacity fractions

2. **Read HARES `heat_pump/heater.rs` and `heater_config.rs`:**
   - What config keys are consumed?
   - How are defaults loaded? From `EquipmentDefaults`?

3. **Read `resolve_hvac.rs` HeatPump section:**
   - What parameters are extracted from HPXML `HeatPump` element?
   - Are lockout temperatures converted (°F→°C)?
   - Is the SEER2→SEER / HSPF2→HSPF conversion applied?

4. **Build comprehensive comparison table** (expect 20+ fields).

5. **Pay special attention to:**
   - Defrost model parameters — HARES has `heat_pump/defrost.rs`
   - Backup heating FSM — PARITY-012 added this
   - Speed count inference from SEER (SEER>21→4 speeds, etc.)

## Findings

### Summary

The comparison traces every ASHP-relevant config field from OCHRE's `parse_hvac`
(`hpxml.py:827–968`) and `ASHPHeater.__init__` / `HeatPumpHeater` (`HVAC.py:1112–1231`)
against HARES `resolve_hvac.rs` and `heater.rs/heater_config.rs/hvac_core.rs`.

HARES achieves coverage on the majority of fields. Three substantive gaps exist; one
is a latent behavioural defect.

### Defect Details

#### F-1 (Severity: Medium) — Single-speed heat pump PLF quadratic not injected

**Location:** `crates/hares-io/src/hpxml/resolve_hvac.rs:828`

OCHRE `HeatPumpHeater.__init__` (`HVAC.py:1124–1126`) injects the quadratic
`[0.89, 0.11, 0]` into `eir_plr` for every single-speed heat pump when HSPF ≥ 7:

```python
hspf = convert(1 / self.eir, "W", "Btu/hour")
if self.biquad_params is not None and self.n_speeds == 1 and hspf >= 7:
    self.biquad_params[1]["eir_plf"] = np.array([0.89, 0.11, 0])
```

The PLF quadratic `PLF = 0.89 + 0.11·PLR + 0·PLR²` applies a smaller cycling
penalty than the default `1 − Cd·(1−PLR)` formula for modern heat pumps. HARES
`apply_multispeed_parameters` early-returns at line 828 for `n_speeds <= 1`, so
no `eir_plr_coefficients` are injected for single-speed ASHP heaters. The result
is that HARES uses the `1 − Cd·(1−PLR)` cycling penalty (with `Cd = 0.11` for
HSPF ≥ 7), slightly over-penalising part-load efficiency compared to OCHRE.

The fix is to inject `eir_plr_coefficients = [[0.89, 0.11, 0.0]]` in
`insert_startup_degradation` (or a new companion function) for single-speed heat pump
heaters with HSPF ≥ 7. Low-HSPF (`< 7`) retains the default Cd=0.20 path with no
quadratic.

#### F-2 (Severity: Low) — Backup efficiency: units element not read

**Location:** `crates/hares-io/src/hpxml/resolve_hvac.rs:409–413`

OCHRE's comment (`hpxml.py:945`) states it "assumes efficiency units are in Percent
or AFUE (0-1)". HARES extracts `BackupAnnualHeatingEfficiency/Value` and computes
`backup_eir = 1 / val` with no units check. HPXML allows a `Units` sibling element
under `BackupAnnualHeatingEfficiency`. If the value were in COP (Value > 1) the
inversion is still correct. If it were in Percent and stored as e.g. `100` (not
`1.0`), the result would be wildly wrong. In practice, ResStock always emits
Percent/AFUE ≤ 1.0 for resistance backup, so this is low risk. However the code
should read and validate the `Units` child element to guard against unexpected inputs.

#### F-3 (Severity: Low) — Lockout temps emitted even when backup_capacity = 0

**Location:** `crates/hares-io/src/hpxml/resolve_hvac.rs:419–444`

OCHRE only emits `Heat Pump Lockout Temperature` and `Backup Lockout Temperature`
when `backup_capacity > 0` (`hpxml.py:957`). HARES emits them unconditionally
whenever the HPXML keys are present. If `backup_capacity_w` resolves to 0 in
`heater.rs:459–461` (`.max(0.0)`), the lockout temps are stored but have no effect
(no backup element to gate). This is benign but produces a semantic mismatch: the
heater has `er_lockout_temp_c != None` for a unit with no backup strip. No incorrect
power calculation results, but it is inconsistent state.

#### F-4 (Severity: Low) — `Backup Soft Lockout Time (minutes)` not configurable

**Location:** `crates/hares-equipment/src/hvac/heat_pump/heater.rs:884–896`

OCHRE exposes `Backup Soft Lockout Time (minutes)` (`HVAC.py:1216`) as a separate
maximum duration for the soft lockout phase. When configured, OCHRE keeps ER off for
at most `er_soft_lockout_time` after the hard lockout expires, even if the zone temp
has already stopped rising. HARES's soft lockout exits as soon as `zone_rising`
becomes false, which is equivalent to an infinite configurable duration (it
self-terminates on the physics). For most residential scenarios the behaviour is
equivalent, but a downstream user passing `Backup Soft Lockout Time` via
`EquipmentConfig` would have no effect. The config key should be accepted and
honoured, or documented as intentionally not supported.

#### F-5 (Severity: Low) — `Minimum Backup On Time` not supported; HARES has minimum OFF time only

**Location:** `crates/hares-equipment/src/hvac/heat_pump/heater.rs:67`; constant
`DEFAULT_MIN_ER_CYCLE_TIME_S = 300` in `constants.rs:39`

OCHRE (`HVAC.py:1229–1231`) has a `Minimum Backup On Time (minutes)` that sets the
minimum time ER must remain on after turning on. HARES implements a minimum **OFF**
time (`min_er_cycle_time_s`, default 300 s — 5 minutes) via `er_cycle_ready`. The
two constraints are complements: OCHRE prevents premature turn-off; HARES prevents
rapid re-cycling. Neither implements the other. The HARES default adds a constraint
not in OCHRE at all (OCHRE's default min on-time is 0), which could suppress ER
activation more aggressively than OCHRE during cold-start. This needs a parity
decision: either match OCHRE by defaulting `min_er_cycle_time_s = 0` or document
the HARES-specific conservative default.

---

### SEER2/HSPF2 Normalisation

HARES (`resolve_hvac.rs:655–656`) correctly normalises HSPF2 → HSPF via `× 1/0.95`
and SEER2 → SEER via the same factor. OCHRE does not handle HSPF2 at all (2019-era
code). This is a deliberate HARES improvement.

### Defrost Model

HARES implements both `OnDemand` (OCHRE default) and `Timed` (EnergyPlus/DOE-2)
defrost control modes in `defrost.rs`. OCHRE only implements `OnDemand`. All
constants (`0.875`, `0.954`, `0.01446`, `0.1528`, `7.222`, `1.01667`, `4.4445`)
match exactly. HARES is a strict superset.

### ER Thermostat Turn-Off Hysteresis

OCHRE (`HVAC.py:1355–1369`) has:
```
temp_turn_on  = setpoint - er_setpoint_offset
temp_turn_off = temp_turn_on + temp_deadband
```
ER turns off when `temp_indoor > temp_turn_off`.

HARES uses a simple `zone.temperature_c <= er_call_threshold` check with no separate
turn-off threshold (`heater.rs:935–936`). When ER is on and zone rises above
`er_call_threshold`, ER turns off on the next step. This is equivalent to a zero
deadband turn-off. OCHRE uses `temp_deadband` (default 1 °C) as the ER turn-off
margin. HARES will cycle ER more aggressively in the transition band than OCHRE.
This is not a configuration gap (no separate config key) but a behavioural delta
that should be covered by a test.

## Recommended Tests

### T-1 — Single-speed ASHP PLF quadratic injection (covers F-1)

In `crates/hares-io/tests/hpxml_parity.rs` or a new
`crates/hares-io/tests/hvac_config_tests.rs`:

Construct an HPXML `HeatPump` element with `CompressorType = "single stage"` and
`AnnualHeatingEfficiency` of 8.0 HSPF. Parse via `resolve_hvac`. Assert that the
resulting `EquipmentSpec` for the ASHP Heater contains `eir_plr_coefficients`
equal to `[[0.89, 0.11, 0.0]]`. Repeat with HSPF = 6.5 and assert `eir_plr_coefficients`
is absent (Cd = 0.20 path).

### T-2 — Backup efficiency units guard (covers F-2)

In `crates/hares-io/tests/hvac_config_tests.rs`:

Parse a HeatPump HPXML with `BackupAnnualHeatingEfficiency` containing `Units = "Percent"`
and `Value = 1.0`. Assert `backup_eir = 1.0`. Then parse with `Value = 0.5` (AFUE)
and assert `backup_eir = 2.0`. Optionally: parse with a `Units` value of `"COP"` and
`Value = 3.0`, assert `backup_eir` is approximately `0.333`.

### T-3 — Lockout temps gated on backup capacity (covers F-3)

In `crates/hares-io/tests/hvac_config_tests.rs`:

Parse a HeatPump HPXML with `BackupHeatingCapacity = 0` but with
`CompressorLockoutTemperature` present. Assert the resulting heater spec does
**not** contain `hp_lockout_temp_c`, matching OCHRE parity.

### T-4 — ER turn-off hysteresis deadband (covers ER thermostat delta)

In `crates/hares-equipment/tests/hvac_tests.rs` or inline in `heater.rs` tests:

Configure an ASHP heater with `heating_setpoint_c = 21.0`, `hysteresis_c = 1.0`,
`er_setpoint_offset_c = 1.6`. Step the heater with zone temp = 19.0 °C (below
er_call_threshold = 19.4 °C) — assert ER turns on. Then step with zone temp = 19.5 °C
(above er_call_threshold but below `setpoint - er_offset + deadband = 20.4 °C` as
OCHRE would compute it) — assert ER turns off in HARES. This test documents the
behavioural difference from OCHRE and establishes the HARES baseline.

### T-5 — `min_er_cycle_time_s` default vs OCHRE parity (covers F-5)

In `crates/hares-equipment/tests/hvac_tests.rs`:

Configure an ASHP heater with default settings (no explicit `min_er_cycle_time_s`).
Step ER on, then off, then attempt to turn ER on again within 300 s — assert it
is blocked by `er_cycle_ready`. Assert that if `min_er_cycle_time_s = 0.0` is
configured, ER can restart immediately. Document the OCHRE default (0 minutes) as
the reference in the test comment.

### T-6 — Soft lockout: zone-rising gate (covers F-4)

In `crates/hares-equipment/tests/hvac_tests.rs` (a test already exists at line 1715):

Verify the existing `er_soft_lockout_blocks_er_while_zone_temp_is_rising` test
covers the soft lockout exit condition. Extend it to assert that once zone temp
stops rising (`prev_zone_temp_c >= current`), the soft lockout clears in the
next control step, matching OCHRE's time-bounded soft lockout at infinite duration.
