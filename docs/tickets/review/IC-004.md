## Background/Context

OCHRE's ERWH `solve_ideal_capacity()` separately computes upper and lower element
duty cycles. The upper element has priority — it activates first when the top of the
tank is cold. The lower element only activates when upper demand is satisfied. Under
ideal mode, the duty cycles are fractions (0–1) representing partial-timestep operation.

## Investigation Instructions

1. **Read OCHRE `ElectricResistanceWaterHeater.solve_ideal_capacity()`:**
   - How are upper/lower duty cycles computed?
   - What determines which element activates?
   - How is total capacity allocated?

2. **Read HARES `resistance.rs`:**
   - Does it have ideal capacity mode?
   - Is there upper/lower element split logic?
   - How does it interact with `IdealCapacity` control signal?

3. **Document** whether HARES matches OCHRE's upper/lower split or uses
   a simpler model.

## Findings

### OCHRE reference: `ElectricResistanceWaterHeater`

**Node indices** (`WaterHeater.__init__`, lines 57–63):
- For a 12-node tank: upper element → node 3 (index 2), lower element → node 10 (index 9).
- For non-12-node tanks: upper element → node 1 (index 0), lower element → node N (index N-1).

**Thermostat control** (`run_thermostat_control`, lines 405–422):
- Checks `t_upper` (upper-element node) and averaged `t_lower` (lower-element node + node above).
- Priority: upper element fires whenever `t_upper < setpoint - deadband`, OR if already "Upper On"
  and `t_upper < setpoint`. Lower element fires only when `t_lower < setpoint - deadband` AND upper
  element is not already calling. Explicit `None` return means "no change" (hold current mode).
- Modes: `"Upper On"`, `"Lower On"`, `"Off"`.

**Ideal capacity** (`ElectricResistanceWaterHeater.solve_ideal_capacity`, lines 376–403):
1. Simulate the tank forward one timestep with both elements off (`self.model.update_model()`).
2. Compute `h_total`: dot product of `(setpoint - off_state)` × node capacitances for **all nodes
   from 0 through lower-element-node** (inclusive). Divide by `dt_s` → watts.
3. Compute `h_upper`: same dot product but only for **nodes 0 through upper-element-node** (inclusive).
4. `h_lower = h_total - h_upper`.
5. Convert each to duty cycle clamped to `[0, 1]`, with upper getting priority:
   - `d_upper = clamp(h_upper / capacity_rated, 0, 1)`
   - `d_lower = clamp(h_lower / capacity_rated, 0, 1 - d_upper)` (lower capped by remaining budget)
6. Both elements can fire in the same timestep with fractional duty cycles; they are independent.

**Heat injection** (`add_heat_from_mode`, lines 252–263):
- Upper element injects `capacity_rated * duty_cycle` into `h_upper_idx` node.
- Lower element injects `capacity_rated * duty_cycle` into `h_lower_idx` node.
- Both elements inject into the same slot `capacity_rated` — there is a **single shared rated
  capacity** used for both upper and lower.

**Simultaneous-element firing in ideal mode**: Both `d_upper` and `d_lower` can be non-zero in the
same timestep. `calculate_power_and_heat` accumulates heat from all modes with non-zero duty
cycles into the same heat-injection array.

### HARES implementation: `resistance.rs`

**Node indices** (`new` / `init`, lines 115–121, 268–273):
- `upper_node` defaults to `0` (top node), `lower_node` defaults to `n_nodes - 1` (bottom node).
- For a 6-node tank this is node 0 (top) and node 5 (bottom).

**Thermostat control** (`thermostat_calls`, lines 197–216 + `hysteresis_call` in `mod.rs` lines
161–173):
- `hysteresis_call`: if currently on → stay on while `temp < setpoint`; if off → turn on only
  when `temp <= setpoint - deadband`. The OCHRE thermostat uses `<` for both transitions; HARES
  uses `<=` for the off→on edge (intentional departure, documented in comment).
- Both upper and lower thermostats are evaluated independently with the same setpoint and deadband.
- **No separate upper thermostat check** of the form `t_upper < setpoint - deadband` to trigger
  upper-element priority. HARES checks the upper-element node temp against the same hysteresis
  function as the lower.

**MasterSlave lockout** (`update_control`, lines 416–426):
```rust
self.upper_element_on = upper_call;
self.lower_element_on = !self.upper_element_on && lower_call;
```
- Upper fires if its thermostat calls; lower fires only when upper is silent. This matches OCHRE's
  structural intent (upper gets priority, lower is locked out while upper runs) but the trigger
  condition differs (see defect 1 below).

**Ideal capacity path** (`step`, lines 449–473):
- Activates when `time_res >= 300 s` (matches OCHRE's ≥5-minute threshold).
- When heating is called: identifies the **single active element** (upper if `upper_element_on`,
  else lower) and calls `ideal_capacity_for_node(element_node, setpoint_c, ambient_c, dt_s)`.
- `ideal_capacity_for_node` predicts the single-node temperature with heater off (using only that
  node's UA × dt), then returns power to bring that node back to setpoint.
- Result: one duty cycle applied to the single active element. **No concurrent dual-element
  ideal-capacity computation**.

**`ideal_capacity_for_node` scope** (`tank.rs` lines 268–285):
- Models only the target node's standby loss: `t_off = t_now - ua_node * (t_now - ambient) * dt / mcp`.
- Ignores conduction between adjacent nodes (inter-node heat transfer is not modelled in this
  single-node prediction, unlike OCHRE's full RC-model forward pass).

### Defects

**Defect 1 — Upper element activation condition is wrong for the non-ideal (thermostat) path**
(Severity: Medium)

OCHRE `run_thermostat_control` line 415:
```python
if t_upper < lower_threshold_temp or (self.mode == "Upper On" and t_upper < self.setpoint_temp):
    return "Upper On"
```
The upper element fires on the initial cold-start condition (`t_upper < setpoint - deadband`) **or**
to continue running while still in "Upper On" mode until the top of the tank reaches setpoint.

HARES `thermostat_calls` applies `hysteresis_call` symmetrically to both elements. For the upper
element this means:
- Turn on: `upper_temp <= setpoint - deadband`
- Stay on: `upper_temp < setpoint`

This is structurally equivalent for the initial-call case, but **OCHRE also continues "Upper On"
when the upper node is between `(setpoint - deadband)` and `setpoint`**, while HARES would have
already turned the upper element off if it rose above `setpoint - deadband` before reaching
setpoint. In practice `hysteresis_call`'s stay-on condition `temp < setpoint` is the same as
OCHRE's `t_upper < self.setpoint_temp`, so the on→off edge aligns. The off→on edge uses `<=`
instead of `<` (intentional, documented). This particular delta is low-impact.

**Defect 2 — CRITICAL: Ideal capacity computes only one element; OCHRE computes both simultaneously**
(Severity: High)

OCHRE computes `d_upper` and `d_lower` in the same pass. Both can be non-zero in a single
timestep: the upper element recovers the top portion of the tank while the lower element
simultaneously recovers the middle-to-bottom portion.

HARES selects the single active element (upper XOR lower, never both), then computes ideal
capacity only for that element's node. This means:
- When the upper element fires in ideal mode, the lower half of the tank receives zero heat
  regardless of how cold it is.
- When the upper element is satisfied and control passes to the lower element, only the lower node
  is heated — but by then only one element fires per timestep.
- The effective heating capacity available to the tank is halved whenever the tank has significant
  stratification (upper warm, lower cold), because HARES ignores the lower deficit while the upper
  is active.

This divergence is most visible in cold-start recovery and post-draw recovery with a 6–12 node
stratified tank at timesteps ≥ 5 min.

**Defect 3 — OCHRE uses a full RC-model forward pass for ideal capacity; HARES uses a single-node
approximation**
(Severity: Medium)

OCHRE `solve_ideal_capacity` runs `self.model.update_model()` — a full matrix exponential
integration over all nodes — to get the heater-off next states. The delta from setpoint across
all nodes up to the lower-element node is then integrated against node capacitances.

HARES `ideal_capacity_for_node` uses a first-order Euler approximation of a **single node** in
isolation:
```
t_off ≈ t_now - ua_node × (t_now - ambient) × dt / mcp
```
This ignores conduction from adjacent nodes. In practice inter-node conduction is significant
for nodes adjacent to a much colder or warmer neighbour (e.g., the boundary between the hot
upper zone and cold lower zone after a large draw). The approximation produces a lower ideal
capacity estimate than the full model, leading to under-heating at 5-min+ timesteps.

**Defect 4 — Single shared `capacity_rated` vs per-element rated power**

OCHRE uses a single `capacity_rated` for both upper and lower elements. HARES correctly
stores `upper_element_power_w` and `lower_element_power_w` as separate fields, defaulting to
the same value but allowing them to differ. In the ideal-capacity path, HARES divides `ideal_w`
by `active_w` (the correct per-element rated power), so this is actually a HARES improvement
over OCHRE. No defect here; noting it to avoid future regression.

**Defect 5 — `heat_injections` Vec allocation in hot loop**
(Severity: Low — performance)

`resistance.rs` line 486:
```rust
let mut heat_injections = Vec::with_capacity(2);
```
This allocates on every `step()` call. The vec is small (capacity 2) but a pre-allocated
`[Option<(usize, f64)>; 2]` scratch buffer would eliminate the allocation. Per project memory
feedback this is a hot-loop concern.

## Recommended Tests

All tests in `crates/hares-equipment/tests/water_heater_tests.rs` or a new
`crates/hares-equipment/tests/resistance_wh_tests.rs`.

1. **`test_ideal_capacity_dual_element_simultaneous`**
   - Configure a 6-node tank, 300-s timestep, upper node=0 cold (below deadband), lower node=5
     also cold (below deadband).
   - Step once. Assert that both upper and lower elements inject heat in the same timestep and
     that total electrical power equals `d_upper * upper_w + d_lower * lower_w`.
   - This test currently fails; it is the acceptance criterion for fixing Defect 2.

2. **`test_ideal_capacity_upper_only_when_lower_satisfied`**
   - Configure tank with upper node below deadband, lower node at setpoint.
   - Step once at 300-s timestep. Assert only upper element fires (lower duty cycle = 0).

3. **`test_ideal_capacity_lower_only_when_upper_satisfied`**
   - Configure tank with upper node at setpoint, lower node below deadband.
   - Step once at 300-s. Assert only lower element fires.

4. **`test_thermostat_upper_priority_lockout`**
   - Configure tank at 60-s timestep (thermostat mode). Set upper node cold, lower node cold.
   - Step once. Assert `upper_element_on == true`, `lower_element_on == false` (MasterSlave lockout).

5. **`test_thermostat_lower_fires_when_upper_satisfied`**
   - Configure 60-s timestep. Upper node at setpoint, lower node below deadband.
   - Step once. Assert `upper_element_on == false`, `lower_element_on == true`.

6. **`test_cold_start_recovery_ideal_mode`**
   - Start tank at ambient (20°C), setpoint 50°C, 6-node, 300-s timestep.
   - Run 10 steps. Assert that average tank temperature rises faster than if only one element
     is allowed per step (compares single-element vs dual-element recovery).
   - This is an integration test for the dual-element fix and verifies parity direction with OCHRE.

7. **`test_node_position_12_node_tank`**
   - Construct `ResistanceWH` with `tank_nodes=12`, no explicit `upper_element_node`/
     `lower_element_node`. Assert `upper_node == 2` and `lower_node == 9` (matching OCHRE's
     node-3 and node-10 convention with 0-based indexing). If the defaults are intentionally
     different, document the rationale.
