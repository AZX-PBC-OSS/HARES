## Background/Context

Previous agents repeatedly ignored failing tests instead of debugging and fixing the
underlying physics bugs. This means:
1. BESTEST cases may be failing due to wrong physics but nobody knows because the
   failures are suppressed.
2. Parity tests are `#[ignore]` with excuses like "requires OCHRE output" or
   "not yet implemented" — but the unimplemented features are actually required.
3. Tests exist that were written to validate physics but have been abandoned.

**This is unacceptable.** Every test must pass. Period. `#[ignore]` is not a status —
it's a hiding place for bugs. We do not delete failing tests. We fix the code until
they pass.

### Pass 2: smoke_resstock_1h reference value issue

`tests/regression/smoke_test.rs` line 608 has an inline `TODO` comment:

```
// TODO: set to OCHRE-verified value (currently HARES baseline)
("Total Electric Power (kW)", 1.1909, &[]),
```

The 1.1909 kW value is HARES's own output used as its own reference. The test asserts HARES is within ±30% of itself — this is not a parity test, it is a tautology. If HARES regresses and produces 0.9 kW total power, the test will still pass (0.9 vs 1.1909 = -24%, within 30%).

Similarly all non-HVAC schedule columns for the ResStock case have unverified TODOs (e.g., `0.0785` for lighting, `0.3102` for MELs) and use ±300% tolerance.

**Classification: LAZY IGNORE pattern without the ignore — the assertions give false confidence of parity verification.**

**Action required:** Run OCHRE 0.9.x on `bldg0112631-up00.xml` + Denver EPW for the May 5 2019 12:00 window and replace the placeholder values. Until then the test should be clearly marked as a smoke test only, not an OCHRE parity assertion.
