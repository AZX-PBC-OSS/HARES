## Background/Context

When simulation time resolution differs from weather file resolution (e.g., 5-min
simulation with hourly EPW), weather data must be resampled. OCHRE uses different
methods per field: temperature/humidity → interpolate, solar irradiance → forward-fill
(step function within the hour), precipitation → sum. Wrong resampling causes systematic
bias in solar gains, temperatures, etc.

## Findings

### Architectural Decision: Local Time Only

**Project policy:** HARES uses local time internally throughout. HPXML and EPW weather are always in local time. There is no reason to support UTC or multiple timezones. All internal timestamps are local to the building site. `start_time` from Python is interpreted as local time. EPW `timezone_offset_h` is metadata for solar position calculation only, not for time conversion. Any findings about UTC/offset mismatches should be resolved by removing UTC conversion entirely, not by fixing the conversion.

### OCHRE Behaviour (confirmed by code audit)

`resample_and_reindex` (schedule.py:480) accepts an `interpolate` boolean that selects between
linear interpolation (`resample().interpolate()`) and forward-fill (`resample().ffill()`).
For weather, the call is always (schedule.py:585):

```python
df_weather = resample_and_reindex(df_weather, **house_args)
```

No call site in the entire codebase passes `interpolate=True`. `house_args` does not inject
it. **OCHRE applies ZOH (forward-fill) uniformly to every weather field when upsampling.**
There is no per-field differentiation — temperature, radiation, wind, humidity all get ffill.

For downsampling, OCHRE uses `.mean()` for all weather fields (schedule.py:562).

---

### HARES Behaviour (weather.rs:402–558)

HARES implements three methods — `Pchip`, `Zoh`, `Linear` — selected per-field at upsampling
time via `resample_with`. The defaults are:

| Field | Default method | Rationale |
|---|---|---|
| `dry_bulb_c` | PCHIP | Continuous instantaneous |
| `dew_point_c` | PCHIP | Continuous instantaneous |
| `rel_humidity_pct` | PCHIP (hardcoded, see Defect 1) | Continuous instantaneous |
| `pressure_kpa` | PCHIP | Continuous instantaneous |
| `horizontal_infrared_w_m2` | PCHIP | Continuous |
| `sky_temp_c` | PCHIP | Derived from infrared |
| `ground_temp_c` | PCHIP | Slow-varying |
| `opaque_sky_cover` | PCHIP (hardcoded, see Defect 1) | Continuous |
| `ghi_w_m2` | ZOH | Period-average energy flux |
| `dni_w_m2` | ZOH | Period-average energy flux |
| `dhi_w_m2` | ZOH | Period-average energy flux |
| `wind_speed_m_s` | ZOH | Period-representative average |
| `wind_dir_deg` | ZOH | Period-representative average |
| `liquid_precip_m` | distribute (÷factor) | Accumulated depth |

`ochre_compat()` (weather.rs:266) overrides all continuous fields to ZOH to match OCHRE,
but is only activated when the caller explicitly passes it to `new_with_resample`.
The default `EnvironmentManager::new` path uses the PCHIP/ZOH split.

For downsampling, HARES uses `mean_downsample` for instantaneous and solar fields, and
`sum_downsample` for accumulated fields (weather.rs:532–556). This matches OCHRE for
instantaneous/solar and is more correct than OCHRE for precipitation.

### Defect 1 — Medium: `rel_humidity_pct` and `opaque_sky_cover` ignore `ResampleOverrides`

`rel_humidity_pct` (weather.rs:428) and `opaque_sky_cover` (weather.rs:432) are computed
before the struct literal using direct `pchip_resample` calls that bypass `resample_field`.
Both corresponding override fields exist in `ResampleOverrides` but are never read during
upsampling — the overrides are silently ignored.

Consequence: `ResampleOverrides::ochre_compat()` sets
`opaque_sky_cover: Some(ResampleMethod::Zoh)` and (after Defect 2 is fixed) will set
`rel_humidity: Some(ResampleMethod::Zoh)`, but both will have no effect. Any user-supplied
override for these two fields is also silently discarded.

**Fix:** Remove the two pre-computed locals. Move clamping into inline closures or a
thin wrapper, and route both fields through `resample_field` inside the struct literal:
```rust
rel_humidity_pct: {
    let mut v = resample_field(
        &self.rel_humidity_pct, factor,
        overrides.rel_humidity.unwrap_or(ResampleMethod::Pchip),
    );
    for x in &mut v { *x = x.clamp(0.0, 100.0); }
    v
},
opaque_sky_cover: {
    let mut v = resample_field(
        &self.opaque_sky_cover, factor,
        overrides.opaque_sky_cover.unwrap_or(ResampleMethod::Pchip),
    );
    for x in &mut v { *x = x.clamp(0.0, 10.0); }
    v
},
```

---

### Defect 2 — Low: `ochre_compat()` missing `rel_humidity` override

`ochre_compat()` (weather.rs:266) sets ZOH for dry_bulb, dew_point, pressure, infrared,
sky_temp, ground_temp, and opaque_sky_cover, but does not set `rel_humidity`. Since OCHRE
uses ffill for all fields including humidity, the compat constructor is incomplete.

**Fix:** Add `rel_humidity: Some(ResampleMethod::Zoh)` to `ochre_compat()`.

---

### Defect 3 — Low (doc-only): ZOH rationale conflation in `ResampleMethod` doc comment

`ResampleMethod::Zoh` is documented (weather.rs:235–237) solely as:
> "Zero-order hold (forward fill) — each sub-step gets the previous hourly value.
> Matches OCHRE's pandas `resample().ffill()` convention. Use for parity testing against OCHRE."

This conflates two distinct reasons ZOH is used: (a) OCHRE compat mode, and (b) physically
correct default for period-representative fields (radiation, wind). A reader of the solar
ZOH assignment will incorrectly infer it was chosen only for OCHRE parity rather than being
the right physics choice.

**Fix (doc-only):** Expand the `ResampleMethod::Zoh` comment to distinguish the two uses:
```rust
/// Zero-order hold (forward fill) — correct default for period-representative
/// measurements (solar irradiance, wind speed) where each hourly value is a
/// period average and interpolation fabricates intra-hour variation. Also matches
/// OCHRE's `resample().ffill()` for compat testing.
```

### Physics Assessment

The HARES default PCHIP-for-temperature / ZOH-for-radiation split is physically correct and
consistent with EnergyPlus practice. EPW hourly dry-bulb and humidity values represent
instantaneous midpoint conditions; cubic interpolation (PCHIP) is appropriate and avoids
the staircase temperature profiles that OCHRE's ffill produces at sub-hourly resolution.
Radiation and wind are hourly period averages; ZOH preserves the stated average and avoids
fabricating intra-hour variation the EPW does not contain.

The intentional departure from OCHRE's uniform ffill is justified under the project's
ASHRAE/EnergyPlus physics target.
