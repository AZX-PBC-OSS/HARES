Mini-split cooling mode counterpart to CW-009. Same DSE=1 and variable-speed
considerations apply.

1. Read OCHRE `MinisplitAHSPCooler` class in `HVAC.py`. (Note: OCHRE uses `MinisplitAHSPCooler` with transposed A and S, not `MinisplitASHPCooler`.)

### Defect detail

#### DEFECT 1 (HIGH): MSHP cooler number of speeds not forced to 4

**Location:** `crates/hares-io/src/hpxml/resolve_hvac.rs`, lines 447-451

OCHRE `hpxml.py:867-868`:
```python
if name == "mini-split":
    number_of_speeds = 4  # MSHP always variable speed
```

HARES calls `insert_mode_and_speed_metadata` (which reads `CompressorType`) and then
`apply_default_hvac_speed_fallback` (which infers from SEER). Neither enforces 4 speeds
for MSHP. If HPXML omits `CompressorType` and SEER ≤ 21, the cooler is silently downgraded
to 1 or 2 speeds. Consequences:

- `apply_multispeed_cooling_parameters` is a no-op for n_speeds ≤ 1, so per-stage
  capacity, EIR, and biquadratic curves from the defaults store are not loaded.
- `startup_cd` reverts to 0.20 (single-speed, SEER < 13) instead of 0.0.
- The equipment operates as single-speed, erasing the variable-speed energy savings
  that mini-splits are specifically designed to deliver.

**Fix:** After `apply_default_hvac_speed_fallback`, add an unconditional override when
`heat_pump_type == "mini-split"`:
```rust
if heat_pump_type == "mini-split" {
    params.insert("number_of_speeds".to_string(), json!(4));
    params.insert("speed_control_mode".to_string(), Value::String("variable_speed".to_string()));
}
```
This must appear before `apply_multispeed_cooling_parameters` and
`insert_startup_degradation` are called on the split params.

#### DEFECT 2 (MEDIUM): Per-stage SHR values not written to params

**Location:** `crates/hares-io/src/hpxml/resolve_hvac.rs`, `apply_multispeed_parameters`,
lines 874-878

OCHRE `HVAC.py:795-796` injects per-speed SHR from the multispeed CSV:
```python
kwargs["SHR (-)"] = [speed_params[f"SHR {i + 1}"] for i in range(self.n_speeds)]
```
These become `self.shr_list` and drive latent heat calculations at each speed.

HARES loads `multispeed.shrs` from the CSV (`defaults.rs:595-610`) but
`apply_multispeed_parameters` only writes capacity and EIR stage params
(resolve_hvac.rs:874-878). The `shrs` field is read and discarded.

At runtime HARES falls back to a single rated SHR (from `CoolingSensibleHeatFraction`
or the 0.75 default). At part-load the effective SHR will be slightly wrong — latent
removal is over- or underestimated depending on which speed is active.

**Fix:** In `apply_multispeed_parameters` (cooling branch only), also emit:
```rust
for (i, &shr) in multispeed.shrs.iter().enumerate().take(stage_count) {
    params.insert(format!("shr_stage_{i}"), json!(shr));
}
```
`CoolingCore::init` must then load these and build a `shr_by_stage: Vec<f64>` that
the biquadratic step uses in place of the single `rated_shr`.

#### DEFECT 3 (LOW): 10-speed to 4-speed remap absent on cooler path

**Location:** `crates/hares-equipment/src/hvac/heat_pump/cooler.rs` /
`crates/hares-equipment/src/hvac/air_conditioner.rs`

OCHRE `MinisplitHVAC.__init__` (HVAC.py:1096-1101) subsamples a 10-entry capacity/EIR
list at indices [1, 3, 5, 9] when a 10-speed lookup table is sourced. HARES implements
`remap_minisplit_stages` in `heater_config.rs` and calls it from `HpHeater::init`, but
`CoolingCore::init` has no equivalent. If the defaults store ever supplies a 10-row
MSHP Cooler entry the cooler will silently use all 10 stages instead of 4.

Currently the defaults CSV for `MSHP Cooler` uses 4 speeds, so this is latent rather
than currently triggered. Still must be fixed for correctness.

## Recommended Tests

All tests should be added to `crates/hares-equipment/tests/hvac_tests.rs` or
`crates/hares-io/tests/comprehensive_tests.rs` as appropriate.

1. **`mshp_cooler_hpxml_forces_4_speeds_regardless_of_compressor_type`**
   Build an HPXML `HeatPump` node with `HeatPumpType = mini-split`, `SEER = 14`
   (below the 15-speed heuristic threshold), and `CompressorType = single stage`.
   Call `resolve_hvac` and assert the resulting `MSHP Cooler` spec has
   `number_of_speeds == 4` and `speed_control_mode == "variable_speed"`.

2. **`mshp_cooler_hpxml_forces_4_speeds_when_compressor_type_absent`**
   Same as above but omit `CompressorType` entirely. Assert same 4-speed outcome.

3. **`mshp_cooler_multispeed_params_loaded_when_n_speeds_forced_4`**
   Verify that when the MSHP cooler resolves to 4 speeds, `cooling_capacity_w_stage_0`
   through `cooling_capacity_w_stage_3` and `cooling_eir_stage_0` through
   `cooling_eir_stage_3` are all present in the params map with non-zero values.

4. **`mshp_cooler_per_stage_shr_written_to_params`**
   Using a defaults store that contains a 4-speed MSHP Cooler row with distinct
   `SHR 1..4` values, assert that `shr_stage_0` through `shr_stage_3` appear in
   the resolved params with values matching the CSV row.

5. **`mshp_cooler_startup_cd_is_zero_for_variable_speed`**
   Verify `startup_cd == 0.0` in the resolved MSHP Cooler params (variable-speed
   units carry no startup degradation per Winkler 2011 and OCHRE parity).

6. **`mshp_cooler_duct_params_not_injected`**
   Verify that `duct_supply_leakage_fraction`, `duct_zone_id`, and related duct keys
   are absent from the resolved MSHP Cooler params (DSE = 1, ductless).

7. **`mshp_cooler_crankcase_defaults_applied_without_init`**
   (Already exists in `cooler.rs` unit tests; confirm it exercises the 0 °C threshold,
   not 12.8 °C.)
