## Background/Context

`DwellingProfilingSummary` contains per-component timing breakdowns (envelope_solve,
hvac, water_heater, etc.) but is not exposed to Python.

## Investigation Instructions

1. Read the Rust profiling summary struct.
2. Confirm not exposed in Python.
3. Assess value for performance debugging.
4. Recommend: expose as dict? Or low priority?


## Findings

### FINDING 1 — profiling_summary() is entirely absent from the Python bindings (Severity: Medium)

`Dwelling::profiling_summary()` exists at `crates/hares-core/src/dwelling/mod.rs:1583–1587` behind `#[cfg(feature = "profiling")]`. There is no corresponding method anywhere in `PyDwelling`'s `#[pymethods]` block, no `cfg(feature = "profiling")` guard in `crates/hares-python/src/py_dwelling.rs`, and no stub entry in `python/ochre_next/_hares.pyi`. A Python user cannot call `dwelling.profiling_summary()` at all.

### FINDING 2 — `profiling` and `actor_profiling` features are not forwarded from hares-python to hares-core (Severity: Medium, blocking fix 1)

`crates/hares-python/Cargo.toml` declares only one feature: `observe = ["hares-core/observe"]`. There is no `profiling = ["hares-core/profiling"]` or `actor_profiling = ["hares-core/actor_profiling"]` entry. Even if a Python binding were written today, activating it from a Python wheel build would be impossible without first adding the feature forwarding.

### FINDING 3 — actor_timing() is also absent from Python bindings (Severity: Medium)

`Dwelling::actor_timing()` exists at `crates/hares-core/src/dwelling/mod.rs:1443–1448` behind `#[cfg(feature = "actor_profiling")]`. Same gap: no `PyDwelling` method, no feature forwarding, no stub. Per-actor timing breakdown is inaccessible from Python.

---

## Required Fixes

1. Add `profiling = ["hares-core/profiling"]` and `actor_profiling = ["hares-core/actor_profiling"]` to `crates/hares-python/Cargo.toml` `[features]`.

2. Add a `#[cfg(feature = "profiling")] pub fn profiling_summary()` method to `PyDwelling` that calls `dwelling.profiling_summary()` and returns a `PyDict` with fields:
   - `envelope_solve_s: f64`
   - `hvac_s: f64`
   - `water_heater_s: f64`
   - `schedule_load_s: f64`
   - `io_s: f64`
   - `other_s: f64`
   - `memory_high_water_kb: u64`
   - `hot_path_alloc_violations: u64`

   `DwellingProfilingSummary` stores `std::time::Duration` fields; convert each to `f64` seconds via `.as_secs_f64()` to avoid exposing a custom duration type to Python.

3. Add a `#[cfg(feature = "actor_profiling")] pub fn actor_timing()` method to `PyDwelling` that returns `Vec<(String, f64)>` (name, seconds), mirroring `Dwelling::actor_timing()`.

4. Add corresponding stubs to `python/ochre_next/_hares.pyi` under `PyDwelling`. Note the methods are only present when the wheel is built with the feature enabled.

## Recommended Tests

- `tests/python/test_py_dwelling_integration.py`: add `test_profiling_summary_fields` — build with `profiling` feature, run `simulate()`, assert `profiling_summary()` returns a dict with all eight expected keys and all numeric values are non-negative.
- `tests/python/test_py_dwelling_integration.py`: add `test_actor_timing_returns_list` — build with `actor_profiling` feature, run a simulation with at least one actor, assert `actor_timing()` returns a non-empty list of `(str, float)` pairs with all times >= 0.
