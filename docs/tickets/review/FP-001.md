## Background/Context

OCHRE fan power model (`HVAC.py` lines 148–153, 514–520, 531–536, 543, 549–554):

1. `fan_power_per_flow_rate = Rated Auxiliary Power (W) / rated_flow_rate_m3_s` — a W/(m³/s) specific intensity derived from a hard input; there is no internal default constant.
2. Per-step: `fan_power = fan_power_per_flow_rate * flow_rate` (staged) or `capacity * eir * fan_power_ratio` (ideal).
3. Fan power is **always** added to `delivered_heat` (zone sensible gain): `delivered_heat = heat_gain * shr + fan_power`.
4. For `is_gas` equipment the fan electric draw is `fan_power / 1000` kW (gas furnace blower).
5. For `is_electric` equipment (non-gas) it is `power_kw + fan_power / 1000` — compressor/element power plus fan power.

## Findings

### FINDING 1 — CRITICAL: ElectricFurnace fan power completely absent
**File:** `crates/hares-equipment/src/hvac/furnace.rs:146–191`

`ElectricFurnace` has no `fan_power_w` field. Its `step` computes:

```rust
let electric_kw = (self.rated_capacity_w * self.eir * duty) / 1_000.0 * sf;
```

Fan power is neither computed nor added to the electrical port, and fan heat is not injected into the zone. This was noted as a known gap in the existing review notes; this investigation confirms the root cause and quantifies the scope.

**OCHRE equivalent (`HVAC.py:553–554`):** `electric_kw = power_kw + fan_power / 1000`.

At a typical 10 kW rated capacity, 350 CFM/ton airflow, and 0.365 W/CFM default specific fan power, the blower draws roughly 170 W that is silently dropped — both as an electrical load and as 170 W of zone sensible heat injection. For a conditioned space this heat contribution persists for the entire heating season.

**Fix:** Add `fan_power_w: f64` to `ElectricFurnace`, compute it in `init` using the same fallback chain as `GasFurnace` (`first_f64` for explicit value, then `hvac.fan_power_w(airflow)` from default W/m³/s), and in `step` add it to `electric_kw` and accumulate it into `total_sensible_w` before calling `write_zone_thermal_contributions`.

### FINDING 2 — MEDIUM: GasFurnace airflow constant mismatch for fan fallback
**File:** `crates/hares-equipment/src/hvac/furnace.rs:30–31, 308–314`

`GasFurnace.init` uses a separate constant `FURNACE_FAN_CFM_PER_TON = 400.0` to derive the fallback airflow for fan power computation:

```rust
const FURNACE_FAN_CFM_PER_TON: f64 = 400.0;
const FURNACE_AIRFLOW_M3_S_PER_W_HEATING: f64 = FURNACE_FAN_CFM_PER_TON * CFM_TO_M3_S / W_PER_TON;
// used in init:
let airflow_m3_s = self.rated_capacity_w * FURNACE_AIRFLOW_M3_S_PER_W_HEATING;
self.fan_power_w = first_f64(...).unwrap_or_else(|| self.hvac.fan_power_w(airflow_m3_s));
```

However, `HvacEquipmentType::GasFurnace` falls through to `AIRFLOW_HEATING_CFM_PER_TON = 350.0` in `default_airflow_cfm_per_ton` (`hvac_core.rs:69, 97–103`), and this is the value loaded into `hvac.airflow_m3_s_per_w` during `hvac.init`. The furnace fan fallback therefore silently uses 400 CFM/ton while the rest of the HVAC stack sees 350 CFM/ton.

OCHRE uses 350 CFM/ton for all heaters (`HVAC.py:142`).

The practical effect: the fan power fallback (when no explicit `fan_power_w` or `fan_power_w_per_cfm` is configured) is ~14% too high. This is a secondary issue but creates an inconsistency that is easy to miss.

**Fix:** Remove `FURNACE_FAN_CFM_PER_TON` and `FURNACE_AIRFLOW_M3_S_PER_W_HEATING`. In the fallback branch, compute airflow as `self.rated_capacity_w * self.hvac.airflow_m3_s_per_w` (which already holds the correctly initialised value from `hvac.init`).

### FINDING 3 — MEDIUM: Fan heat not injected into zone for heat pump heater or AC
**File:** `crates/hares-equipment/src/hvac/heat_pump/heater.rs:817`, `crates/hares-equipment/src/hvac/air_conditioner.rs:637–642`

Heat pump heater `step` builds:

```rust
let mut thermal_output_w = hp_capacity_w + er_capacity_w;
```

`fan_power_w` contributes to `electric_kw` (correct) but is not added to `thermal_output_w`. The call to `write_zone_thermal_contributions` therefore excludes fan motor heat from the zone sensible gain. The AC analogously passes only `-sensible_cooling_w`/`-latent_cooling_w` without netting fan heat.

OCHRE adds `fan_power` to `delivered_heat` unconditionally for all types (`HVAC.py:543`).

For a typical 3-ton ASHP at 350 CFM/ton and 0.365 W/CFM, blower heat is ~450 W — a persistent and meaningful zone heating offset that affects zone temperature and therefore thermostat duty cycle.

**Note on AC:** Fan shaft heat _does_ affect coil entering conditions via the `fan_shaft_heat_correction_c` correction (`air_conditioner.rs:786–804`), which is the OCHRE-equivalent of `coil_input_db += fan_power_per_flow_rate / 1000 / rho_air / cp_air`. However the fan's electrical energy dissipated into room air after the coil (duct/discharge side) is _not_ added to zone sensible gains. OCHRE adds fan heat to zone in `add_gains_to_zone`. This gap also applies to AC.

**Fix:** In the heat pump heater, add `fan_power_w` (after all scaling/limiting) to `thermal_output_w` before `write_zone_thermal_contributions`. In the AC, add `fan_kw * 1000.0` to `sensible_cooling_w` (as a heat gain that partially offsets the cooling removal) before writing to the zone port.

### FINDING 4 — LOW: Default fan power constant lacks citation
**File:** `crates/hares-equipment/src/hvac/hvac_core.rs:24–26`

```rust
/// Default fan power [W/CFM]. ACCA Manual D residential air handler.
const DEFAULT_FAN_POWER_W_PER_CFM: f64 = 0.365;
```

OCHRE does not embed a default W/CFM constant; it always receives `Rated Auxiliary Power (W)` as a hard input from the HPXML/ResStock resolver. The 0.365 W/CFM value is used when neither `fan_power_w`, `fan_only_power_w`, `auxiliary_power_w`, `fan_power_w_per_cfm`, nor `fan_power_w_per_m3_s` is configured.

ResStock's typical range is 0.25–0.58 W/CFM depending on equipment class (see ResStock `hvac.rb`). 0.365 is a reasonable mid-range default, but the fallback path for `ElectricFurnace` (once Finding 1 is fixed) and the discrepancy noted in Finding 2 both depend on getting this default correct. The citation should reference a specific source (e.g., RESNET HERS Addendum 82 or ACCA Manual D Table 1-1) so reviewers can verify.

This is documentation quality only and does not affect correctness once Findings 1–3 are remediated.

## Recommended Tests

1. `electric_furnace_fan_power_in_electric_load` — configure an `ElectricFurnace` with an explicit `fan_power_w_per_cfm`, step it, assert that the electrical port power equals `capacity * eir * duty / 1000 + fan_power * duty / 1000`.
2. `electric_furnace_fan_heat_injected_into_zone` — same setup, assert zone sensible contribution includes fan heat on top of rated capacity.
3. `gas_furnace_fan_fallback_uses_hvac_airflow` — configure `GasFurnace` without explicit fan power, assert `eq.fan_power_w ≈ eq.hvac.fan_power_w(eq.rated_capacity_w * eq.hvac.airflow_m3_s_per_w)` (350 CFM/ton path, not 400).
4. `heat_pump_heater_fan_heat_in_zone` — step an ASHP heater and assert zone sensible contribution equals compressor capacity + ER capacity + fan heat.
5. `ac_fan_heat_in_zone_sensible` — step an AC and assert the net zone cooling is `sensible_cooling_w - fan_heat_w` (fan heat partially offsets removal).
