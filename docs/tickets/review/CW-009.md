## Background/Context

Mini-split heat pumps differ from ducted ASHPs: no ducts (DSE=1), typically variable
speed (4+ speeds inferred from high SEER), different default curves. FX-032 mentions
MSHP 4-speed as a needed fix.

## Investigation Instructions

1. Read OCHRE `MinisplitAHSPHeater` class in `HVAC.py` — how does it differ from `ASHPHeater`? (Note: OCHRE uses `MinisplitAHSPHeater` with transposed A and S, not `MinisplitASHPHeater`.)
2. Read HARES — how does `resolve_hvac.rs` distinguish mini-split from ducted ASHP?
   - Is it the `DistributionSystemType` or `HeatPumpType`?
   - Does mini-split skip duct params?
3. Verify DSE=1 for mini-splits.
4. Check speed count: OCHRE infers 4 speeds for MSHP. Does HARES?
5. Build comparison table.

### Defects found

**DEFECT-1 (High) — Mini-split does not guarantee 4 speeds when CompressorType is absent or not "variable speed"**

`resolve_hvac.rs:447-451`: HARES calls `insert_mode_and_speed_metadata` with whatever CompressorType the HPXML contains, then falls back to SEER-based inference. OCHRE `hpxml.py:867-868` unconditionally sets `number_of_speeds = 4` when `name == "mini-split"`, overriding everything.

Consequence: a mini-split HPXML entry with no `<CompressorType>` element and only `AnnualHeatingEfficiency` (HSPF) — which is legal and common in ResStock — gets `number_of_speeds = 1` from the SEER fallback (SEER defaults to 0.0, which is ≤15 → single speed). The equipment will be initialised as `MultiSpeedInterpolated` (line 388 of `heater.rs`) with only 1 stage, which is physically wrong and differs from OCHRE.

Fix: add a branch in `resolve_hvac.rs` after `insert_mode_and_speed_metadata` that forces `number_of_speeds = 4` and `speed_control_mode = "variable_speed"` when `heat_pump_type == "mini-split"`.

**DEFECT-2 (Medium) — Soft ER lockout is not time-bounded; OCHRE has a configurable `Backup Soft Lockout Time`**

OCHRE `HVAC.py:1216`: soft lockout persists until `er_lockout_time >= er_soft_lockout_time` (configurable, defaults to equal to hard lockout time). HARES `heater.rs:884-896` implements soft lockout as a pure zone-temperature-rising check with no configurable duration — it can persist indefinitely while the zone is heating. This is a behavioural divergence that is not parameterised, so it cannot be corrected by HPXML wiring alone. It requires a `er_soft_lockout_time_s` field and updated logic.

**DEFECT-3 (Medium) — PLF quadratic for single-speed high-HSPF heat pump not overridden**

OCHRE `HVAC.py:1124-1126`: `HeatPumpHeater.__init__` checks `n_speeds == 1 and hspf >= 7` and sets `biquad_params[1]["eir_plf"] = [0.89, 0.11, 0]`. This tightens the PLF curve for efficient single-speed heat pumps. HARES has no equivalent override; it uses a single Cd-based formula across all single-speed heat pumps regardless of HSPF. This affects single-speed ducted ASHPs too, but the ticket scope is mini-split. In practice most MSHP are variable speed (DEFECT-1), so this will rarely be triggered, but it is a systematic correctness gap.

**GAP-1 (Low) — `er_hard_lockout_time_s` not extracted from HPXML**

OCHRE reads `Backup Lockout Time (minutes)` from the equipment kwargs; there is no corresponding extraction in `resolve_hvac.rs`. HARES defaults to 0 s which matches the OCHRE default (0 minutes), so behaviour is identical in typical ResStock files. However, files that specify this field will silently ignore it.

**GAP-2 (Low) — `min_er_cycle_time_s` not wired from HPXML**

OCHRE reads `Minimum Backup On Time (minutes)` (default 0). HARES `heater.rs:457-458` defaults to `DEFAULT_MIN_ER_CYCLE_TIME_S = 300 s`. OCHRE default is 0. This means HARES ER cycle guard is more restrictive than OCHRE by default when the HPXML does not specify the field. Not extractable from HPXML currently, but the default mismatch is a latent parity gap.

**GAP-3 (Low) — `min_time_per_speed_s` default mismatch vs OCHRE `min_time_in_speed`**

OCHRE `HVAC.py:759-761`: default is 5 minutes per speed. HARES defaults to 300 s (5 minutes) in `hvac_core.rs:286` — this matches. Neither side extracts it from HPXML, so the parity is adequate. No action needed, but confirms the field is not HPXML-addressable in either system.


## Recommended Tests

1. **`resolve_hvac_mshp_forces_4_speeds_no_compressor_type`** — Parse a synthetic mini-split HeatPump HPXML node with no `<CompressorType>` element and HSPF=10 (no SEER). Assert `number_of_speeds == 4` and `speed_control_mode == "variable_speed"` in the output params. This exercises the DEFECT-1 fix.

2. **`resolve_hvac_mshp_forces_4_speeds_override_single_stage_compressor_type`** — Parse a mini-split with `<CompressorType>single stage</CompressorType>`. Assert the result still yields `number_of_speeds == 4`, not 1. This guards against a compressor-type value in HPXML incorrectly downgrading the mini-split to single speed.

3. **`resolve_hvac_ashp_respects_compressor_type`** — Parse an air-to-air (non-mini-split) with `<CompressorType>single stage</CompressorType>`. Assert `number_of_speeds == 1`. Ensures the MSHP override is not applied to ducted ASHPs.

4. **`mshp_heater_uses_multi_speed_interpolated_when_4_stages_loaded`** — Construct a `MinisplitHeater` with 4-stage capacity and EIR vectors loaded from config. After `init()`, assert `speed_control_mode == SpeedControlMode::MultiSpeedInterpolated` and that `heating_capacities_w.len() == 4`.

5. **`mshp_heater_duct_dse_is_1`** — After `init()` on a `MinisplitHeater`, assert `hvac.duct_dse == 1.0` regardless of what duct params (if any) are present in config.

6. **`mshp_heater_pan_heater_fires_below_0c`** — Step a `MinisplitHeater` at OAT -5 °C, mode Off, and assert reported electric power includes 0.150 kW pan heater contribution. Step at OAT +5 °C and assert no pan heater contribution.

7. **`mshp_heater_er_hard_lockout_is_honoured_when_configured`** — Configure `er_hard_lockout_time_s = 600` and raise the setpoint by 2 °C. Assert ER is blocked for exactly 600 s of simulation time, then permitted. Verifies GAP-1 behaviour once the HPXML extraction is added.

8. **`mshp_heater_single_speed_fallback_when_n1_stages`** — If a mini-split has only 1 speed stage in the multispeed lookup (edge case), verify `remap_minisplit_stages` returns the single value without index-out-of-bounds, and that `reconcile_stage_lengths` does not error.
