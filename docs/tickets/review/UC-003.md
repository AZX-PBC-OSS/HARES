## Background/Context

HPXML duct fields include: `DuctLeakageMeasurement` (CFM25 or % of airflow),
`DuctSurfaceArea` (ft²), `DuctInsulationRValue` (ft²·°F·hr/BTU). These must be
converted to SI for the ASHRAE 152 DSE calculation. Errors here directly affect
duct loss estimates.

## Investigation Instructions

1. **Read `resolve_hvac.rs` duct parsing section:**
   - How are supply/return leakage values parsed? CFM25 → what unit?
   - Leakage percentage — is it stored as fraction (0–1) or percent (0–100)?
   - Duct surface area — ft² → m² conversion applied?
   - Duct R-value — ft²·°F·hr/BTU → m²·K/W conversion applied?
     (Factor: 1 ft²·°F·hr/BTU = 0.17611 m²·K/W)

2. **Read `crates/hares-physics/src/ashrae152.rs`:**
   - What units does the ASHRAE 152 calculation expect for inputs?
   - Does it expect SI or imperial? If imperial, conversions in resolve_hvac.rs
     may be wrong (converting too early or not at all).

3. **Compare with OCHRE:**
   - Read `hpxml.py` duct parsing — what units does OCHRE store duct params in?
   - Read `equipment.py` `calculate_duct_dse()` — what units does it expect?
   - Note: OCHRE may keep some duct values in imperial for the ASHRAE 152 calc.

4. **Write findings** with per-field conversion table.

**Summary for questions 1–6:**

1. **CFM25 vs Percent — HARES does NOT handle CFM25.** The HPXML 4.x structure places leakage under `<DuctLeakageMeasurement>/<DuctLeakage>/<Value>` alongside a `<Units>` child. HARES searches for `<DuctLeakage>` as a descendant of each `<Ducts>` node (`building.rs:1496`), but in the HPXML 4.x format `<DuctLeakageMeasurement>` is a **sibling** of `<Ducts>` under `<AirDistribution>`, not a child. Consequently `first_descendant("DuctLeakage")` always returns `None` for parity-fixture XMLs and leakage silently defaults to `0.0`. This is a critical correctness defect affecting all parity cases.

   Even if the element were found, `text_as_f64()` is called on the `<DuctLeakage>` node itself, whose text content is empty — the numeric value is in a `<Value>` child. The parser would need `duct_leakage_node.child("Value").and_then(text_as_f64)` and must also check `<Units>` to detect CFM25 vs Percent and reject or convert accordingly. OCHRE asserts `Units == "Percent"` (or value == 0); HARES has no such guard.

2. **Surface area ft²→m² conversion is correct.** `DuctSurfaceArea` in HPXML carries no `units` attribute in practice (only a `dataSource` attribute). The `convert_area_to_m2` `None` branch defaults to `area_ft2_to_m2()`. The test at `building.rs:2102-2110` validates this for `DuctInsulationRValue` conversion; a parallel assertion for surface area is absent but the code path is correct.

3. **R-value IP→SI conversion is correct.** `parse_value_with_units(..., ValueKind::RValue)` with no units attribute calls `r_value_ip_to_si()` (via `uom`). 1 IP R = 0.17611 m²·K/W; R-8 IP → 1.4089 m²·K/W, verified by test at line 2107. The ASHRAE 152 function then converts back to IP internally using `SI_R_TO_IP_R = 5.67826` — a round-trip that is numerically sound.

4. **ASHRAE 152 calculation expects SI inputs, converts to IP internally.** The `DuctDseInput` struct documents all fields as SI (`building.rs` and `ashrae152.rs:47`). The first section of `calculate_dse()` converts all dimensional inputs to IP before applying the ASHRAE 152 formulas. This is the correct architecture.

5. **HARES keeps no values in IP for ASHRAE 152.** All stored struct fields are SI. IP conversion is isolated to `ashrae152.rs:339-345`. This is correct.

6. **Per-field conversion table** — see table above.

### Additional defect: `convert_r_to_m2_k_w` with explicit `hr-ft2-f/btu` units branch

`building.rs:1670-1683`: when a `units` attribute IS present and matches the SI string pattern (anything other than IP or the known IP strings), the value passes through unchanged. If an HPXML file were to explicitly mark `units="hr-ft2-f/btu"`, the conversion fires. If it marks `units="m2*k/w"` (SI), it passes through — which is correct. However there is no guard against an unknown-but-non-SI units string silently passing as SI; this is a pre-existing issue outside scope.

### `SI_R_TO_IP_R` constant accuracy

`5.67826` vs exact `5.67826...` (derived from BTU(IT) definition). The value is consistent with the `uom`-derived `u_value_ip_to_si(1.0) ≈ 5.678` used in `units.rs`. The round-trip error is below 0.01%, acceptable for ASHRAE 152.

### `FLOOR_INS_THRESHOLD_M2_K_W` constant

`resolve_hvac.rs:144`: uses `5.3 / 5.678` (approximate denominator) rather than `5.3 / 5.67826`. The error is `< 0.0001 m²·K/W` — negligible for a threshold comparison.

## Recommended Tests

1. **`parse_duct_leakage_from_hpxml4x_measurement_element`** — Parse an HPXML 4.x fragment containing `<AirDistribution>` with `<DuctLeakageMeasurement>/<DuctLeakage>/<Units>Percent</Units>/<Value>0.06</Value>` siblings to supply/return `<Ducts>` elements. Assert `leakage_fraction == Some(0.06)` on both ducts. Currently fails (returns `None` / 0.0). Covers defect #1 and #2.

2. **`parse_duct_leakage_cfm25_is_rejected_or_converted`** — Parse a fragment with `<Units>CFM25</Units><Value>50.0</Value>`. Assert that the parser either returns an error or converts CFM25 using the fan-flow-normalised fraction before storing. This test documents the intended contract and will drive the fix for defect #3.

3. **`parse_duct_surface_area_ft2_to_m2`** — In the existing `parses_zones_boundaries_windows_and_ducts` test (or as a separate case), assert that `surface_area_m2` on the `DuctSystem` is approximately `324.0 * 0.092903 ≈ 30.11 m²` for a `<DuctSurfaceArea>324.0</DuctSurfaceArea>` element with no units attribute. Covers test gap #4.

4. **`parse_duct_r_value_no_units_defaults_ip`** — Already partially covered by the 1.4088 assertion in the existing test; expand to also assert that a `<DuctInsulationRValue units="hr-ft2-f/btu">8.0</DuctInsulationRValue>` (explicit IP units attr) produces the same result within tolerance, confirming both code paths in `convert_r_to_m2_k_w`.

5. **`ashrae152_dse_leakage_sensitivity`** — Unit test in `hares-physics`: call `calculate_dse` with supply/return `leakage_frac = 0.0` vs `0.06` and assert the zero-leakage case gives DSE closer to 1.0 (≥0.98 for typical R-8, attic-vented scenario). Ensures the DSE calculation is sensitive to leakage in the expected direction and would catch silent 0.0 fallback.

## Review Notes

**Critical gap**: HPXML `DuctLeakageMeasurement` can carry leakage in `Percent` (fraction 0-1) or `CFM25` (absolute flow). OCHRE asserts `Units == "Percent"`. HARES never reads a units attribute and never converts CFM25 to fraction. If HPXML supplies CFM25, HARES treats it as a fraction (e.g., 50 CFM25 → 50 × fan flow). OCHRE asserts `len(ducts) == 2`; HARES handles arbitrary numbers via area-weighted average.
