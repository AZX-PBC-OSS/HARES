## Background/Context

EA-003 covered distribution losses. This ticket audits the tank outlet temperature
model: how is delivery temperature computed from stratified nodes? Mixing valve logic?
Tempering valve? Unmet load when tank can't meet setpoint?

---

## How Outlet Temperature Is Computed

### OCHRE reference (Water.py)

OCHRE calls `update_water_draw()` **before** the state-space ODE step. Inside that
function:

1. `outlet_temp` is initialized to `states[t_1_idx]` — the current top-node temperature
   (Water.py:284).
2. Draw-volume reduction via mixing-valve ratio is computed using that same
   `outlet_temp` snapshot.
3. `_water_draw_general` (or `_water_draw_2node`) is called. For the multi-node path,
   if `draw_fraction >= min_vol_fraction`, the outlet is computed as a
   **volume-weighted average over the drawn segment** (Water.py:54-61). This means the
   outlet temperature can be lower than the top node whenever the draw volume spans more
   than the top node.
4. `outlet_temp` is **reassigned** to this computed value (may differ from the
   pre-step top-node temperature).
5. Unmet-load is computed from this **post-draw** `outlet_temp` at Water.py:363.

The `_water_draw_2node` fast-path (Water.py:79-104) also updates `outlet_temp` to a
volume-weighted blend of upper and lower nodes when `draw_fraction > vol_fractions[0]`.

### HARES implementation (tank.rs)

**`step()` (untempered)**:

- Pre-step top-node temperature is captured as `pre_step_outlet_temp_c` (line 320).
- `apply_conduction_and_standby` → `apply_heat_injections` → `apply_draw` run in
  order.
- `apply_draw` (line 585) records `outlet_temp_c = node_temps_c[0]` at call-time
  (post-heating, pre-draw) as an intermediate return value.
- The returned `DrawResult.outlet_temp_c` is **overwritten** with `pre_step_outlet_temp_c`
  (line 330) — the top-node temp from before heating.
- `unmet_load_w` is hard-wired to 0.0 (line 332) — correct for untempered draws.

**`step_tempered()` (TMV path)**:

- `outlet_est_c = node_temps_c[0]` snapshot taken pre-step (line 361).
- Mixing-valve volume-reduction uses `outlet_est_c` (lines 365-389) — matches OCHRE.
- After `apply_draw`, `DrawResult.outlet_temp_c` is overwritten with `outlet_est_c`
  (line 400) — the pre-step top-node value.
- Unmet-load at line 408 is computed using `draw.outlet_temp_c`, which is the
  **pre-step top-node snapshot**, not a segment-averaged or post-draw value.

## Findings

### FINDING 1 — MEDIUM: `step_tempered` is dead code — no WH calls it

`step_tempered` is public and implemented, but no production WH equipment calls it.
`ResistanceWH`, `GasWH`, and `HeatPumpWH` all invoke `tank.step()` only.
Tempered / mixing-valve draw reduction therefore **never activates** in production.

The TMV logic (volume ratio reduction when tank is above delivery setpoint) and the
resulting unmet-load reporting are entirely bypassed. For tanks running above the
fixture delivery setpoint (the common case — setpoint ~52°C, delivery target ~40.6°C),
the raw hot-water draw volume is always used without blending, overestimating the
volumetric draw from the tank.

**Impact**: Hot-water draw mass and energy throughput is overstated by factor
`(outlet_est_c - mains_temp_c) / (tempered_draw_temp_c - mains_temp_c)` whenever
tank temperature exceeds fixture setpoint. For a 52°C tank, 15°C mains, and 40.6°C
fixture target, the overstatement factor is approximately 1.46× for all fixture draws.
`unmet_load_w` is always zero for `ResistanceWH` and `GasWH`.

**Fix**: Each storage WH `step()` implementation must resolve tempered and hot draw
flow rates separately, then call `step_tempered()` with the appropriate
`TemperedDrawConfig` rather than `step()` with a single aggregate volume.

---

### FINDING 2 — MEDIUM: Outlet temperature uses pre-step top-node snapshot, not
segment-averaged post-draw value

In both `step()` and `step_tempered()`, `DrawResult.outlet_temp_c` is overwritten with
the top-node temperature captured **before** the draw occurs. In OCHRE,
`update_water_draw()` recomputes the outlet as a volume-weighted average across the
drawn segment (Water.py:54-61). These differ whenever the draw volume is larger than
the top node volume, which is normal for multi-node tanks with 12 equal-volume nodes
(each ≈ 1.6 L) against typical 2–4 L/min fixture draws over a 60 s step (2–4 L total).

For the common case where the draw volume fits inside the top node, both methods agree.
For larger draws the HARES outlet is the pre-step top-node temperature; OCHRE's is
cooler (blended with lower nodes). This means HARES reports a warmer outlet than
physically occurs and misreports unmet-load accordingly.

**Note**: OCHRE's multi-node draw routine also updates node temperatures in-place as
heat-exchange terms fed into the state-space ODE (Water.py:64-73), whereas HARES
computes node temperatures in `apply_draw` with a simpler volume-displacement shift.
The approaches are architecturally different but both conserve energy; the primary
behavioral difference is the reported `outlet_temp_c`.

---

### FINDING 3 — LOW: HPWH tempering valve applies a simple min-clamp, not a
mixing-valve energy correction

`heat_pump_wh.rs:809-811` implements the tempering valve as:

```rust
let delivery_temp_c = match self.tempering_valve_setpoint_c {
    Some(valve_sp) => draw.outlet_temp_c.min(valve_sp),
    None => draw.outlet_temp_c,
};
```

This caps the reported delivery temperature but does not correct the flow rate or
energy delivered. A real tempering valve blends cold mains water into the hot stream,
reducing the hot-side draw volume needed (exactly the TMV ratio computed in
`step_tempered()`). Using `min()` without adjusting `flow_rate_kg_s` or
`draw_volume_m3` means the tank is still drained at full hot-water flow even when the
valve would have reduced it. The `draw.outlet_temp_c` used for `unmet_load_w` in HPWH
is the pre-step snapshot from `tank.step()` (always 0.0 for unmet load from the
`step()` path), making unmet-load reporting for HPWH inoperative.

**Fix**: HPWH should also use `step_tempered()` once Finding 1 is resolved, which will
make the tempering valve logic consistent with the mixing valve logic and enable
unmet-load reporting.

---

### FINDING 4 — LOW: OCHRE 2-node fast path (empirical flow_fraction=0.95) has no
equivalent in HARES

OCHRE's `_water_draw_2node` (Water.py:79-104) uses an empirical factor of 0.95 to
partition heat between the two nodes when the draw fraction is less than the lower
node volume fraction. HARES `apply_draw` uses the same volume-displacement algorithm
regardless of node count. This is an OCHRE-specific empirical correction for 2-node
models validated against lab data; it is not a physics requirement and HARES is not
obligated to replicate it. No action required unless 2-node parity with OCHRE is
specifically targeted.

---

### FINDING 5 — LOW: No overflow guard on unmet-load computation when mains ~= outlet

In `step_tempered()` at line 371, the denominator guard is `max(1e-9)`:

```rust
(tmv.hot_draw_temp_c - mains_temp_c) / (outlet_est_c - mains_temp_c).max(1e-9)
```

When mains temperature equals outlet temperature (e.g. a cold, depleted tank), the
denominator clamps to 1e-9 and the ratio could be very large. The subsequent
`.clamp(0.0, 1.0)` prevents a volume explosion, so this is benign. However, the
same guard is used at line 383-384 for the fixture draw ratio; if `outlet_est_c < mains_temp_c`
(physically impossible during normal operation but possible during initialization or
abnormal states), the ratio goes negative and `.clamp(0.0, 1.0)` clamps it to 0.0,
silently producing no fixture draw. This should be guarded with a warning or assertion.

## Recommended Tests

1. **TMV volume reduction**: construct a `StratifiedTank` at 55°C with 15°C mains,
   call `step_tempered()` with `tempered_draw_temp_c=40.6`, verify that the actual
   draw volume is reduced by the expected `(40.6-15)/(55-15) = 0.64` ratio.

2. **Outlet temp blending**: with a 12-node tank at 55°C upper / 20°C lower, draw
   a volume exceeding the top node; verify `outlet_temp_c` reflects the blended
   value, not the pre-draw top-node temperature.

3. **Unmet-load non-zero**: call `step_tempered()` with outlet below fixture setpoint;
   assert `unmet_load_w > 0`.

4. **ResistanceWH uses step_tempered**: integration test asserting that when
   `draw_flow_rate_kg_s > 0` and tank > delivery setpoint, the tempered draw volume
   is less than the raw draw volume.
