## Background/Context

Ground temperature affects foundation/slab heat loss — the dominant heat loss path for
well-insulated homes. The Kusuda-Achenbach model uses annual mean air temp, amplitude,
and soil diffusivity. Wrong inputs or wrong formula → wrong foundation heat loss.

## Investigation Instructions

1. **Read HARES `ground.rs`:**
   - What model? Kusuda-Achenbach? What depth?
   - Formula: `T_ground = T_mean - T_amp * exp(-depth * sqrt(π/(α*period))) * cos(2π(t-t_shift)/period - depth * sqrt(π/(α*period)))`
   - What are the parameter values? Soil diffusivity α?

2. **Read HARES `environment.rs`:**
   - How are `ground_t_mean_c` and `ground_t_amplitude_c` derived?
   - Known issue: `ground_t_mean_c = mains_t_annual_avg_c` and
     `ground_t_amplitude_c = mains_dt_annual_range_c / 2.0`.
   - The mains annual range is already a half-amplitude? Or peak-to-peak?
     Dividing by 2 again gives quarter-amplitude — likely a bug.

3. **Read OCHRE ground temperature:**
   - How does OCHRE compute ground temperature?
   - Does it use weather data or a separate ground model?
   - What depth does it assume?

4. **Compare for a reference location:**
   - Denver: T_mean ≈ 10°C, T_amp ≈ 12°C at surface, ~3°C at 2m depth.
   - What does HARES compute? What does OCHRE compute?

5. **Check slab/foundation coupling:**
   - Is ground temperature used as the boundary condition for slab RC nodes?
   - Or is it used as a fixed temperature source?
   - How does this differ from OCHRE?

## Findings

### Finding 1 — ACCEPTABLE DIFFERENCE: Kusuda-Achenbach formula is correct

`crates/hares-physics/src/ground.rs` implements the Kusuda-Achenbach formula exactly:

```
T(z,t) = T_mean - T_amp × exp(-z × √(π/(α×τ))) × cos(2π(t-θ)/τ - z × √(π/(α×τ)))
```

Parameters match EnergyPlus Engineering Reference Ch. 3.17:
- `τ = 365.0` days
- `α = 0.05 m²/day` (DEFAULT_SOIL_DIFFUSIVITY_M2_PER_DAY) — documented as moist soil
- Phase θ = 35.0 days northern hemisphere (day of minimum surface temperature)

The formula is algebraically correct. The `decay` factor is computed once and reused for
both the attenuation exponent and the phase argument, which is the correct implementation
of the standard form.

### Finding 2 — ACCEPTABLE DIFFERENCE: `ground_t_amplitude_c` division is correct, not a double-divide bug

The ticket identified a suspected double-divide:

```rust
// environment.rs:220
ground_t_amplitude_c: mains_dt_annual_range_c / 2.0,
```

`mains_dt_annual_range_c` is computed in `compute_mains_inputs()` as:

```rust
let monthly_range_c = simple_range(&month_means);  // = max(monthly_means) - min(monthly_means)
```

`simple_range` returns the **full peak-to-peak** range of monthly averages. The
Kusuda-Achenbach `t_amplitude_c` parameter is defined as *half* of that range (the
half-amplitude). The `/ 2.0` is therefore correct and necessary.

Note: the DOE-2 fallback in `epw.rs` (`doe2_ground_temp_from_monthly_avg`) independently
computes `dt_monthly = (t_max - t_min) / 2.0` for the same reason — both are consistent.

There is no double-divide bug.

### Finding 3 — BUG: `ground_temp_at_depth_c()` is never called by the thermal solver

`EnvironmentManager` stores `ground_t_mean_c`, `ground_t_amplitude_c`, and
`ground_phase_day` and exposes the public method `ground_temp_at_depth_c()`. However,
**no code in the thermal solver or dwelling engine calls this method**. The thermal solver
reads `env.weather.ground_temp_c` exclusively:

```rust
// thermal_solver/mod.rs:501
u[idx] = env.weather.ground_temp_c;

// thermal_solver/initialization.rs:30
u[idx] = env.weather.ground_temp_c;

// thermal_solver/longwave.rs:190
super::config::DrivingTemp::Ground => env.weather.ground_temp_c,
```

`env.weather.ground_temp_c` is populated from the EPW GROUND TEMPERATURES header
(shallowest available depth, typically 0.5 m) or the DOE-2 fallback sinusoid at a fixed
10 m effective depth (`DOE2_GROUND_DEPTH_FACTOR = 10.0`). The Kusuda-Achenbach model and
all the parameters stored on `EnvironmentManager` are dead code with respect to the actual
simulation.

Effect: the Kusuda-Achenbach depth is never applied. The depth passed to the RC solver
always comes from whichever EPW depth entry was shallowest, regardless of the actual slab
foundation depth. For EPW files that include a GROUND TEMPERATURES section, this is
typically 0.5 m; for the DOE-2 fallback the effective depth is 10 m. The two code paths
produce substantially different ground temperatures and neither is depth-aware at
simulation time.

Files:
- `crates/hares-core/src/environment.rs:305` — `ground_temp_at_depth_c()` defined but never called internally
- `crates/hares-core/src/environment.rs:548` — EPW/DOE-2 path used by all callers
- `crates/hares-envelope/src/thermal_solver/mod.rs:499-503` — reads `env.weather.ground_temp_c`

### Finding 4 — GAP: Two independent ground temperature paths are not reconciled

HARES has two parallel ground temperature implementations:

**Path A** — EPW/DOE-2 (what the simulation actually uses):
- Populated at parse time from the EPW GROUND TEMPERATURES header (monthly values,
  shallowest depth) or DOE-2 damped sinusoid fallback.
- Stored in `WeatherTimeSeries.ground_temp_c`.
- Used by the thermal solver, longwave solver, and initialization as the slab boundary.
- Depth: whatever the EPW header specifies (typically 0.5 m) or DOE-2 10 m effective depth.

**Path B** — Kusuda-Achenbach (unused by simulation):
- Parameters derived from `mains_dt_annual_range_c` and stored on `EnvironmentManager`.
- Accessible via `ground_temp_at_depth_c(depth_m, day_of_year)`.
- Never called internally; currently a public API with no internal consumer.

The architecture implies that Path B was intended to replace or supplement Path A for
foundation coupling, but the wiring was never completed. Callers that need depth-specific
ground temperature (e.g. for basement walls at 1.5 m or slab at 0.5 m) must manually call
`ground_temp_at_depth_c()`, but neither the thermal solver nor any envelope code does so.

### Finding 5 — GAP: OCHRE uses a different model (DOE-2 GTEMP, not Kusuda-Achenbach)

OCHRE (`ochre/utils/schedule.py:243-255`) uses the DOE-2 GTEMP correlation:

```python
beta = (np.pi / (8760 * 0.025)) ** 0.5 * 10   # α=0.025 m²/h, depth=10 m
x = np.exp(-beta)
gm = sqrt((x² - 2x·cos(β) + 1) / (2β²))
z = (1 - x(cos β + sin β)) / (1 - x(cos β - sin β))
T_ground = T_avg - ΔT_monthly × gm × cos(2π/365 × mday - 0.6 - atan(z))
```

Key differences from HARES:
- `α = 0.025 m²/h = 0.6 m²/day` vs HARES Kusuda α = 0.05 m²/day
- Implicit depth 10 m hardcoded in `beta`; HARES Kusuda accepts variable depth
- OCHRE indexes to mid-month ordinal (`mday`); HARES uses actual day-of-year
- OCHRE does not vary by depth at simulation time — it produces monthly ground temps
  which are then interpolated hourly and stored in the schedule

The HARES EPW fallback (`doe2_ground_temp_from_monthly_avg` in `epw.rs`) faithfully
replicates the OCHRE DOE-2 model including `α = 0.025`, `depth = 10`, and `phase = 0.6`.
So when an EPW file lacks a GROUND TEMPERATURES header, HARES is parity-correct with
OCHRE on this path.

### Finding 6 — GAP: Denver reference case numerical comparison

For Denver (Denver Intl Airport, TMY3), representative annual parameters:
- T_mean ≈ 10.0°C
- Monthly range (max monthly avg − min monthly avg) ≈ 24°C → half-amplitude ≈ 12°C

**OCHRE DOE-2 at implicit 10 m depth:**
- β ≈ (π/(8760×0.025))^0.5 × 10 ≈ 2.46
- gm ≈ 0.0034 (strongly damped at 10 m)
- Ground temp ≈ 10.0 ± 0.04°C (essentially constant at annual mean)

**HARES Kusuda-Achenbach at z=0 (surface, if the public method were used):**
- Amplitude = 12°C; ground temp oscillates ±12°C around mean
- At z=0.5 m, α=0.05 m²/day: decay ≈ 0.415 m⁻¹, attenuation = exp(-0.208) ≈ 0.81
- Ground temp ≈ 10.0 ± 9.7°C

**HARES EPW path (actual simulation behavior):**
- Reads from the EPW GROUND TEMPERATURES header at ~0.5 m or uses DOE-2 at 10 m.
- For TMY EPW files, the GROUND TEMPERATURES header typically lists depths 0.5/2/4 m
  computed by EnergyPlus from K-A parameters embedded in the file. HARES selects the
  shallowest, which gives reasonable amplitude (~9°C at 0.5 m).

The simulation output is correct only because it bypasses the Kusuda-Achenbach path
entirely and uses the EPW-embedded ground temperatures. The Kusuda-Achenbach
implementation is correct but orphaned.

### Finding 7 — GAP: Soil diffusivity mismatch between the two internal paths

`DEFAULT_SOIL_DIFFUSIVITY_M2_PER_DAY = 0.05 m²/day` (in `ground.rs`) and DOE-2
`DOE2_GROUND_DIFFUSIVITY = 0.025 m²/hour = 0.6 m²/day` (in `epw.rs`). These are
dimensionally different units and represent very different soil types (dry generic vs moist
mixed). The comment in `ground.rs` correctly documents this difference, but the
inconsistency is a future maintenance hazard if the Kusuda-Achenbach path is ever wired
into the simulation.

## Recommended Tests

### Test A — Amplitude parameter regression (hares-physics)
Add a test in `crates/hares-physics/src/ground.rs` that validates numerical output against
a published table entry from Kusuda & Achenbach (1965) or EnergyPlus reference docs for a
known location (e.g., Washington DC: T_mean=13.1°C, T_amp=12.0°C, α=0.0432 m²/day,
depth=1m). Confirm amplitude attenuation matches expected value within 1%.

### Test B — EPW vs Kusuda-Achenbach path equivalence (hares-core integration)
Add an integration test that runs a one-year simulation with a synthetic EPW that has a
GROUND TEMPERATURES header at a known depth, then calls `ground_temp_at_depth_c()` with
the same depth and parameters. The two paths should agree within 0.5°C at mid-month
sample points. This test will currently fail, exposing the wiring gap in Finding 3.

### Test C — DOE-2 fallback parity (hares-io)
Add a test in `crates/hares-io/src/epw.rs` (or its test module) that computes
`doe2_ground_temp_from_monthly_avg` with the same monthly averages used in the OCHRE
schedule test fixtures and compares output to OCHRE's computed ground temps to within
0.1°C. This verifies that the EPW fallback path stays parity-correct with OCHRE when
the EPW header is absent.

### Test D — `ground_temp_at_depth_c` with zero depth returns surface sinusoid
`ground_temp_at_depth_c(0.0, day)` should return `T_mean - T_amp * cos(2π(day-θ)/τ)`.
The existing unit test `kusuda_at_surface_matches_sinusoidal` in `ground.rs` already
covers this; it should be confirmed to be run in CI (it is, as a `#[test]` function).
No new test needed here.

### Test E — Depth-aware slab boundary (future, after wiring gap is fixed)
Once Finding 3 is resolved and the thermal solver calls `ground_temp_at_depth_c` with the
actual slab depth, add a thermal pathway test that verifies winter slab heat loss changes
by the expected ratio when depth is changed from 0.5 m to 2.0 m.
