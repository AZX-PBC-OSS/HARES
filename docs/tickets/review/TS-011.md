## Background/Context

Attic zones have unique thermal behavior: radiant barrier emissivity override, roof deck solar gain, and forced or natural ventilation. Existing TS tickets address foundation zones (TS-004) but not attic zones — this is an asymmetric gap. Attic heat gain is the dominant summer cooling load in many climates.

## Investigation Instructions

1. **Trace attic zone construction** from HPXML parsing through boundary assembly to thermal solver.
2. **Verify radiant barrier** emissivity (0.05 vs 0.90 default) is applied to correct surfaces.
3. **Check attic ventilation model:** Is attic air exchange with outdoor modeled? What ACH value?
4. **Compare with OCHRE's attic model.** Does OCHRE treat attic as a fully-modeled zone or a simplified buffer?
5. **Check roof deck solar gain path:** Does solar radiation on roof correctly heat the attic zone air?

## Findings

### F-1 (Severity: HIGH) — Silent fallback to 200 m³ volume when attic volume cannot be computed

**File:** `crates/hares-core/src/environment.rs:748`

```rust
volume_m3: zone.volume_m3.unwrap_or(DEFAULT_ZONE_VOLUME_M3),  // 200.0 m³
```

`compute_attic_volume` (`crates/hares-io/src/hpxml/building.rs:1847`) returns `None` when no gable wall or roof `<Pitch>` data exists in HPXML. The unit test `zones_have_correct_volumes` at line 2139 explicitly **asserts** `attic_vol.volume_m3.is_none()`, confirming this failure mode is exercised but not caught. When `None`, the zone volume falls through to `DEFAULT_ZONE_VOLUME_M3 = 200.0 m³`. For `InfiltrationMethod::Ach { ach: 2.0 }` (the vented-attic default), the infiltration flow is:

```
Q = 2.0 × 200.0 / 3600 = 0.111 m³/s
```

For a typical 140 m² single-story house the true attic volume (triangular prism, 1.5 m ridge height) is ~105 m³, giving Q = 0.058 m³/s — a 90% overestimate. For a larger 200 m² house with 2.0 m ridge, volume ~200 m³ exactly matches the fallback, so the error is geometry-dependent. No warning is emitted.

OCHRE never reaches this code path silently: `vendors/OCHRE/ochre/utils/hpxml.py:670` raises `OCHREException` when a vented attic lacks explicit ventilation data, forcing the user to supply `<VentilationRate>`.

### F-2 (Severity: HIGH) — Vented attic without `<VentilationRate>` silently defaults to 2.0 ACH; OCHRE raises an exception

**File:** `crates/hares-core/src/dwelling/solver_builder.rs:827-830`

```rust
} else if bz.vented {
    // Vented attic with no HPXML data: default 2.0 ACH
    InfiltrationMethod::Ach { ach: 2.0 }
```

OCHRE `hpxml.py:662-670` treats the absence of `VentilationRate` on a vented attic as an error. HARES silently uses 2.0 ACH. The ASHRAE 62.2 range for vented attics is 0.5–10 ACH depending on SLA and wind; a hardcoded 2.0 may be reasonable as a default but is unvalidated and should at minimum emit a diagnostic warning. This is a correctness divergence from the reference for any real-world HPXML file that omits the ventilation rate.

### F-3 (Severity: MEDIUM) — Radiant barrier applied only to `interior_zone == Attic`, not to `exterior_zone == Attic`

**File:** `crates/hares-core/src/dwelling/solver_builder.rs:203-204`

```rust
let is_attic_radiant_barrier = boundary.has_radiant_barrier
    && boundary.interior_zone.as_ref() == Some(&hares_io::hpxml::ZoneType::Attic);
```

OCHRE `Envelope.py:221-222` applies the override based on `self.zone_name == "Attic"` for **both** interior and exterior surfaces of a boundary — `zone_name` is the zone the surface "belongs to", which for a roof is `"Attic"` (the interior zone). HARES correctly checks `interior_zone == Attic` for the attic-facing surface, which is the primary case: the roof deck's interior surface faces the attic.

However, the same logic assigns `emissivity` and `solar_absorptance` to a single `SolverBoundary` that serves as **both** the exterior surface (`ExteriorSurfaceInfo`) and the attic-interior surface (in LWR). The `ExteriorSurfaceInfo.absorptance` (roof deck exterior absorptance — what the sun sees from above) picks up the same `solar_absorptance = 0.05` from the radiant-barrier path when `interior_zone == Attic`. This is wrong: the exterior (outdoor-facing) surface of a roof does not have radiant barrier properties; the radiant barrier is on the *underside* (attic-side). The exterior roof absorptance should remain at 0.60 regardless of whether an attic radiant barrier is present. This causes solar gain into the roof deck to be underestimated by ~12× in the presence of a radiant barrier.

OCHRE avoids this: it creates separate `Surface` objects for the exterior and interior sides of each boundary, and the `zone_name` check applies only to the attic-side (interior) surface.

### F-4 (Severity: MEDIUM) — Attic zone excluded from interior LWR distribution

**File:** `crates/hares-core/src/dwelling/solver_builder.rs:614-615`

```rust
} else {
    sb.is_conditioned_interior && sb.area_m2 > 0.0
};
```

Interior LWR distribution is restricted to surfaces where `is_conditioned_interior = true`, which requires `interior_zone == Conditioned`. Attic-interior surfaces (e.g. the underside of the roof deck, interior face of gable walls) have `interior_zone == Attic`, not `Conditioned`, so they are excluded from the zone's interior LWR loop. This means no interior longwave exchange is computed between the roof deck underside, attic floor, and gable walls within the attic zone. In OCHRE, the attic zone has its own `Zone` object with its own interior LWR calculation. The effect is that absorbed solar diffusing into the attic air node via the RC network is correct (conduction path), but inter-surface longwave within the attic is missing. This can matter significantly for radiant barrier effectiveness, which works by reducing interior LWR to the ceiling surface.

### F-6 (Severity: LOW) — Attic zone temperature oracle tolerance is 50% (very wide)

**File:** `tests/envelope_oracle.rs:471`

```rust

```

The oracle check for `"Temperature - Attic (C)"` uses a 50% tolerance band. The comment acknowledges this is deliberately loose. With F-1, F-3, F-4 in play, this wide tolerance masks real errors. The oracle is currently insufficient to detect the mis-routing of radiant barrier absorptance or missing attic LWR.

### Summary: Attic Zone Tracing

1. **HPXML parsing** (`crates/hares-io/src/hpxml/building.rs`): `<Attic>` node parsed into `Zone { zone_type: Attic, vented, ventilation_ach, ventilation_sla }`. Volume computed by `compute_attic_volume` via triangular prism formula from gable area and pitch.

2. **Boundary assembly** (`crates/hares-core/src/dwelling/solver_builder.rs`): Each boundary with `exterior_zone == Outdoor` is flagged `is_exterior = true` (roof deck solar goes here). Each boundary with `interior_zone == Conditioned` is flagged `is_conditioned_interior = true` (interior LWR/solar distribution). Attic-zone boundaries are neither, so they participate only in the RC conduction path.

3. **Thermal solver**: Attic zone gets its own `ZoneState` with an air node in the RC state vector. Infiltration with outdoor air is applied via `InfiltrationMethod` in the coupling loop. No interior LWR loop for the attic zone.

4. **Solar**: Roof deck exterior absorbs solar via `apply_exterior_solar_inputs` → outer RC node state → conducts through layers → attic air node heated by conduction. There is no separate solar distribution pass for the attic zone.

5. **Comparison with OCHRE**: OCHRE models the attic as a fully-resolved zone with its own interior LWR and solar distribution. HARES models the attic as an intermediate RC node zone (conduction-only interior, infiltration with outdoor, no interior LWR). This is a structural simplification that is likely acceptable for conditioned-zone heating/cooling loads but will produce incorrect attic temperatures and incorrect radiant barrier effectiveness.

## Recommended Tests

1. **Radiant barrier exterior absorptance regression**: Create a `Boundary` with `has_radiant_barrier = true`, `interior_zone = Attic`, `exterior_zone = Outdoor`. Assert that `ExteriorSurfaceInfo.absorptance == SOLAR_ABSORPTANCE_DEFAULT (0.60)` — not 0.05. Currently this test would fail, confirming F-3.

2. **Attic volume fallback diagnostic**: Construct a building with an attic zone whose `compute_attic_volume` returns `None` (no pitch/gable data). Assert that a diagnostic warning is emitted and the fallback to `DEFAULT_ZONE_VOLUME_M3` is logged.

3. **Vented attic infiltration diagnostic**: Load HPXML with a `<AtticType><Attic><Vented>true</Vented>` but no `<VentilationRate>`. Assert that the solver builder emits a warning (`tracing::warn!` or equivalent) identifying the fallback to 2.0 ACH.

4. **Attic temperature with known geometry**: Build a synthetic two-zone (conditioned + attic) model with known roof area, R-value, attic volume, and ACH. Apply a fixed outdoor temperature, zero solar. Verify attic steady-state temperature analytically: `T_attic = (UA_roof × T_out + UA_ceiling × T_in + m_inf × cp × T_out) / (UA_roof + UA_ceiling + m_inf × cp)`.

5. **Radiant barrier reduces attic solar gain**: Run two otherwise-identical dwellings with and without `has_radiant_barrier`. Assert that attic temperatures diverge significantly under strong solar input, and that the radiant-barrier case shows lower attic temperature (not higher, as the current F-3 bug would cause).
