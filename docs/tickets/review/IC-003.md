## Background/Context

OCHRE clips ideal capacity to `[capacity_min, capacity_max * ext_capacity_frac]`.
If the required capacity exceeds the maximum, the setpoint cannot be met — this is
how OCHRE reports unmet loads. If HARES doesn't clip, it may report infinite capacity
or fail to detect unmet loads.

## Investigation Instructions

1. **Read OCHRE** — where is capacity clipped? What are the bounds?
2. **Read HARES** — is ideal capacity clipped anywhere?
   - In `ideal_hvac.rs`?
   - In `hvac_core.rs`?
   - In the thermal solver's `solve_ideal_capacity_for_target()`?
3. **Check for `ext_capacity_frac`** — does HARES have this concept? (See WO-003)
4. **Document** whether unmet loads are detectable in HARES.


## Findings

### 1. OCHRE capacity clipping contract (reference)

`HVAC.update_capacity()` (`vendors/OCHRE/ochre/Equipment/HVAC.py:431-452`) applies:

```
if capacity < capacity_min:        # force off (includes negative values)
    capacity = 0
elif capacity > capacity_max * ext_capacity_frac:
    capacity = capacity_max * ext_capacity_frac   # clip; note: setpoint won't be met
```

- `capacity_min` defaults to 0 W (configurable via `"Minimum Capacity (W)"`).
- `capacity_max` is the biquadratic-adjusted maximum for the current outdoor conditions.
- `ext_capacity_frac` (default 1.0) is an external control multiplier (e.g. DR signal).
- When clipped at `capacity_max`, OCHRE logs the note "setpoint won't be met" — this is how unmet load propagates to the thermal zone.
- OCHRE's `capacity_ideal` field always retains the raw unconstrained solve value; the clamped value goes into `capacity` which is what actually drives the zone.

### 2. HARES `IdealHvac` — ideal path (`use_ideal_cached = true`)

File: `crates/hares-equipment/src/hvac/ideal_hvac.rs:403-417`

```rust
ThermostatMode::Heating if self.use_ideal_cached => {
    (self.ideal_capacity_w * self.load_fraction).max(0.0)
}
ThermostatMode::Cooling if self.use_ideal_cached => {
    (self.ideal_capacity_w * self.load_fraction).min(0.0)
}
```

The only clamping applied here is sign-correction (prevent heating mode from delivering cooling and vice versa). **There is no upper bound clip against `rated_capacity_w` or `cooling_capacity_w` on the ideal path.** If the solver computes a value exceeding the rated capacity, the full unconstrained value is delivered to the zone.

This means `IdealHvac` in ideal mode has effectively unbounded capacity — a 10 kW unit will silently deliver 50 kW if that is what the solver says is needed.

### 3. HARES `IdealHvac` — dynamic (non-ideal) path

```rust
ThermostatMode::Heating => self.rated_capacity_w * self.load_fraction,
ThermostatMode::Cooling => -self.cooling_capacity_w * self.load_fraction,
```

The dynamic path correctly clamps to rated capacity. This is the physically correct behaviour but it is only reached when `use_ideal_cached = false` (time_res < 5 min and non-variable-speed, or `IdealCapacityMode::Off`).

### 4. No `capacity_min` / minimum capacity concept in `IdealHvac`

OCHRE forces the unit off when `capacity < capacity_min`. HARES has no equivalent. If the solver returns a very small positive value for heating, `IdealHvac` will deliver it even if the physical equipment has a minimum modulation threshold. For equipment such as ASHP with a compressor minimum speed, this can produce unrealistic continuous low-level output.

### 5. No `ext_capacity_frac` / max-capacity-fraction control path

OCHRE supports an external demand-response signal that reduces `capacity_max` by a fraction. HARES has `ControlSignal::LoadFraction` which is applied as a multiplier on whichever branch is taken, but `LoadFraction` is already clamped to `[0.0, 1.0]` at line 531, so it can only reduce output, never act as an explicit capacity cap. However, it does not expose the OCHRE semantics of "what fraction of rated capacity is the maximum allowed this timestep" as a distinct concept. This is a minor API gap rather than a correctness bug.

### 6. Unmet-load detection

Unmet-load tracking lives in `crates/hares-io/src/output/metrics.rs`. It operates post-hoc by comparing the `"HVAC Heating Delivered (W)"` and `"HVAC Heating Capacity (W)"` output columns.

**`IdealHvac` never emits `"HVAC Heating Capacity (W)"` or `"HVAC Cooling Capacity (W)"`.**

`ideal_hvac_default_telemetry()` at line 561-567 only inserts `thermal_output_w`, `operating_mode`, `ideal_capacity_w`, and `current_target_c`. There is no capacity-ceiling column.

As a result, `discover_hvac_capacity_pairs()` (`metrics.rs:857`) finds no pairs for dwellings running `IdealHvac`, and `unmet_load_hours` is always `None` (or never incremented) for those simulations regardless of how much the zone deviates from setpoint.

### 7. Summary of gaps

| OCHRE behaviour | HARES `IdealHvac` status |
|---|---|
| Clip ideal capacity at `capacity_max` | Missing — ideal path is unbounded above |
| Force off when capacity < `capacity_min` | Missing — no minimum capacity concept |
| `ext_capacity_frac` DR control | Partially covered by `LoadFraction`; no named max-capacity-fraction signal |
| Emit capacity ceiling column for unmet-load detection | Missing — `IdealHvac` emits no `HVAC Heating/Cooling Capacity (W)` column |
| Raw ideal solve value preserved separately | Preserved in `ideal_capacity_w` telemetry (correct) |

### 8. Severity

- **Missing upper bound clip (finding 2)**: HIGH. A 10 kW unit silently delivering 50 kW corrupts energy balance and thermal parity tests, and makes the simulation non-physical.
- **Missing capacity column for unmet-load (finding 6)**: HIGH. `unmet_load_hours` metric is silently zeroed for all ideal-HVAC dwellings; consumers relying on this metric receive incorrect data.
- **Missing `capacity_min` (finding 4)**: MEDIUM. Affects modulation-limited equipment (ASHP, mini-split) at coarse timesteps.

## Recommended Tests

All tests belong in `crates/hares-equipment/src/hvac/ideal_hvac.rs` unless noted.

**T1 — ideal heating is clipped at `rated_capacity_w`**
- Configure `IdealHvac` with `capacity_w = 10_000`, `ideal_capacity_mode = "on"`.
- Inject `ControlSignal::IdealCapacity { capacity_w: 50_000.0 }`.
- Call `step()` and assert `thermal_output_w <= 10_000.0`.
- Currently fails (expected to fail until fix is applied).

**T2 — ideal cooling is clipped at `cooling_capacity_w`**
- Configure `IdealHvac` with `cooling_capacity_w = 8_000`, `ideal_capacity_mode = "on"`.
- Inject `ControlSignal::IdealCapacity { capacity_w: -40_000.0 }` in cooling mode.
- Call `step()` and assert `thermal_output_w >= -8_000.0` (magnitude no larger than rated).
- Currently fails.

**T3 — ideal capacity below zero in heating mode is clamped to zero (existing behaviour, regression guard)**
- Inject negative `ideal_capacity_w` while in heating mode.
- Assert `thermal_output_w == 0.0`.
- This covers the existing sign-clamp at line 408.

**T4 — `IdealHvac` emits `HVAC Heating Capacity (W)` telemetry field**
- After fix: call `telemetry_fields()` and assert a field named `"HVAC Heating Capacity (W)"` is present.
- Call `step()` in heating mode and assert the telemetry value equals `rated_capacity_w`.

**T5 — `IdealHvac` emits `HVAC Cooling Capacity (W)` telemetry field**
- Same pattern for the cooling capacity column.
- Telemetry value in cooling mode must equal `cooling_capacity_w` (positive value representing ceiling magnitude).

**T6 — unmet-load hours accumulate when ideal HVAC is at capacity (integration, `crates/hares-io`)**
- Build a synthetic `MetricsCalculator` schema that includes `"HVAC Heating Delivered (W)"` and `"HVAC Heating Capacity (W)"`.
- Feed rows where delivered == capacity and zone is outside setpoint.
- Assert `unmet_load_hours > 0`.
- This test already passes for non-ideal HVAC (see `metrics.rs:1108`); add a parallel scenario for the ideal path once `IdealHvac` emits the capacity column.

**T7 — `LoadFraction` applied before capacity clip, not after**
- Configure 10 kW unit, `load_fraction = 0.5`, inject `ideal_capacity_w = 30_000`.
- Assert `thermal_output_w == 5_000.0` (fraction applied to rated cap, not to unconstrained ideal).
- This specifies the correct order-of-operations once the clip is added.
