## Background/Context

OCHRE HVAC duty cycle: 0 → Off, 1 → max speed On, fractional → mode priority computed
with optional thermostat override (unless `ext_ignore_thermostat=True`).

## Investigation Instructions

1. Read OCHRE `HVAC.run_duty_cycle_control()`.
2. Read HARES — how does `DutyCycle` control signal affect HVAC operation?
3. Is there a thermostat override option?
4. Does fractional duty cycle produce correct partial-timestep operation?

---

## Findings

### 1. How OCHRE computes PLR and duty cycle

OCHRE uses a single float `speed_idx` (HVAC.py line 94) that carries double duty: it is
both a discrete speed selector (integers 0..n_speeds) and a PLR carrier (fractional values
in [0, 1]).

- `speed_idx = 0` → Off (zero capacity)
- `speed_idx = k` (integer k ≥ 1) → running at speed k, full capacity at that stage
- `speed_idx ∈ (0, 1)` → below lowest stage; part-load at speed 1 with `plr = speed_idx`
- `speed_idx ∈ (k, k+1)` where k ≥ 1 → interpolate capacity/EIR between stage k and k+1,
  `frac_high = speed_idx % 1`

The PLF ("eir_plr") correction is applied **inside** the `_biquadratic` kernel (lines 57-60)
as a divisor on the EIR term only, not on capacity:

```
plf_ratio = coeffs_plr[0] + coeffs_plr[1]*plr + coeffs_plr[2]*plr**2
plf_ratio = clamp(plf_ratio, min_plf, max_plf)   # default min_plf = 0.7
return rated * t_ratio * ff_ratio / plf_ratio     # divides EIR by PLF
```

The `plr` argument passed to `_biquadratic` for the EIR curve is `speed_idx` when
`speed_idx < 1`, i.e. when the unit is cycling at below-lowest-stage capacity
(HVAC.py line 1039). For integer speeds ≥ 1 `part_load_ratio=1` is passed, meaning
PLF is 1.0 and the correction is inactive (HVAC.py line 1034-1036).

Runtime fraction (RTF) is never computed as a separate quantity in OCHRE; the model treats
`capacity * eir` at fractional speed as the time-averaged power implicitly, since both
capacity and EIR are already part-load-corrected by the single `speed_idx` carrier.

### 2. How HARES computes PLR, PLF, and duty cycle

HARES separates the concepts into distinct fields and a defined pipeline:

**Step 1 — speed selection (staging.rs `select_speed_with_zone_temp`)**

Returns `SpeedSelection { speed_index, part_load_ratio, speed_frac }`:
- `SingleSpeed`: `speed_index = 0`, `part_load_ratio = load_fraction`
- `TwoSpeedSetpoint/TwoSpeedTime`: discrete 0/1 index; at low speed, `PLR = load/low_cap_frac`
- `MultiSpeedInterpolated`: bracketing between two stages; inter-stage PLR = 1.0,
  intra-lowest-stage PLR = `load / cap_frac[0]`
- `VariableSpeedIdeal`: `speed_index = 0`, `part_load_ratio = 1.0`, `speed_frac = load_fraction`

**Step 2 — duty_cycle assignment (air_conditioner.rs line 559, heat_pump/heater.rs line 565)**

For non-variable-speed modes: `duty_cycle = selection.part_load_ratio`
For `VariableSpeedIdeal`: `duty_cycle = 1.0` when on (the speed_frac carries the modulation)

At coarse timesteps the solver overrides `duty_cycle` with `|ideal_capacity_w| / steady_capacity_w`
(air_conditioner.rs line 831, heater.rs line 722).

**Step 3 — PLF (staging.rs `part_load_factor_for_stage`)**

```
plf = 1 - Cd * (1 - plr)          // default Cd = 0.25 (AHRI 210/240 S6.6.3)
// or quadratic from eir_plr_coefficients if configured
plf = clamp(plf, max(0.7, plr), 1.0)
```

**Step 4 — RTF (air_conditioner.rs line 885-888)**

```
rtf = (plr / plf).clamp(0.0, 1.0)
```

RTF is used for Henderson-Rengarajan latent degradation and crankcase heater accounting.
It is also emitted to telemetry as `RUNTIME_FRACTION`.

For the heat pump heater (heater.rs line 655-660), RTF is simply `duty_cycle`, not
`plr / plf`. This is asymmetric with the AC path.

**Step 5 — actual capacity and power**

```
total_capacity_w = steady_capacity_w * plr      // air_conditioner.rs line 860
compressor_kw    = total_capacity_w * eir * (eir_ratio / plf)
fan_kw           = fan_power_w(flow) * plr
```

EIR correction applies PLF as a divisor on EIR only, matching OCHRE.
Capacity is scaled by PLR directly (not by RTF), also matching OCHRE.

### 3. Duty cycle control signal path

OCHRE `run_duty_cycle_control` (lines 325-354):
- 0 → force off, speed_idx = 0
- 1 → force max speed
- fractional → compute `mode_priority` from duty cycle vector; thermostat result is
  preferred if in the priority stack unless `ext_ignore_thermostat = True`

HARES compound path (air_conditioner.rs line 614-617):
```rust
let effective_load = self.ctrl_duty_cycle
    * self.ctrl_load_fraction
    * self.dr_load_fraction
    * self.dr_duty_cycle;
```
This product then multiplies the biquadratic-corrected capacity. HARES has no equivalent
to OCHRE's thermostat-override logic when a fractional duty cycle is provided externally —
the thermostat still runs and may override the duty cycle by forcing the unit off when the
zone is comfortable. This is a behavioral divergence: OCHRE's `ext_ignore_thermostat` flag
can bypass the thermostat entirely; HARES has no such option.

### 4. Furnace and electric resistance: no PLF

The gas furnace (`furnace.rs` line 338-342) and electric furnace (`furnace.rs` line 152-155)
apply `duty_cycle` directly to capacity and power with no PLF step:
```rust
let gross_capacity_w = self.rated_capacity_w * duty;
let fuel_input_w     = gross_capacity_w / self.fuel_efficiency;
```
This is correct for on/off equipment — furnaces run fully on or fully off; fractional duty
cycle represents time-averaging over the timestep, and PLF is an efficiency degradation
that only applies to compressor cycling. No defect here.

### 5. Variable-speed RTF asymmetry between AC and HP heater paths

**AC path** (air_conditioner.rs lines 885-888):
```rust
let rtf = (plr / plf).clamp(0.0, 1.0);
```
PLF is explicitly forced to 1.0 for `VariableSpeedIdeal` (line 838-842), so RTF = PLR/1.0 = PLR.
Correct for variable-speed: no cycling penalty.

**HP heater path** (heater.rs lines 655-660):
```rust
let rtf = if self.operating_mode != OperatingMode::Off {
    self.hvac.duty_cycle.clamp(0.0, 1.0)
} else {
    0.0
};
```
For single-speed and two-speed HP heater, `duty_cycle = PLR` but PLF is not used to derive
RTF here. The AC path correctly computes RTF = PLR/PLF; the HP heater path uses RTF = PLR.
At PLR < 1 with Cd = 0.25, RTF = PLR/PLF > PLR, so the HP heater telemetry underreports
RTF. This RTF is fed to the companion AC as `companion_heating_rtf` for crankcase accounting
(air_conditioner.rs line 658), meaning crankcase heat is over-allocated when the HP heater
is cycling, since a higher RTF (= more compressor running time) reduces crankcase heater
on-time.

**Severity: Medium.** RTF error propagates to crankcase heater power; at Cd=0.25, PLR=0.5:
PLF = 0.875, true RTF = 0.571, reported RTF = 0.500. Difference = 0.071, meaning crankcase
heater is on ~7% more steps than it should be. Energy impact is small (crankcase ≈ 50 W)
but the asymmetry is a correctness gap.

### 6. TwoSpeedTime: fresh-cycle init starts at speed 0 regardless of load magnitude

In `select_two_speed_time` (staging.rs line 149-165), when `prev_zone_temp_c` is `None`
(fresh start or post-off), the unit always starts at speed 0 (`desired_index = 0`).
OCHRE's `run_two_speed_control` (HVAC.py line 868-870) also starts at speed 1 (low) when
`mode == "Off"`, so the behavior matches.

One subtle difference: OCHRE's `TwoSpeedTime` escalates to high speed when temperature is
"moving wrong way" (line 872); HARES uses the same logic. However OCHRE initializes
`time_in_speed = self.time_res` on a fresh transition (line 912), advancing the timer by
one timestep immediately. HARES resets `time_at_current_speed_s = 0.0` on a speed change
and advances via `advance_speed_timer` called externally. If the caller does not call
`advance_speed_timer` after a speed change, the timer never advances and `min_time_per_speed_s`
could block escalation indefinitely.

**Severity: Low.** Timer advance is caller-responsibility; if every equipment that uses
TwoSpeedTime correctly calls `advance_speed_timer` each timestep the behavior is correct.
Not verified in test coverage.

### 7. MultiSpeed: PLR = 1.0 between stages but PLF is still computed with PLR = 1.0

In `select_multi_speed`, when the load falls between two speed stages, `part_load_ratio`
is returned as 1.0 (staging.rs lines 227-231). This PLR = 1.0 is then passed to
`part_load_factor`, giving PLF = 1.0 regardless of actual load fraction — correct, since
the unit is running continuously at an interpolated speed and there is no cycling.

When load is below the lowest stage capacity (lines 204-210), PLR = `load / cap_frac[0]`
and PLF is computed normally. This matches OCHRE's `speed_idx < 1` path.

No defect.

### 8. PLF floor clamping: HARES vs OCHRE

HARES: `plf = plf_raw.clamp(max(0.7, plr), 1.0)` (staging.rs line 291)
OCHRE: `plf_ratio = clamp(plf_ratio, min_plf, max_plf)` where `min_plf = 0.7` by default
(HVAC.py lines 58, 833).

HARES adds an additional constraint `plf >= plr` (the EnergyPlus RTF ≤ 1 invariant) which
OCHRE does not enforce. This is a deliberate improvement over OCHRE and is correct per
EnergyPlus engineering reference. No defect.

### 9. VariableSpeedIdeal: speed_frac carries modulation, not duty_cycle

For variable-speed AC (staging.rs lines 103-107):
```rust
SpeedControlMode::VariableSpeedIdeal => SpeedSelection {
    speed_index: 0,
    part_load_ratio: 1.0,
    speed_frac: load_fraction,   // modulation depth
},
```
And in `update_control` (air_conditioner.rs lines 560-568):
```rust
SpeedControlMode::VariableSpeedIdeal => {
    if selection.speed_frac > 0.0 { 1.0 } else { 0.0 }
}
```
So `duty_cycle` is binary (0 or 1) for variable speed; `speed_frac` is the continuous
modulation. In `calculate_performance`, stage_cap_w is set to `max_cap * speed_frac`
(line 763), so the output scales continuously. PLR = 1.0, PLF = 1.0, RTF = 1.0 while on.
This is the correct variable-speed model.

OCHRE does this the same way via fractional `speed_idx` when `use_ideal_capacity=True`
(HVAC.py line 1008). Equivalent.

|---|----------|----------|-------------|
| D1 | Medium | `heater.rs:655-660` | HP heater RTF reported as PLR, not PLR/PLF. Underreports RTF for single/two-speed compressors; propagates to crankcase over-activation. |
| D2 | Low | `staging.rs`, caller contract | `advance_speed_timer` is caller-responsibility; no test confirms it is called every step for TwoSpeedTime equipment. Timer stall risk. |

## Recommended Tests

### T1: HP heater RTF vs PLF correctness
Construct a single-speed HP heater with `Cd = 0.25`. Drive at `PLR = 0.5`. Assert that
`RUNTIME_FRACTION` telemetry ≈ `0.5 / (1 - 0.25*(1-0.5))` = `0.5 / 0.875` ≈ 0.571,
not 0.5. Confirm crankcase heater on-time is correspondingly reduced.

### T2: TwoSpeedTime timer advance integration
Construct a TwoSpeedTime HP in a full-step loop, verify `time_at_current_speed_s` increments
each step and that escalation to high speed occurs after `min_time_per_speed_s` elapses.

### T3: Compound duty cycle multiplier with thermostat-off zone
Set `ctrl_duty_cycle = 0.5` on a cooling AC with zone temperature below setpoint. Confirm the
thermostat forces OperatingMode::Off and capacity = 0 despite the duty cycle signal — document
that this is the intended behavior (no `ext_ignore_thermostat` equivalent in HARES).
