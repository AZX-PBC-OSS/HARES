## Background/Context

SU-001 found the fan-heat correction misuses the psychrometric library. The library
functions themselves (wet-bulb solver, enthalpy, dew point, humidity ratio conversions)
were never validated against ASHRAE reference tables or PsychroLib.

---

## Findings

### FINDING 1 — PASS: Saturation pressure polynomial coefficients are correct
**Severity: None (confirmed correct)**

The ASHRAE piecewise polynomial in `saturation_pressure_pa` uses the same
coefficients as OCHRE's `psychrolib_jit.py::get_sat_vap_pressure` to floating-point
precision. OCHRE uses the ASHRAE HOF 2017 Ch.1 Eqs. 5–6 (ASHRAE Standard 55 /
ISO 7730 form). Coefficients match exactly:

Above 0°C (`t_c > 0.01`):
- HARES: `−5.800_220_6e3`, `1.391_499_3`, `−4.864_023_9e-2`, `4.176_476_8e-5`, `−1.445_209_3e-8`, `6.545_967_3`
- OCHRE: `−5.8002206e3`, `1.3914993`, `−4.8640239e-2`, `4.1764768e-5`, `−1.4452093e-8`, `6.5459673`

At/below 0°C:
- HARES: `−5.674_535_9e3`, `6.392_524_7`, `−9.677_843e-3`, `6.221_570_1e-7`, `2.074_782_5e-9`, `−9.484_024e-13`, `4.163_501_9`
- OCHRE: `−5.6745359e3`, `6.3925247`, `−9.677843e-3`, `6.2215701e-7`, `2.0747825e-9`, `−9.484024e-13`, `4.1635019`

All trailing-digit underscore-separated forms are equivalent.

### FINDING 2 — INTENTIONAL DEVIATION: Above-freezing wet-bulb psychrometer coefficient
**Severity: None (deliberate, documented, tested)**

HARES uses `c_s = 2.381 kJ/(kg·K)` per ASHRAE HOF 2021 Ch.1 Eq.35.
OCHRE uses `c_s = 2.326 kJ/(kg·K)` per PsychroLib default (ASHRAE 1989/2017 form).

This is documented in the source comment and covered by regression test
`wet_bulb_from_humidity_ratio_ashrae_hof_2021_reference`. The test `humidity_ratio_from_twb_matches_psychrolib_reference` uses a 0.5% tolerance to accommodate the discrepancy when comparing against the PsychroLib reference value. This is correct behaviour — HARES targets ASHRAE 2021, OCHRE targets 2017.

The deviation produces a wet-bulb temperature that is slightly higher (by ~0.1–0.2°C at standard conditions) than the OCHRE/PsychroLib result. This is the correct ASHRAE 2021 value.


### FINDING 3 — CONFIRMED BUG FIX: Below-freezing wet-bulb psychrometer coefficient
**Severity: None (already fixed, regression test present)**

OCHRE `psychrolib_jit.py` line: `(2830.0 - 0.24 * t_wet_bulb)` — uses `0.24` which
is the IP-unit coefficient in BTU/(lb·°F). In SI the correct value per ASHRAE HOF 2021
Eq.37 is `2.006 kJ/(kg·K)`. HARES correctly uses `SPECIFIC_HEAT_WET_BULB_BELOW_FREEZE = 2.006`.

Regression test `humidity_ratio_from_twb_sub_freezing_uses_correct_ice_specific_heat`
confirms the fix.

Impact of OCHRE bug: At Tdb=−10°C, Twb=−15°C, the OCHRE formula with 0.24 yields a
humidity ratio approximately 15% lower than correct because the latent heat numerator
term `(2830 − 0.24·(−15))·w_sat ≈ 2833.6·w_sat` vs the correct
`(2830 − 2.006·(−15))·w_sat ≈ 2860.1·w_sat`.


### FINDING 4 — BUG: `wet_bulb_from_humidity_ratio` bisection has degenerate bracket for supersaturated input
**Severity: Medium**
**File: `crates/hares-physics/src/psychrometrics.rs`, lines 126–141**

When the caller passes a humidity ratio `w` that exceeds saturation at `t_db_c`
(physically impossible but can occur from noisy sensor data or a mis-coded caller),
`dew_point(w, p)` returns a value `t_dp > t_db_c`. The bisection bracket becomes:

```rust
let low = t_dp.min(t_db_c);   // = t_db_c
let high = t_db_c.max(t_dp);  // = t_dp  (> t_db_c)
```

The search interval is `[t_db_c, t_dp]` — i.e., the wet-bulb is searched *above* the
dry-bulb, which is physically impossible. The function `humidity_ratio_from_twb(t_db_c, mid, p)`
with `mid > t_db_c` will compute a wet-bulb humidity ratio for a wet-bulb above the
dry-bulb. The bisection will terminate (it always does due to bracket shrinkage) but
returns a value ≥ t_db_c. The caller in `environment.rs:427` then stores this as
`outdoor_wet_bulb_c`, which is used downstream in HVAC coil capacity biquadratic
lookups. An out-of-range wet-bulb fed to a biquadratic will extrapolate, possibly
producing negative capacity or negative COP.

The fix is to clamp the return value to `t_db_c` at saturation:

```rust
pub fn wet_bulb_from_humidity_ratio(t_db_c: f64, w: f64, p_pa: f64) -> f64 {
    let w_eff = w.max(MIN_HUMIDITY_RATIO);
    // Clamp w to saturation: wet-bulb cannot exceed dry-bulb
    let w_sat = humidity_ratio_from_tdp(t_db_c, p_pa);
    if w_eff >= w_sat {
        return t_db_c; // saturated: Twb = Tdb
    }
    let t_dp = dew_point(w_eff, p_pa);
    bisect(
        t_dp,
        t_db_c,
        |mid| humidity_ratio_from_twb(t_db_c, mid, p_pa) - w_eff,
        PSYCHRO_TOLERANCE_C,
        WET_BULB_HUMIDITY_TOLERANCE,
        MAX_BISECTION_ITERS,
    )
}
```

Note this also simplifies the bracket: `low = t_dp`, `high = t_db_c` always, removing
the `.min()/.max()` gymnastics entirely.

Reproduction path: any weather file with `dew_point_c > dry_bulb_c` (corrupted EPW),
or any direct call to `wet_bulb_from_humidity_ratio` with an oversaturated w.


### FINDING 5 — BUG: `dew_point` bisection is silent on unconverged result
**Severity: Low**
**File: `crates/hares-physics/src/psychrometrics.rs`, lines 152–165, 188–214**

The `bisect` helper unconditionally returns `0.5*(lo+hi)` after exhausting
`MAX_BISECTION_ITERS = 100`. At `bracket_tol = 0.01°C`, 100 iterations on a
300°C starting bracket gives final bracket width of `300 / 2^100 ≈ 2.4e-28°C` —
which is below `bracket_tol` within 15 iterations. So in practice this is never
hit for normal inputs.

However, the `dew_point` function also applies `value_tol = 0.05 Pa`. If
`saturation_pressure_pa(mid) - p_v` does not converge to within 0.05 Pa due to
floating-point plateau (e.g., near the triple-point discontinuity at 0.01°C),
bisection will still exhaust and silently return a midpoint. There is no debug
assertion or `#[cfg(debug_assertions)]` check to detect this during development.

OCHRE's Newton-Raphson `get_dew_point_from_vap_pressure` raises a `ValueError` on
non-convergence. HARES silently returns a degraded answer.

Recommendation: add a `debug_assert` after the bisect call that the returned value
satisfies `|f(result)| < value_tol * N` where N is a small multiplier, or add a
`tracing::warn!` when `MAX_BISECTION_ITERS` is reached.


### FINDING 6 — PASS: Enthalpy formula matches ASHRAE HOF and OCHRE
**Severity: None**

HARES `moist_air_enthalpy`:
```
h = (1.006·T + W·(2501 + 1.86·T)) × 1000  J/kg
```
OCHRE `get_moist_air_enthalpy`:
```
h = (1.006·T + W·(2501.0 + 1.86·T)) × 1000  J/kg
```
Identical. Matches ASHRAE HOF 2017 Ch.1 Eq.30 with reference state at 0°C.

Validated reference points (all existing tests pass):

| T (°C) | W (kg/kg) | ASHRAE (J/kg) | HARES formula (J/kg) |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 20 | 0 | 20120 | 20120 |
| 25 | 0.01 | 50625 | 50625 |
| 30 | 0.02 | 81316 | 81316 (verified vs PsychroLib) |

At ASHRAE standard conditions (25°C, 50% RH, 101325 Pa):
- `w ≈ 0.009926 kg/kg` (from saturation)
- `h = (1.006×25 + 0.009926×(2501 + 1.86×25)) × 1000 ≈ 50318 J/kg ≈ 50.3 kJ/kg`
- ASHRAE HOF Table 2 gives approximately 50.1 kJ/kg at 25°C/50% RH — within 0.4%.


### FINDING 7 — PASS: Dew-point inversion accuracy
**Severity: None**

`dew_point(humidity_ratio_from_tdp(T_dp, p), p)` round-trips to within `bracket_tol = 0.01°C`
across the tested range (−10 to 25°C). Validated by `dew_point_inverts_humidity_ratio_from_tdp`
and `dew_point_humidity_ratio_round_trip` tests.

OCHRE uses Newton-Raphson which converges in ~5 iterations to tolerance 0.001°C.
HARES bisection needs ~15 iterations to reach 0.01°C bracket tolerance. The extra
~10 iterations per `dew_point` call are negligible for building simulation (not a hot loop),
but note that `wet_bulb_from_humidity_ratio` calls `dew_point` internally, so the combined
wet-bulb cost is ~30 total bisection iterations.


### FINDING 8 — PASS: Extreme-temperature behaviour
**Severity: None**

Sub-zero (−20°C): `saturation_pressure_pa(−20)` = 103.2 Pa vs ASHRAE Table 2 = 103.24 Pa
(0.04% error). `humidity_ratio_from_twb(−10, −15, 101325)` produces a physically
reasonable result with the corrected `c_s = 2.006`. Round-trip error < 2%.

High altitude (Denver, 1609 m, 83460 Pa): humidity functions correctly scale with
pressure since pressure is a parameter. No hardcoded sea-level assumption in any formula.

High temperature (45°C): `saturation_pressure_pa(45)` evaluates using the above-0°C
branch. No special handling needed. Enthalpy is unbounded positive, as expected.

Near triple-point (0.01°C): HARES switches branches at `t_c <= 0.01`, matching the
ASHRAE convention. OCHRE switches at `t_dry_bulb <= TRIPLE_POINT_WATER_SI = 0.01`. Identical.


### FINDING 9 — GAP: No test for `dew_point` with w=0.0 exact input
**Severity: Low (test gap, not a runtime defect)**

`dew_point(0.0, p)` floors to `MIN_HUMIDITY_RATIO = 1e-7`, yielding
`p_v = 101325 × 1e-7 / (0.621945 + 1e-7) ≈ 0.01629 Pa`.
`saturation_pressure_pa(−100)` ≈ 0.0014 Pa (sub-milliPascal, ice branch extrapolated).
The bisection lower bound of −100°C yields `f(−100) = 0.0014 − 0.01629 < 0` and
`f(200) = sat_pressure(200) − 0.01629 >> 0`, so the bracket is well-formed.
The returned dew-point will be near −80°C (approximately, where
`sat_pressure(T) = 0.01629 Pa`).

No test covers `dew_point(0.0, p)` to confirm the floor guard works end-to-end.
This is not a defect but a testing gap — confirm the floor guard is exercised.


### FINDING 10 — PASS: Re-exported constants are consistent
**Severity: None**

The three constants re-exported from `psychrometrics` for downstream use
(`EPSILON`, `LATENT_HEAT_VAPORISATION_KJ_KG`, `SPECIFIC_HEAT_DRY_AIR_KJ_KG_K`,
`SPECIFIC_HEAT_WATER_VAPOUR_KJ_KG_K`) are thin aliases over `constants.rs` values.
They are annotated as "Re-export for backward compatibility" but this is a greenfield
codebase — this comment is inaccurate per project policy (no backward-compat shims).

The air_conditioner at `crates/hares-equipment/src/hvac/air_conditioner.rs:789`
imports `psychrometrics::SPECIFIC_HEAT_DRY_AIR_KJ_KG_K` rather than
`constants::CP_DRY_AIR_KJ_KG_K`. Both resolve to `1.006`; no numeric error.
But the indirection is unnecessary and the comment is misleading.


### FINDING 11 — GAP: No test for `humidity_ratio_from_twb` with Twb > Tdb (invalid input)
**Severity: Low (test gap)**

OCHRE `get_hum_ratio_from_t_wet_bulb` raises `ValueError("Wet bulb temperature is above dry bulb temperature")`.
HARES silently proceeds with no guard, computing a result that passes through
`MAX(_, MIN_HUMIDITY_RATIO)`. For `t_wb > t_db`, the numerator of the above-freezing
formula becomes larger and the result can exceed physically valid saturation values.
This is the prerequisite condition for Finding 4. There is no test that asserts
the behaviour when `t_wb > t_db`.


### FINDING 12 — PASS: `relative_humidity` clamps to [0, 1]
**Severity: None**

`relative_humidity` applies `.clamp(0.0, 1.0)`. For supersaturated states (w > w_sat),
this correctly caps RH at 1.0 rather than returning > 1. OCHRE does not clamp —
`get_rel_hum_from_hum_ratio` can return > 1.0, which HARES improves upon.


### FINDING 13 — OBSERVATION: Missing `get_moist_air_volume` equivalent
**Severity: Informational**

OCHRE exposes `get_moist_air_volume(t_dry_bulb, hum_ratio, pressure)` returning
specific volume [m³/kg_da]. HARES does not expose this function in `psychrometrics.rs`
or `air_properties.rs`. The inverse (density) is in `air_properties.rs`. Volume is
derivable as `1/ρ_da` from `moist_air_density_kg_m3`. No caller needs specific volume
directly in the current codebase — no gap for existing functionality.

## Summary

All 22 existing psychrometrics unit tests pass (`cargo test -p hares-physics`).
The polynomial implementation is numerically identical to OCHRE/PsychroLib.
The ASHRAE 2021 wet-bulb coefficient correction (`2.381` vs OCHRE's `2.326`) is correct
and well-justified. The below-freezing coefficient fix (`2.006` vs OCHRE's broken `0.24`) is
confirmed correct.

**Two defects require remediation:**

| # | Severity | Summary |
|---|---|---|
| 4 | Medium | `wet_bulb_from_humidity_ratio` bracket is inverted for w > w_sat; downstream HVAC biquadratics receive out-of-range Twb |
| 5 | Low | `bisect` is silent on non-convergence; add debug assertion |

**Two test gaps require new test cases:**

| # | Severity | Summary |
|---|---|---|
| 9 | Low | No test for `dew_point(0.0, p)` — floor guard exercised end-to-end |
| 11 | Low | No test asserting behaviour of `humidity_ratio_from_twb` with Twb > Tdb |

**One comment quality issue:**

| # | Severity | Summary |
|---|---|---|
| 10 | Trivial | "Re-export for backward compatibility" comment is inaccurate on a greenfield codebase |

## Recommended Tests

#[test]
fn wet_bulb_from_humidity_ratio_supersaturated_input_returns_tdb() {
    // w > w_sat(t_db): physically impossible; should return Tdb (saturated)
    let p = 101_325.0;
    let t_db = 20.0;
    let w_sat = humidity_ratio_from_tdp(t_db, p);
    let t_wb = wet_bulb_from_humidity_ratio(t_db, w_sat * 2.0, p);
    approx_eq(t_wb, t_db, 0.01); // must not return a value above Tdb
}

#[test]
fn dew_point_at_minimum_humidity_ratio_does_not_panic() {
    let p = 101_325.0;
    let tdp = dew_point(0.0, p); // floors to MIN_HUMIDITY_RATIO internally
    assert!(tdp.is_finite());
    assert!(tdp < -50.0, "dew point at near-zero w should be very cold, got {tdp}°C");
}

#[test]
fn humidity_ratio_from_twb_above_tdb_does_not_produce_nonsense() {
    // Document current behaviour when t_wb > t_db; ensure result >= 0
    let w = humidity_ratio_from_twb(20.0, 25.0, 101_325.0); // Twb > Tdb
    assert!(w >= 0.0, "humidity ratio must be non-negative");
    // This test is intentionally lenient — it documents the absence of a guard
    // and will need updating once Finding 4 fix is applied (should assert panic or Err)
}
