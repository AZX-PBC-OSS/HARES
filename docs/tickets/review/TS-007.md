## Background/Context

The thermal solver uses a state-space model (A, B, C, D matrices) with Crank-Nicolson
time stepping (THERMAL-005). Crank-Nicolson is unconditionally stable but can produce
oscillations if the timestep is too large relative to the smallest RC time constant.
The discretization method (ZOH vs Van Loan) also matters.

## Investigation Instructions

1. **Read HARES `stepping.rs`:**
   - What is the time-stepping scheme? Crank-Nicolson (θ=0.5)?
   - How is the state vector `x` updated each step?
   - What is the input vector `u` (boundary temperatures, solar, internal gains)?

2. **Read `state_space.rs`:**
   - How is the continuous A,B,C,D discretized?
   - `discretize_zoh` vs `van_loan_discretize` — which is used? When?
   - `matrix_exp` — what method? Padé? Scaling-and-squaring?

3. **Read OCHRE state-space solver:**
   - What discretization method?
   - What time-stepping scheme?
   - How does OCHRE handle the matrix exponential?

4. **Check numerical stability:**
   - What is the smallest RC time constant in a typical model?
   - At 5-minute timestep, is Crank-Nicolson stable? At 15-minute?
   - Does `StabilityResult` check for this?
   - Are there any damping or limiting mechanisms?

5. **Check THERMAL-005 status** — was Crank-Nicolson fully implemented?

## Findings

### Q1 — Time-stepping scheme

The base model stepping scheme is **Zero-Order Hold (ZOH)**, not Crank-Nicolson.

`from_continuous` (`state_space.rs:261`) calls `discretize_auto`, which produces a
discrete-time A_d, B_d via matrix exponential. At construction time `M = I` (identity)
is stored, so the step degenerates to a pure forward recurrence:

```
x[k+1] = A_d · x[k] + B_d · u[k]
```

The function docstring at line 253 is contradictory: the first sentence says
"Crank-Nicolson discretization" but the second sentence correctly says "ZOH (matrix
exponential)". The CN language is stale and incorrect. **This is a correctness bug in
the documentation** — the math is ZOH throughout.

There is no CN θ=0.5 path in `from_continuous`. A prior CN path was replaced by ZOH.
The `m_mat`, `n_mat` field names are therefore misleading; with M = I they carry no
implicit weighting.

The **infiltration path** is different and deliberately so. `stepping.rs:87-92` applies
Backward Euler (fully implicit) for infiltration: it adds `d = h_inf * b_coeff` to the
`M` diagonal and subtracts it from the explicit half via forcing. This matches
EnergyPlus's zone-air heat balance predictor treatment and is unconditionally stable for
arbitrarily large infiltration conductances.

### Q2 — Discretization method

`discretize_auto` (`state_space.rs:856`) picks the method based on the condition number
of A_c:

- If A_c is well-conditioned (rcond > 1e-12): `discretize_zoh` — computes A_d = expm(A_c·dt)
  and then B_d = A_c⁻¹ · (A_d − I) · B_c via LU solve.
- If A_c is singular or near-singular: `van_loan_discretize` — augments the system to
  a (n+m)×(n+m) block matrix and extracts both A_d and B_d from a single expm call.

This matches OCHRE's `to_discrete` in `StateSpaceModel.py:247-266` exactly:
- OCHRE tries `linalg.inv(A_c)` first; if that raises `LinAlgError` it falls through to
  the Van Loan block-matrix expm path.
- Both codebases therefore produce identical discretization results for the same RC
  network, matching the parity goal.

### Q3 — Matrix exponential method

`matrix_exp` (`state_space.rs:958`) implements **Padé order-13 with scaling-and-squaring**
(Al-Mohy & Higham 2009). The scaling factor `s = ceil(log2(‖A‖₁ / θ₁₃))` where
`θ₁₃ = 5.37...` is the standard value. After the Padé rational evaluation the result is
squared back `s` times. This is the same algorithm used by `scipy.linalg.expm` and
MATLAB's `expm`. OCHRE delegates to `scipy.linalg.expm` directly.

Both implementations should agree to floating-point precision. HARES carries its own
implementation (no runtime dependency on LAPACK/scipy), which is appropriate for the
Rust target.

### Q4 — Numerical stability at 5 min / 15 min timestep

**ZOH is unconditionally stable for any timestep** regardless of stiffness. A_d =
expm(A_c·dt) preserves |λ(A_d)| < 1 for any dt whenever all continuous eigenvalues have
Re(λ) < 0, because exp(λ_c · dt) maps the open left half-plane into the open unit disk.
This is demonstrated by the test at line 1460 ("massively stiff system: τ=0.1s, dt=60s,
dt/τ=600") where A_d = exp(-600) ≈ 0 with no oscillation.

There is therefore no timestep-sensitivity concern for the base ZOH step.

The eigenvalue stability check in `from_continuous` (lines 285-336) confirms this at
construction time. For n ≤ 20 it computes exact eigenvalues of A_d; for n > 20 it falls
back to a Gershgorin row-sum bound on A_c. Both paths return `Err(UnstableSystem)` if
either check fails — **there is no runtime fallback for instability after construction**
(see Q6 below).

The near-unity threshold `NEAR_UNITY_EIGENVALUE_THRESHOLD = 0.99` (`state_space.rs:12`)
triggers a `tracing::warn` but does not fail. A near-unity eigenvalue (slow time
constant — large wall thermal mass relative to UA) is physically expected for heavyweight
construction (BESTEST 900) and is not a bug.

**Smallest expected RC time constant**: For typical residential envelope nodes (thin
window glass, interior surface node), τ_min ~ 100-300 s. At dt = 300 s (5 min),
dt/τ ≈ 1-3, placing A_d = exp(-dt/τ) in [0.05, 0.37] — well within the unit circle.
At dt = 900 s (15 min), A_d drops to [0.003, 0.14]. Neither triggers instability; ZOH
simply damps faster nodes more aggressively. No test currently validates this explicitly.

### Q5 — Infiltration implicit treatment vs. Crank-Nicolson

Confirmed above in Q1. The infiltration coupling uses Backward Euler, not ZOH or CN.
The mathematical justification is correct: the infiltration load is temperature-dependent
(`q = h_inf·(T_out − T_zone)`), so the T_zone term must be treated implicitly to avoid
instability when h_inf·dt/C ≫ 1 (e.g. high ACH or large timestep). The EnergyPlus
Engineering Reference §13.3 calls this the "predictor-corrector" implicit coefficient.

OCHRE handles this differently: it clips the infiltration gain to a maximum `h_limit`
(the gain required to drive the zone to outdoor temperature in one step), then adds it
as an explicit input. This is cheaper but introduces a clamping nonlinearity. HARES's
fully-implicit treatment is more accurate and avoids the clamp.

### Q6 — Fallback when StabilityResult indicates instability

There is **no runtime fallback**. `from_continuous` returns
`Err(StateSpaceError::UnstableSystem(stability))`. The production call site in
`solver_builder.rs:504` converts this to `HaresError::Envelope(...)` and propagates it
to the caller as a hard initialisation failure:

```rust
let model = StateSpaceModel::from_continuous(&a_c, &b_c, dt_s, &output_mapping)
    .map_err(|err| HaresError::Envelope(format!("state-space setup failed: {err}")))?;
```

If an RC network is ill-conditioned or has a positive eigenvalue, the dwelling will fail
to construct and the error surfaces to the user. There is no graceful degradation (e.g.,
clamp, regularise, or reduce model order). This is likely intentional — a silently
unstable simulation would be worse than a clear failure — but it is not documented as a
design decision.

### Defects and Issues Found

**DEFECT — Stale CN documentation in `from_continuous` docstring**
`state_space.rs:253-255`. The first sentence says "Crank-Nicolson discretization" and
describes CN matrices M, N. The next sentence correctly describes ZOH. The CN sentence
is wrong and the description of M and N as CN matrices is misleading. Severity: low
(documentation only, no behaviour impact), but violates the no-broken-windows policy.

**DEFECT — `b_coeff` scaling in infiltration coupling may be incorrect for ZOH**
`stepping.rs:86-92`. `b_coeff = b_eff[(state_idx, input_idx)]`. For a ZOH model,
`b_eff = B_d` (discrete). The infiltration forcing then computes
`d = h_inf * B_d[(i,j)]` and `forcing = h_inf * t_forcing * B_d[(i,j)] + d * x[i]`.
This mixes a continuous-domain heat-conductance (W/K) with a discrete-domain input
matrix entry (K/W or dimensionless depending on convention). For ZOH, `B_d[(i,j)]`
has units implicit in the discretization (it is not the same as the continuous `B_c` or
simply `dt · B_c`). The correct implicit augmentation should be derived from the
**continuous** `B_c` coefficient, not the discretised `B_d`. The only reason this works
in practice is that for the specific zone-heat-injection wiring, B_d ≈ dt·B_c for
modestly stiff modes. For stiff boundaries with small τ, B_d can differ substantially
from dt·B_c. No test exists that validates the coupled-implicit path for a stiff RC node.
Severity: medium (silent physics error under high-ACH or stiff boundary conditions).

**OBSERVATION — Eigenvalue skip for n > 20**
For large RC networks (more than 20 states), the discrete eigenvalue check is skipped and
only the Gershgorin continuous bound is applied. The Gershgorin bound is conservative
(can pass unstable matrices) and cannot detect instability introduced by the ZOH
discretization itself (though for passive RC networks this is impossible by construction
since A_c is diagonally dominant and negative-definite). This is noted but not a defect.

**OBSERVATION — Output evaluated with x[k+1] and u[k]**
`stepping.rs:115`: `y_next = model.output(&self.x, &u)` where `self.x` is already x[k+1]
after the swap. The output equation y = C·x[k+1] + D·u[k] mixes the new state with the
old input. For purely state-output C matrices (no D term), this is correct. For models
with non-zero D (feedthrough), u[k] rather than u[k+1] is used. This is consistent with
the convention for ZOH and matches OCHRE's `C.dot(next_states) + D.dot(inputs)` which
also uses the same-step input. Not a defect, but should be documented.

## Recommended Tests

1. **ZOH vs CN identity**: Unit test that for a 1R-1C network with τ = 100 s and dt = 300 s,
   the ZOH step produces A_d = exp(-3) ≈ 0.0498 exactly, confirming no oscillation.
   Compare against a hypothetical CN step (A_d = (1 - dt/2τ)/(1 + dt/2τ) = -0.5) to
   confirm ZOH is used and does not oscillate.

2. **`b_coeff` scaling test**: Build a coupled-implicit model where the RC node has a fast
   time constant (τ = 10 s), set h_inf = 100 W/K, dt = 300 s. Verify that the implicit
   infiltration path produces the same steady-state result as an analytical closed-form
   solution (which is T_zone → T_out). Currently missing.

3. **Instability rejection test**: Construct an A_c with a positive eigenvalue and assert
   that `from_continuous` returns `Err(UnstableSystem)`.

4. **Large network Gershgorin coverage**: Build a network with n = 25 states (> 20) and a
   known unstable A_c and confirm the Gershgorin path still catches it. Currently the n > 20
   path is tested only by integration tests where the network is always stable by
   construction.

5. **15-minute timestep regression**: Run the BESTEST 600 and 900 cases at dt = 900 s and
   assert that zone temperature trajectories remain bounded and stay within 2°C of the 300 s
   results. This would validate that ZOH at coarse timesteps does not introduce drift.

6. **Docstring fix verification**: After correcting `from_continuous` docstring, CI should
   still pass `cargo test -p hares-envelope` (regression guard only).
