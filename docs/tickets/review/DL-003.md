## Background/Context

OCHRE's ASHRAE 152 calculation uses zone temperatures from a CSV file
(`ASHRAE152_zone_temperatures.csv`) keyed by zone type and climate station. HARES
must have equivalent data or use a different approach.

## Investigation Instructions

1. **Read OCHRE's CSV** — what zone types and data does it contain?
2. **Read HARES `ashrae152.rs`** — how does it obtain duct zone temperatures?
   - Does it use a lookup table? Live zone temperatures? Hardcoded values?
3. **Compare approaches** — if HARES uses live zone temps (from the thermal solver),
   this is potentially better than OCHRE's static lookup, but the difference should
   be documented.


## Answer

The zone temperature is a **formula computed from ASHRAE 152 climate station seasonal/design temperatures, not a live zone temperature from the thermal solver**. Both HARES and OCHRE derive a static seasonal duct-zone temperature at equipment init time via haversine lookup of the nearest climate station.

OCHRE loads `ASHRAE152_zone_temperatures.csv` (indexed by zone-type string) and evaluates each cell as a Python expression with `heating_seas_init`, `cooling_seas_init`, `heating_des_init`, `cooling_des_init`, and `ground_temp` in scope. HARES encodes the same 16 formulas as Rust `match` arms in `zone_temps()` (`ashrae152.rs` lines 192–323). The return-zone temperature is then conditionally derived from the supply zone temperature and the climate seasonal value. Regain coefficients are zone-type constants, not live values.

## Findings

### FINDING 1 — Severity: Medium
**`capacity_low_w` / `fan_flow_low_m3_s` always `None` for multi-speed equipment**

`crates/hares-equipment/src/hvac/helpers.rs` lines 253–254 hardcode both to `None` regardless of `n_speeds`. When `n_speeds > 1`, `calculate_dse()` falls through to high-speed values for the low-speed branch (`ashrae152.rs` lines 461–480). This understates duct losses for variable-speed equipment: at low speed the lower airflow produces larger exponential decay factors (`bs_low`, `br_low`), meaning higher conductive loss that the calculation silently omits.

Fix: `resolve_duct_dse` must accept and forward low-speed capacity/airflow. Callers that already extract `n_speeds` from `cooling_capacities_w.len()` / `heating_capacities_w.len()` should also pass the `first()` element as low-speed capacity and derive its fan flow.

Affected files:
- `crates/hares-equipment/src/hvac/helpers.rs` lines 196–259
- `crates/hares-equipment/src/hvac/air_conditioner.rs` line 459
- `crates/hares-equipment/src/hvac/furnace.rs` lines 122 and 290
- `crates/hares-equipment/src/hvac/heat_pump/heater.rs` line 416

### FINDING 2 — Severity: Low
**Flex duct `fcycloss` variant not exposed**

OCHRE selects `fcycloss = 0.02` for flex duct vs `0.05` for sheet metal (`equipment.py` lines 286–289). HARES hardcodes `0.05` (`ashrae152.rs` line 422) and `DuctDseInput` has no `duct_material` field. HPXML distinguishes duct system type; ignoring this slightly overstates losses for flex-duct buildings.

Fix: Add `flex_duct: bool` to `DuctDseInput`; select `fcycloss` accordingly. Populate from HPXML `SystemType` in `hares-io/src/hpxml/resolve_hvac.rs`.

### FINDING 3 — Severity: Low
**Tests are range-only smoke tests with no numeric regression**

The four tests in `ashrae152.rs` (lines 627–752) only assert `dse > 0 && dse <= 1.0`. A silent formula regression would not be caught.

Fix: Add at least two tests (one heating, one cooling) that assert a specific numeric DSE value computed against the OCHRE reference for identical inputs, with tolerance ±0.005.
