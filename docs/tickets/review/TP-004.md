## Background/Context

Battery outputs include SOC, power, voltage, temperature, degradation state.
HARES has a richer battery model — document what's available beyond OCHRE.

## Investigation Instructions

1. Read OCHRE Battery output columns.
2. Read HARES battery telemetry.
3. Build comparison table.
4. Document HARES-only fields (degradation, thermal, OCV) as improvements.


## Recommended Tests

- `cargo test -p hares-equipment battery::` — verify all existing battery tests pass.
- Add a new test `degradation_reduces_nominal_capacity` that runs 365 simulated days of cycling and asserts `capacity_kwh_nominal` is strictly less than `capacity_kwh_rated` and `capacity_fade_pct` equals `1.0 - (capacity_kwh_nominal / capacity_kwh_rated)`.
- Add a test `capacity_fade_pct_is_percentage` that verifies a known 1-year calendar-aging run produces a `capacity_fade_pct` telemetry value in units of percent (e.g. ~0.3% ≈ 0.3, not 0.003).

## Findings

### CRITICAL — Degradation does not reduce `capacity_kwh_nominal`

**File:** `crates/hares-equipment/src/battery/mod.rs:640, 928`

OCHRE's `calculate_degradation()` (Battery.py:438) explicitly reduces the nominal capacity:
```python
self.capacity_kwh_nominal = self.capacity_rated * (b0 - deg_sum)
```

In HARES, `capacity_kwh_nominal` is set once at `init()` (line 640) and never updated by degradation. Per-step capacity is only reduced by the temperature-dependent Arrhenius derating (line 928). `degradation.capacity_fade_pct()` is computed correctly and written to telemetry, but it has no effect on actual energy stored or delivered. After simulated years of cycling, the battery behaves identically to a new cell.

**Fix:** Store the rated capacity as an immutable `capacity_kwh_rated` field. At the daily degradation update (around line 1075) apply:
```rust
let soh = 1.0 - self.degradation.capacity_fade_pct();
self.capacity_kwh_nominal = self.capacity_kwh_rated * soh;
```

---

### HIGH — `capacity_fade_pct` name/unit mismatch

**Files:**
- `crates/hares-equipment/src/battery/degradation.rs:215-218` — docstring says "fraction in [0, 1]"; returns raw `self.capacity_fade` (a fraction).
- `crates/hares-equipment/src/battery/mod.rs:1374` — `TelemetryField` declares `unit: "%"`.
- `crates/hares-equipment/src/battery/mod.rs:1099` — stores the fraction directly: `self.degradation.capacity_fade_pct()`.

The key name ends in `_pct`, the unit annotation says `%`, but the stored value is a fraction [0, 1]. A consumer reading `capacity_fade_pct` expecting a percent-scale value (2.4 for 2.4% fade) silently receives 0.024. Same defect present in EV model at `crates/hares-equipment/src/ev/mod.rs:642`.

**Fix:** Either rename to `capacity_fade` with unit `-` and a docstring saying fraction, or multiply by 100 before storing in telemetry and document the function as returning a percent. Apply consistently across battery and EV.

---

### MEDIUM — Missing telemetry: `nominal_capacity_kwh` and `actual_capacity_kwh`

**OCHRE reference:** Battery.py:450-451 (verbosity >= 7)
```python
results[f"{self.end_use} Nominal Capacity (kWh)"] = self.capacity_kwh_nominal
results[f"{self.end_use} Actual Capacity (kWh)"] = self.capacity_kwh
```

HARES emits neither. Both are available internally but not exposed. Without them, temperature-derating and degradation behaviour cannot be observed or verified through telemetry alone.

**Fix:** Add `nominal_capacity_kwh` and `actual_capacity_kwh` keys to `telemetry_keys.rs`, `default_telemetry()`, `battery_telemetry_fields()`, and emit at end of `step()`.

---

### MEDIUM — Missing telemetry: `energy_to_discharge_kwh`

**OCHRE reference:** Battery.py:448 (verbosity >= 7)
```python
results[f"{self.end_use} Energy to Discharge (kWh)"] = self.get_kwh_remaining()
```

OCHRE's `get_kwh_remaining()` returns `(soc - soc_min) * capacity_kwh * efficiency`. HARES has no equivalent telemetry field. Dispatch actors must reconstruct this from raw fields, creating duplication and risk of inconsistency if any of the constituent fields change meaning.

**Fix:** Compute and emit `energy_to_discharge_kwh = (self.soc - self.soc_min) * self.capacity_kwh * self.discharge_efficiency` at end of `step()`.

---

### LOW — Individual degradation states (Q1/Q2/Q3) not exposed

**OCHRE reference:** Battery.py:452-454 (verbosity >= 7)
```python
results[f"{self.end_use} Degradation State Q1"] = self.degradation_states[0]
results[f"{self.end_use} Degradation State Q2"] = self.degradation_states[1]
results[f"{self.end_use} Degradation State Q3"] = self.degradation_states[2]
```

HARES rolls all three lithium-loss mechanisms into a single `capacity_fade_pct` scalar. `q_li1` (calendar SEI), `q_li2` (cycle), `q_li3` (BOL transient) are private/crate-internal in `DegradationState`. Without them it is not possible to attribute fade to calendar vs. cycling aging, which is the primary application of the degradation model in fleet simulations.

**Fix:** Add `deg_q_calendar`, `deg_q_cycle`, `deg_q_bol_transient` to telemetry keys; add pub(crate) accessors on `DegradationState`; emit in `step()`.

---

### LOW — EBM (equivalent battery model) fields absent

**OCHRE reference:** Battery.py:468-480 — `make_equivalent_battery_model()` emits 8 fields: EBM Energy, Min/Max Energy, Max Power, Efficiency, Baseline Power, Max Discharge Power, Discharge Efficiency.

HARES has no EBM output. This is optional in OCHRE too, but it is the primary interface for fleet-level dispatch (optimizer-friendly single-timestep model). Not a blocking defect.
