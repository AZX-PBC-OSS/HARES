## Background/Context

OCHRE routes `Average Water Draw (L/day)` from clothes washer/dishwasher to the water heater. HARES `WetAppliance` has no fluid/water port. The water heater is under-loaded, missing thermal coupling with appliances.

## Work to Do

Use the existing `PortContribution::Custom` / `DomainId` mechanism — no new coupling architecture needed.

- [ ] Register `pub const HOT_WATER_DRAW: DomainId = DomainId(4)` in `crates/hares-types/src/domain_solver.rs`
- [ ] Add `hot_water_draw_rate_kg_s: f64` field to `WetAppliance`. Computed at init: `hot_water_draw_volume_l / total_cycle_duration_s` (water ≈ 1 kg/L). Dryer defaults to 0.0
- [ ] In `WetAppliance::update_outputs()`, when `self.active && self.hot_water_draw_rate_kg_s > 0.0`, write `PortContribution::Custom { domain_id: HOT_WATER_DRAW, payload: [draw_rate_kg_s, 0..] }`. Zero-copy stack-allocated payload
- [ ] Add `PortDeclaration { port_type: Custom, domain_id: Some(HOT_WATER_DRAW) }` to wet appliance port declarations
- [ ] In each water heater's `step()` (resistance, gas, heat_pump_wh), read `ports.custom` for `HOT_WATER_DRAW` domain before calling `resolve_storage_step_inputs`. Sum with schedule-sourced draw: `total_draw_kg_s = schedule_draw_kg_s + wet_appliance_draw_kg_s`
- [ ] In `hpxml/equipment.rs`, inject `hot_water_draw_volume_l` into clothes washer and dishwasher equipment specs from HPXML `WaterHeatingUse` (defaults: 15.0 L/cycle washer, 6.0 L/cycle dishwasher per OCHRE)
- [ ] `schedule_resolve.rs` needs no `COLUMN_MAPPINGS` changes — draw volume is a static HPXML parameter, not a per-timestep schedule column
- [ ] Draw rate is temporal (constant while cycle active), NOT proportional to electrical power

**Stage ordering**: WetAppliance = `Independent` (rank 0), WaterHeater = `Thermal` (rank 2). Demand is written to `ports.custom` before WH reads it. Zero-copy.
