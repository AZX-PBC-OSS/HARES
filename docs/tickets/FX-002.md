## Background/Context

`build_aggregate_batch` (aggregation.rs:325) applies `weighted_values[idx] += v * sample_weight` uniformly to all columns. For `(C)` (temperature) and `(-)` (dimensionless ratios like SOC) columns, the correct fleet-level aggregate is a weighted mean (`sum(v*w) / sum(w)`), not a weighted sum. The code never divides by total weight. The `Accumulator::finish` Phase 1 path (line 98) is **not** buggy — it's purely intra-dwelling temporal resampling.

For 2 buildings with weights [1.0, 2.0] and temps [20°C, 30°C]: the actual wrong output is `80` (raw weighted sum, no division). The correct answer is `(1×20 + 2×30)/(1+2) = 26.7°C`. The existing test at line 624 asserts the buggy value (`temp == 49.0`).

**Critical semantic distinction**: Phase 1 (temporal) and Phase 2 (cross-dwelling fleet) need different aggregation rules for the same column. `(kW)` should be `Mean` in Phase 1 (temporal average) but `Sum` in Phase 2 (fleet total power). Only `(C)` and `(-)` should be `WeightedMean` in Phase 2. The current `ColumnAggregation` enum conflates these two phases.
