## Background/Context

Each HVAC equipment type needs a real `core_output()` implementation replacing the
default stub. All HVAC equipment are `Consumption` electrical, most have thermal
output (via ports, not CoreOutput), many have operating mode. Gas furnace/boiler
also report fuel.

## Work to Do

For each HVAC equipment file:
- [ ] Add `core_output: CoreOutput` field to the equipment struct.
- [ ] Set `core_capabilities` in EquipmentDescriptor constructor (see plan table).
- [ ] Build local `CoreOutput` during `step()` from the same internal state that
      drives PortContributions and telemetry. Assign to `self.core_output` only on
      success (after ports are written, before returning Ok).
- [ ] Override `fn core_output(&self) -> &CoreOutput { &self.core_output }`.
- [ ] `core_output` is a derived cache, NOT persisted in checkpoints. After
      restore, it starts as `CoreOutput::default()` and is refreshed on the next
      `step()` call. This matches the existing pattern (e.g., generator.rs:738
      recomputes derived caches post-restore).
