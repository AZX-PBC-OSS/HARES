## Background/Context

Batch of medium Python/RL fixes:
- M24: `VecDwellingGymEnv.step` ignores `actions` arg in Rust path; Python fallback applies no controls
- M25: `reset()` calls `load_state` then `reset_with_seed` which discards the loaded state
- M26: `record_batches_to_polars_df` crashes on non-Float64/String Arrow types

## Work to Do

- [ ] **M24**: In `batch_step_py`, call `apply_control` for each action within the same closure before `step_core`. Remove stale comment at line 31 (`// v1 baseline: actions are accepted for API shape but not yet mapped`). Note: `PyRef<'_, PyDwelling>` is not `Send` — see FX-015 for the GIL constraint; this fix should coordinate with FX-015
- [ ] **M25**: In `reset()`, add a `fn reseed_rng(&mut self, seed: u64)` method to `PyDwelling` that only replaces the RNG without rebuilding. Then `reset()` calls `load_state` + `reseed_rng` instead of `load_state` + `reset_with_seed`. Same fix needed in `vec_env.py:118-120`
- [ ] **M26**: In `record_batches_to_polars_df`, add handlers for `Int32Array`, `Int64Array`, `UInt32Array`, `UInt64Array`, `Float32Array`, `BooleanArray`, `TimestampSecondArray`/`TimestampMillisecondArray` (convert timestamps to `i64` epoch — polars accepts this)
- [ ] **Error reporting**: `StepResult.info` is `HashMap<String, f64>` — a string error cannot fit. Either add a separate `error: Option<String>` field or change the type to `HashMap<String, serde_json::Value>`
- [ ] **`_max_steps`**: Add `time_res: timedelta | float = 60.0` parameter to `VecDwellingGymEnv.__init__` (mirroring `DwellingGymEnv`)
- [ ] Add Python tests for each fix
- [ ] **Add `uv run pytest tests/python/ -x` to verification steps** (currently only Rust tests are listed)
