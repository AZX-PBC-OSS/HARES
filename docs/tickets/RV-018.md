## Background/Context

Both smoke tests (`smoke_beopt_1h` and `smoke_resstock_1h`) print OCHRE reference values and HARES outputs via `eprintln!` but make zero numeric assertions. The only assertion is `!matches!(result.status, SimStatus::Failed(_))`, which passes even if every kWh value is off by 100%. These tests cannot detect physics regressions.

## Work to Do

- [ ] Add tolerance-bounded assertions on key simulation outputs for both smoke tests
- [ ] Use relative tolerance where values are large, absolute tolerance where values are small
- [ ] Assertions should be broad enough to not break on minor physics improvements but tight enough to catch regressions

## Tests Added

**tests/regression/smoke_test.rs (additions to existing tests):**

For `smoke_beopt_1h`:
- `assert_zone_temp_within_physical_bounds` — all zone temperatures in [-50, 80]°C at every recorded step
- `assert_total_hvac_energy_nonzero` — total HVAC energy > 0 kWh (equipment actually fired)
- `assert_total_electrical_consumption_in_range` — total electrical within [expected * 0.5, expected * 2.0] of OCHRE reference (50% tolerance band for now, tighten as parity improves)
- `assert_no_nan_in_results` — no NaN values in any output column

For `smoke_resstock_1h`:
- Same four assertion categories as above with ResStock-appropriate reference values

## Measures of Success

- [ ] A deliberate physics regression (e.g., zeroing out solar gains) causes at least one smoke test to fail
- [ ] Normal simulation passes all assertions
- [ ] Tolerance bands are documented with rationale

## Verification

- [ ] `cargo test --test smoke_test` passes
- [ ] Deliberately break a physics parameter → test fails
