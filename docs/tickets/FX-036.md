## Background/Context

Batch of medium control/fleet fixes:
- M11: `simulation_results.steps` stores every StepResult in memory (unbounded growth). StreamingRecorder should be the only copy.
- M12: Battery self-consumption has no `net_power` injection. Need to pass net household power to battery before its step.
- M13: `ochre_signal_to_control` iterates HashMap non-deterministically. Control ordering could be unstable.

## Work to Do

- [ ] **M11**: Remove `simulation_results.steps.push(step_result.clone())` from the hot path. Also remove `run_warmup`'s `steps.clear()` (line 745) as dead code. Either remove `SimulationResults.steps` from the public type entirely or document it as always-empty
- [ ] **M12**: Split `Electrical` stage into sub-ranks via `stage_rank()` in `dwelling.rs`. Change `stage_rank` to accept `&EquipmentDescriptor` and use `EndUse::Battery` to discriminate:
  ```rust
  fn stage_rank(desc: &EquipmentDescriptor) -> u8 {
      match desc.stage {
          ExecutionStage::Independent => 0,
          ExecutionStage::Electrical if desc.end_use == EndUse::Battery => 2,
          ExecutionStage::Electrical => 1,
          ExecutionStage::Thermal => 3,
          ExecutionStage::EnvelopeResolution => 4,
      }
  }
  ```
  No new `ExecutionStage` variant. Battery stays `Electrical` but sorts to rank 2 after all other `Electrical` equipment (rank 1). Battery reads `ports.electrical.net_active_kw()` directly — no snapshot, no injection field needed. Zero-copy, zero-allocation. Update sort call at dwelling.rs:801 and the unit test at dwelling.rs:1966
- [ ] **M13**: In `ochre_signal_to_control`, collect keys into a `BTreeMap` for deterministic order. Replace all three `eprintln!("[WARN]")` sites: two in `dwelling.rs` (lines 359, 374) and one in `compat.rs` (line 78) with `tracing::warn!`
- [ ] **Price signal**: Add `// TODO` comment in `run_timestep` near where price signal would be read. Do not remove the public setter (Python API already exposes it)
