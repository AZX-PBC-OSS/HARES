## Background/Context

Five code quality issues:

1. **T7-1:** `usize::MAX` sentinel for missing zone env index. Should be `Option<usize>` for compiler-enforced safety.
2. **T7-4:** `save_postcard` panics on serialization failure. Should return `Result` for graceful checkpoint failure handling.
3. **T7-6:** `InvariantChecker::new()` constructed every timestep. Should be a Dwelling field.
4. **T7-7:** 6 pre-existing clippy errors (unused imports/fields) in BMS and ev_driver.
5. **T7-9:** Zero `time_res_minutes` produces `u32::MAX` trip steps in EV driver.

## Work to Do

- [ ] Replace `usize::MAX` sentinel at `dwelling/mod.rs:213-214` with `Option<usize>`. Update all access sites to use `if let Some(idx)` instead of `if idx < len`
- [ ] **Decision: keep the panic in `save_postcard`, add `try_save_postcard`.** The existing `save_postcard` is called at 20+ sites via the `SaveState` trait. Changing the return type is a large, risky refactor for a path that is "infallible in practice" (postcard serialization only fails for unsupported types, which would be caught at development time). Instead: add `pub fn try_save_postcard<T: Serialize>(state: &T) -> Result<Vec<u8>, HaresError>` alongside the existing function. Update `DwellingCheckpoint::save()` (the file-writing path where graceful failure matters) to use `try_save_postcard`. Leave per-equipment `save_state()` calls using the panicking version since they serialize known types
- [ ] ~~Move `InvariantChecker` to a Dwelling field~~ — handled by RV-005 (dwelling hot-path consolidation). Do NOT duplicate this work
- [ ] Fix all 6 clippy errors in `bms.rs`, `ev_driver/mod.rs`, `ev_driver/time_window.rs`: remove unused imports, address unused field warnings
- [ ] Add `debug_assert!(self.time_res_minutes > 0.0)` at the start of `EvDriverActor::decide()`. In release builds, guard with `.max(1.0)` to prevent `u32::MAX` trip steps
