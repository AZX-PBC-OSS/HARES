# FIX-011: Generator ramp rate units documented as kW/s, OCHRE uses kW/min

> **Resolved** (2026-03-19): Clean implementation approach adopted.

> **Architecture note:** HARES Rust core must use clean, typed, SI-unit config keys only. Any OCHRE key/unit translation happens in the Python adapter layer (`python/ochre_next/compat/`). Do not add dual-key lookups or OCHRE naming conventions to Rust code.

> **Status:** Already handled. The Rust core uses `delta_kw_per_s` (SI). The OCHRE `ramp_rate` (kW/min) conversion already exists in `python/ochre_next/compat/ochre_config.py:66`. No Rust changes needed.

## Resolution

HARES uses **kW/s** as the native/internal unit for generator ramp rate. This is documented in the code comments at `generator.rs:67-70`:

```rust
/// Conservative ramp rate for a residential-class reciprocating generator.
/// A 10 kW unit ramps to full load in ~10 s → 1 kW/s.
/// OCHRE uses 0.1 kW/min (~0.0017 kW/s) which is unrealistically slow for
/// residential reciprocating units; we use kW/s for finer-grained control.
const DEFAULT_DELTA_KW_PER_S: f64 = 1.0;
```

## Architecture

### Clean Core (generator.rs)

The Rust implementation is clean with **no backward compatibility shims**:

- **Config key**: `delta_kw_per_s` (kW/s, native/internal units)
- **Default**: 1.0 kW/s (10 kW generator reaches full load in 10 seconds)
- **Application**: `delta.min(self.delta_kw_per_s * dt_s)` at `generator.rs:479`

### OCHRE Migration Layer (Python)

OCHRE migration is handled via a clean Python adapter that translates OCHRE-style configs to HARES-style:

**Location:** `python/ochre_next/compat/ochre_config.py`

```python
from ochre_next.compat import ochre_generator_config

# OCHRE: ramp_rate in kW/min → HARES: delta_kw_per_s in kW/s
config = ochre_generator_config(
    capacity=10.0,
    ramp_rate=1.0,  # OCHRE: 1 kW/min
    efficiency=0.30,
)
# Result: {"rated_power_kw": 10.0, "delta_kw_per_s": 0.01667, ...}
```

**Key translation:** `delta_kw_per_s = ramp_rate_kw_per_min / 60.0`
