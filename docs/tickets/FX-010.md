## Background/Context

For opaque surfaces, the solver injects raw POA irradiance without multiplying by surface absorptivity. Additionally, the opaque solar branch (`solar_input_indices`) is **dead code in production** — `dwelling.rs` never populates `solar_input_indices` for opaque boundaries. The result is that opaque surfaces currently receive **zero solar gain** in all real simulations, not just incorrectly-scaled gain.

## Work to Do

- [ ] Add `absorptivity: f64` field to `ExteriorSurfaceInfo` (sourced from HPXML via FX-006)
- [ ] **Wire opaque solar into the active code path**: deliver solar gain via `exterior_surfaces` (which is already the canonical list with correct `input_index`), adding a new `apply_exterior_solar_inputs` method that iterates `self.config.exterior_surfaces`. This avoids touching `solar_input_indices` or `dwelling.rs`
- [ ] Formula: `u[idx] += (direct + diffuse + reflected) * absorptivity * area_m2` — note `+=` (accumulate, not overwrite) and `* area_m2` (convert W/m² to W)
- [ ] Also fix the existing window path: change `=` to `+=` at line 468, and the opaque path at line 471
- [ ] Default absorptivity to **0.60** when not specified (matching OCHRE Envelope.py:222; EnergyPlus uses 0.70 but OCHRE uses 0.60)
- [ ] Add test: two surfaces with different absorptivities, verify proportional solar gain in W (not W/m²)
