# FIX-028: HPXML system type parsed as empty string when missing

> **Clarified** (Codex review 2026-03-19): `resolve_hvac` and related HVAC resolver paths in `equipment.rs` are currently non-fallible. Fix requires making them return `Result<>` and emitting hard errors when required HPXML type tags (HeatingSystemType, CoolingSystemType, HeatPumpType) are missing. This is an API change that affects all callers.

**Severity:** HIGH
**Crate:** `hares-io`
**File:** `crates/hares-io/src/hpxml/equipment.rs`

---

## Bug

In `equipment.rs` lines 100, 138, and 168, missing HVAC system type elements default to empty strings:

```rust
// equipment.rs:100 (HeatingSystem)
let system_type = parse_named_type(heating, "HeatingSystemType").unwrap_or_default();

// equipment.rs:138 (CoolingSystem)
let system_type = child_text(cooling, "CoolingSystemType").unwrap_or_default();

// equipment.rs:167-168 (HeatPump)
let heat_pump_type = child_text(heat_pump, "HeatPumpType")
    .unwrap_or_default()
    .to_ascii_lowercase();
```

When the system type is missing, `unwrap_or_default()` produces an empty string. This empty string then flows into `canonical_hvac_heating_name("", fuel)` or `canonical_hvac_cooling_name("", fuel)`, which may return an incorrect or generic equipment name. The equipment gets instantiated with the wrong type, wrong performance curves, and wrong default parameters.

`HeatingSystemType`, `CoolingSystemType`, and `HeatPumpType` are all required fields in the HPXML 4.0 schema.

## OCHRE Reference

OCHRE `ochre/inputs/hpxml.py` reads system type as a required field. If the element is missing or unrecognized, OCHRE raises a `KeyError` or logs an explicit warning and skips the equipment. OCHRE never silently maps an empty string to an equipment name.

## Fix

1. For `HeatingSystemType`: return an error if missing.

```rust
let system_type = parse_named_type(heating, "HeatingSystemType")
    .ok_or_else(|| HaresError::Hpxml(
        "HeatingSystem is missing required HeatingSystemType element".into(),
    ))?;
```

2. For `CoolingSystemType`: return an error if missing.

```rust
let system_type = child_text(cooling, "CoolingSystemType")
    .ok_or_else(|| HaresError::Hpxml(
        "CoolingSystem is missing required CoolingSystemType element".into(),
    ))?;
```

3. For `HeatPumpType`: return an error if missing.

```rust
let heat_pump_type = child_text(heat_pump, "HeatPumpType")
    .ok_or_else(|| HaresError::Hpxml(
        "HeatPump is missing required HeatPumpType element".into(),
    ))?
    .to_ascii_lowercase();
```
