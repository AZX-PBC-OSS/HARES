## Background/Context

Rust exposes 16 enum/bitflag types that Python users must currently reference via raw strings. Exposing them as proper `#[pyclass]` types enables IDE autocomplete, type safety, and use in other PyO3 APIs (e.g., typed ControlSignal constructors in PY-006, equipment descriptors in PY-008).

**Note:** There are two distinct `SimStatus` enums in the codebase — `hares_core::engine::SimStatus` and `hares_fleet::fleet::SimStatus`. Both have identical variants (Ok, Flagged, Failed) with the same semantics. Expose a single `PySimStatus` that can convert `From<>` both Rust types.

  - `PyOperatingMode` — 12 variants: Off, Heating, Cooling, Defrost, Standby, Charging, Discharging, HeatingHP, HeatingER, HeatingHPAndER, HeatPumpWH, BackupElement
  - `PyExecutionStage` — 4 variants: Independent, Electrical, Thermal, EnvelopeResolution
  - `PyFluidType` — 3 variants: Water, Glycol, Refrigerant
  - `PyDRLevel` — 5 variants: Normal, Moderate, High, Critical, GridEmergency
  - `PyInverterPriority` — 3 variants: Watt, Var, Cpf
  - `PyDutyCycleComponent` — 2 variants: Compressor, BackupElement
  - `PySimStatus` — 3 variants: Ok, Flagged, Failed. `Flagged`/`Failed` carry a `message: Option<String>` accessible via getter. Implement `From<hares_core::SimStatus>` and `From<hares_fleet::SimStatus>` so a single Python type maps both Rust types.
  - `PyAggregationResolution` — 2 variants: FifteenMin, Hourly
  - `PyResStockVersion` — 3 variants: V2024_1, V2024_2, V2025_1. `from_str` must accept both dotted ("2024.1") and underscore ("V2024_1") forms.

    - `__contains__` to check if a capability is present
    - `__repr__` showing active flags
    - `from_list(names: list[str])` classmethod
  - `PyLutType` — 3 variants: ChargingCurve, Ocv, UNeg. Used for battery LUT injection in PY-014.
  - `PyBatteryChemistry` — 4 variants: Nmc, Lfp, Nca, Lto. Used for battery model selection in PY-014.
