# FIX-024: HPXML window area silently defaults to 0 m²

> **Clarified** (Codex review 2026-03-19): `parse_boundary` and `parse_windows` in `building.rs` are currently non-fallible (return default structs). Fix requires refactoring these to return `Result<>` with structured HPXML parsing errors. Apply boundary-type-specific validation: windows MUST have non-zero area, walls MUST have non-zero area, etc.

**Severity:** HIGH
**Crate:** `hares-io`
**File:** `crates/hares-io/src/hpxml/building.rs`

---

## Bug

In `building.rs` line 477, missing window area defaults to zero:

```rust
// building.rs:477
let area_m2 = parse_value_with_units(window.child("Area"), ValueKind::Area).unwrap_or(0.0);
```

The same pattern appears in `parse_boundary` at line 517 for walls, floors, and other surfaces:

```rust
// building.rs:517
let area_m2 = parse_value_with_units(node.child("Area"), ValueKind::Area).unwrap_or(0.0);
```

A window with area 0 m² contributes zero solar gains and zero conduction losses. If the HPXML is malformed or the `<Area>` element is missing, the window silently disappears from the thermal model. This can remove hundreds of watts of solar gain and significant conduction loss from a building.

`Area` is a required field in the HPXML 4.0 schema for windows and enclosure surfaces.

## OCHRE Reference

OCHRE `ochre/inputs/hpxml.py` reads window area and raises an error if the HPXML element is missing or unparseable. OCHRE does not silently default to zero area for any envelope surface.

## Fix

1. For windows: return an error if `Area` is missing or zero. A zero-area window is physically meaningless and indicates bad input data.

```rust
let area_m2 = parse_value_with_units(window.child("Area"), ValueKind::Area)
    .ok_or_else(|| HaresError::Hpxml(format!(
        "Window '{}' is missing required Area element", id
    )))?;
if area_m2 <= 0.0 {
    return Err(HaresError::Hpxml(format!(
        "Window '{}' has non-positive area: {}", id, area_m2
    )));
}
```

2. For `parse_boundary`: return an error if `Area` is missing for boundary types where it is required (walls, roofs, floors, doors). Foundations may legitimately have computed area.
