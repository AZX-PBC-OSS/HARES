# FIX-016: Water heater draw profiles are constant average

> **Clarified** (Codex review 2026-03-19): Draw rate is effectively static after init across ALL storage WH types (resistance, gas, HPWH), not just resistance. Fix must add per-step schedule lookup for draw flow rate AND mains temperature in the base WH module, consumed by all three WH implementations. See `resistance.rs:341`, `heat_pump_wh.rs:566`, `gas.rs:334` — all have same pattern.

**Severity:** HIGH
**Crate:** `hares-equipment`
**Files:** `crates/hares-equipment/src/water_heater/resistance.rs`, `crates/hares-equipment/src/water_heater/tank.rs`

---

## Bug

HARES water heater uses a constant `draw_flow_rate_kg_s` set during init and never updated from a time-varying schedule:

```rust
// resistance.rs:178-179
mains_temp_c: 15.0,
draw_flow_rate_kg_s: 0.0,
```

```rust
// resistance.rs:339-341
self.mains_temp_c =
    first_f64(config, &["mains_temp_c", "inlet_temp_c"]).unwrap_or(self.mains_temp_c);
self.draw_flow_rate_kg_s = resolve_draw_rate_kg_s(config);
```

The tank model (`tank.rs`) supports per-timestep draws via `DrawResult` and tempered draw configs (lines 35-67), but the resistance WH feeds a constant `draw_flow_rate_kg_s` to it every step. OCHRE loads per-timestep hot water draws from schedule CSV, producing realistic peak draw events that stress the tank.

Using constant average flow rate misses peak draw dynamics (e.g., a 10 L/min shower draw followed by no-draw periods). This affects tank stratification, recovery dynamics, and annual energy consumption.

## OCHRE Reference

OCHRE `Equipment/WaterHeater.py` reads per-timestep draw rates from the schedule:

```python
# Each timestep gets a draw rate from the schedule CSV
# draw_rate = schedule['Hot Water Draw (L/min)']
```

OCHRE loads draw profiles that have realistic event-based patterns: high flow during showers/dishwasher, zero flow at night, etc.

## Fix

1. Pass per-timestep draw profile as a schedule column (similar to how power schedules work in `schedule_resolve.rs`).
2. In the water heater `step()` method, read the current draw rate from the environment state's schedule domain payload.
3. Replace the constant `self.draw_flow_rate_kg_s` with a per-timestep lookup.

```rust
// In step():
let draw_l_per_min = lookup_schedule_value(env, self.draw_schedule_col_idx);
let draw_kg_s = draw_l_per_min / 60.0; // L/min -> kg/s (water density ~1 kg/L)
```
