## Background/Context

**Blocked on HARES-071** — the `InvariantChecker` infrastructure must exist before this ticket can proceed. Verify HARES-071 has landed and its API matches assumptions below before starting.

**Blocked on RV-005** — both tickets modify `dwelling/mod.rs`. RV-005 must land first to avoid merge conflicts. RV-005 also moves `InvariantChecker` to a Dwelling field, so this ticket should NOT duplicate that work.

Four invariant checks are fully implemented in `InvariantChecker` but never wired into `Dwelling::check_invariants`:

1. **Tank temperature bounds (T4-1):** `check_temperatures` is called with an empty slice for tank temps. Water heater tank nodes are never validated against the `[0, 100]°C` bounds.

2. **SOC bounds (T4-2):** `check_soc` is never called for Battery or EV. Both write `"soc"` to telemetry but the check is dead code. The `.clamp()` calls in equipment silently normalize out-of-range values.

3. **Thermal balance (T4-3):** `check_thermal` requires zone thermal mass and previous-step temperatures from `ThermalSolver`, which are not currently exposed. Design gap requires a small API addition.

4. **Moisture balance (T4-4):** `check_moisture` is never called despite inputs being available (humidity solver deltas + latent port gains).

## Work to Do

- [ ] **Tank temps:** In `check_invariants`, iterate `self.equipment`, identify water heater types by `end_use`. Read per-node telemetry keys (`tank_node_0_c` through `tank_node_{n}_c`), collect into a Vec, pass to `checker.check_temperatures(&zone_temps_c, &tank_temps)`
- [ ] **SOC:** In `check_invariants`, iterate `self.equipment` for Battery and EV end-uses. Read `telemetry().get("soc")`. Call `checker.check_soc(soc, 0.0)` (use 0.0 for accumulated_error until error tracking is added)
- [ ] **Thermal balance:** Add a method to `ThermalSolver` with this contract:
  ```rust
  /// Returns the inputs needed for thermal balance invariant checking.
  /// Must be called AFTER `resolve()` but BEFORE the solver state is
  /// updated for the next step.
  pub fn balance_inputs(&self) -> ThermalBalanceInputs {
      ThermalBalanceInputs {
          /// Per-zone thermal capacitance [J/K], fixed after init
          zone_capacitances_j_per_k: &[f64],
          /// Per-zone temperature BEFORE this step's resolve [°C]
          prev_zone_temps_c: &[f64],
      }
  }
  ```
  In `check_invariants`, compute `delta_e_storage = sum((T_new - T_old) × C_zone)` and call `checker.check_thermal(q_gains, delta_e_storage, q_loss)`. The `q_gains` slice comes from `EnvelopeComponentGains` and the `q_loss` is the envelope conduction loss (available from the component gains breakdown)
- [ ] **Moisture balance:** After humidity solver resolves, compute per-zone `delta_m_water = (w_new - w_old) × rho_air × V_zone`. Collect latent gains from `self.ports.thermal` (each `ThermalAccumulator` has `latent_gain_w`). Call `checker.check_moisture(delta_m, q_latent_terms)`
- [ ] Store `InvariantChecker` as a field on `Dwelling` instead of constructing per-timestep

## Tests Added

**hares-core (with `--features check_invariants`):**

**Telemetry injection approach:** Tests inject out-of-bounds values by constructing equipment with deliberately bad internal state (e.g., a `StratifiedTank` with `node_temps_c[0] = 150.0`), NOT by overriding telemetry after the fact. This ensures the invariant check reads from the same path as production.

- `invariant_tank_temp_out_of_bounds_detected` — construct a water heater with initial node temperature > 100°C. Run one step with `check_invariants` enabled. Assert `InvariantViolation` with `check_name` containing "temperature"
- `invariant_tank_temp_nan_detected` — construct with NaN node temperature. Assert violation on first step
- `invariant_soc_above_one_detected` — construct a battery with initial SOC > 1.0 (bypass clamp in test setup). Assert `check_soc` fires a `tracing::warn!` (soc_bounds is non-fatal per spec). Use `tracing_test` or similar to capture the warning
- `invariant_soc_negative_detected` — initial SOC < 0.0. Assert warning
- `invariant_thermal_balance_sign_flip_detected` — create a custom equipment that writes a sign-flipped thermal gain to ports (e.g., `port.add_sensible(-5000.0)` when it should be positive). Wire into a dwelling. Assert `InvariantViolation` with `check_name == "thermal_balance"`
- `invariant_moisture_balance_double_count_detected` — create a custom equipment that double-writes latent gain. Assert violation with `check_name == "moisture_balance"`
- `invariant_all_pass_normal_simulation` — run a 24-hour simulation with `check_invariants` enabled. Assert zero violations (regression guard — if this fails, either the check has a false positive or the simulation has a real bug)
- `invariant_checker_stored_on_dwelling` — verify `InvariantChecker` is a field on `Dwelling` (compile-time check via field access in test)
