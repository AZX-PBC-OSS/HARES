## Background/Context

DER_Detection defines 12 behavioral archetypes combining driver patterns with charging strategies. These become factory presets for the EvDriverActor (DER-007). Archetype IDs live in `hares-equipment` (catalog concern).

Users can use presets for common configurations OR construct a fully custom `EvDriverActor` with arbitrary strategy, policy, and driving parameters for research scenarios.

All stochastic parameters (daily miles, arrival/departure fuzz) produce reproducible results via a required numerical seed passed to the EvDriverActor.

  ```rust

      pub id: EvArchetypeId,

      pub charging_level: ChargingLevel,

      pub plug_in_policy: PlugInPolicy,

  }
  ```
  Note: `ArchetypePreset` does NOT contain `daily_drive_miles` because the miles schedule is a `ScheduleSource` (which contains RNG state and isn't `Copy`/`const`). Instead, each preset provides a `fn build_miles_schedule(&self, seed: [u8; 32]) -> ScheduleSource` method that constructs the appropriate noisy TimeWindows schedule. Simple archetypes use a single Gaussian; richer ones (WFH, WeekendWarrior) use day-dependent distributions with min_value=0.0 clamps.
