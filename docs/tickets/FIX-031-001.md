## Background/Context

The thermal port lumps HVAC heating, cooling, appliance waste heat, jacket
losses, and duct losses into a single `sensible_gain_w` field. The dwelling
uses fragile post-hoc subtraction to split HVAC from internal gains. Adding
a category field lets each equipment declare the nature of its contribution
at the source.

## Work to Do

- [ ] Add `ThermalCategory` enum to `crates/hares-types/src/ports.rs`:
  ```rust
  #[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
  pub enum ThermalCategory {
      HvacHeating,
      HvacCooling,
      InternalGain,
      JacketLoss,
      DuctLoss,
  }
  ```
- [ ] Add `category: ThermalCategory` field to `PortContribution::Thermal` variant
- [ ] Add `category` field to `ThermalAccumulator` — change from single accumulator
  per zone to a per-zone, per-category accumulator. **Alternative (simpler):** keep
  `ThermalAccumulator` unchanged but add a parallel `categorized_sensible_w: HashMap<ThermalCategory, f64>`
  field that accumulates alongside the existing `sensible_gain_w`.
- [ ] Update `PortSlots::accumulate` to route categorized contributions
- [ ] Update `PortSlots::zero` to clear categorized data
- [ ] Export `ThermalCategory` from `hares-types`
- [ ] Fix all callers of `PortContribution::Thermal { zone, sensible_gain_w, latent_gain_w }`
  to add the `category` field. Use `InternalGain` as default for scheduled loads,
  `HvacHeating`/`HvacCooling` for HVAC, `JacketLoss` for water heaters.
