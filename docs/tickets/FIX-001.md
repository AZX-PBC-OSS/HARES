# FIX-001: Schedule fallback produces constant power instead of using default profiles

> **REVISED** (Codex review 2026-03-19): OCHRE does NOT error when a profile/column is missing — `convert_power_column` returns `None`. Corrected root cause: HARES should use default schedule profiles from `Default Schedule Parameters.csv`, not fall back to constant average power.

**Severity:** CRITICAL
**Crate:** `hares-io`
**File:** `crates/hares-io/src/schedule_resolve.rs`
**Status:** IMPLEMENTED

---

## Bug

When no CSV column exists for an equipment, the code fell back to `annual_kwh / 8760` constant power. This silently masked missing schedule data. Equipment ran at a flat average power instead of the time-varying default profile that exists in `Default Schedule Parameters.csv`.

## Fix (implemented)

1. Default schedule profiles from `Default Schedule Parameters.csv` are loaded at init via `load_default_profiles()` and passed to the schedule resolver.
2. When no CSV column exists, the fallback chain is:
   - **HPXML profile fractions** (building-specific, from `weekday_schedule_fractions` / `weekend_schedule_fractions` / `month_multipliers` in equipment parameters) — highest priority because they represent the actual building.
   - **Default CSV profile** (generic ANSI/RESNET/ICC 301 standard values from `Default Schedule Parameters.csv`) — used when no building-specific fractions are available.
   - **Constant power** (`annual_kwh / 8760`) — absolute last resort with a loud "THIS MAY BE INCORRECT" warning.
3. Warnings are logged via `tracing::warn!` at each fallback level.
4. `max_electric_power_w` is checked before `annual_electric_kwh` (matching OCHRE precedence, see FIX-002).

### Improvements over OCHRE

- **Analytical `annual_mean_fraction`**: Computes the annual mean of a profile using days-per-month weighting and 5:2 weekday/weekend ratio, rather than materializing 8760 values and calling `.mean()`. More precise and avoids year-specific day-of-week layout artifacts.
- **Compact profile storage**: Stores `power_profile_weekday`/`weekend`/`month` arrays + `power_profile_max_kw` instead of materializing 8760 values. Equipment evaluates the profile at runtime.
- **HPXML profile fallback**: An additional fallback layer using building-specific HPXML fractions before falling back to generic ANSI/RESNET defaults.

### Bug fix (2026-03-19): Corrected fallback priority

The initial implementation had HPXML and default CSV profile fallbacks in the wrong order (default CSV first, HPXML second). This caused building-specific HPXML fractions to be silently discarded in favor of generic standards whenever a default profile existed. Fixed to match OCHRE's priority: HPXML fractions first, then default CSV profiles.

## Tests

- `missing_csv_column_uses_default_profile_and_logs_warning` — No CSV column + default profile available → uses daily_profile source, logs warning.
- `missing_csv_and_missing_default_profile_falls_back_to_constant_with_loud_warning` — No CSV column + no default profile → constant power, logs "THIS MAY BE INCORRECT".
- `default_profile_scaling_varies_and_scales_with_annual_kwh` — Doubling `annual_kwh` doubles `power_profile_max_kw`.
- `max_electric_power_w_without_annual_kwh_default_profile_branch_is_non_zero` — `max_electric_power_w` alone produces non-zero profile in default-profile branch.
- `max_electric_power_w_takes_precedence_over_annual_kwh_csv_branch` — When both are present, `max_electric_power_w` wins.
