# FIX-001: Schedule fallback produces constant power instead of using default profiles

> **REVISED** (Codex review 2026-03-19): OCHRE does NOT error when a profile/column is missing — `convert_power_column` returns `None`. Corrected root cause: HARES should use default schedule profiles from `Default Schedule Parameters.csv`, not fall back to constant average power.

**Severity:** CRITICAL
**Crate:** `hares-io`
**File:** `crates/hares-io/src/schedule_resolve.rs`

---

## Bug

In `schedule_resolve.rs` lines 409-417, when no CSV column exists for an equipment, the code falls back to `annual_kwh / 8760` constant power. This silently masks missing schedule data. Equipment runs at a flat average power instead of the time-varying default profile that exists in `Default Schedule Parameters.csv`.

```rust
// schedule_resolve.rs:409-417
} else {
    let constant_kw = if annual_kwh > 0.0 {
        annual_kwh / 8760.0
    } else {
        0.0
    };
    let kw_series = vec![constant_kw; schedule_len];
    inject_kw_schedule(spec, &kw_series);
}
```

The real issue is that default schedule profiles from `Default Schedule Parameters.csv` are not being loaded and used as the primary fallback when a CSV column is missing. These profiles contain normalized hourly load shapes for each equipment type and should always be available.

## OCHRE Reference

OCHRE `ochre/utils/schedule.py` `convert_power_column` returns `None` (not an error) when a schedule column is missing. The caller then falls back to using the default schedule profile from `Default Schedule Parameters.csv`, which provides a normalized hourly load shape scaled by annual energy. OCHRE does NOT fabricate a flat constant schedule.

OCHRE also checks `Max Electric Power (W)` FIRST before computing from annual energy (see FIX-002).

## Fix

1. Ensure default schedule profiles from `Default Schedule Parameters.csv` are always loaded at init and available to the schedule resolver.
2. When no CSV column exists for an equipment type, look up the default profile by equipment type from the loaded defaults. Scale the normalized profile by annual energy to produce a time-varying schedule.
3. Log a warning (via `tracing::warn!`) when falling back to the default profile.
4. Only use constant power (`annual_kwh / 8760`) as an absolute last resort — when no CSV column AND no default profile exists — and log a loud warning (`tracing::warn!`) that this is happening.

Replace lines 409-417:

```rust
} else if let Some(profile) = default_profiles.get(&mapping.equipment_type) {
    // No CSV column -- use default schedule profile scaled by annual energy
    tracing::warn!(
        "schedule_resolve: no CSV column '{}' for '{}'; using default profile",
        col_name, mapping.equipment_name
    );
    let kw_series = scale_default_profile(profile, annual_kwh, schedule_len);
    inject_kw_schedule(spec, &kw_series);
} else {
    // Absolute last resort -- no CSV column AND no default profile
    tracing::warn!(
        "schedule_resolve: no CSV column '{}' and no default profile for '{}'; \
         falling back to constant power {:.3} kW -- THIS MAY BE INCORRECT",
        col_name, mapping.equipment_name, annual_kwh / 8760.0
    );
    let constant_kw = if annual_kwh > 0.0 { annual_kwh / 8760.0 } else { 0.0 };
    let kw_series = vec![constant_kw; schedule_len];
    inject_kw_schedule(spec, &kw_series);
}
```
