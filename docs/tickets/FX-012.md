## Background/Context

`apply_interior_longwave_inputs` collects `t_surfaces` from `self.x[s.state_index]` (capacitor node temp, not true surface temp). OCHRE computes: `t_surf_no_rad = rad_fractions * t_boundaries + (1 - rad_fractions) * t_zone`. For low-mass boundaries the error can be several degrees.

## Work to Do

- [ ] Add `radiation_frac: f64` to `InteriorSurfaceInfo` — range `[0, 1]`, defined as `R_film / (R_film + R_material)`, default to `1.0` (node temp = surface temp when no film resistance)
- [ ] Compute true interior surface temp: `t_surf = rad_frac * t_node + (1 - rad_frac) * t_zone`
- [ ] Use these true surface temps in `interior_longwave_linearised_w` call
- [ ] Update all existing test constructions of `InteriorSurfaceInfo` (thermal_solver.rs lines 845, 957, 1020, 1368, 1501, 1610, 1921, 2019, 2092, 2171, 2293) to supply the new field
- [ ] Add test comparing true vs node temps for a lightweight boundary — verify both magnitude of correction and energy conservation across zone surfaces

**Note**: `interior_lwr_zones` is currently `vec![]` in production (never wired into HPXML loading). This fix is necessary for correctness when the feature is connected. A follow-on task should wire up `interior_lwr_zones` during HPXML building construction using film resistance values already present in `EnvelopeLookup` (`FILM_R_WALL_ROOF = 0.1585`, `FILM_R_FLOOR_CEILING = 0.2642`).
