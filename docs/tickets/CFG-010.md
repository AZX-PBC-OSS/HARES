## Background/Context

All AC and heat pump cooling paths have the same SEER key mismatch: the resolver
writes `"efficiency_seer"` (from the bare `<SEER>` XML element) or
`"cooling_efficiency"` with `"cooling_efficiency_units" = "SEER"`, but the AC
`init()` reads `"seer"` or `"SEER"`. Neither key matches. Every AC/HP simulation
runs with the default SEER (typically 3.0 EIR equivalent), not the HPXML-provided
value. This corrupts cooling energy and capacity for every run.

The heat pump cooling path additionally drops per-stage SHR data (CW-008,
CW-010) and fails to infer 4-speed for mini-splits regardless of compressor type
(CW-009, CW-010).

Confirmed mismatches (Cluster A in CROSS-CUTTING.md):
- `air_conditioner.rs` reads `"seer"` / `"SEER"` — no match
- Resolver writes `"efficiency_seer"` at `resolve_hvac.rs:848`
- `heat_pump.rs` cooling side: same SEER mismatch

Confirmed structural bugs fixed here via typed config:
- CW-008 / CW-010: per-stage SHR is loaded but discarded because the config key
  `"shr_i"` is not in the equipment's read list
- CW-009 / CW-010: mini-split speed count read from `"number_of_speeds"` but
  the resolver writes 1 regardless of CompressorType for MSHPs

Fixes: CW-005 (AC SEER mismatch), CW-006 (room AC EER key), CW-008 (HP SHR not
propagated), CW-009 (mini-split speed count), CW-010 (combined HP cooling), UC-002
(cooling efficiency routing), CW-019 (dehumidifier config).

## Typed config structs to add

### `CentralAirConditionerConfig`
```rust
#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct CentralAirConditionerConfig {
    pub equipment_id: Option<u32>,
    pub zone_id: Option<u16>,
    pub capacity_w: f64,
    pub seer: f64,                       // replaces "efficiency_seer"/"seer"/"SEER"
    pub shr: Option<f64>,
    pub number_of_speeds: u8,
    pub stage_capacities_w: Option<Vec<f64>>,
    pub stage_eirs: Option<Vec<f64>>,
    pub stage_shrs: Option<Vec<f64>>,   // per-stage SHR — was discarded before
    pub fan_power_w: Option<f64>,
    pub fan_power_w_per_cfm: Option<f64>,
    pub fraction_load_served: Option<f64>,
    #[serde(flatten)]
    pub duct: DuctConfig,               // from core_config.rs (CFG-009)
    pub system_type: Option<String>,
    pub startup_cd: Option<f64>,
}
```
`equipment_type_name() = "Central AC"`.

### `RoomAcConfig`
`eer: f64`, `capacity_w`, `zone_id`, `equipment_id`.
`equipment_type_name() = "Room AC"`.

### `HeatPumpCoolerConfig` / `HeatPumpHeaterConfig`
Split into two structs (cooler and heater each have distinct key sets). Both
used by the same `HeatPump` equipment, deserialized into the appropriate struct
for each functional mode. Alternatively, use one `HeatPumpConfig` with both
heating and cooling fields and `Option` where one side may be absent.

Recommendation: single `HeatPumpConfig` with:
- `heating_capacity_w: f64`, `hspf: f64`
- `cooling_capacity_w: f64`, `seer: f64`
- `number_of_speeds: u8` (force 4 for MSHP — see mini-split rule below)
- `is_mini_split: bool`
- `stage_heating_capacities_w: Option<Vec<f64>>`
- `stage_cooling_capacities_w: Option<Vec<f64>>`
- `stage_heating_eirs: Option<Vec<f64>>`
- `stage_cooling_eirs: Option<Vec<f64>>`
- `stage_shrs: Option<Vec<f64>>`       // per-stage SHR, now preserved
- `backup_fuel: Option<String>`
- `backup_capacity_w: Option<f64>`
- `backup_eir: Option<f64>`
- `shr: Option<f64>`
- `fan_power_w: Option<f64>`, `fan_power_w_per_cfm: Option<f64>`
- `fraction_heating_load_served: Option<f64>`
- `fraction_cooling_load_served: Option<f64>`
- `#[serde(flatten)] duct: DuctConfig`
`equipment_type_name() = "Heat Pump"`. Also registered as `"Mini-Split Heat Pump"`.

Mini-split speed rule: the resolver must set `number_of_speeds = 4` and
`is_mini_split = true` unconditionally when the HPXML CompressorType indicates
variable-speed or when system_type is "mini-split". The equipment uses
`is_mini_split` to bypass CompressorType detection that currently breaks (CW-009).
