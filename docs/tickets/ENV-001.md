## Background/Context

To validate fixes in ENV-002 through ENV-007, we need per-boundary diagnostic data captured during RC construction. Currently `assemble_building_rc` returns only the state-space matrices — there's no way to inspect what R, C, and UA values were computed for each boundary. This makes it impossible to compare against OCHRE boundary-by-boundary.

## Work to Do

- [ ] Add `BoundaryDiagnostic`, `RCPath`, and `EnvelopeDiagnostics` types to `boundary_rc.rs`
  ```rust
  #[derive(Debug, Clone, Copy)]
  pub enum RCPath { Precomputed, MaterialLayer, FallbackR }

  #[derive(Debug, Clone)]
  pub struct BoundaryDiagnostic {
      pub boundary_idx: usize,
      pub ua_w_per_k: f64,        // area / R_total
      pub r_total_m2_k_w: f64,    // sum of all layer R + film R
      pub capacitance_j_k: f64,   // sum of all layer C
      pub n_rc_nodes: usize,
      pub interior_zone_idx: usize,
      pub exterior_target: ExteriorTarget,
      pub area_m2: f64,
      pub r_film_int_m2_k_w: f64,
      pub r_film_ext_m2_k_w: f64,
      pub path: RCPath,
  }

  #[derive(Debug, Clone)]
  pub struct EnvelopeDiagnostics {
      pub boundaries: Vec<BoundaryDiagnostic>,
      pub zone_capacitances_j_k: Vec<f64>,
      pub total_ua_w_per_k: f64,
  }
  ```
- [ ] Modify `assemble_building_rc` signature to return `Result<(BuildingRC, EnvelopeDiagnostics), String>`
- [ ] Populate `BoundaryDiagnostic` in each of the three construction paths (precomputed, layered, fallback) by computing R_total from the actual resistances added
- [ ] Update all call sites of `assemble_building_rc` (solver_builder.rs, tests) to destructure the tuple
- [ ] Re-export diagnostic types from `crates/hares-envelope/src/lib.rs`
- [ ] Add `beopt_boundary_ua_diagnostics` test in `tests/structural_envelope_oracle.rs`:
  - Builds the RC network, captures diagnostics
  - Prints a table: `idx | type | area | R_total | UA | path | zone_int | exterior`
  - Prints total UA and zone capacitances
  - **No assertions** — capture-only for development use
