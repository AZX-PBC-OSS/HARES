## Background/Context

OCHRE's `get_slab_insulation` (envelope.py:462-485) reads HPXML slab insulation attributes (`PerimeterInsulation`, `UnderSlabInsulation`) to generate format strings that the LUT uses to select the correct slab construction variant. HARES doesn't parse these, so the LUT may match the wrong R-value.

Depends on ENV-002 because slab zone assignment must be correct (Ground, not Outdoor) before insulation details matter for LUT matching.

## Work to Do

- [ ] Add `extract_slab_insulation(node: &XmlNode) -> Option<String>` to `building.rs`:
  - Parse `PerimeterInsulation/Layer/NominalRValue` and `PerimeterInsulation/Layer/InsulationDepth`
  - Parse `UnderSlabInsulation/Layer/NominalRValue`, `InsulationWidth`, `InsulationSpansEntireSlab`
  - Format strings matching OCHRE conventions exactly:
    - Perimeter only: `"{depth}ft R{r} Perimeter"` (e.g., `"2ft R10 Perimeter"`)
    - Underslab full width: `"R{r} Whole Slab"` (e.g., `"R20 Whole Slab"`)
    - Underslab partial: `"{width}ft R{r} Exterior"` (e.g., `"4ft R10 Exterior"`)
    - Both ≥100: `"Minimal"`
    - None: `"Uninsulated"`
  - **Important**: Number formatting must match OCHRE's Python `:n` format — use integers (no decimal point) for whole numbers. Verify against CSV entries.
- [ ] In `parse_boundary` for `BoundaryType::Slab`:
  - Call `extract_slab_insulation` and set `insulation_details`
- [ ] Add unit tests:
  - Perimeter insulation: depth=2, R=10 → `"2ft R10 Perimeter"`
  - Underslab full: R=20, spans_entire=true → `"R20 Whole Slab"`
  - Underslab partial: width=4, R=10 → `"4ft R10 Exterior"`
  - Minimal: both R≥100 → `"Minimal"`
  - No insulation → `"Uninsulated"`
- [ ] Verify format strings match entries in `defaults/envelope/Envelope Boundary Types.csv`
