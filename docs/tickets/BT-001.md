## Background/Context

When `boundary_rc.rs:build_layered_boundary` splits a thick dense layer (e.g., 100mm concrete) into sub-layers for Fourier stability, the split thickness information is lost. `solver_builder.rs` then computes `r_outermost_half` and `r_inner_half` from the **original** `material_layers` thickness, not the post-split sub-layer thickness.

For Case 900's 100mm concrete outer layer (k=0.51, density=1400), split into 2×50mm:
- Buggy `r_outermost_half`: `0.100 / (2 × 0.51) = 0.098` → `exterior_rad_frac = 0.234`
- Correct `r_outermost_half`: `0.050 / (2 × 0.51) = 0.049` → `exterior_rad_frac = 0.379`

This 38% underestimate of heat injection into thermal mass directly causes Case 900 heating to be 17% over and 900FF peak to be 6% over.

The interior side (`r_inner_half`, lines 260-278) has the identical bug — using original innermost layer thickness. While 9mm drywall never triggers splitting for BESTEST, any config with interior concrete/masonry would be affected.

Additionally, `r_zone_to_inner_m2_k_w` (boundary_rc.rs:481-485) has the same pre-split bug. It uses `inner_layer.thickness_m` from `valid_layers.last()` — also the pre-split thickness. This field feeds into `solver_builder.rs` for `diagnostic_r_zone_to_inner`. Once `r_inner_half_m2_k_w` is added, `r_zone_to_inner` must also be fixed to use the post-split inner layer thickness.

## Work to Do

### boundary_rc.rs

- [ ] Add two fields to `BoundaryDiagnostic` struct (after line 202):
  ```rust
  /// Half-resistance of the post-split outermost sub-layer [m²·K/W].
  /// `None` for fallback-R boundaries with no RC nodes.
  pub r_outer_half_m2_k_w: Option<f64>,
  /// Half-resistance of the post-split innermost sub-layer [m²·K/W].
  /// `None` for fallback-R boundaries with no RC nodes.
  pub r_inner_half_m2_k_w: Option<f64>,
  ```

- [ ] Modify `build_layered_boundary` return type from `Option<(NodeId, NodeId)>` to `Option<(NodeId, NodeId, f64, f64)>` — inner/outer nodes + inner/outer half-R values. The half-R values must be computed **inside** `build_layered_boundary` because `effective_layers` is local to that function. Reference: lines 758-762 already compute `outer.thickness_m / (2.0 * k_outer * outer_area)` for the post-split outer layer — extract the per-unit-area half-R from this existing calculation. Specifically:
  ```rust
  let ff = params.framing_factor;
  let outer = effective_layers[0];
  let k_outer = parallel_path_conductivity(outer.conductivity_w_m_k, ff);
  let r_outer_half = outer.thickness_m / (2.0 * k_outer);

  let inner = effective_layers.last().unwrap();
  let k_inner = parallel_path_conductivity(inner.conductivity_w_m_k, ff);
  let r_inner_half = inner.thickness_m / (2.0 * k_inner);
  ```
  **Critical**: use `parallel_path_conductivity(k, framing_factor)` not raw `k`. The existing code at line 760 already does this correctly — follow the same pattern.

- [ ] At the call site in `build_rc_graph` (lines 437-503), capture the returned half-resistances and populate the new `BoundaryDiagnostic` fields.

- [ ] Fix `r_zone_to_inner_m2_k_w` computation (lines 481-485): currently uses `inner_layer.thickness_m` from `valid_layers.last()` (pre-split). Replace with the post-split `r_inner_half` returned from `build_layered_boundary`:
  ```rust
  let r_zone_to_inner = if n_nodes > 0 {
      Some(bd.r_film_interior_m2_k_w + r_inner_half)
  } else {
      None
  };
  ```

- [ ] For the precomputed-RC path (lines ~360-425), compute half-resistances from the first/last precomputed RC layer:
  ```rust
  r_outer_half = precomputed_rc.first().map(|l| l.resistance_m2_k_w / 2.0)
  r_inner_half = precomputed_rc.last().map(|l| l.resistance_m2_k_w / 2.0)
  ```
