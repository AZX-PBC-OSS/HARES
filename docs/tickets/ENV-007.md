## Background/Context

OCHRE does NOT pass `insulation_details` for regular walls, roofs, or floors — only for foundation walls and slabs. HARES currently generates "R-{n}" strings from nominal R-value layers for ALL boundary types via `extract_insulation_details`. This can cause the LUT to over-narrow matches and select a wrong construction variant.

With ENV-005 and ENV-006 providing proper insulation detail parsers for foundation walls and slabs, this ticket replaces the generic `extract_insulation_details` with boundary-type-specific dispatch.

## Work to Do

- [ ] Replace the current `extract_insulation_details(node: &XmlNode) -> Option<String>` with:
  ```rust
  fn extract_insulation_details(node: &XmlNode, boundary_type: &BoundaryType) -> Option<String> {
      match boundary_type {
          BoundaryType::FoundationWall => extract_foundation_wall_insulation(node, 0.0).0,
          BoundaryType::Slab => extract_slab_insulation(node),
          _ => None,  // OCHRE does NOT pass insulation details for regular walls/roofs
      }
  }
  ```
- [ ] Update the call site in `parse_boundary` to pass `boundary_type`
- [ ] Remove or mark as dead code the old generic R-value string formatting logic (the `imperial_r` formatting path)
- [ ] Add unit test: verify `extract_insulation_details(_, BoundaryType::Wall)` returns `None`
- [ ] Add unit test: verify `extract_insulation_details(_, BoundaryType::Roof)` returns `None`
