## Background/Context
PV generation is the primary source of behind-the-meter generation and drives self-consumption logic in the battery model. Multi-array support is needed for buildings with arrays on multiple roof surfaces at different tilts and azimuths.

v1 uses PVWatts equations directly in Rust (matching OCHRE). SAM LUT path is an optional optimization loaded from adapter-generated Parquet when available — not required for v1.

## Work to Do
- [ ] Add HPXML data interface: parse `PVSystem` elements for `SystemSize` (kW DC), `ArrayTilt` (deg), `ArrayAzimuth` (deg), and `ModuleType` (Standard/Premium/ThinFilm); populate `PvArray` config from parsed values during HPXML loading
- [ ] Define `PvArray` struct: `tilt_deg`, `azimuth_deg`, `capacity_kw`, `noct_c` (configurable via `EquipmentConfig`, default 47°C); at `init`, register a `surface_id` for the array's tilt/azimuth. `surface_id` is a deterministic function of `(tilt_deg, azimuth_deg)` rounded to configurable resolution (default: nearest 5°). The engine pre-computes `SurfaceIrradiance` entries for all unique array orientations at init. If no matching surface exists at init, return `Err` — do NOT silently fall back. Use the matched `SurfaceIrradiance` entry each step.
- [ ] Implement PVWatts DC model: `P_dc = capacity_kw * (irradiance / 1000.0) * f_temp_derate`
- [ ] Implement cell temperature model: `T_cell = T_amb + irradiance * NOCT_factor` where `NOCT_factor = (noct_c - 20.0) / 800.0`; NOCT is read from `EquipmentConfig` (not hardcoded)
- [ ] Implement temperature derating: `f_temp = 1.0 + gamma * (T_cell - T_ref)` where `gamma = -0.0047 / °C`, `T_ref = 25.0°C`
- [ ] Compute AC output: `P_ac = P_dc * inverter_efficiency`; default `inverter_efficiency = 0.96`
- [ ] SAM LUT upgrade path: when a Parquet LUT file is provided via `EquipmentConfig` (generated by the SAM PVWatts adapter in `docs/architecture/05-external-tools.md`), use multi-dimensional interpolation from the LUT instead of the PVWatts equations; fall back to PVWatts equations when no LUT is present
- [ ] Implement `apply_control` for `ControlSignal::PowerLimit { max_power_kw, .. }`: curtail AC output to `min(P_ac, max_power_kw)`
- [ ] Define `PV` struct holding a `Vec<PvArray>`; sum AC outputs across all arrays
- [ ] Write Electrical port: `active_power_kw = -P_ac_total` (negative convention = generation), `reactive_power_kvar = 0.0` (v1; reactive control is a future extension)
- [ ] Declare `control_capabilities`: `POWER_LIMIT`
- [ ] Declare `telemetry_fields`: `dc_power_kw`, `ac_power_kw`, `cell_temp_c`, `irradiance_w_m2`, `inverter_efficiency`, `curtailment_kw` (when PowerLimit active)
- [ ] Implement `save_state() -> Vec<u8>`: PV is effectively stateless between steps; serialize curtailment state if a PowerLimit is active
- [ ] Implement `load_state(&mut self, state: &[u8]) -> Result<()>`
- [ ] Assign `ExecutionStage::Independent` (Stage 1) in `EquipmentDescriptor`
- [ ] Register in `EquipmentRegistry`
