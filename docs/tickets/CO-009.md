## Background/Context

The typed CoreOutput system needs enforcement: capability flags must match actual
outputs, core_output must agree with port contributions, and failed steps must not
update cached core_output.

## Work to Do

- [ ] Add `validate_core_contract(desc, co)` function in dwelling or hares-types.
      Checks all declared capabilities have corresponding Some values in CoreOutput.
      Returns `Err(HaresError)` on violation.
- [ ] Call validator in dwelling after each successful `eq.step()`, before populating
      `equipment_core`. On failure, abort timestep with error.
- [ ] Add lifecycle tests for all water heater types (gas, HPWH, resistance, tankless):
      assert `telemetry.len() == descriptor.telemetry_fields.len()`.
- [ ] Add lifecycle test: step every registered equipment type, assert core_output
      capabilities match descriptor's `core_capabilities`.
- [ ] Add cross-check test: for each equipment, capture the electrical port
      contribution emitted during step. Assert
      `core_output.flows.electric_kw.net_consumption_kw() ≈ captured_port_kw`
      within tolerance.
- [ ] Add test: failed step() does NOT update cached core_output (step with invalid
      environment, verify core_output unchanged from previous step).
- [ ] Add test: OperatingMode numeric code stability (assert Off==0, ...,
      BackupElement==11).
- [ ] Add test: reactive power sign convention (PV with capacitive output produces
      negative reactive_power_kvar in core_output).

## Measures of Success

- [ ] Central validator catches capability violations as hard errors
- [ ] All water heater types have lifecycle tests
- [ ] Cross-check proves core_output ↔ ports agreement
- [ ] Failed step leaves core_output unchanged
