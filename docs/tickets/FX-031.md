## Background/Context

The ticket's original "stale environment" claim is **inaccurate**: `environment.update()` runs at line 773 *before* `dispatch_into` at lines 777-778, so `apply_control` already sees current-step environment. The real concern is an **architectural contract risk**: `update_control` runs after `apply_control` and could theoretically overwrite externally-applied control state. For all current equipment, this does not happen — but it's undocumented and untested.

**IMP-01 (capability pre-check) is already implemented**: `Equipment::apply_control` (lib.rs:59-62) calls `ensure_signal_supported` before delegating.

## Work to Do

- [ ] Add a contract test: queue a control signal, call `run_timestep`, assert the signal was honored in the equipment's `step` output
