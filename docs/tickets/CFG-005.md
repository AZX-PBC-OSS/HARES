## Background/Context

SetpointSource in hvac_core.rs and WaterHeaterScheduleRefs in water_heater/mod.rs duplicate the lazy schedule pattern. SCHEDULE_DOMAIN_ID defined in 4 places. Consolidate to unified ScheduleSource.

## Work to Do

- [ ] Replace `SetpointSource` in hvac_core.rs with `hares_types::ScheduleSource`:
  - `Constant(f64)` -> `ScheduleSource::Constant(f64)`
  - `DailyProfile { weekday, weekend }` -> `ScheduleSource::DailyProfile { weekday, weekend, month_multipliers: [1.0;12], max_value: 1.0 }`
  - `ScheduleColumn(usize)` -> `ScheduleSource::ColumnRef { col_idx, boundary: BoundaryPolicy::Clamp }`
- [ ] Replace `WaterHeaterScheduleRefs` with `Option<ScheduleSource>` fields for draw rate and mains temp. Keep `resolve_storage_step_inputs` pipeline semantics — ScheduleSource is the data source *inside* that pipeline. The pipeline still does L/min->kg/s conversion, NaN filtering, and fallback chain (schedule -> mains domain -> config default). Add tests for conversion and fallback parity.
- [ ] Remove local `SCHEDULE_DOMAIN_ID` from hvac_core.rs, water_heater/mod.rs, dwelling.rs, environment.rs -> use `hares_types::SCHEDULE_DOMAIN_ID`
- [ ] Update callers of `SetpointSource::value()` -> `ScheduleSource::value_at()`
- [ ] Update WH models to use `ScheduleSource::value_at()` for draw rate and mains temp
- [ ] Delete `SetpointSource` enum
- [ ] Delete `WaterHeaterScheduleRefs` struct
- [ ] Update call sites in `resistance.rs`, `gas.rs`, `heat_pump_wh.rs` that reference `WaterHeaterScheduleRefs` fields — pass `&mut ScheduleSource` where needed for `value_at()`
- [ ] Handle `PartialEq` — `HvacEquipment` currently derives `PartialEq` containing `Option<SetpointSource>`. Either impl custom `PartialEq` on `ScheduleSource` (skip RNG field) or remove `PartialEq` from `HvacEquipment`
- [ ] Add verification grep: `rg "DomainId\(u16::MAX\)|SCHEDULE_DOMAIN_ID" crates/` — must return only `hares-types/src/schedule.rs`
- [ ] All existing HVAC and WH tests pass
