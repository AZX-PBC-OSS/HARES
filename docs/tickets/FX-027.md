## Background/Context

`steps_to_polars_df` emits only `Time` and `Total Electric Power (kW)`. OCHRE returns dozens of columns at verbosity >= 3 (zone temps, equipment modes, SOC, gas, reactive power). Any OCHRE user inspecting the DataFrame for diagnostics finds an empty view.

## Work to Do

- [ ] **Do NOT extend `StepResult`** — the full telemetry is already available via `dwelling.flushed_batches()` + `record_batches_to_polars_df`. Extending `StepResult` would duplicate data already written by `StreamingRecorder` and break the streaming architecture
- [ ] Route `PyDwelling::simulate()` (py_dwelling.rs:89-102) and `PyDwelling::results()` (py_dwelling.rs:160) through `dwelling.flushed_batches()` → `record_batches_to_polars_df` instead of `steps_to_polars_df`
- [ ] Add `"Total Reactive Power (kVAR)"` to `LEVEL_0_COLUMNS` in `columns.rs:17` (OCHRE emits it at verbosity >= 0)
- [ ] Add reactive power writing to `record_step` in `dwelling.rs:963`
- [ ] Note: `record_step` does not yet populate Setpoint, SOC, Energy, Reactive Power, or Power Factor columns at higher verbosity levels — those schema columns will be present but zero-filled. Track populating them as follow-on work
- [ ] Also update `PyDwelling::step()` (py_dwelling.rs:104-113) — it returns only a 2-key dict; should return a richer dict consistent with the batch path
- [ ] Test must be written against `flushed_batches` path (not `steps_to_polars_df`)
