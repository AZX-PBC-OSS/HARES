## Background/Context

After CFG-011, CFG-012, and CFG-013, all HPXML resolvers produce typed configs
and all equipment init() paths have a typed-first branch. The `Raw` fallback
branch in each init() is now only reachable from:
1. In-process test fixtures that were updated in CFG-009 through CFG-013
2. Python user-defined equipment overrides passed via `EquipmentConfig::raw`
3. Any remaining test code that still uses the old `HashMap<String, ConfigValue>`
   construction

This ticket removes the dead `Raw` branches from all built-in equipment `init()`
methods. Built-in equipment now requires `ConfigPayload::Typed` — passing `Raw`
is an init-time error with a clear diagnostic.

Additionally, this ticket adds init-time key consumption tracking (CC-003 /
P0-D) for the Python override path. When a user passes Python-side config
overrides (which arrive as a `Map<String, Value>` merged over the typed config),
unrecognized keys are a hard `Err` at init time. This catches misspelled Python
override keys immediately instead of silently defaulting.

Fixes: CC-003 (init-time config validation), CC-006 (silent default on missing
required input, partially — required fields now error at typed::<T>() time since
they are non-Option fields), AR-002 F-6 (override keys never validated).

## Work to Do

### Remove Raw fallback branches from built-in equipment

For each of the 16 built-in equipment types migrated in CFG-009 through CFG-013:

- [ ] In `init()`: remove the `else { /* first_f64 fallback chain */ }` branch.
  Replace with:
  ```rust
  // Built-in equipment requires typed config from CFG-011/CFG-012/CFG-013.
  // Raw payload is only valid for custom Python equipment.
  let c = config.typed::<GasFurnaceConfig>().map_err(|e| {
      HaresError::Equipment(format!(
          "Gas Furnace requires typed config (was Raw). \
           Did you use EquipmentConfig::from_typed()? Error: {e}"
      ))
  })?;
  ```
- [ ] Remove the `HEATING_CAPACITY_KEYS`, `DUCT_DSE_KEYS`, and similar
  multi-key alias arrays from `helpers.rs` once all callers are gone.
  Keep `first_f64` if any custom Python equipment code path still uses it,
  but mark it `#[doc(hidden)]`.
- [ ] In `config.rs`: add `EquipmentConfig::raw(name, ochre_class, map)` as an
  explicit constructor for the Raw path. This makes it clear at the call site
  that Raw configs are intentional (Python custom equipment), not accidental.
  Remove the old implicit `EquipmentConfig { raw_config: map }` construction
  style by removing the `pub raw_config` field — use `payload` with private
  access, exposed only via accessors.

### Init-time key consumption tracking (Python override path)

The Python API allows users to pass override dicts like:
```python
dwelling.configure_equipment("Gas Furnace", {"afue": 0.96})
```
These overrides are merged into the typed config as a JSON patch before
`EquipmentConfig::from_typed` is called. Any key in the patch that is not a
field in the target struct is an unknown key.

- [ ] In the Python override merge path (in `hares-python` or `hares-core`,
  wherever Python override dicts are applied): after merging the override dict
  into the typed config JSON, attempt deserialization with `deny_unknown_fields`.
  If it fails with an unknown field error, return hard `Err` naming the
  unknown key and equipment name. No silent fallback — unknown keys are always
  a programming error, whether from resolver or Python override.
- [ ] Add test: Python override with misspelled key `"afuee"` on Gas Furnace →
  hard `Err` returned, equipment does not init. Error message names the
  unknown key.
- [ ] Add test: Python override with correct key `"afue": 0.96` → equipment
  `fuel_efficiency == 0.96` after init. No warning.

### Required field enforcement

After removing the Raw path, fields that are not `Option<T>` in the typed config
structs become implicitly required (serde will error if they are missing). Audit
each struct:

- [ ] `capacity_w` on heating equipment: not Option — required. Confirm that all
  resolvers always provide it (error in resolver if XML element is missing, not
  a default).
- [ ] `afue` / `eir` / `seer`: not Option — required. Same audit.
- [ ] `fuel_type` on gas equipment: not Option — required.
- [ ] Document which fields are required vs optional with a comment on each
  struct field: `// required — resolver errors if absent` vs `// optional — defaults
  are applied in init()`.
