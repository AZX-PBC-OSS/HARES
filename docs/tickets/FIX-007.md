# FIX-007: Startup capacity degradation not extracted from HPXML

> **STATUS: CLOSED — Invalid** (Codex review 2026-03-19)
> HARES already derives Cd (cycling degradation coefficient) by mode/efficiency when the explicit key is absent. See `hvac_core.rs:375` where Cd is computed as a fallback. The ticket's claim that startup capacity degradation is not extracted is incorrect.

**Severity:** CRITICAL
**Crate:** `hares-io`, `hares-equipment`
**Files:** `crates/hares-io/src/hpxml/equipment.rs`, `crates/hares-equipment/src/hvac/hvac_core.rs`

---

## Bug

HPXML parsing does not extract or compute the startup capacity degradation factor (`Cd`) for AC/heat pump equipment from HPXML data. The equipment model has a `StartupConfig` struct and `startup_cd` config key (hvac_core.rs lines 344-352), but the HPXML parser never inserts this value:

```rust
// hvac_core.rs:344-352 -- reads from config, but config is never populated by HPXML
let cd = extract_numeric(config, "startup_cd")
    .or_else(|| extract_numeric(config, "cooling_cd"))
    .or_else(|| extract_numeric(config, "cd"))
    .unwrap_or(DEFAULT_PLF_DEGRADATION_COEFF);
self.startup = StartupConfig {
    c_d: cd,
    time_since_start_min: 0.0,
};
```

The default `DEFAULT_PLF_DEGRADATION_COEFF` is 0.25 (line 33), which is the AHRI Standard 210/240-2023 default. However, OCHRE derives Cd from equipment efficiency data and HPXML specifications, producing different values for different equipment types.

## OCHRE Reference

OCHRE `Dwelling.py` computes Cd (startup/cycling degradation coefficient) based on equipment type and efficiency. For AC equipment, it uses the AHRI default of 0.25 when no test data is available. For heat pumps, it may differ. The key issue is that OCHRE also checks for explicit Cd values in the HPXML extension elements.

## Fix

1. Check for `CyclingDegradationCoefficient` or similar extension elements in HPXML during AC/HP parsing.
2. If present, insert `startup_cd` into equipment config parameters.
3. If absent, derive from efficiency data per OCHRE's logic (or use AHRI default 0.25 for AC, which already matches).

In `equipment.rs` heat pump / cooling system parsing:

```rust
// Extract cycling degradation coefficient from extension
if let Some(ext) = node.child("extension") {
    if let Some(cd) = child_f64(ext, "CyclingDegradationCoefficient") {
        params.insert("startup_cd".to_string(), json!(cd));
    }
}
```

## Test

- Parse HPXML with AC that has a `CyclingDegradationCoefficient=0.15` extension. Verify `startup_cd=0.15` in config.
- Parse HPXML with heat pump and no explicit Cd. Verify `startup_cd` defaults to 0.25.
