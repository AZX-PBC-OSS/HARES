## Background/Context

`SimulationMetrics` (annual energy, peak power, comfort hours, efficiency, envelope loads, grid interaction) and `FullSimulationMetrics` (which adds gas energy) are computed in Rust but only accessible indirectly via the results DataFrame. Exposing them as typed Python objects gives users structured access to summary metrics without post-processing DataFrames.

## Work to Do

- [ ] Create `crates/hares-python/src/py_metrics.rs` with `#[pyclass(frozen)]` wrappers:
  - `PySimulationMetrics`:
    - `annual_energy_kwh` → `PyAnnualEnergyKwh`
    - `peak_power_kw` → `PyPeakPowerKw`
    - `comfort_hours` → `Option<f64>`
    - `unmet_load_hours` → `Option<f64>`
    - `renewable_energy_fraction` → `Option<f64>`
    - `grid_interaction` → `PyGridInteractionMetrics`
    - `envelope_loads_kwh` → `Option<PyEnvelopeComponentLoadsKwh>`
    - `efficiency` → `PyEfficiencyMetrics`
    - `gas_energy` → `Option<PyGasEnergyMetrics>`
    - `__repr__` with key totals
  - `PyAnnualEnergyKwh`:
    - `total: f64`
    - `per_end_use: dict[str, float]` (getter converts BTreeMap)
  - `PyPeakPowerKw`:
    - `per_end_use: dict[str, float]`
    - `rolling_15min_kw: f64` — **Note:** Rust has nested `rolling: RollingPeakKw` sub-struct. Flatten for Python ergonomics: `self.inner.rolling.peak_15min_kw` → getter `rolling_15min_kw`.
    - `rolling_30min_kw: f64`
    - `rolling_60min_kw: f64`
  - `PyGridInteractionMetrics`:
    - `peak_import_kw: f64`
    - `peak_export_kw: f64`
  - `PyEnvelopeComponentLoadsKwh`:
    - getters for all 9 fields: `window_solar_kwh`, `opaque_solar_lwr_kwh`, `interior_lwr_kwh`, `infiltration_kwh`, `ventilation_kwh`, `hvac_heating_kwh`, `hvac_cooling_kwh`, `internal_gains_kwh`, `duct_loss_kwh`
  - `PyEfficiencyMetrics`:
    - `hvac_heating_cop: Option<f64>`
    - `hvac_cooling_cop: Option<f64>`
    - `water_heater_cop: Option<f64>`
    - `battery_round_trip_efficiency: Option<f64>`
  - `PyGasEnergyMetrics`:
    - `total_therms: f64`
    - `total_kwh_equivalent: f64`
- [ ] Add `metrics()` method to `PyDwelling` that returns `PySimulationMetrics`
  - Internally: run `MetricsCalculator` on flushed batches, use `FullSimulationMetrics` (not just `SimulationMetrics`) to capture gas energy
  - Raise `ValueError` if no batches flushed yet (simulation hasn't run)
- [ ] Register all new classes in `lib.rs` (7 classes)
- [ ] Update `_hares.pyi` with stubs for all new types
- [ ] Update `__init__.py` to re-export `SimulationMetrics`

  - Verify `peak_power_kw.rolling_15min_kw >= 0`

  - Verify `grid_interaction.peak_import_kw >= 0`
  - Verify `grid_interaction.peak_export_kw >= 0`
  - Verify `efficiency` fields are `None` or positive floats
  - Verify `envelope_loads_kwh` is `None` or has all 9 fields as floats
  - Verify `gas_energy` is `None` or has `total_therms` and `total_kwh_equivalent` as floats
  - Verify `metrics()` raises `ValueError` before `simulate()` is called
