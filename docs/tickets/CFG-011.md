## Background/Context

After CFG-009 and CFG-010, equipment can accept typed configs via
`config.typed::<T>()` but resolvers still write `ConfigPayload::Raw`. This
ticket flips the resolver to produce `ConfigPayload::Typed` for all HVAC
equipment. Once this lands, all real HPXML-sourced equipment uses typed configs
and the mismatches are eliminated at the source.

The resolver currently builds `params: Map<String, Value>` incrementally via
`params.insert(...)` then passes it to `build_spec`. After this ticket, the
resolver constructs the typed struct directly, then calls
`EquipmentConfig::from_typed(name, ochre_class, config)`.

This is the critical commit that actually fixes the 25+ CW-series key mismatches
for HVAC equipment. All efficiency, capacity, and fan values now flow through
named struct fields instead of magic strings.

Fixes: CW-001 (gas furnace AFUE), CW-002 (electric furnace EIR), CW-004 (boiler
AFUE), CW-005 (central AC SEER), CW-006 (room AC EER), CW-007 (boiler electric
efficiency), CW-008 (per-stage SHR discarded), CW-009 (mini-split speed count),
CW-010 (HP cooling), AR-002 F-1 through F-3 (heating/cooling efficiency key).

## Work to Do

### Replace Map-based construction for heating equipment

- [ ] In `resolve_hvac.rs`, locate the function(s) that construct heating system
  specs (furnaces, boilers, baseboards, ideal HVAC). Replace the
  `let mut params = Map::new(); params.insert(...); build_spec(...)` pattern with
  direct struct construction:
  ```rust
  let cfg = GasFurnaceConfig {
      equipment_id: None,
      zone_id: Some(zone_id),
      capacity_w: capacity_w,
      afue: heating_afue,   // was written as "heating_efficiency"
      fan_power_w: fan_power_w,
      duct: DuctConfig { ... },
      ..Default::default()
  };
  EquipmentConfig::from_typed(name.clone(), ochre_class.clone(), cfg)
  ```
- [ ] Verify that `heating_afue` now carries the correct value from HPXML (the
  AFUE read from `AnnualHeatingEfficiency/Value` normalized by the resolver's
  existing unit conversion logic). The key `"heating_efficiency"` in the old
  path corresponds to `afue` in the new struct.
- [ ] Repeat for `ElectricFurnaceConfig`, `GasBoilerConfig`,
  `ElectricBoilerConfig`, `ElectricBaseboardConfig`, `IdealHvacConfig`.

### Replace Map-based construction for cooling/HP equipment

- [ ] Locate AC spec construction functions. Replace with direct
  `CentralAirConditionerConfig` / `RoomAcConfig` construction.
  The existing `"efficiency_seer"` key value maps to `seer` field.
- [ ] For heat pumps: construct `HeatPumpConfig` directly. Enforce mini-split
  rule here: if `CompressorType` is variable-speed or `system_type` is
  "mini-split", set `is_mini_split = true` and `number_of_speeds = 4`.
  Propagate per-stage SHR values from the existing stage loop into
  `stage_shrs: Some(vec![...])`.
- [ ] For dehumidifiers: construct `DehumidifierConfig` directly.

### Fix startup degradation gating (CW-001 F1)

- [ ] In `resolve_hvac.rs`, `insert_startup_degradation` is unconditionally called
  for all heating equipment, including furnaces and boilers. It should only apply
  to heat pumps. Gate the call on equipment type — only call for HP equipment.
  For non-HP heating equipment, set `startup_cd = None` in the typed config.
  This is a behavioral fix that the typed config migration naturally enables.

### Propagate biquadratic bounds from CSV (DV-003 F3/F4)

- [ ] In `resolve_hvac.rs`, `select_primary_curve_pair` currently returns only
  coefficients and discards `x1_bounds`/`x2_bounds`. Return bounds alongside
  coefficients. Write `biquadratic_x1_min/max` and `biquadratic_x2_min/max`
  into the typed config struct fields added in CFG-010.
- [ ] Similarly propagate `min_ff/max_ff/min_plf/max_plf` from CSV defaults
  into `ff_min/max` and `plf_min/max` fields.
- [ ] Fix MSHP missing-row default: `get_row()` must default missing
  `min_Twb`/`min_Tdb` rows to `-100.0` and `max_Twb`/`max_Tdb` to `100.0`
  (not `0.0`).
