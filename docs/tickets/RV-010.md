## Background/Context

The battery degradation model (`RainflowCounter` and `DegradationState`) has no targeted unit tests. The only test is a "won't crash" smoke check in `der_parity.rs`. The rainflow counter implements ASTM E1049-85 cycle extraction, and `DegradationState` implements calendar + cycling aging per Smith 2017. Both are physics-critical for battery capacity fade predictions.

- [ ] Test degradation accumulation with known temperature and cycling profiles
- [ ] Test day-boundary reset logic

## Tests Added

**hares-equipment (degradation.rs inline tests):**

- `rainflow_astm_reference_cycles` — push the ASTM E1049-85 standard example sequence. Assert extracted cycle count and DOD values match the standard's expected output
- `rainflow_single_full_cycle` — push SOC sequence [1.0, 0.0, 1.0]. Assert one full cycle with DOD = 1.0
- `rainflow_partial_cycles` — push SOC sequence with partial discharge. Assert correct half-cycle extraction
- `rainflow_monotonic_no_cycles` — push monotonically decreasing SOC. Assert zero complete cycles extracted
- `rainflow_sum_squared_dod_daily` — push known sequence. Assert `sum_squared_dod_daily` accumulates correctly
- `degradation_calendar_aging_only` — hold battery at constant SOC and temperature for 30 simulated days. Assert `capacity_fade_pct` increases monotonically and matches Smith 2017 calendar aging formula within 1%
- `degradation_cycling_aging` — run 100 full cycles at 25°C. Assert cycling component of `capacity_fade_pct` matches expected value from Smith 2017 within 5%
- `degradation_temperature_weighting` — compare fade at 25°C vs 45°C for identical cycling. Assert higher temperature produces more degradation (Arrhenius weighting)
- `degradation_reset_day_tracking` — cross a midnight boundary. Assert daily tracking metrics reset correctly and accumulated lifetime metrics are preserved
- `degradation_accumulate_multi_day` — run 7 days. Assert `capacity_fade_pct` increases each day and the final value is consistent with the sum of daily contributions
