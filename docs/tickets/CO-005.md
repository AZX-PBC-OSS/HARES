## Background/Context

BMS actor reads `telemetry.0.get("soc")` for battery SoC. EV driver reads
`tel.get("soc")`. Both must switch to `env.equipment_core.get(&id)` using typed
`CoreOutput`. Actors currently use `DispatchTarget::ByName(Arc<str>)` — they need
to resolve name → EquipmentId via the dwelling-provided lookup map.

## Work to Do

- [ ] In `bms.rs`: replace `telemetry.0.get(tk::SOC)` with
      `env.equipment_core.get(&id).and_then(|co| co.state.soc).map(|s| s.get())`.
- [ ] In `ev_driver/mod.rs`: replace `tel.get(tk::SOC)` with same pattern.
- [ ] `equipment_id_by_name` lives in dwelling context (NOT EnvironmentState).
      Actors resolve their dispatch target name → EquipmentId at actor init time
      using the dwelling-provided name→ID map. Store resolved `EquipmentId` on the
      actor struct. Do NOT look up name→ID per step.
- [ ] `equipment_core` population in EnvironmentState is CO-003's responsibility
      (single owner). This ticket only consumes it.
- [ ] Test: actor correctly reads SoC from CoreOutput.
- [ ] Test: actor handles missing equipment ID gracefully.

## Measures of Success

- [ ] Zero `telemetry.0.get` or `telemetry.get` calls in actor code
- [ ] BMS and EV driver read typed SoC values
- [ ] All actor tests pass
