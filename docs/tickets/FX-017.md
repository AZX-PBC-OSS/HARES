## Background/Context

`FourSpeed` uses uniform 25% thresholds — wrong by 40-67% vs actual MSHP capacity fractions. But fixing thresholds alone is insufficient: discrete stage selection introduces step discontinuities in PLR/EIR at every stage boundary. OCHRE uses continuous inter-speed interpolation (`use_ideal_capacity=True`) for all 4+ speed equipment, matching EnergyPlus `VariableSpeed` SpeedRatio model. HARES must do the same.

## Work to Do

- [ ] Rename `SpeedControlMode::FourSpeed` to `SpeedControlMode::MultiSpeedInterpolated`
- [ ] Change `SpeedSelection` to carry a fractional speed index:
  ```rust
  pub struct SpeedSelection {
      pub speed_index: usize, // lower bracket index (0-based)
      pub speed_frac: f64,    // interpolation weight for upper bracket [0.0, 1.0]
      pub part_load_ratio: f64, // PLR, only <1 when at lowest speed and cycling
  }
  ```
- [ ] Replace `select_speed` FourSpeed branch with capacity-bracket binary search:
  - `required_cap = load_fraction * capacities[last]`
  - Below lowest stage: `speed_index=0, speed_frac=0, plr=required/cap[0]`
  - Between stages: `partition_point` to find bracket, `frac = (required - cap[lo]) / (cap[hi] - cap[lo])`
  - Above max: `speed_index=last, speed_frac=0, plr=1.0`
- [ ] In `heater.rs` and `air_conditioner.rs` `compute_step`, interpolate both capacity and EIR between bracket stages:
  ```
  cap = cap_lo * (1 - frac) + cap_hi * frac
  eir = eir_lo * (1 - frac) + eir_hi * frac
  ```
  Same pattern for biquadratic curve evaluation. PLR/PLF cycling penalty applies only at lowest speed (`speed_frac == 0.0 && plr < 1.0`)
- [ ] Remove `speed_fraction` field from `SpeedSelection` and `HvacEquipment.variable_speed_fraction` — made redundant by `speed_frac`
- [ ] Replace all four `FourSpeed` tests (hvac_core.rs:1803-1985) with:
  - Correct bracket selection test
  - PLR-only path for load below lowest stage (load=0.30, cap[0]=0.40 → PLR=0.75)
  - Interpolation at midpoint between two stages (speed_frac=0.5)
  - Full-capacity clamp test
- [ ] `VariableSpeedIdeal` mode (non-MSHP ideal solver) remains unchanged
