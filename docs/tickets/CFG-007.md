## Background/Context

`EquipmentConfig.raw_config` is a `HashMap<String, ConfigValue>` with no
compile-time key contract. Resolvers write keys under one naming convention;
equipment `init()` reads different names. Every mismatch silently uses a
default. This ticket adds the foundational types that CFG-009 through CFG-013
build on. No equipment is migrated here — this keeps the tree green while
subsequent tickets migrate equipment one batch at a time.

Fixes (foundation for): CC-001, AR-002, CW-001 through CW-022.

## Design

The approach uses a `ConfigPayload` enum that can hold either the new typed
struct or the legacy `HashMap`. The `Equipment` trait's `init()` signature does
not change yet — migration is per equipment batch. The `EquipmentTypedConfig`
trait provides a common interface for typed configs.

```rust
/// Marker trait for per-equipment typed config structs.
/// All structs that implement this must derive Serialize + Deserialize
/// and use #[serde(deny_unknown_fields)].
pub trait EquipmentTypedConfig: Serialize + for<'de> Deserialize<'de> {
    /// Equipment canonical name this config belongs to.
    /// Must match the string registered in EquipmentRegistry.
    fn equipment_type_name() -> &'static str;

    /// Schema version for forward compatibility. Default 1.
    fn schema_version() -> u32 { 1 }
}

/// Config payload for one equipment instance.
/// Typed variant is used by built-in equipment after migration.
/// Raw variant is used by custom Python equipment and unmigrated built-ins.
///
/// Uses explicit tagging (not #[serde(untagged)]) to avoid ambiguous
/// deserialization between Raw and Typed variants.
#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(tag = "kind")]
pub enum ConfigPayload {
    #[serde(rename = "raw")]
    Raw { data: HashMap<String, ConfigValue> },
    #[serde(rename = "typed")]
    Typed {
        /// Canonical equipment type name — must match EquipmentTypedConfig::equipment_type_name().
        type_name: String,
        /// Schema version — must match EquipmentTypedConfig::schema_version().
        version: u32,
        /// The typed config data as a JSON object.
        data: serde_json::Value,
    },
}
```

The shim accessor on `EquipmentConfig`:

```rust
impl EquipmentConfig {
    /// Deserialize the payload as a typed config struct T.
    /// Returns Err if the payload does not match T's schema.
    pub fn typed<T: EquipmentTypedConfig>(&self) -> crate::Result<T> { ... }

    /// Whether the payload is already in typed (JSON object) form.
    pub fn is_typed(&self) -> bool { matches!(self.payload, ConfigPayload::Typed { .. }) }
}
```

The resolver constructs typed configs and serializes them into
`ConfigPayload::Typed { type_name, version, data }` using `serde_json::to_value`. Equipment `init()` calls `config.typed::<FurnaceConfig>()`
which deserializes with `deny_unknown_fields` — dead keys are a hard error at
init time, not at parse time.

      `Raw { data: HashMap<String, ConfigValue> }` and
      `Typed { type_name: String, version: u32, data: serde_json::Value }`.
      Derive Clone, Debug, Serialize, Deserialize. Must match the Design section.
- [ ] Add `EquipmentTypedConfig` trait to `config.rs`:
      `fn equipment_type_name() -> &'static str`. Bounds: `Serialize +
      for<'de> Deserialize<'de> + Clone + Debug`.
- [ ] Change `EquipmentConfig.raw_config` field to `payload: ConfigPayload`.
      Keep the existing `get_f64`, `get_str`, `get_bool`, `get_f64_array`
      accessors working by delegating to the `Raw` variant. For `Typed` variant,
      these accessors return `None` (equipment using typed path does not use them).
- [ ] Add `EquipmentConfig::typed<T: EquipmentTypedConfig>(&self) -> crate::Result<T>`:
      - If `payload` is `Typed { type_name, version, data }`:
        1. Verify `type_name == T::equipment_type_name()` — return
           `Err(HaresError::Equipment("config type mismatch: expected {expected}, got {type_name}"))` on failure.
        2. Verify `version == T::schema_version()` — return
           `Err(HaresError::Equipment("config schema version mismatch: expected {expected}, got {version}"))` on failure.
        3. `serde_json::from_value::<T>(data.clone())` mapping serde error to
           `HaresError::Equipment(...)`. `deny_unknown_fields` on `T` causes
           unknown keys to return `Err` here.
      - If `payload` is `Raw { .. }`: return `Err(HaresError::Equipment(
        "equipment X was not initialized with typed config".to_string()))`.
