# FIX-006: DER external control signals partially stubbed

> **STATUS: CLOSED — Invalid** (Codex review 2026-03-19)
> EV control IS implemented in `ev.rs` (line 822+) with full `apply_control_unchecked` handling PowerSetpoint, SOCTarget, and departure logic. The audit agent inspected `ev/archetype.rs` (driver profile enum) instead of the equipment implementation. Battery and PV also have full control implementations. The blanket "all DER stubs" claim is incorrect.

**Severity:** CRITICAL
**Crate:** `hares-equipment`
**Files:** `crates/hares-equipment/src/battery.rs`, `crates/hares-equipment/src/pv.rs`, `crates/hares-equipment/src/generator.rs`, `crates/hares-equipment/src/ev/archetype.rs`

---

## Bug

Battery and PV `apply_control_unchecked()` implementations handle some signals, but the EV equipment model has NO `apply_control` implementation at all (grep for `apply_control` in `crates/hares-equipment/src/ev/` returns zero results). Any RL/control-based simulation sending signals to EVs silently does nothing.

Battery (`battery.rs` line 1323-1331) handles `PowerSetpoint` and `SOCTarget`:
```rust
fn apply_control_unchecked(&mut self, signal: &ControlSignal) -> crate::Result<()> {
    match signal {
        ControlSignal::PowerSetpoint { active_power_kw, .. } => {
            self.power_setpoint_kw = Some(*active_power_kw);
            self.soc_target = None;
            self.self_consumption_enabled = false;
        }
        ControlSignal::SOCTarget { target_soc, .. } => { ... }
```

PV (`pv.rs` line 1005-1015) handles `PowerLimit`:
```rust
fn apply_control_unchecked(&mut self, signal: &ControlSignal) -> crate::Result<()> {
    match signal {
        ControlSignal::PowerLimit { max_power_kw, .. } => {
            self.power_limit_kw = Some((*max_power_kw).max(0.0));
            Ok(())
        }
```

Generator (`generator.rs` line 784) handles `PowerSetpoint`.

**EV** (`ev/archetype.rs`) has no `apply_control_unchecked` method. The `Equipment` trait's default implementation (which returns an error or no-op) is used.

## OCHRE Reference

OCHRE `Equipment/Battery.py` `update_external_control` applies power setpoints, SOC targets, import/export limits, and self-consumption mode. OCHRE `Equipment/EV.py` handles charging power setpoints and departure SOC targets.

## Fix

For EV: Implement `apply_control_unchecked` on the EV equipment struct:

```rust
fn apply_control_unchecked(&mut self, signal: &ControlSignal) -> crate::Result<()> {
    match signal {
        ControlSignal::PowerSetpoint { active_power_kw, .. } => {
            self.charging_power_setpoint_kw = Some((*active_power_kw).max(0.0));
            Ok(())
        }
        ControlSignal::SOCTarget { target_soc, .. } => {
            self.departure_soc_target = Some(target_soc.clamp(0.0, 1.0));
            Ok(())
        }
        _ => Err(HaresError::Control(
            format!("EV does not support control signal: {signal:?}")
        ))
    }
}
```
