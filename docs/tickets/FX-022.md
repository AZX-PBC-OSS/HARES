## Background/Context

Checkpoint stores a single `f64` humidity state (`humidity_values[1]`). On restore, that scalar is written to every zone. Multi-zone buildings are all restored to the same humidity ratio, corrupting state.

## Work to Do

- [ ] Change checkpoint format to store `Vec<(ZoneId, f64)>` for humidity state (`ZoneId` already derives `Serialize, Deserialize`)
- [ ] Bump `CHECKPOINT_VERSION` to 2
- [ ] On save: iterate `humidity_solver.humidity_ratios` and store all zone→value pairs (do NOT port the existing `flat_map` → index `[1]` pattern)
- [ ] On restore: write each zone's humidity ratio from the stored map
- [ ] **Handle zone-set mismatch on restore**: if the checkpoint's zone set differs from the live building's zones, either fail hard (consistent with equipment-state restore) or warn and fall back to initial humidity ratio for unmatched zones
- [ ] Update existing `save_then_load_round_trip` test in `checkpoint.rs:80` (it uses the old scalar `humidity_state: 0.005` and will fail to compile after the type change)
- [ ] Add new test: save/restore a 3-zone dwelling, verify per-zone humidity preserved

## Files to Touch

- `crates/hares-core/src/dwelling.rs`: update save/restore calls to handle per-zone humidity
- `crates/hares-core/src/checkpoint.rs`: change humidity field to `Vec<(ZoneId, f64)>`, bump version

## Measures of Success

- [ ] Each zone's humidity ratio survives checkpoint round-trip
- [ ] Version 1 checkpoints are rejected with a clear error
