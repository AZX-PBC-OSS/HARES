## Background/Context

After CFG-015, no built-in equipment `init()` method should use `config.get_f64()`,
`config.get_str()`, `config.get_bool()`, `first_f64()`, or direct
`raw_config.get()` calls. These are the magic-string access patterns that caused
the 25+ key mismatches in the CW series.

This ticket adds a CI grep guard that fails the build if any of these patterns
appear inside equipment `init()` method bodies in the built-in equipment files.
It follows the same pattern as CO-011 (the telemetry CI guard for magic-string
telemetry key reads).

The guard does not need to be perfect — a false negative (missing a call) is
acceptable. A false positive (flagging legitimate custom equipment code) must be
avoided. The guard scans only the built-in equipment source files, not the
custom equipment adapter layer.

Fixes (final enforcement): CC-001, AR-002 F-6 (override keys validated by CFG-015,
this guard prevents future regressions).

## Work to Do

### CI grep guard

- [ ] Add a `check-no-magic-config` step to CI (or a `make check-no-magic-config`
  target) that runs:
  ```sh
  # Fail if any built-in equipment init() uses raw config accessors.
  # Custom equipment (Python adapter layer) is excluded.
  # Uses explicit exit handling to avoid false-pass on rg runtime errors.
  rg --type rust \
     'config\.get_f64\(|config\.get_str\(|config\.get_bool\(|first_f64\(' \
     crates/hares-equipment/src/hvac/ \
     crates/hares-equipment/src/water_heater/ \
     crates/hares-equipment/src/battery/ \
     crates/hares-equipment/src/ev/ \
     crates/hares-equipment/src/pv/ \
     crates/hares-equipment/src/generator.rs \
     crates/hares-equipment/src/ventilation.rs \
     --ignore-glob '*/tests/*'
  exit_code=$?
  if [ "$exit_code" -eq 0 ]; then
    echo "FAIL: magic-string config access found in built-in equipment"
    exit 1
  elif [ "$exit_code" -eq 1 ]; then
    echo "PASS: no magic-string config access in built-in equipment"
  else
    echo "FAIL: rg returned unexpected exit code $exit_code"
    exit 1
  fi
  ```
  Exit code 0 = matches found (fail). Exit code 1 = no matches (pass).
  Any other exit code (e.g., rg error) also fails to prevent false passes.
- [ ] Add the check to the CI workflow after the `cargo clippy` step.
- [ ] Document the guard in a comment at the top of `helpers.rs`:
  "get_f64/get_str/first_f64 must only be called from custom equipment or the
  Python adapter layer. Built-in equipment uses typed config structs (see
  CFG-007 through CFG-015). CI enforces this."
