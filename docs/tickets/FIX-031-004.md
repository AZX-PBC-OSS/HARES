## Background/Context

The dwelling currently uses post-hoc HVAC subtraction to compute
`internal_gain_w` from `port_sensible_w`. With `ThermalCategory` on each
port contribution, the thermal solver can read categorized subtotals
directly — no subtraction needed.

## Work to Do

- [ ] In `apply_port_sensible_inputs()`: the thermal solver still adds all
  `sensible_gain_w` to `u` (physics unchanged). But separately accumulate
  per-category totals for the indoor zone from `ThermalAccumulator`'s
  categorized map.
- [ ] Update `EnvelopeComponentGains`:
  - Replace `port_sensible_w` and `internal_gain_w` with:
    ```rust
    pub hvac_heating_w: f64,
    pub hvac_cooling_w: f64,
    pub internal_gain_w: f64,  // InternalGain + JacketLoss
    pub duct_loss_w: f64,
    ```
  - Keep `port_sensible_w` as a convenience sum for backward compat.
- [ ] Remove the HVAC subtraction block in `dwelling/mod.rs` (the
  `EndUse::HvacHeating | HvacCooling` filter + telemetry.get code).
  Replace with direct reads from categorized gains.
- [ ] Update `record_step()` envelope column wiring to use the new fields.
- [ ] Update observer `SolverCapture` (it already clones `EnvelopeComponentGains`).
