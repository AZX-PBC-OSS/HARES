## Background/Context

Three confirmed mismatches in DER and load equipment (from AR-002):

**AR-002 F-2 — EV battery capacity key**: `resolve_loads.rs:423` writes
`"battery_capacity_kwh"` for the EV PlugLoad path, but `ev/config.rs:8` reads
`"capacity_kwh"`. All HPXML-sourced EVs use the `DEFAULT_CAPACITY_KWH` (75 kWh)
regardless of the HPXML range specification. Note: the DER path (`resolve_der.rs`)
already writes `"capacity_kwh"` correctly — this is only the loads path.

**AR-002 F-3 — Ventilation key mismatches (3 keys)**:
- `resolve_loads.rs:554` writes `"ventilation_rate_cfm"` (in CFM), but
  `ventilation.rs:34` reads `"flow_rate_m3_s"` (in m³/s, different name AND unit)
- `resolve_loads.rs:577` writes `"sensible_recovery_efficiency"`, but
  `ventilation.rs:35` reads `"sensible_effectiveness"`
- `resolve_loads.rs:585` writes `"latent_recovery_efficiency"`, but
  `ventilation.rs:36` reads `"latent_effectiveness"`
  All three ventilation parameters are silently defaulted on every HPXML run.

**CW-016 — Battery double-sqrt**: `resolve_der.rs:95` writes
`inverter_efficiency: rte.sqrt()` (stores pre-processed value), but
`battery/mod.rs` applies `.sqrt()` again during init, resulting in the square
root of the round-trip efficiency instead of the correct one-way efficiency.

Additionally, `FuelType` serialization uses `{:?}` Debug format in some places
(AR-002 F-4), which produces `"Gas"` / `"Electric"` (Rust identifier casing) but
parsers expect `"natural gas"` / `"electricity"`. Typed configs use `FuelType`
enum fields directly, bypassing string serialization entirely.

Fixes: AR-002 F-2 (EV capacity key), AR-002 F-3 (ventilation 3 keys + unit),
AR-002 F-4 (FuelType Debug format), CW-016 (battery double-sqrt), CW-018
(ventilation flow rate).

## Typed config structs to add

All new config files alongside the relevant equipment module.

### `BatteryConfig` (crates/hares-equipment/src/battery/config.rs)
```rust
#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct BatteryConfig {
    pub equipment_id: Option<u32>,
    pub zone_id: Option<u16>,
    pub capacity_kwh: f64,
    pub max_charge_kw: Option<f64>,
    pub max_discharge_kw: Option<f64>,
    pub inverter_efficiency: f64,  // one-way efficiency, NOT pre-sqrt; resolver fixes
    pub initial_soc: Option<f64>,
}
```
`equipment_type_name() = "Battery"`.

**Critical**: the resolver currently writes `rte.sqrt()` for `inverter_efficiency`.
The Battery `init()` applies `.sqrt()` again, yielding `rte^0.25` instead of
`rte^0.5`. Fix: resolver writes `inverter_efficiency = rte.sqrt()` (one-way
efficiency, correct), and Battery init does NOT apply sqrt. Document this in
the struct: `// one-way charge/discharge efficiency; resolver writes rte.sqrt()`.

## Work to Do

### Equipment typed init paths

- [ ] `battery/mod.rs init()`: add typed-first path reading `c.capacity_kwh`
  and `c.inverter_efficiency` directly. Remove the `.sqrt()` call on
  `inverter_efficiency` in the typed path (resolver supplies one-way efficiency).
  Raw fallback unchanged.
- [ ] `ev/mod.rs init()`: add typed-first path reading `c.capacity_kwh`
  directly. Raw fallback reads both `"capacity_kwh"` and `"battery_capacity_kwh"`
  (keeping the existing multi-key alias for any remaining Raw callers).
- [ ] `pv/mod.rs init()`: add typed-first path.
- [ ] `generator.rs init()`: add typed-first path. `FuelType` field directly,
  no string parsing.
- [ ] `ventilation.rs init()`: add typed-first path reading `c.flow_rate_m3_s`,
  `c.sensible_effectiveness`, `c.latent_effectiveness` directly. No CFM→m³/s
  conversion needed (resolver does it). Raw fallback unchanged.

### Resolver migration

- [ ] `resolve_loads.rs` EV path: replace `"battery_capacity_kwh"` key with
  `EvConfig { capacity_kwh: battery_capacity_kwh, ... }` typed construction.
  The variable name in the resolver is `battery_capacity_kwh` — map it to the
  `capacity_kwh` field.
- [ ] `resolve_loads.rs` ventilation path: replace three mismatched keys with
  `VentilationConfig` struct. Convert CFM to m³/s here at construction time
  (not in the equipment): `flow_rate_m3_s: flow_cfm * CFM_TO_M3_S`.
  Map `"sensible_recovery_efficiency"` → `sensible_effectiveness`,
  `"latent_recovery_efficiency"` → `latent_effectiveness`.
- [ ] `resolve_der.rs` battery path: replace `Map` construction with
  `BatteryConfig`. Write `inverter_efficiency = rte.sqrt()` as before, but
  document that this is the one-way efficiency (Battery init no longer doubles
  the sqrt).
- [ ] `resolve_der.rs` PV path: replace with `PvConfig`.
- [ ] `resolve_der.rs` generator path: replace with `GeneratorConfig`. Use
  `FuelType` enum value directly — no `{:?}` Debug formatting.
- [ ] `resolve_loads.rs` ScheduledLoad paths: leave as `Raw` for now (these have
  no confirmed key mismatches and the schedule source refactoring in CFG-003
  handles them separately).
