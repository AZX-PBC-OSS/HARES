## Background/Context

`OcvTable::default_li_nmc()` is the only built-in OCV curve. All batteries and EVs use NMC regardless of what chemistry the user specifies. LFP (dominant residential market at 89%) has a fundamentally different voltage profile — flat 3.2V plateau vs NMC's sloping 3.5-4.2V curve. The method lives on `OcvTable` itself so both Battery and EV equipment can call it.

## Work to Do

### `crates/hares-equipment/src/battery/ocv.rs`

- [ ] Add `pub fn for_chemistry(chem: BatteryChemistry) -> Self` dispatch on `OcvTable`:
  ```rust
  pub fn for_chemistry(chem: BatteryChemistry) -> Self {
      match chem {
          BatteryChemistry::Nmc => Self::default_li_nmc(),
          BatteryChemistry::Lfp => Self::default_lfp(),
          BatteryChemistry::Nca => Self::default_nca(),
          BatteryChemistry::Lto => Self::default_lto(),
      }
  }
  ```

- [ ] Add `pub fn default_lfp() -> Self`:
  - 11-point table, SOC 0.0-1.0 in 0.1 steps
  - LFP characteristic: flat 3.2-3.3V plateau (SOC 0.2-0.8), steep drop below 0.1, steep rise above 0.9
  - Voltage range: 2.50V (empty) to 3.65V (full)
  - Reference: Prada et al. 2013 LFP model, validated against A123 26650 cells

- [ ] Add `pub fn default_nca() -> Self`:
  - 11-point table, SOC 0.0-1.0 in 0.1 steps
  - NCA: similar shape to NMC but ~50mV higher across mid-SOC, steeper top-of-charge
  - Voltage range: 2.70V (empty) to 4.20V (full)
  - Reference: Chen et al. 2020 NCA parametrisation

- [ ] Add `pub fn default_lto() -> Self`:
  - 11-point table, SOC 0.0-1.0 in 0.1 steps
  - LTO: low voltage titanate anode, flat ~2.3V plateau
  - Voltage range: 1.50V (empty) to 2.80V (full)

- [ ] Add same `for_chemistry()` dispatch on `UNegTable`:
  - LFP, NCA, LTO can all share the NMC graphite anode U_neg curve initially (same anode chemistry)
  - LTO has a different anode (Li4Ti5O12) — use a placeholder that returns the NMC curve with a TODO comment

### `crates/hares-equipment/src/battery/mod.rs`

- [ ] Add `const KEY_CHEMISTRY: &str = "chemistry";`
- [ ] In the init path where OCV table is set up (where `OcvTable::default_li_nmc()` is currently called), read chemistry from config:
  ```rust
  let chemistry = config.get_str(KEY_CHEMISTRY)
      .and_then(|s| BatteryChemistry::from_str(s).ok())
      .unwrap_or(BatteryChemistry::Nmc);
  ```
- [ ] Only apply the chemistry-default OCV table if no user-provided table was injected. The codebase already tracks this via `self.custom_ocv: bool` (set to `true` by `set_ocv_table()`, `false` by `reset_ocv_table()`). Guard with:
  ```rust
  if !self.custom_ocv {
      self.ocv_table = OcvTable::for_chemistry(chemistry);
  }
  if !self.custom_u_neg {
      self.u_neg_table = UNegTable::for_chemistry(chemistry);
  }
  ```
- [ ] When `reset_ocv_table()` is called, it should now restore the chemistry-appropriate default (not always NMC). Store the resolved chemistry on the Battery struct:
  ```rust
  fn reset_ocv_table(&mut self) -> crate::Result<()> {
      self.ocv_table = OcvTable::for_chemistry(self.chemistry);
      self.custom_ocv = false;
      Ok(())
  }
  ```
