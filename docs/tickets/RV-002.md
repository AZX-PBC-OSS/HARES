## Background/Context

`batch_step` in `py_gym.rs` accepts action arrays from RL agents but silently discards them (`let _ = actions.get(idx)` at lines 34 and 134). The `TODO(H-7)` comment is not visible to callers. RL training loops run without error but produce no influence on the simulation, making the RL integration non-functional.

## Decision

**Raise `NotImplementedError` immediately.** The action-to-control mapping requires H-7 (action space definition) which is not yet designed. Silently discarding is the worst option. Raising an explicit error ensures RL callers discover the gap at first use, not after a full training run. When H-7 lands, this error path becomes the wire-up site.

## Work to Do

- [ ] Replace `let _ = actions.get(idx)` at both call sites with a check: if any action array is non-empty / non-None, raise `PyErr::new::<pyo3::exceptions::PyNotImplementedError, _>("batch_step action mapping is not yet implemented (H-7)")`
- [ ] Remove the `TODO(H-7)` comment — the error message now documents the gap
- [ ] Ensure `actions = None` (the default) continues to work without error
- [ ] Validate action array dimensions match dwelling count before raising, to give a useful error for shape mismatches too
