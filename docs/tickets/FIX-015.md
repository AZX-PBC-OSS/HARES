# FIX-015: Multi-speed parameter CSV not loaded

> **Clarified** (Codex review 2026-03-19): The broader issue is that HVAC defaults/curve sets from `defaults.rs` are not being propagated into equipment specs beyond ZIP coefficients. Fix should: (1) add explicit HVAC defaults merge path in HPXML equipment resolution, (2) then add multispeed selection keyed by equipment_type + efficiency + speed_count from CSV.

> **Architecture note:** HARES Rust core must use clean, typed, SI-unit config keys only. Any OCHRE key/unit translation happens in the Python adapter layer (`python/ochre_next/compat/`). Do not add dual-key lookups or OCHRE naming conventions to Rust code.

**Severity:** HIGH
**Crate:** `hares-io`
**File:** `crates/hares-io/src/hpxml/equipment.rs`

---

## Bug

OCHRE loads `HVAC Multispeed Parameters.csv` to derive per-speed capacity ratios and COP values from rated efficiency. HARES has the file in `defaults/HVAC Multispeed Parameters.csv` but never loads it. A grep for `Multispeed` or `multispeed` or `multi_speed` across `crates/hares-io/src/` returns zero results.

This means multi-speed equipment (2-speed AC, variable-speed heat pumps) cannot get their per-speed capacity ratios, COPs, or SHR values from the CSV. Combined with FIX-004 (number_of_speeds not derived), all multi-speed equipment runs as single-speed with a single set of performance curves.

## OCHRE Reference

OCHRE `Equipment/HVAC.py` loads the multispeed CSV during initialization:

```python
# Load multispeed parameters from CSV
# Lookup by equipment name + efficiency + number_of_speeds
# Derive per-speed: capacity_ratio, COP, SHR for each speed stage
```

The CSV contains rows keyed by equipment type, efficiency range, and speed count, with columns for each speed stage's capacity ratio relative to rated, COP at that stage, and SHR.

## Fix

The CSV lookup happens entirely in `hares-io` during HPXML resolution. Equipment config receives clean per-speed capacity/EIR arrays as typed fields. No CSV file paths, OCHRE column names, or CSV parsing in equipment code.

1. Add a loader in `hares-io/src/defaults.rs` or a new module that reads `HVAC Multispeed Parameters.csv`.
2. During HPXML equipment parsing in `hares-io` (after computing `number_of_speeds` per FIX-004), look up the CSV by equipment type + efficiency + number_of_speeds.
3. Extract per-speed capacity ratios, COPs, and SHRs.
4. Insert into equipment config as clean typed arrays: `capacity_ratios: Vec<f64>`, `speed_cops: Vec<f64>`, `speed_shrs: Vec<f64>`.

```rust
// In hares-io HPXML parsing, after FIX-004 inserts number_of_speeds:
if n_speeds > 1 {
    if let Some(multispeed_params) = defaults.multispeed_params(&name, seer, n_speeds) {
        params.insert("capacity_ratios".to_string(), json!(multispeed_params.capacity_ratios));
        params.insert("speed_cops".to_string(), json!(multispeed_params.cops));
        params.insert("speed_shrs".to_string(), json!(multispeed_params.shrs));
    }
}
```

The equipment model reads these arrays from its typed config — no CSV loading or OCHRE column name matching at runtime.
