## Background/Context

The telemetry system uses `HashMap<String, f64>` with magic string keys for all
equipment outputs. Core simulation logic reads these via fallback chains that hide
bugs and provide no compile-time guarantees. This ticket adds the foundational types
that all subsequent tickets build on.

**Parallel dependency:** Typed CoreOutput is only as trustworthy as the config that
constructs equipment. The CFG ticket series (typed equipment configs with fail-fast
validation) should land in parallel or shortly after CO to ensure end-to-end typed
safety from config → equipment → core output.

## Work to Do

- [ ] Add `ElectricPower` enum with `Consumption(f64)`, `Generation(f64)`,
      `Bidirectional(f64)` variants. Result-returning constructors that validate
      `>= 0` for Consumption/Generation, `is_finite()` for all. Methods:
      `net_consumption_kw()`, `signed_kw()`.
- [ ] Add `Soc` newtype wrapping `f64` in `[0.0, 1.0]`. Implement `TryFrom<f64>`
      returning `Result<Self, HaresError>`. Method: `get() -> f64`.
- [ ] Add `FuelPower` struct: `{ fuel_type: FuelType, consumption_w: f64 }`.
      Derive Clone, Copy, Debug, PartialEq, Serialize, Deserialize.
- [ ] Add `CoreFlows` struct: `{ electric_kw: Option<ElectricPower>,
      reactive_power_kvar: Option<f64>, fuel_w: Option<FuelPower> }`. Default all None.
- [ ] Add `CoreState` struct: `{ operating_mode: Option<OperatingMode>,
      soc: Option<Soc> }`. Default all None.
- [ ] Add `CoreOutput` struct: `{ flows: CoreFlows, state: CoreState }`. Default.
- [ ] Add `#[repr(u8)]` to existing `OperatingMode` enum with explicit discriminants
      for every variant (Off=0, Heating=1, ..., BackupElement=11).
      Add `pub fn as_code(&self) -> f64 { *self as u8 as f64 }`.
- [ ] Add `CoreCapabilities` bitflags: `ELECTRIC`, `REACTIVE`, `FUEL`, `HAS_SOC`,
      `HAS_MODE`. Enable bitflags serde feature. If serde doesn't work cleanly with
      bitflags, use a newtype wrapper with manual Serialize/Deserialize.
- [ ] Add `core_capabilities: CoreCapabilities` field to `EquipmentDescriptor`.
- [ ] Update `equipment_descriptor_round_trips_through_json` test to include new field.
- [ ] Add test locking all OperatingMode numeric codes (assert Off==0, Heating==1, etc.).
- [ ] Add test: `ElectricPower::consumption(-1.0)` returns Err.
- [ ] Add test: `Soc::try_from(1.5)` returns Err.
- [ ] Document reactive power sign convention in doc comment on `reactive_power_kvar`:
      positive = inductive/lagging (IEEE 1547).
