## Background/Context

Gas/Electric Furnace, Gas/Electric Boiler, and Baseboard all have the same
heating efficiency key mismatch: the resolver writes `"heating_efficiency"`,
but the equipment reads `"fuel_efficiency"` / `"afue"` / `"efficiency"` via a
`first_f64` fallback chain. The fallback chain never finds `"heating_efficiency"`
because that key is not in the list, so these equipment types always use the
hard-coded default efficiency (0.8 for gas furnace). This means real HPXML AFUE
values are silently discarded for every simulation.

Confirmed mismatches (from CW-001, CW-002, CW-004, CW-007):
- `furnace.rs:300` reads `"fuel_efficiency"`, `"afue"`, `"efficiency"` — none
  match what resolver writes
- `boiler.rs` reads same set of keys — same miss
- Resolver writes `"heating_efficiency"` at `resolve_hvac.rs:637`

This ticket defines typed config structs for all HVAC heating equipment, updates
their `init()` methods to use `config.typed::<T>()`, and updates the test helpers
that construct `EquipmentConfig` in-process. The resolver is NOT updated here —
that is CFG-011. Equipment uses `typed()` in `init()`, and if the payload is
`Raw` (as it will be until CFG-011 lands), it falls back to the existing
`first_f64` chain. This keeps the tree green through the migration.

Fixes: CW-001 (gas furnace AFUE mismatch), CW-002 (electric furnace eir key),
CW-004 (boiler efficiency key), CW-007 (boiler electric efficiency key).

## Typed config structs to add

### `GasFurnaceConfig`
```rust
#[derive(Clone, Debug, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct GasFurnaceConfig {
    pub equipment_id: Option<u32>,
    pub zone_id: Option<u16>,
    pub capacity_w: f64,
    pub afue: f64,                    // replaces fuel_efficiency/afue/efficiency
    pub fan_power_w: Option<f64>,
    pub fan_power_w_per_cfm: Option<f64>,
    pub fraction_load_served: Option<f64>,
    pub duct_dse: Option<f64>,
    pub duct_zone_id: Option<u16>,
    pub duct_house_volume_m3: Option<f64>,
    pub duct_supply_leakage_frac: Option<f64>,
    pub duct_supply_area_m2: Option<f64>,
    pub duct_supply_r_m2_k_w: Option<f64>,
    pub duct_return_leakage_frac: Option<f64>,
    pub duct_return_area_m2: Option<f64>,
    pub duct_return_r_m2_k_w: Option<f64>,
    pub duct_zone_type: Option<String>,
    pub basement_zone_id: Option<u16>,
    pub basement_airflow_ratio: Option<f64>,
    pub system_type: Option<String>,
    pub number_of_speeds: Option<u8>,
}
```
`impl EquipmentTypedConfig for GasFurnaceConfig` with
`equipment_type_name() = "Gas Furnace"`.

### `ElectricFurnaceConfig`
Same fields but `eir: f64` instead of `afue`.
`equipment_type_name() = "Electric Furnace"`.

### `GasBoilerConfig`
`afue: f64`, plus hot-water loop fields (`loop_id`, etc.).
`equipment_type_name() = "Gas Boiler"`.

### `ElectricBoilerConfig`
`eir: f64`, plus hot-water loop fields.
`equipment_type_name() = "Electric Boiler"`.

### `ElectricBaseboardConfig`
`capacity_w: f64`, `eir: f64`, `zone_id`, `equipment_id`.
`equipment_type_name() = "Electric Baseboard"`.

### `IdealHvacConfig`
`heating_capacity_w: Option<f64>`, `cooling_capacity_w: Option<f64>`,
`heating_eir: Option<f64>`, `cooling_eir: Option<f64>`, `shr: Option<f64>`,
`fraction_heating_load_served: Option<f64>`,
`fraction_cooling_load_served: Option<f64>`, `zone_id`, `equipment_id`.
`equipment_type_name() = "Ideal HVAC"`.

  Each implements `EquipmentTypedConfig`.
- [ ] In each equipment `init()`: add a typed-first path:
  ```rust
  if config.is_typed() {
      let c = config.typed::<GasFurnaceConfig>()?;
      self.rated_capacity_w = c.capacity_w;
      self.fuel_efficiency = c.afue;
      // ... remaining fields
  } else {
      // existing first_f64 fallback chain — unchanged
  }
  ```
  The else branch is the existing code verbatim. This pattern is repeated for
  every equipment type. When CFG-011 lands, all real HPXML paths go through the
  typed branch; the Raw branch remains for in-process test fixtures until those
  are updated.
- [ ] Add `Default` impl for each struct with the same defaults that the current
  `first_f64(...).unwrap_or(default)` code uses. The `Default` value serves as
  documentation of the fallback.
- [ ] Update in-process test fixtures in `furnace.rs`, `boiler.rs`, etc. to use
  `EquipmentConfig::from_typed(...)` instead of manually building

  not `fuel_efficiency`). This surfaces any test relying on wrong key names.
- [ ] Add round-trip test per struct: `serde_json::to_value(&config)` then
  `serde_json::from_value::<T>(v)` — fields match original.
- [ ] Add negative test: inject JSON with an unknown field into `typed::<GasFurnaceConfig>()` —
  returns `Err` naming the unknown key.
- [ ] Verify the existing physics tests in `furnace.rs` and `boiler.rs` pass
  with typed-path init (efficiency values must be correct, not defaulted).
