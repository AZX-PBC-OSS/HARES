## Background/Context

`conversions.rs` converts Arrow `RecordBatch` data to Polars DataFrames via a triple-nested loop (batches × columns × rows) that creates one Python float object per cell. For a 1-year simulation at 1-minute resolution (525,600 rows × ~20 columns), this creates ~10 million Python objects one at a time, with no pre-allocation on the column value vectors.

This is both a performance bottleneck and a memory fragmentation issue. Arrow and Polars share the same underlying memory format — there should be zero-copy or near-zero-copy conversion.

## Work to Do

- [x] Replace `record_batches_to_polars_df()` with Arrow IPC zero-copy path:
  - Serialize batches to Arrow IPC bytes in Rust, pass as `PyBytes`, call `polars.read_ipc()` on the Python side
  - Eliminates the triple-nested loop entirely
- [x] Add `arrow = { workspace = true, features = ["ipc"] }` to Cargo.toml
- [x] Pre-allocate column vectors with `Vec::with_capacity()` in `steps_to_polars_df()` and `dwelling_metrics_to_polars_df()`
- [x] Extract `batches_or_steps_to_polars_df()` helper to DRY the routing logic shared by `simulate()` and `results()`
- [x] Write `tests/python/test_py_conversions.py`:
  - Session-scoped fixture to avoid redundant simulations
  - Verify DataFrame shape, column names, data types, Time column dtype
  - Verify fallback path (results before simulate returns empty DataFrame)
  - Fleet tests with proper fixture-level skips (not hardcoded `@pytest.mark.skip`)
