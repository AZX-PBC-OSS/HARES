## Background/Context

`conversions.rs` converts Arrow `RecordBatch` data to Polars DataFrames via a triple-nested loop (batches × columns × rows) that creates one Python float object per cell. For a 1-year simulation at 1-minute resolution (525,600 rows × ~20 columns), this creates ~10 million Python objects one at a time, with no pre-allocation on the column value vectors.

This is both a performance bottleneck and a memory fragmentation issue. Arrow and Polars share the same underlying memory format — there should be zero-copy or near-zero-copy conversion.

## Work to Do

- [ ] Replace `record_batches_to_polars_df()` (lines 12-100) with Arrow IPC zero-copy path:
  - Concatenate all `RecordBatch`es into a single batch (or write to IPC buffer)
  - Use `polars.from_arrow()` or `polars.read_ipc()` on the Python side
  - This eliminates the triple-nested loop entirely
  - Implementation: serialize batches to Arrow IPC bytes in Rust, pass as `PyBytes`, let Polars deserialize natively
  - Alternative: use `pyarrow` as bridge — convert `RecordBatch` to `pyarrow.RecordBatch` via PyO3-arrow, then `polars.from_arrow(pa_table)`
- [ ] If pyarrow bridge: add `arrow = { version = "58", features = ["pyarrow"] }` to workspace deps or use `arrow-pyarrow` interop
- [ ] Pre-allocate column vectors with `Vec::with_capacity(total_rows)` as a fallback if zero-copy path isn't viable (line 46 currently uses `Vec::new()`)
- [ ] Fix `steps_to_polars_df()` (lines 102-145) — this operates on `&[StepResult]` not Arrow batches, so IPC approach doesn't apply. Instead: pre-allocate column vectors with `Vec::with_capacity(steps.len())`, collect all f64 values as Rust vecs, then convert each column to a Python list in one call (not per-row). This is the fallback path used when no Arrow batches are flushed.
- [ ] Fix `dwelling_metrics_to_polars_df()` — acceptable as-is (small N), but add `Vec::with_capacity` for consistency
- [ ] Write `tests/python/test_py_conversions.py`:
  - Benchmark: simulate 1000 steps → `results()` → verify DataFrame has correct shape
  - Verify column names match expected output schema
  - Verify data types are all Float64 (or appropriate)
  - Verify no data loss: first/last row values match expected from Rust
  - Verify timestamp column is correct dtype
