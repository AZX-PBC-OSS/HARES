## Background/Context

The behavioral logic stripped from the EV equipment in DER-006 needs a new home. The EV Driver Actor implements the Actor trait and handles all scheduling/charging decisions, dispatching control signals (PlugIn, DrivingConsumption, SOCTarget, PowerSetpoint) to the EV equipment.

Users can use factory methods from catalog presets (DER-010) OR construct a fully custom EvDriverActor with arbitrary parameters for custom archetypes and strategies.

      // Runtime state

      todays_event: Option<DayEvent>,
      trip_remaining_kwh: f64,       // energy remaining in current trip

- [ ] Define `EventDistributionRow` and `DayEvent` types in the actor module (`crates/hares-core/src/actors/ev_driver.rs`). These are actor-internal types — no other crate needs them. Delete the copies from `crates/hares-equipment/src/ev/schedule.rs` when that file is removed.

- [ ] Use `ScheduleSource::TimeWindows` with noise (DER-011) for `daily_drive_miles`. This supports day-of-week-dependent distributions with seeded RNG: e.g., WFH driver averages 12 miles on weekdays (σ=6) but 25 on weekends (σ=10), with min_value=0.0 clamp to prevent negative miles. For simple archetypes, a single `ScheduleSource::Stochastic` Gaussian is sufficient. The actor's `daily_drive_miles` field is a generic `ScheduleSource`, so users can plug in any variant.

### Actor→Equipment state visibility

The `Actor::decide()` method currently receives only `EnvironmentState` (weather, zones, grid). The EvDriverActor needs to observe the EV's SOC, connection state, and capacity to make behavioral decisions (range anxiety, low-SOC plug-in, ready-by charging rate).

Two options:
1. **Extend `EnvironmentState`** with an equipment telemetry snapshot (adds coupling, affects all actors)
2. **Actor holds a shared reference** to the equipment's telemetry (the old EV accessed `self.soc` directly — this is the internal-state equivalent for actors)

Preferred: **Option 2** — the `EvDriverActor` stores a read-only handle to the target EV's telemetry (e.g., `Arc<Telemetry>` or a query callback set at registration). The dwelling wires this up when the actor is added. This keeps `EnvironmentState` clean and lets only actors that need equipment state pay for it.

- [ ] Add `equipment_telemetry: Option<Arc<dyn Fn() -> Telemetry + Send + Sync>>` callback field to `EvDriverActor`, set by dwelling on `add_actor()`
- [ ] The callback returns the target EV's current `Telemetry` snapshot (SOC, connection_state, capacity_kwh, active_power_kw)
- [ ] If the callback is not set (actor used standalone for testing), the actor falls back to tracking its own SOC estimate from EvDrive/EvAwayCharge signals it has emitted

- [ ] Implement `Actor::decide()`:
  1. Query EV telemetry for current SOC, connection_state, capacity_kwh
  2. Roll daily event if new day (from old `maybe_roll_event_for_day`)
  The actor is a **driver proxy** — it makes the same decisions a human driver would: when to plug in, when to leave, how much driving to do, and what charge settings to put into the car's computer. The EV's internal BMS handles the actual charging physics.

  2. Read EV telemetry (SOC, capacity_kwh, connection_state) to make informed decisions
  3. Roll daily event: sample miles from `daily_drive_miles` ScheduleSource, decide departure/arrival times
  4. Check plug-in policy: if `LowSoc { threshold }`, only plug in when SOC < threshold
  5. Check range anxiety: if SOC after planned trip would be dangerously low, adjust (charge more, skip trip, etc.)

  **Range anxiety override** (checked before any strategy):
  5a. Compute tomorrow's trip energy: `trip_kwh = tomorrow_miles × kwh_per_mile_temp_corrected(T_amb)`
  5b. If `current_soc - trip_kwh/capacity_kwh < range_anxiety_soc_floor` → override strategy, emit `SOCTarget { target_soc: 1.0 }` to charge at max power regardless of strategy. This is the universal safety override from the DER_Detection reference.

  **On arrival home** (plug in and set car's charge settings):
  6. Emit `EvPlugIn { HomePluggedIn }`
  7. Apply charging strategy by updating the EV's computer settings:
     - `Immediate` → emit `SOCTarget { target_soc }` (charge at full power immediately — no BMS delay)
     - `Nightly { off_peak_start, off_peak_end, target_soc }` → emit `EvSetReadyBy { departure_hour: off_peak_end, target_soc }` — uses off-peak end as the deadline so BMS naturally delays charging into the off-peak window.
     - `LowSoc` → only plug in if SOC < threshold; emit `SOCTarget { target_soc }` (charge immediately when plugged in)
     - `QuickThenWait` → emit `SOCTarget { partial_soc }` (immediate partial charge, then BMS idles)
     - `PreDeparture` → emit `EvSetReadyBy { departure_hour, target_soc }` (BMS computes latest start time)
     - `TouAware` → emit `EvSetReadyBy { departure_hour, target_soc }` + `PowerLimit` during peak hours (BMS + DR-style curtailment). If `soc < emergency_soc_floor` during peak, bypass limit and charge at full power.
     - `V2H` → emit `SOCTarget { discharge_threshold_soc }`. V2H discharge logic requires household net load observation — actor reads net_power from telemetry and emits negative `PowerSetpoint` when load exceeds threshold and SOC > min_soc. (Requires household load visibility — deferred to DER-012 if EnvironmentState doesn't yet carry net load.)
     - `V2G` → emit `SOCTarget { 1.0 }` for charging. V2G export logic requires grid price signal — actor reads price from EnvironmentState and emits negative `PowerSetpoint { -max_export_kw }` when price > price_threshold and SOC > min_soc. (Requires price signal — deferred to DER-012 if EnvironmentState doesn't yet carry grid price.)
     - `SolarSurplus` → emit `SelfConsumption { enabled: true, solar_only_charging: true }`. Actor observes PV surplus and modulates `PowerLimit` to track surplus above min_charge_rate_kw. Departure schedule constraints handled via `EvSetReadyBy`. (Requires PV generation visibility — deferred to DER-012 if not available.)

  **Temperature-corrected driving efficiency**:
  - Actor stores `fuel_economy_kwh_per_mi: f64` (base, at 20°C)
  - On each trip: `effective_kwh_per_mi = base / max(0.60, 1.0 - 0.008 × max(0, 20 - T_amb))` (0.8% loss per °C below 20°C, floored at 60% of base)
  - `trip_kwh = miles × effective_kwh_per_mi`

  **On departure** (multi-timestep driving):
  8. Emit `EvPlugIn { Disconnected }`
  9. Over subsequent timesteps while driving: emit `EvDrive { kwh }` each step with that timestep's share of trip energy (temperature-corrected). Trip duration = `miles / average_speed_mph` hours; energy per timestep = `total_kwh × (time_res / trip_duration)`.
  10. Actor tracks remaining trip miles/energy internally and stops emitting EvDrive when trip is complete.

  **While away** (optional, for archetypes with workplace/DCFC charging):
  11. `away_charge_fraction: f64` determines what fraction of trip energy is recouped away from home
  12. Emit `EvPlugIn { AwayPluggedIn }` + `EvAwayCharge { power_kw }` for external sessions (workplace L2 at 6.6 kW)
  13. On long trips (> 70% of vehicle range): roll Bernoulli(dcfc_probability) for DCFC stop, top up to dcfc_target_soc (0.80)
  14. Emit `EvAwayCharge { 0.0 }` when session ends, `EvPlugIn { Disconnected }` when leaving

All stochastic behavior (daily miles sampling, arrival time jitter, event day rolling) derives from this seed via ChaCha8Rng for reproducible results.
