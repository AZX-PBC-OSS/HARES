## Background/Context

The behavioral logic stripped from the EV equipment in DER-006 needs a new home. The EV Driver Actor implements the Actor trait and handles all scheduling/charging decisions, dispatching control signals (PlugIn, DrivingConsumption, SOCTarget, PowerSetpoint) to the EV equipment.

Users can use factory methods from catalog presets (DER-010) OR construct a fully custom EvDriverActor with arbitrary parameters for custom archetypes and strategies.

## Work to Do

### Create `crates/hares-core/src/actors/ev_driver.rs`

- [ ] Define `EvDriverActor` struct implementing `Actor` trait:

  ```rust
  pub struct EvDriverActor {
      name: String,
      target_equipment: Arc<str>,  // name of EV equipment to control

      // Behavioral config (strong types from hares-types)
      strategy: ChargingStrategy,
      plug_in_policy: PlugInPolicy,

      // Driving patterns
      daily_drive_miles_mean: f64,
      daily_drive_miles_stddev: f64,
      event_day_ratio: f64,
      arrival_fuzz_minutes: f64,
      departure_fuzz_minutes: f64,

      // Arrival/departure distribution (moved from ev/schedule.rs)
      distributions: Vec<EventDistributionRow>,

      // Runtime state
      rng: ChaCha8Rng,
      current_day_ordinal: i32,
      todays_event: Option<DayEvent>,
      plugged_in: bool,
      arrival_soc_applied: bool,
  }
  ```

- [ ] Define `EventDistributionRow` and `DayEvent` types in the actor module (`crates/hares-core/src/actors/ev_driver.rs`). These are actor-internal types — no other crate needs them. Delete the copies from `crates/hares-equipment/src/ev/schedule.rs` when that file is removed.

- [ ] Use `ScheduleSource::Stochastic` (already exists in `hares-types/src/schedule.rs`) for daily miles sampling. This provides seeded ChaCha8Rng with Gaussian distribution, which is exactly what the EV driver needs for `daily_drive_miles_mean/stddev`. The existing schedule infrastructure handles deterministic replay via seed.

- [ ] Implement `Actor::decide()`:
  1. Roll daily event if new day (from old `maybe_roll_event_for_day`)
  2. Check if within event window → emit `PlugIn { connected: true/false }`
  3. On arrival: emit `DrivingConsumption { kwh }` for trip energy
  4. Apply `ChargingStrategy` logic → emit appropriate control signals:
     - `Immediate` → `SOCTarget { target: target_soc }`
     - `Nightly` → check time, emit SOCTarget only during off-peak window
     - `LowSoc` → emit SOCTarget only when below threshold
     - `QuickThenWait` → SOCTarget to partial_soc, then nothing
     - `PreDeparture` → calculate latest start, emit PowerSetpoint at max
     - `TouAware` → block during peak, emit SOCTarget during off-peak
  5. On departure: emit `PlugIn { connected: false }`

- [ ] Implement `Actor::interests()` → `[ActorInterest::EveryStep]`

- [ ] Provide `EvDriverActor::new()` constructor accepting all config params directly (for custom archetypes). **`seed: u64` is required** — no default, no Option. All stochastic behavior (daily miles sampling, arrival time jitter, event day rolling) derives from this seed via ChaCha8Rng for reproducible results.

- [ ] Provide `EvDriverActor::from_preset(target: &str, preset: &ArchetypePreset, seed: u64)` factory (used by DER-010). Same seed requirement.

- [ ] Deterministic guarantee: two actors with identical config and seed produce identical control signal sequences regardless of platform or Rust version (ChaCha8Rng is platform-independent).
