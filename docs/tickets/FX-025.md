## Background/Context

`EventBasedLoad` hard-codes `fuel: FuelType::Electric` at line 158. HPXML parser correctly extracts fuel type but `EventBasedLoad::new` ignores it. Gas cooking ranges silently become electric.

## Work to Do

- [ ] Read `fuel_type` from config in `EventBasedLoad::init` (use `parse_fuel_type` from helpers — note `build_spec` writes `"Gas"` via Debug format, `parse_fuel_type` handles case-insensitive matching after `to_ascii_lowercase()`)
- [ ] **Also fix `WetAppliance`** — it has the identical bug at line 476 (hardcodes `FuelType::Electric`). Gas clothes dryers are wired through `WetAppliance` and OCHRE explicitly supports them
- [ ] Declare `PortType::Fuel` port dynamically at init time when fuel type is gas — follow the `ScheduledLoad::update_ports` pattern. Without this, `ports.accumulate(&PortContribution::Fuel{...})` will fail at runtime
- [ ] Route gas consumption to gas port when fuel type is gas
- [ ] Handle dual-fuel case: gas cooking ranges have both gas AND electric consumption. Follow `ScheduledLoad`'s dual-source pattern (separate `power_source` for electric + `gas_source` for gas)
- [ ] Add `gas_consumption_w` telemetry field when equipment is gas (consistent with `ScheduledLoad`)
- [ ] Add tests: gas cooking range reports gas, gas clothes dryer reports gas, electric cooking range still reports electric
