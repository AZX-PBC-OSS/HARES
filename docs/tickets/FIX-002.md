# FIX-002: Missing max_electric_power_w config path

> **Clarified** (Codex review 2026-03-19): Fix must apply the `max_electric_power_w` precedence check consistently in BOTH the CSV-column branch AND the default-profile branch. Create a shared `determine_max_kw(spec) -> Option<f64>` helper that checks: (1) `max_electric_power_w` / 1000 first, (2) `annual_electric_kwh / 8760 / mean_fraction` second. Both branches of `inject_power_schedule` should call this helper.

> **Architecture note:** HARES Rust core must use clean, typed, SI-unit config keys only. Any OCHRE key/unit translation happens in the Python adapter layer (`python/ochre_next/compat/`). Do not add dual-key lookups or OCHRE naming conventions to Rust code.

**Severity:** CRITICAL
**Crate:** `hares-io`
**File:** `crates/hares-io/src/schedule_resolve.rs`

---

## Bug

In `schedule_resolve.rs` lines 349-353, `inject_power_schedule` only checks `annual_electric_kwh`. OCHRE checks `Max Electric Power (W)` FIRST, and only falls back to annual energy if max power is missing. Some HPXML files provide max power directly without annual energy.

```rust
// schedule_resolve.rs:349-353
let annual_kwh = spec
    .parameters
    .get("annual_electric_kwh")
    .and_then(|v| v.as_f64())
    .unwrap_or(0.0);
```

When `annual_electric_kwh` is absent but `max_electric_power_w` is present, the code defaults `annual_kwh` to 0.0, producing a zero schedule -- the equipment appears dead.

## OCHRE Reference

OCHRE `ochre/utils/schedule.py` `convert_power_column` checks for `Max Electric Power (W)` first. If present, it uses `max_kw = max_power_w / 1000` directly, skipping the annual energy derivation entirely. Only when max power is absent does it compute `max_kw = annual_kwh / 8760 / mean_fraction`.

## Fix

`max_electric_power_w` is the HARES-native config key. The Rust `schedule_resolve.rs` checks for this single clean key — no OCHRE aliases like `"Max Electric Power (W)"`. If OCHRE or HPXML uses a different name, the HPXML parser (`hares-io`) or the Python adapter layer (`python/ochre_next/compat/`) translates it to `max_electric_power_w` at extraction time.

Before computing `max_kw` from `annual_electric_kwh / 8760 / mean_fraction`, check for `max_electric_power_w` in spec parameters. If present, use `max_kw = max_electric_power_w / 1000.0` directly and skip the annual energy derivation.

Insert before line 349:

```rust
let max_power_w = spec
    .parameters
    .get("max_electric_power_w")
    .and_then(|v| v.as_f64());

if let Some(max_w) = max_power_w {
    let max_kw = max_w / 1000.0;
    // Use fraction series or profile to shape, but scale to max_kw directly
    // ... (apply fraction series scaled by max_kw)
    return;
}
```
