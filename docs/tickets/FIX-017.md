# FIX-017: Battery degradation formula handles initial condition correctly but diverges from OCHRE at edge

> **Clarified** (Codex review 2026-03-19): HARES formula is a valid startup-stability treatment, not plainly wrong. The OCHRE formula citation in this ticket is not exact. Before changing, compare full daily integration trajectories against OCHRE to confirm actual divergence. Downgraded from HIGH to MEDIUM.

**Severity:** MEDIUM
**Crate:** `hares-equipment`
**File:** `crates/hares-equipment/src/battery.rs`

---

## Bug

HARES battery degradation model (`battery.rs` lines 472-480) implements Smith 2017 Mechanism 1 (calendar SEI) with a branching formula:

```rust
// battery.rs:472-480
// Mechanism 1: calendar SEI (sqrt-of-time progression)
let dq_li1 = if self.q_li1.abs() < 1e-5 && self.day_age > 0 {
    b1_eff / (self.day_age as f64).sqrt()
} else if self.q_li1.abs() >= 1e-5 {
    0.5 * b1_eff.powi(2) / self.q_li1
} else {
    // day_age == 0: first day, skip to avoid division-by-zero
    0.0
};
```

The first branch (`q_li1 < 1e-5 && day_age > 0`) uses `b1_eff / sqrt(day_age)` as an initial condition bootstrapping formula. This is a valid numerical technique, but it diverges from OCHRE's implementation.

OCHRE always uses `dq_li1 = 0.5 * b1^2 / q_li1` (state-dependent), and handles the initial condition by seeding `q_li1` to a small nonzero value on the first day rather than having a separate formula branch.

The divergence is small for long runs (the two formulas converge after ~10 days), but for short RL episodes or capacity fade rate comparisons, the trajectories differ in the first few days.

## OCHRE Reference

OCHRE `Equipment/Battery.py` Smith 2017 degradation:

```python
# Calendar aging increment (Mechanism 1)
dq_li1 = 0.5 * b1**2 / q_li1  # Always state-dependent
```

OCHRE seeds `q_li1` with a small initial value to avoid division by zero.

## Fix

Align to OCHRE's approach: seed `q_li1` to a small initial value instead of branching:

```rust
impl Default for DegradationState {
    fn default() -> Self {
        Self {
            q_li1: 1e-6,  // Small seed to avoid div-by-zero, matches OCHRE
            // ...
        }
    }
}

// Then always use the state-dependent formula:
let dq_li1 = 0.5 * b1_eff.powi(2) / self.q_li1;
```
