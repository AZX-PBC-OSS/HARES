# FIX-005: Mains water temperature not wired into dwelling/environment

> **Clarified** (Codex review 2026-03-19): Mains temperature should be injected via the schedule/custom domain pattern (like setpoint schedules), not only as a weather field. All WH models (resistance, gas, HPWH) must consume the per-step mains temp, not just resistance. Currently `mains_temp_c` in `resistance.rs:89` is static after init — it needs per-step update from environment.

> **Architecture note:** HARES Rust core must use clean, typed, SI-unit config keys only. Any OCHRE key/unit translation happens in the Python adapter layer (`python/ochre_next/compat/`). Do not add dual-key lookups or OCHRE naming conventions to Rust code.

**Severity:** CRITICAL
**Crate:** `hares-core`, `hares-io`
**Files:** `crates/hares-core/src/dwelling.rs`, `crates/hares-core/src/environment.rs`, `crates/hares-io/src/weather.rs`

---

## Bug

The Burch-Christensen mains water temperature model IS implemented in `hares-physics/src/water_mains.rs`, but it is NOT wired into the dwelling or environment. A grep for `water_mains` or `mains_temp` in `hares-core` and `hares-io` returns zero results.

The water heater equipment (`resistance.rs` line 178) defaults to a static `mains_temp_c: 15.0` and only reads it from config (`first_f64(config, &["mains_temp_c", "inlet_temp_c"])`). There is no time-varying mains temperature flowing through the environment.

```rust
// resistance.rs:178 -- hardcoded constant
mains_temp_c: 15.0,
```

The `WeatherTimeSeries` struct (`weather.rs` lines 52-67) has no `mains_temperature_c` field. The `WeatherState` (`environment.rs` lines 66-88) also lacks a mains temperature field. Water heater energy calculations are wrong by 5-15% because the temperature lift is constant year-round instead of varying seasonally.

## OCHRE Reference

OCHRE computes mains temperature using Burch-Christensen in `ochre/utils/schedule.py` and passes it as a time-varying schedule column to the water heater. The seasonal variation is ~10-15 degC in cold climates.

## Fix

The Burch-Christensen mains temperature calculation belongs in `hares-io` weather loading or `hares-physics`. The Rust WH equipment reads `mains_temp_c` from environment state — a clean, typed, SI field. No OCHRE schedule column naming (e.g., `"Mains Temperature (C)"`) in equipment code.

1. Compute mains temperature per-timestep in `hares-core` environment updates using `hares_physics::water_mains::water_mains_temperature_c()`. Add `mains_temp_c: f64` as a typed field on `WeatherState` or pass it as a custom domain payload.
2. Water heater equipment reads `mains_temp_c` from environment state each timestep — one clean typed field, no string lookups.
3. The HPXML parser in `hares-io` provides annual average and range parameters needed for the Burch-Christensen model.

In `environment.rs` (the EnvironmentManager), during `update()`:

```rust
let mains_temp_c = hares_physics::water_mains::water_mains_temperature_c(
    t_annual_avg_c,
    dt_annual_range_c,
    day_of_year,
    Hemisphere::Northern,  // or derive from latitude
);
```

## Test

- **Unit test:** For Denver CO (lat 39.7, annual avg ~10 degC), verify mains temp at summer peak (~18 degC) and winter trough (~4 degC) match the Burch-Christensen model.
- **Integration test:** Run a water heater simulation for 1 year, verify mains temp varies seasonally (not stuck at 15 degC).
