## Background/Context

`EquipmentDescriptor` is the Rust struct that describes each equipment model's identity, type, capabilities, and telemetry channels. It's essential for equipment introspection from Python — users need to know what equipment exists in a dwelling, what control signals each accepts, and what telemetry it reports. Currently none of this is exposed.

`TelemetryField` (name, unit, description) is also unexposed, making telemetry channel discovery impossible.

## Work to Do

- [ ] Add `PyEquipmentDescriptor` to `py_equipment.rs`:
  - `#[pyclass(frozen)]` wrapper around `EquipmentDescriptor`
  - Read-only getters:
    - `id` → `u32` (unwrap `EquipmentId`)
    - `name` → `String`
    - `end_use` → `PyEndUse` (from PY-005)
    - `equipment_type` → `String`
    - `zone` → `Option<u16>` (unwrap `ZoneId`)
    - `fuel_type` → `PyFuelType` (from PY-005). **Note:** Rust field is `fuel: FuelType` but Python getter is named `fuel_type` for clarity.
    - `stage` → `PyExecutionStage` (from PY-005)
    - `control_capabilities` → `PyControlCapabilities` (from PY-005)
    - `telemetry_fields` → `Vec<PyTelemetryField>`
  - `__repr__` showing name, equipment_type, end_use
- [ ] Add `PyTelemetryField` to `py_equipment.rs`:
  - `#[pyclass(frozen)]` wrapper
  - Read-only getters: `name: String`, `unit: String`, `description: String`
  - `__repr__` showing `name (unit)`
- [ ] Add `equipment_descriptors()` method to `PyDwelling`:
  - Returns `Vec<PyEquipmentDescriptor>` by iterating `dwelling.equipment` and calling `.descriptor()` on each
  - This enables Python users to discover all equipment, their capabilities, and available telemetry channels
- [ ] Add `validate_control(name: str, signal: &PyControlSignal) -> bool` method to `PyDwelling`:
  - Checks if the named equipment's `ControlCapabilities` supports the signal type
  - Returns `True` if valid, `False` if not (does not raise)
  - Internally: find equipment by name, call `signal.required_capability()`, check against `descriptor.control_capabilities`
- [ ] Add `equipment_names()` convenience method to `PyDwelling`:
  - Returns `Vec<String>` — just the names, for quick listing
- [ ] Register `PyEquipmentDescriptor` and `PyTelemetryField` in `lib.rs`
- [ ] Update `_hares.pyi` with stubs for both new classes and new dwelling methods
- [ ] Update `__init__.py` to re-export `EquipmentDescriptor`, `TelemetryField`
- [ ] Write `tests/python/test_py_equipment_descriptor.py`:
  - Construct a dwelling from test fixture
  - Call `equipment_descriptors()` → verify returns non-empty list
  - Verify each descriptor has `name` as non-empty string
  - Verify `end_use` returns a `PyEndUse` instance (not a string)
  - Verify `fuel_type` returns a `PyFuelType` instance
  - Verify `stage` returns a `PyExecutionStage` instance
  - Verify `control_capabilities` is a `PyControlCapabilities` with correct flags
  - Verify `telemetry_fields` returns list of `PyTelemetryField` with name, unit, description
  - Verify `equipment_names()` returns list of strings matching descriptor names
  - Verify `__repr__` works on both descriptor and telemetry field
  - Verify equipment with known capabilities (e.g., battery should have `POWER_SETPOINT | SOC_TARGET`)
  - Verify `validate_control("battery_name", ControlSignal.power_setpoint(1.0))` returns `True`
  - Verify `validate_control("battery_name", ControlSignal.thermal_setpoint(heat_c=20.0))` returns `False`
  - Verify `validate_control("nonexistent", ControlSignal.power_setpoint(1.0))` returns `False`
