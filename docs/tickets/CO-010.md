## Background/Context

Python consumers currently read equipment power/soc from DwellingTelemetry which
is now built from CoreOutput. They should also be able to access CoreOutput directly
for authoritative typed values. Document that telemetry HashMap is non-authoritative
diagnostics.

## Work to Do

- [ ] Add read-only `PyCoreOutput` Python class exposing:
      - `electric_kw` → Optional float (net_consumption_kw)
      - `electric_convention` → str ("consumption"/"generation"/"bidirectional")
      - `reactive_power_kvar` → Optional float
      - `fuel_w` → Optional float (consumption_w)
      - `fuel_type` → Optional str
      - `operating_mode` → Optional str (variant name)
      - `soc` → Optional float
- [ ] Expose `core_output` property on PyEquipment returning PyCoreOutput.
- [ ] Update type stubs in `_hares.pyi`.
- [ ] Add Python test asserting core_output values match expected after step.
- [ ] Document in docstrings: "telemetry dict is non-authoritative diagnostics;
      use core_output for simulation-critical values."
