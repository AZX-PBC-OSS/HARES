# FIX-025: HVAC cutout_ratio and min_cycle_time_s default to 0.0

> **STATUS: CLOSED — Invalid** (Codex review 2026-03-19)
> The OCHRE vendored code does NOT default cutout_ratio or min_cycle_time_s to the values claimed (0.25 and 60s). OCHRE's HVAC.py uses 0 for both. HARES matching 0 is correct OCHRE parity. This is a model policy choice, not a bug.

**Severity:** HIGH
**Crate:** `hares-equipment`
**File:** `crates/hares-equipment/src/hvac/hvac_core.rs`

---

## Bug

In `hvac_core.rs` lines 295-296, two thermostat cycling parameters default to zero:

```rust
// hvac_core.rs:295-296
cutout_ratio: extract_numeric(config, "cutout_ratio").unwrap_or(0.0),
min_cycle_time_s: extract_numeric(config, "min_cycle_time_s").unwrap_or(0.0),
```

With `cutout_ratio = 0.0`, there is no minimum input power threshold -- the HVAC can modulate down to arbitrarily small power fractions. With `min_cycle_time_s = 0.0`, there is no minimum on-time constraint, allowing the HVAC to cycle on and off every timestep. Together, these allow unrealistically rapid cycling that no physical system exhibits, and can produce numerical instability in the thermal solver.

## OCHRE Reference

OCHRE `ochre/equipment/hvac.py` uses sensible defaults for cycling parameters:

- `cutout_ratio` defaults to 0.25 (equipment cannot modulate below 25% of rated capacity)
- `min_cycle_time_s` defaults to 60.0 seconds (equipment must stay on for at least 1 minute once engaged)

These values prevent sub-timestep cycling artifacts and match typical residential HVAC behavior.

## Fix

1. Define named constants:

```rust
const DEFAULT_CUTOUT_RATIO: f64 = 0.25;
const DEFAULT_MIN_CYCLE_TIME_S: f64 = 60.0;
```

2. Replace the `.unwrap_or(0.0)` calls:

```rust
cutout_ratio: extract_numeric(config, "cutout_ratio").unwrap_or(DEFAULT_CUTOUT_RATIO),
min_cycle_time_s: extract_numeric(config, "min_cycle_time_s").unwrap_or(DEFAULT_MIN_CYCLE_TIME_S),
```

## Test

- **Unit test:** Create an HVAC with no `cutout_ratio` in config. Verify default is 0.25.
- **Unit test:** Create an HVAC with no `min_cycle_time_s` in config. Verify default is 60.0.

- **Cycling test:** Step HVAC with default min_cycle_time_s. Verify it cannot turn off before 60 seconds have elapsed since turn-on.
