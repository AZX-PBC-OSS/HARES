## Background/Context

Individual binding tests (PY-001 through PY-015) verify each type in isolation. This ticket adds integration tests that exercise the full PyDwelling lifecycle: construction → configuration → control injection → stepping → metrics extraction → checkpoint/restore. It also includes GIL safety stress tests for the `batch_step` function which uses raw pointers across thread boundaries (`SendDwellingPtr` in `py_gym.rs`).

## Work to Do

- [ ] Write `tests/python/test_py_dwelling_integration.py` covering:
  - **Construction round-trip**: `from_hpxml` → verify `config` property returns matching config
  - **Full simulation**: `simulate()` → verify returns non-empty polars DataFrame with expected columns
  - **Step-by-step**: `step()` in a loop → verify each step returns dict with `time`, `net_electric_power_kw`, zone temperatures
  - **Control injection**: Create each ControlSignal variant via typed constructors → `apply_control()` → `step()` → verify telemetry reflects the control
  - **Price signal**: `set_price_signal({"electricity_price": 0.15})` → `step()` → verify no error
  - **Grid voltage**: `set_grid_voltage(1.05)` → `step()` → verify no error
  - **Telemetry**: `telemetry()` → verify `.zone()` returns dict with keys, `.equipment()` returns dict, `.total_power_kw()` returns float
  - **Equipment descriptors** (from PY-008): `equipment_descriptors()` → verify returns list of dicts with `name`, `end_use`, `fuel_type`, `control_capabilities` fields
  - **Metrics**: After `simulate()`, call `metrics()` → verify structured access to `annual_energy_kwh.total`, `gas_energy`, etc.
  - **Checkpoint**: `save_state()` → `step()` N times → `load_state()` → verify state restored (next step matches pre-modification state)
  - **Reset**: `reset_with_seed(42)` → `step()` → `reset_with_seed(42)` → `step()` → verify identical output (deterministic replay)
  - **Timesteps iterator**: `timesteps()` → iterate → verify correct count and monotonic timestamps
  - **GIL safety stress test**: Create 4+ dwellings → call `batch_step()` from multiple Python threads concurrently → verify no segfault, no deadlock, results are valid dicts. **Note:** `py_gym.rs:111-119` extracts raw pointers from `PyRef` borrows that are dropped after `.collect()` — the `Py<PyDwelling>` vec keeps objects alive, but this pattern is fragile. The stress test must verify no use-after-free under concurrent load.
  - **batch_step basic**: Call `batch_step([dwelling], [[0.0]], ["total_power_kw"])` → verify returns list with one dict containing `obs`, `reward`, `terminated`, `truncated`, `info` keys
  - **Solar override lifecycle**: `surface_ids()` → generate synthetic POA as polars DataFrame → `set_solar_override(df)` → step → verify PV output → `clear_solar_override()` → step → verify Perez resumes
  - **Battery LUT injection**: `add_battery("B1", 10.0, charging_curve=[(0,1),(0.8,0.8),(1,0.1)])` → charge to high SoC → verify power tapers
  - **EV with PyBaMM curve**: `add_ev("EV1", 75.0, charging_curve=cc_cv_df)` → charge → verify taper matches curve
  - **Equipment mutation round-trip**: add battery → set LUT → save_state → load_state → verify LUT persists → remove battery → verify clean state
  - **Actor system**: subclass `PyActor` → implement `decide()` returning `[DispatchRequest.thermal_setpoint(...)]` → `add_actor()` → step → verify actor-dispatched setpoint is applied
  - **Built-in actor**: `add_actor_by_name("IdealThermostat", ...)` → step → verify thermostat behavior
  - **DER simulation explorer workflow** (end-to-end, matches `simulation_explorer.py`):
    1. Construct dwelling from HPXML/schedule/weather with 2-week duration at 15-min resolution
    2. `add_pv("PV", 6.0, 26.0, 180.0)` — add PV with tilt/azimuth
    3. `add_battery("Battery", 13.5, max_charge_kw=5.0, max_discharge_kw=5.0)` — add battery
    4. Apply self-consumption control: `apply_control("Battery", ControlSignal.self_consumption(True, False))`
    5. `add_ev("EV", 75.0, max_charging_power_kw=7.68, charging_level=ChargingLevel.L2)` — add EV
    6. `simulate()` → get results DataFrame
    7. Verify DataFrame has columns: `"Total Electric Power (kW)"`, `"PV Electric Power (kW)"`, `"Battery Electric Power (kW)"`, `"Battery SOC (-)"`, `"EV Electric Power (kW)"`, `"EV SOC (-)"`
    8. Verify PV column has negative values (generation)
    9. Verify Battery SOC column is in [0, 1] range
    10. Verify Total Electric Power has both positive and negative values (import/export)
    11. Verify DataFrame has expected number of rows (2 weeks × 96 steps/day = 1344 rows)
