## Background/Context

`PyFleet` currently only supports `from_resstock` construction. The Rust `Fleet` also supports `from_buildings(configs: Vec<DwellingConfig>)` for programmatic fleet assembly and `with_progress(cb)` for progress callbacks. Additionally, the current `simulate()` aborts on first failure and hardcodes `FifteenMin` aggregation. This ticket exposes the full fleet API surface.

## Work to Do

- [ ] Add `from_buildings(configs)` classmethod to `PyFleet`:
  - Accept a list of `PyDwellingConfig` objects from PY-007 (NOT raw dicts — the config type exists now)
  - Each `PyDwellingConfig` is converted to `DwellingConfig` via `to_dwelling_config()`
  - Optional `sample_weights: Option<Vec<f64>>` kwarg — if provided, must match length of configs; if None, all weights default to 1.0
  - Internally calls `Fleet::from_buildings(dwelling_configs)` then patches weights
- [ ] Add `resolution` kwarg to `simulate()`:
  - Accept `AggregationResolution` enum from PY-005 as the primary type in the stub signature
  - Default: `AggregationResolution::FifteenMin`
  - String convenience ("15min", "hourly") is a `FromPyObject` fallback only, not the documented API
- [ ] Update `from_resstock` to accept `ResStockVersion` enum (from PY-005) as the primary type for the `resstock_version` parameter — string is a `FromPyObject` fallback only, not the documented API
- [ ] Change `simulate()` error handling to be fault-tolerant by default:
  - Collect both successes and failures instead of aborting on first error
  - Add `failures` property to `PyFleetResults` returning a list of dicts `{bldg_id: int, error: str}`
  - Add `n_succeeded` and `n_failed` properties to `PyFleetResults`
  - Only raise `ValueError` if ALL dwellings fail (total fleet failure)
  - **Breaking change:** Add `raise_on_failure: bool = False` kwarg. When `True`, raises on first failure (old behavior). Default `False` is the new fault-tolerant behavior. Document in docstring.
  - This requires a minor version bump in the release that includes this change
- [ ] Add `__len__` to `PyFleet` returning number of entries
- [ ] Add progress callback support:
  - `simulate(progress: Optional[Callable[[int, int], None]])` kwarg
  - Bridge Python callable to Rust `with_progress` via `Python::with_gil` inside the callback
  - GIL re-acquisition in the callback is safe because `simulate` releases the GIL via `py.detach()`
- [ ] Update `_hares.pyi` with all new methods and properties
- [ ] Write `tests/python/test_py_fleet.py`:
  - Verify `from_buildings([DwellingConfig(...)])` constructs a fleet with correct length
  - Verify `from_buildings` with custom `sample_weights=[2.0, 1.0]`
  - Verify `from_buildings` raises if `sample_weights` length != configs length
  - Verify `__len__` returns correct count
  - Verify `simulate(resolution=AggregationResolution.Hourly)` works
  - Verify `simulate(resolution="hourly")` string convenience works
  - Verify `simulate()` default uses FifteenMin
  - Verify `failures` property is empty list on all-success runs
  - Verify `n_succeeded` and `n_failed` properties
  - Verify that `from_resstock` still works (regression)
  - Verify progress callback is invoked with (completed, total) during simulate
  - Verify `from_buildings([])` with empty list raises ValueError (or returns fleet with len 0)
  - Verify `simulate(raise_on_failure=True)` raises on first failure (old behavior preserved)
  - Verify `simulate(raise_on_failure=False)` returns results with failures property populated
