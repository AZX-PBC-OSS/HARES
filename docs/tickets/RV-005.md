## Background/Context

`EnvironmentManager::update()` constructs a fresh `EnvironmentState` every timestep with 5+ Vec allocations that are immediately dropped when `self.latest_env = env` replaces the previous state. At 525,600 steps/year this produces ~7-10M alloc/free cycles, causing memory fragmentation and cache pressure.

Separately, `equipment_telemetry` in `dwelling/mod.rs:1642-1648` clones `desc.name` (String) and `eq.telemetry()` (HashMap) for every equipment piece every step when actors are present — another ~2-5M allocations/year.

This is the single highest-impact allocation source in the hot loop.

**Note:** This ticket subsumes RV-008 (StepResult clone, thermal_update clone, timestamp allocation) to avoid concurrent modifications to `dwelling/mod.rs`. All dwelling step-loop allocation work is consolidated here.

## API Change Risk

Changing `update()` from returning `EnvironmentState` to mutating `&mut EnvironmentState` is a significant internal API change. All call sites within `dwelling/mod.rs` that consume the returned value must be updated. No external callers exist (the method is `pub(crate)`), so this is safe. Verify no code caches a returned `EnvironmentState` by value.

## Progress

**Session 2026-03-27 (T2-6, T2-8, telemetry, zone lookup maps):**

- [x] **(T2-6)** `thermal_update` clone eliminated: `apply_thermal_update_to_zones` is now called before `upsert_domain(thermal_update)` so the value is moved, not cloned. Clone is retained only under `#[cfg(feature = "observe")]`.
- [x] **(T2-8)** `timestamp_buf`: pre-allocated `String` field on the recorder. Formatted in-place via `write!` with `%+` format instead of `to_rfc3339()`. No per-step String allocation.
- [x] **equipment_telemetry**: removed per-step `clear()`. Uses `get_mut()` + `clone_from()` for in-place updates — avoids String key reallocation on steady-state steps.
- [x] `zone_infiltration_columns` and `zone_lwr_columns` converted from `Vec<(ZoneId, usize)>` to `HashMap<ZoneId, usize>` for O(1) lookups in `record_step`.
- [x] One-step telemetry lag documented with a clear comment in source.
- [ ] **(T2-5)** `StepResult` clone is structurally unavoidable: `step()` returns `Result<StepResult>` AND stores it in `simulation_results.steps`. Both consumers need ownership; there is no safe borrow-then-move ordering here. Documented with a comment in source.

- [x] `EnvironmentManager::update_in_place()` — in-place mutation API implemented. Solar irradiance, schedule_values, zones Vecs pre-allocated on `EnvironmentManager`.
- [x] `custom_domains` — drain-recover-fill-swap pattern eliminates per-step allocation (recovers Vec allocation from previous step's DomainUpdates via drain).
- [x] `InvariantChecker` stored as a `Dwelling` field (line 586), constructed once at init.
