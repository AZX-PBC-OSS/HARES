## Background/Context

Currently:
- **EV** has `ChargingCurveLut` (soc → power_fraction) loaded via `pybamm_lut_path` config key at init time. Supports CSV/Parquet.
- **Battery** has hardcoded Li-NMC OCV table (11-point). No external injection, no charging curve LUT.
- Python adapters (`pybamm_battery.py`) can generate efficiency LUTs and degradation params, but these aren't wirable to the Rust model at runtime.

Users need to:
1. Generate CC-CV charging curves from PyBaMM for realistic battery behavior
2. Inject custom OCV tables for different chemistries (LFP, NCA, LTO)
3. Pass LUT data as numpy arrays, polars DataFrames, or Parquet file paths
4. Update LUTs on existing dwellings without reconstructing

### Python-side: LUT injection methods on PyDwelling

- [ ] Add `set_equipment_lut(name: str, lut_type: LutType, data)` to `PyDwelling`:
  - `name`: equipment name (e.g., "Battery", "EV")
  - `lut_type`: `LutType` enum from PY-005 — use `LutType.ChargingCurve`, `LutType.Ocv`, or `LutType.UNeg`
  - `data`: accepts multiple formats:
    - **Parquet file path** (`str`): load and parse
    - **polars DataFrame** with columns `soc` + `power_fraction` (LutType.ChargingCurve) or `soc` + `voltage` (LutType.Ocv) or `soc` + `potential` (LutType.UNeg)
    - **numpy arrays** as dict: `{"soc": array, "power_fraction": array}` or `{"soc": array, "voltage": array}`
    - **list[tuple[float, float]]**: list of (soc, value) pairs
  - Internally: find equipment by name, downcast to Battery/EV, call the appropriate setter
  - Raise `ValueError` if equipment doesn't support the LUT type
  - Raise `ValueError` if data dimensions are wrong or values are invalid
- [ ] Add `clear_equipment_lut(name: str, lut_type: LutType)` to `PyDwelling`:
  - Resets to default (hardcoded NMC for LutType.Ocv/LutType.UNeg, None for LutType.ChargingCurve)
- [ ] Add `get_equipment_lut(name: str, lut_type: LutType) -> Optional[polars.DataFrame]` to `PyDwelling`:
  - Returns current LUT data as polars DataFrame, or None if using defaults
  - Enables inspection and debugging of active LUT state
- [ ] **Checkpoint behavior**: LUTs are **configuration, not state** — they are NOT saved in checkpoints. After `load_state()`, LUTs must be re-injected. Document this clearly in docstrings and add test for it.
