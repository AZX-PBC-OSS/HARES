## Background/Context

Water heater equipment has three confirmed config key mismatches:

**CW-012 — Gas WH fuel type casing**: `gas.rs:350` reads `"FuelType"` (PascalCase),
but `resolve_water_heater.rs` writes `"fuel_type"` (snake_case via build_spec).
Every gas WH simulation runs with `FuelType::Gas` by coincidence (it's the default)
but the key never actually matches — any non-default fuel type would silently
use Gas.

**CW-013 — HPWH backup element capacity**: `heat_pump_wh.rs` reads
`"backup_element_power_w"` but the resolver writes `"heating_capacity_w"`.
The backup element power is always 0 W (the default), meaning HPWH backup heat
never activates regardless of what was in the HPXML.

**CW-014 — Tankless WH fuel type and EF casing**: `tankless.rs:80` reads
`"FuelType"` (PascalCase). The resolver writes `"fuel_type"` (snake_case). The
energy factor key `"energy_factor"` does match, but `"EnergyFactor"` alias reads
in the equipment are dead code (the value is never missing but the alias never
helped).

These are combined into a single ticket because all four WH types share the same
resolver file and the typed config approach for WH is structurally similar.

Fixes: CW-012 (gas WH fuel type), CW-013 (HPWH backup capacity), CW-014 (tankless
fuel type), AR-002 F-1 (WH side).

```rust
#[derive(Clone, Debug, Serialize, Deserialize)]

pub struct GasWaterHeaterConfig {
    pub equipment_id: Option<u32>,
    pub zone_id: Option<u16>,
    pub loop_id: Option<u16>,

    pub tank_height_m: Option<f64>,
    pub energy_factor: Option<f64>,
    pub uniform_energy_factor: Option<f64>,
    pub heating_capacity_w: Option<f64>,

    pub setpoint_c: Option<f64>,

    pub flue_loss_fraction: Option<f64>,

    pub zone_type: Option<String>,

}
```
`equipment_type_name() = "Gas Water Heater"`.

### `HeatPumpWaterHeaterConfig`
```rust
#[derive(Clone, Debug, Serialize, Deserialize)]

pub struct HeatPumpWaterHeaterConfig {
    pub equipment_id: Option<u32>,
    pub zone_id: Option<u16>,
    pub loop_id: Option<u16>,
    pub tank_volume_m3: Option<f64>,
    pub tank_height_m: Option<f64>,
    pub cop: Option<f64>,
    pub backup_element_power_w: Option<f64>,  // was "heating_capacity_w" — the mismatch
    pub ua_w_per_k: Option<f64>,
    pub setpoint_c: Option<f64>,
    pub tempering_valve_setpoint_c: Option<f64>,
    pub avg_water_draw_l_per_day: Option<f64>,
    pub performance_adjustment: Option<f64>,
    pub zone_type: Option<String>,
    pub first_hour_rating_m3: Option<f64>,
}
```
`equipment_type_name() = "Heat Pump Water Heater"`.

Note: the resolver writes `"heating_capacity_w"` for the backup element. This
struct uses `backup_element_power_w` as the canonical name. The resolver must be
updated in this ticket to write `backup_element_power_w` when constructing the
typed struct (not the old string key).
