## Background/Context

HARES-IO provides public weather parsers and a `WeatherTimeSeries` type, but none are exposed to Python. Users working with weather data, validating inputs, or building custom preprocessing pipelines need access.

**Verified Rust struct fields** (from `crates/hares-io/src/weather.rs`):

`WeatherMeta`: `location: String`, `latitude: f64`, `longitude: f64`, `timezone_offset_h: f64`, `elevation_m: f64`, `source_step_secs: u32`, `midpoint_offset_secs: u32`

`WeatherTimeSeries`: `meta: WeatherMeta`, `dry_bulb_c`, `dew_point_c`, `rel_humidity_pct`, `pressure_kpa`, `ghi_w_m2`, `dni_w_m2`, `dhi_w_m2`, `wind_speed_m_s`, `wind_dir_deg`, `opaque_sky_cover`, `horizontal_infrared_w_m2`, `sky_temp_c`, `ground_temp_c`, `liquid_precip_m` (all `Vec<f64>`), `surface_albedo: Option<Vec<f64>>`

**Note:** `parse_resstock_csv` requires 5 args `(path, elevation_m, latitude, longitude, timezone_offset_h)` — the Python binding must match this exactly. Solar position calculations need longitude and timezone.
