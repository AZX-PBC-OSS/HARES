## Background/Context

Architectural hardening: the dwelling reads equipment power/mode/soc/fuel via
string-keyed fallback chains (~line 1538, ~line 2240, ~line 2264). These are
structurally fragile — wrong key = silent zero, no compile-time guarantee. The
earlier AR-001 string-literal fixes (BUG-1/2, GAP-1/2) are already landed; this
ticket replaces the entire string-based read path with typed `core_output()` reads,
eliminating the class of bug permanently. Default stubs (CO-002) return zeros,
matching old unwrap_or(0.0) behavior during migration.

Also add `equipment_core: HashMap<EquipmentId, CoreOutput>` to EnvironmentState for
actor consumption (CO-005), with `#[serde(default, skip_serializing)]`.

**Parallel dependency:** This ticket assumes CFG fail-fast config validation is
in place or landing in parallel — typed core outputs are only trustworthy if
equipment is constructed from validated configs.
