## Background/Context

Two separate quality issues:

**1. SendDwellingPtr fragility (py_gym.rs:111-119):**
The current pattern extracts raw pointers from `PyRef` borrows that are dropped after `.collect()`:
```rust
let ptrs: Vec<SendDwellingPtr> = dwellings
    .iter()
    .map(|d| {
        let bound = d.bind(py).borrow();  // PyRef dropped here
        SendDwellingPtr(&*bound as *const PyDwelling)
    })
    .collect();
```
The `Py<PyDwelling>` handles keep objects alive, so this is technically safe, but the pattern is fragile — a refactor that moves the `dwellings` vec or changes the borrow could introduce UB. The raw pointer extraction should be more robust.

**2. Missing `__repr__` on 7 pyclass types:**
`PyDwelling`, `PyTimestepsIter`, `PyFleet`, `PyBattery`, `PyPvSoilingConfig`, `PyPv`, `PyEv` all lack `__repr__`. This makes debugging painful — printing any of these shows `<builtins.PyDwelling object at 0x...>` instead of useful state.

## Work to Do

### SendDwellingPtr Hardening
- [ ] Refactor `batch_step_py()` to hold `PyRef` borrows alive across the detach:
  ```rust
  // Hold borrows alive for the duration of the parallel section
  let borrows: Vec<PyRef<'_, PyDwelling>> = dwellings
      .iter()
      .map(|d| d.bind(py).borrow())
      .collect();
  let ptrs: Vec<SendDwellingPtr> = borrows
      .iter()
      .map(|b| SendDwellingPtr(&**b as *const PyDwelling))
      .collect();
  // borrows live until end of function scope
  ```
  This makes the lifetime relationship explicit — `borrows` outlives `ptrs`.
- [ ] Add a `// SAFETY:` comment explaining: borrows kept alive in `borrows` vec, `Py<PyDwelling>` handles keep objects alive, step_core()/observation() only use internal Mutex
- [ ] Verify this works with `py.detach()` — `PyRef` implements `!Send` so it stays on the calling thread; only the raw pointers cross thread boundaries via `SendDwellingPtr`
