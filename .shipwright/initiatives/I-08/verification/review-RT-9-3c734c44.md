## Findings

### 1. HIGH - config_mut callers left behind; observe-feature test target does not compile
tests/freefloat_oracle.rs:208, :1343, :1365 call `thermal_solver.config_mut().natural_ventilation = None` (target `freefloat_oracle` of hares-core, gated by `observe`). The commit removed config_mut, so with `--features observe` three E0599 errors break the target. The commit's claim that ventilation is "the only part of the configuration mutated after construction" is false: these tests mutate `natural_ventilation` after construction. The default-feature gate hides it, so the red team's "one production use" held but test usage was not grepped.
Failure: `cargo test -p hares-core --features observe --test freefloat_oracle` fails to compile; the OCHRE free-float oracle (which the plan relies on) is unrunnable.
Fix: decide the contract. Either expose a narrow `set_natural_ventilation(Option<NaturalVentilationConfig>)` / `natural_ventilation_mut` (natural ventilation also does not affect scratch sizing), or have the test disable natural ventilation via the dwelling config/overrides before construction (preferred: keeps geometry and config immutable). Then run the observe-feature suites.

### 2. MEDIUM - last_coupled_state is redundant state; derive it
mod.rs:129-130, :413-414 (and snapshot field). Every writer sets it from the same condition as last_coupling: stepping.rs:715-722 (prepare_inputs: Identity iff coupling_buf non-empty, then last_coupling = coupling_buf) and :757-763 with :1175 (integrate_inner). Constructor starts empty/Uncoupled (mod.rs:1011-1012). So it is exactly `!last_coupling.is_empty()` in all reachable states. Storing it forces the new cross-check in restore_state (mod.rs:1354-1362) whose only purpose is rejecting snapshots that contradict themselves, and widens the public API: CoupledState was pub(crate) and is now `pub`, exported from lib.rs and serde-derived, solely to be a snapshot field. Correct design: remove `last_coupled_state` from ThermalSnapshot and from the solver (use `fn coupled(&self) -> bool { !self.last_coupling.is_empty() }` or keep a private enum computed on demand; shared_prefix_variant compares with the derived value). That deletes the consistency check, one error path, the public enum, the Serialize/Deserialize derives on it, and one field of the checkpoint contract; an invalid combination becomes unrepresentable. Test resumed_run_equals_continuous_run (checkpoint_regressions.rs:615) would assert `!checkpoint.thermal.last_coupling.is_empty()` instead.

### 3. MEDIUM - ThermalSnapshot is now an unversioned serialization contract
checkpoint.rs:92 embeds hares_envelope::ThermalSnapshot directly; it now derives Serialize/Deserialize/PartialEq (mod.rs:400). Any future field added to the snapshot silently changes the checkpoint format without the CHECKPOINT_VERSION bump the format relies on (the bump is manual, in a different crate). The "travels by construction" benefit is real and the unification is the right call, but the versioning link must be enforced: e.g. a test that pins the serialized form of a fully populated checkpoint (field names) so a snapshot change forces a version decision, or a doc note on ThermalSnapshot that its shape is the checkpoint schema. PartialEq on the public type is acceptable (tests use it for atomicity assertions) but is also only needed by tests; fine to keep. Round-trip completeness: all five replaced fields (envelope_state->x, thermal_last_u, lwr_t_prev_c, interior_surface_temps, interior_surface_prev_temps) are present in ThermalSnapshot and both restore call sites (dwelling/mod.rs:5054, :5173) pass `&cp.thermal`; no field lost. No Python/benches/examples reference the removed checkpoint fields (grep of python/, benches/, tests/ clean).
